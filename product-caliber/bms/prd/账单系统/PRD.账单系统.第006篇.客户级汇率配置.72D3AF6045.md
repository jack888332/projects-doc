## 1. 客户级汇率配置

[🔗原型链接](http://localhost:4181/#/billing/rates)

<a id="doc-72D3AF6045-rate-config-c1470f0a"></a>
### 1.1 章节概述

客户级汇率配置解决的是“账单生成前，某个客户、某个货币对默认采用什么汇率”的问题。它位于账单生成之前，是账单特调汇率快照的前置配置；账单生成之后，采用的汇率会进入账单侧快照，由[金额汇兑](PRD.账单系统.第014篇.金额汇兑.27B80EF314.md#doc-27B80EF314-currency-exchange-e7e21dd6)继续定义换算、汇总和核销规则。特调汇率采用与账单配置相同的统一可复用配置模型，客户引用稳定的配置编号，任务创建时解析并锁定当时生效的准确版本；店铺和客户组仅用于批量选客和筛选，不参与运行时汇率命中。

本章的业务链路如下：

1. 财务先维护基准汇率表。基准汇率表支持手动导入，也支持财务在页面中添加、修改、移除基准汇率；`抓取`仅保留功能入口，不开放使用，也不参与基准汇率表维护。
2. 账单默认汇率按`账单级锁定汇率 > 客户引用的特调配置准确版本 > 基准汇率表 > 店铺汇率表 > 1`取值；若这些来源都找不到可用汇率，该货币对汇率固定按 `1` 处理。
3. 财务维护统一的特调汇率配置并通过向导分配给具体客户；特调配置不再按应收 / 返款等账单类型拆分专属规则。
4. 生成账单时，系统按客户和货币对命中默认汇率。本章不设置`账单特调汇率日期`概念，也不支持按账期开始日、账期结束日或指定日期切换汇率口径。
5. 账单生成成功后，系统把客户实际采用的配置编号、准确版本、客户引用记录、货币对规则、基准汇率、店铺汇率、推导关系和最终默认汇率固化到账单特调汇率快照。

客户级汇率配置不直接改写已生成账单，也不替代账单详情页中的账单级汇率调整。基准汇率、特调规则或店铺汇率表发生变化后，只供后续新账单计算默认汇率，不触发既有账单重跑，也不得自动回写历史账单。普通账单重算必须沿用目标账单锁定的汇率快照；只有财务在账单详情显式提交账单级汇率调整时，系统才按本次明确输入或明确选择的准确汇率版本形成新的账单级汇率快照，再据此重算。

基准汇率和特调汇率在导入、添加、修改、发布、分配、确认或启用前，必须校验币种、货币对、汇兑方向、汇率值、调整方式、调整方向、调整值、客户引用唯一性及推导结果是否合法。任一校验不通过时，不得保存、发布、分配、确认或启用，并应定位到具体客户或字段说明原因。账单任务只读取已经通过校验且可以生效的汇率配置；缺少兜底汇率时按本章规定使用`1`，不得把可在配置阶段识别的问题转化为任务执行异常。

<a id="doc-72D3AF6045-rate-config-59ab0ea9"></a>
### 1.2 页面原型概述

客户级汇率配置页面用于让财务先维护基准汇率，再维护特调配置及其客户引用。页面划分为左右并列的两个业务区域：左侧为基准汇率表区，右侧为特调配置区，并在右侧通过页签切换`配置清单`和`客户引用配置情况`；窄屏仅调整为上下排列，不改变区域字段与业务操作。

| 区域 | 区域用途 | 业务字段 | 支持操作 |
| :--- | :--- | :--- | :--- |
| 基准汇率表区 | 展示当前已确认或待确认的基准货币对汇率 | `货币对`、`汇兑方向`、`基准汇率`、`汇率来源`、`来源时间`、`确认状态`、`当前生效` | 查看、确认、添加、修改、移除基准汇率；支持手动导入基准汇率；`抓取`仅保留功能入口，不开放使用，也不参与基准汇率表维护；确认后的基准汇率作为客户级汇率配置的兜底来源。 |
| 配置清单区 | 维护可供一个或多个客户复用的特调规则集合 | `配置编号`、`配置版本`、`配置标签`、`命中客户数`、`状态`、`特调汇率`、`调整规则` | 新建配置（先设置配置，再指定适用客户，可跳过）、另存为新配置、编辑并发布新版本、从操作列查看版本记录、查看任一版本的完整货币对规则、分配客户、查看引用客户、停用；`配置备注`以备注文字显示在`配置编号`下方，未填写时显示`--`；`配置版本`列紧随`配置编号`列，当前生效版本以小号版本标签显示在上方；存在待生效版本时，在同一单元格下方以备注文字显示`将在 YYYY/MM/DD 切换为 Vx`，日期取该版本的指定生效日期。`特调汇率`列按当前生效版本的每条规则换行展示货币对 / 汇兑方向与默认汇率预览；非固定汇率值规则没有可用基准汇率时，该列按 `1` 展示，不追加店铺汇率说明。`调整规则`列紧随其后，与`特调汇率`行对齐；百分比缩放和固定汇率差显示调整方式、调整方向和调整值，固定汇率值只显示`固定汇率值`，不显示调整方向、调整值或`直接指定`；多条规则依次换行。配置清单不单独展示`待生效版本`、`历史版本数量`和`配置备注`列；历史版本数量及全部版本详情在版本记录弹窗中查看，并执行[配置版本、停用与引用约束](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-67bb7ea2)；分配客户只选择配置编号，不选择历史版本。 |
| 客户引用配置情况 | 展示每个客户当前引用的特调配置及当前生效版本；未配置或查询时点不存在有效引用的客户不进入本表 | `客户（会员）`、`客户编码`、`会员编码`、`所属店铺`、`所属客户组`、`引用配置`、`配置版本`、`配置标签`、`特调汇率`、`调整规则` | 按客户 / 会员、店铺、客户组和配置编号筛选；选择店铺后只显示该店铺创建的客户组选项；切换配置；查看所引用配置。列表不展示`生效期间`和`状态`列；客户引用关系不设置启用状态，是否为当前有效引用由客户、配置编号和生效时段共同判定，启用状态只归属于配置并在配置清单展示和维护。`引用配置`下方以备注文字显示`配置备注`，未填写时显示`--`；`配置版本`列紧随`引用配置`列，显示查询时点生效的准确版本号，不显示组合后的配置版本编号。`特调汇率`和`调整规则`按配置清单区的同一口径展示，并与每条货币对规则逐行对齐。 |

原型页面的阅读顺序应理解为：

1. 财务先通过`导入`、`添加`、`修改`或`移除`维护基准汇率表；`抓取`仅保留功能入口，不开放使用，也不参与基准汇率表维护。来源接入、认证方式和失败重试规则不由本 PRD 定义。
2. 基准汇率表只要求维护以财务本位币为锚点的货币对，方向可以是`外币 -> 财务本位币`，也可以是`财务本位币 -> 外币`，不要求支持批量货币对预览。
3. 财务新建特调配置时先设置配置，再进入`指定适用客户`步骤选择初始引用客户；该步骤可以跳过，跳过时创建`未引用配置`，指定客户时可按店铺和客户组筛选，规则按[客户配置分配向导](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-4a7dfa43)和[配置版本、停用与引用约束](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-67bb7ea2)执行。同一客户、特调汇率配置类型和生效时段只能有一份引用；特调配置新版生效时，全部引用该配置的客户统一采用新版。
4. 客户当前特调配置中没有所需货币对或对应规则不可用时，系统先使用已确认的基准汇率兜底；若基准汇率也不可用，再使用店铺汇率表兜底；若仍找不到兜底汇率，该货币对汇率固定按 `1` 处理。
5. 特调配置的配置标签、店铺、客户组与指定客户的组合选客、统一版本升级、强制切换、停用和引用留痕采用[统一配置与配置标签](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-4f4a8fbe)至[配置版本、停用与引用约束](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-67bb7ea2)。应收、返款和特调汇率三类配置分别建立引用，一个客户可分别引用不同配置。特调汇率配置切换和版本生效只进入内部审计，不触发客户账单配置变更邮件。
6. 页面所有操作均由财务执行。页面及编辑弹窗不展示操作人和操作时间；基准汇率以及特调配置、配置版本、客户分配的新增、导入、修改、发布、移除、确认和停用统一进入内部审计，规则见[内部审计](#doc-72D3AF6045-rate-config-fdd56741)。

### 1.3 基准汇率表

基准汇率表是客户级汇率配置的基础来源，用于承接财务确认的标准汇率。基准汇率由财务维护，可以通过手动导入产生，也可以由财务在页面中添加、修改或移除。`抓取`仅保留功能入口，不开放使用，也不参与基准汇率表维护。

1. 手动导入：财务上传基准汇率表，系统校验币种、货币对、汇兑方向和汇率值。
2. 手动维护：财务可以在页面中添加、修改或移除单条基准汇率记录，系统校验规则与手动导入一致。
3. 系统抓取：仅保留功能入口，不开放使用，也不参与基准汇率表维护。
4. 店铺汇率表是现有能力，本 PRD 不重新定义其配置需求；店铺汇率表不写入基准汇率表，也不替代特调汇率和基准汇率，仅在特调汇率和基准汇率都不可用时，作为后续兜底来源。

基准汇率货币对必须以财务本位币为锚点；财务本位币固定为人民币，系统内统一用 `CNY` 表达。货币对的摆位用`左侧币种`和`右侧币种`表达，因为汇兑方向可以独立变化，货币摆位也可以调整。货币对方向不是固定的，可以是`外币 -> CNY`，也可以是`CNY -> 外币`。但同一条基准汇率必须明确方向，不能只记录无方向的汇率值。

货币对是否相同，只看两个币种的组合是否相同，不看左侧币种和右侧币种的排列，也不看汇兑方向。例如 `USD / CNY`、`CNY / USD`、`USD -> CNY` 和 `CNY -> USD` 都属于同一货币对。

本 PRD 将`左侧币种 + 右侧币种 + 汇兑方向`称为汇率设置的三元口径。三元口径不是一个必须落库的独立字段，也不是判断货币对是否相同的方法，而是系统判断“是否同一条汇率设置”的业务唯一性口径。

三元口径的理解方式如下：

1. `左侧币种`和`右侧币种`只表达货币对在页面、导入文件和快照中的摆位。
2. `汇兑方向`表达汇率值实际从哪一侧换算到哪一侧。
3. 判断两个货币对是否相同，只比较左侧币种和右侧币种组成的币种集合；只要币种集合一致，即认定为同一货币对。
4. 判断两个汇率设置是否相同，才需要同时比较左侧币种、右侧币种和汇兑方向。
5. 汇率值只对同一三元口径有效，不得脱离汇兑方向单独复用。
6. 例如 `左侧币种 = USD`、`右侧币种 = CNY`、`汇兑方向 = USD -> CNY` 与 `左侧币种 = USD`、`右侧币种 = CNY`、`汇兑方向 = CNY -> USD` 属于同一货币对，但属于两条不同汇率设置；后者如未直接维护，应通过倒数推导，而不是直接复用前者汇率。
7. 基准汇率、特调汇率、账单特调汇率和账单内锁定汇率都必须按三元口径判断汇率设置唯一性、命中关系和汇率一致性。

1. 外币对外币的组合很难穷举，若要求财务直接维护所有外币货币对，容易产生漏配、重复配置和方向冲突。
2. 账单汇总、调账归属和内部核算都需要形成财务本位币金额，因此外币对外币汇率可以通过两条以 `CNY` 为锚点的汇率间接推导。
3. 例如需要计算`USD -> TWD`时，系统先得到 `USD -> CNY` 和 `TWD -> CNY` 的等价汇率，再相除得到：`USD -> TWD = (USD -> CNY) / (TWD -> CNY)`。若基准表维护的是 `CNY -> USD` 或 `CNY -> TWD`，系统先取倒数得到对应的`外币 -> CNY`等价汇率，再参与相除。
4. 基准汇率推导只要求货币对可通过 `CNY` 换算，不要求两条参考汇率归属同一供应链、店铺或其它业务对象。

基准汇率表应至少记录以下业务字段：

| 字段 | 说明 |
| :--- | :--- |
| 汇率来源 | 基准汇率表来源取`手动导入`或`手动添加`；`抓取`仅保留功能入口，不开放使用，也不参与基准汇率表维护。 |
| 来源时间 | 汇率被导入、添加或修改的时间，用于追溯来源，不作为账单特调汇率日期。 |
| 左侧币种 | 货币对左侧展示的币种。 |
| 右侧币种 | 货币对右侧展示的币种。左侧币种与右侧币种二者必须有一端是财务本位币 `CNY`，另一端是外币。 |
| 汇兑方向 | 明确表达 `左侧币种 -> 右侧币种`或`右侧币种 -> 左侧币种`，不得只保存无方向汇率。 |
| 基准汇率 | 财务基于左侧币种、右侧币种和汇兑方向确认的原始汇率值。 |
| 获取方式 | 手动导入、手动添加、手动修改；系统抓取仅保留功能入口，不开放使用。 |
| 确认状态 | 待确认、生效、停用。 |
| 当前生效标记 | 同一货币对、同一汇兑方向存在多来源或多条记录时，由财务确认哪一条作为当前账单生成兜底汇率。 |
| 内部审计记录 | 导入、添加、修改、移除、确认、停用等操作统一记录操作人、操作时间和操作原因，不在页面展示；规则见[内部审计](#doc-72D3AF6045-rate-config-fdd56741)。 |

基准汇率表规则：

1. 基准汇率表只有在财务确认生效后，才能作为客户级汇率配置的基础汇率来源。
2. 未确认、解析失败、币种缺失、方向不明确或数值异常的汇率，不得参与账单生成。
3. 基准汇率表中的货币对必须有一端是财务本位币 `CNY`，另一端是外币；方向可以是`外币 -> CNY`，也可以是`CNY -> 外币`。
4. 基准汇率表不允许直接维护外币对外币的基准汇率，也不需要支持任意货币对批量预览。
5. 基准汇率表中的货币对方向必须明确；系统不得只保存无方向汇率。
6. 同一货币对、同一汇兑方向在同一时点只能有一条当前生效基准汇率。若同一货币对和汇兑方向存在多个来源或多条记录，必须由财务确认当前生效记录；系统不得自动随机选择。
7. 财务允许添加、修改、移除已确认生效的基准汇率。修改或移除后，系统需要重新计算所有受该货币对影响的特调汇率结果，但不得因此触发账单重跑。
8. 已生成账单始终以账单特调汇率快照为准；基准汇率添加、修改、移除、停用或重新导入，不得自动回写历史账单。
9. 基准汇率变更必须进入内部审计记录并保存变更原因，避免后续无法解释客户级默认汇率变化。

基准汇率命中规则：

1. 未命中任何特调汇率时，系统先使用已确认生效的基准汇率兜底。
2. 若同一货币对、同一汇兑方向存在多个已确认来源，系统不得随机选择，必须按财务确认的当前生效记录命中。
3. 若无法命中当前生效基准汇率，系统再按账单归属店铺和货币对命中店铺汇率表；若店铺汇率也不可用，该货币对汇率固定按 `1` 处理，并在账单特调汇率快照中记录未命中兜底汇率的原因。
4. 当账单需要的汇兑方向与基准表已维护方向相反时，系统允许在同一左侧币种和右侧币种范围内按倒数推导。
5. 当账单需要`外币A -> 外币B`方向时，系统允许通过`外币A -> CNY`和`外币B -> CNY`的等价汇率间接推导：`外币A -> 外币B = (外币A -> CNY) / (外币B -> CNY)`。
6. 所有推导后的汇率必须在账单特调汇率快照中记录原始货币对、推导方式和推导后结果。
7. 本规则只约束基准汇率表的兜底与推导口径，不限制特调汇率直接维护外币对外币等非 `CNY` 锚点货币对。

<a id="doc-72D3AF6045-rate-config-4cd47ea6"></a>
### 1.4 特调汇率规则

特调汇率规则用于在基准汇率基础上，按客户和货币对生成账单默认汇率。它只处理“这个客户是否要按不同于基准汇率的方式生成默认汇率”，不处理账单生成后的金额换算。

特调汇率采用统一配置实体并实行版本控制。编辑过程不保存草稿；财务从当前生效版本进入编辑，发布成功后形成不可修改的新准确版本。发布时默认立即生效，也可指定未来日期生效；新版本生效时全部引用该配置编号的客户统一采用新版，历史账单快照不得被回写。

规则维度如下：

| 规则维度 | 说明 |
| :--- | :--- |
| 配置版本 | 版本快照分别记录配置编号和准确版本，页面组合展示为配置版本编号。 |
| 客户引用 | 记录客户引用记录编号、生效时点和配置编号；账单任务创建时再解析并锁定当时生效的准确版本。 |
| 货币对 | 用左侧币种和右侧币种表达货币摆位，并必须明确汇兑方向，例如 `USD -> TWD`。特调货币对不要求锚定财务本位币，汇率设置必须基于左侧币种、右侧币种和汇兑方向共同确定。 |
| 基准汇率 | 当前生效基准汇率。使用固定汇率值时，基准汇率可记录为`不适用`。 |
| 调整方向 | 上浮或下浮；固定汇率值不需要调整方向。 |
| 调整方式 | 百分比缩放、固定汇率差、固定汇率值。 |
| 调整值 | 百分比、固定汇率差或固定汇率值。 |
| 特调后默认汇率 | 系统根据基准汇率和特调规则计算出的默认汇率结果。 |
| 配置启用状态 | 归属于特调配置，不归属于客户引用关系；配置启用后参与对应客户的账单生成，配置停用或客户未配置所需货币对时，回到基准汇率表、店铺汇率表和`1`的兜底链路。 |
| 内部审计 | 新增、另存为新配置、发布版本、分配客户、强制切换、解除引用和停用统一进入内部审计记录；页面不展示操作人和操作时间。 |

支持的调整方式如下：

| 调整方式 | 计算方式 | 示例 |
| :--- | :--- | :--- |
| 百分比缩放 | 上浮：`账单默认汇率 = 基准汇率 × (1 + 调整比例)`；下浮：`账单默认汇率 = 基准汇率 × (1 - 调整比例)` | 基准汇率 `7.0000`，调整方向为上浮，调整值填 `2`，表示 `2%`，默认汇率为 `7.1400`。 |
| 固定汇率差 | 上浮：`账单默认汇率 = 基准汇率 + 固定差值`；下浮：`账单默认汇率 = 基准汇率 - 固定差值` | 基准汇率 `7.0000`，调整方向为上浮，固定差值 `0.0300`，默认汇率为 `7.0300`。 |
| 固定汇率值 | `账单默认汇率 = 固定汇率` | 不再引用基准汇率，直接使用 `7.1000`。 |

特调汇率规则要求：

1. 同一客户在同一特调汇率配置类型和同一生效时段只有一份配置引用；该引用的准确版本内，同一货币对只允许存在一条启用中的特调规则。特调汇率不按账单类型拆分。
2. 货币对方向必须明确。特调规则可以直接维护账单实际需要的货币对，不要求一端必须是财务本位币 `CNY`；若账单需要反向换算，系统按明确的倒数规则推导，并在账单特调汇率快照中记录推导来源。
3. 固定汇率值适用于有明确约定汇率的场景；使用固定汇率值时，不要求存在对应基准汇率，但必须保存固定汇率值和操作原因。
4. 百分比缩放和固定汇率差都以基准汇率为基础；若特调货币对无法直接命中基准汇率，但可通过[基准汇率表](#doc-72D3AF6045-rate-config-09c87a60)的财务本位币锚点规则推导出基准汇率，系统允许先推导再计算特调后默认汇率。
5. 百分比缩放和固定汇率差不以店铺汇率为基础继续调整；若基准汇率直接命中和推导均不可用，该特调规则本次不产出默认汇率，系统继续按基准汇率表、店铺汇率表、`1`兜底，并在账单特调汇率快照中记录未命中原因。
6. 百分比缩放的输入单位为百分数，输入 `2` 表示 `2%`，不是 `0.02`。
7. 固定汇率差不允许出现负数；若需要下浮，应选择调整方向为`下浮`，固定差值仍填写正数。
8. 调整后默认汇率必须大于 `0`；固定汇率值也必须大于 `0`。
9. 原型表格中展示的特调汇率，是当前基准汇率可用时计算出的默认汇率预览。非固定汇率值规则没有可用基准汇率时，特调汇率固定显示 `1`，不追加店铺汇率说明；该展示值不代表以 `1` 为基础继续执行百分比缩放或固定汇率差，也不改变账单生成时按店铺汇率表、`1`逐级兜底的规则。固定汇率值的调整规则只显示`固定汇率值`，不显示调整方向、调整值或`直接指定`。系统仍需保留配置编号、准确版本、客户引用、调整方式、调整方向和调整值。
10. 新建特调配置时配置编号必填且唯一，配置备注选填；备注未填写时，在配置清单的`配置编号`下方以备注文字显示`--`，配置编号和配置版本仍按独立字段展示。财务配置货币对、调整方式和调整值后，按[配置版本、停用与引用约束](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-67bb7ea2)进入`指定适用客户`步骤选择具体客户，该步骤可跳过，再发布配置；规则编辑弹窗不直接保存店铺、客户组或多个适用对象。配置清单保留每个已发布版本的完整货币对规则、版本状态、发布时间、生效时间和变更原因；财务从操作列打开版本记录弹窗后，可以查看任一版本的完整详情。
11. 发布特调配置新版本或停用配置时，只影响后续新账单；任何既有账单的普通重算均沿用该账单锁定的汇率快照，不得隐式读取客户当前特调配置。财务显式提交账单级汇率调整时，系统按本次输入或所选准确版本另建账单级汇率快照，不回写旧快照。
12. 存量特调汇率须在固定迁移时点按旧配置层级`客户级 > 客户组级 > 店铺级`逐客户计算唯一最终生效规则，并把同一份存量规则转换为一个统一配置及对应客户引用。同一优先级命中多份规则或无法确定唯一结果时进入冲突清单，由财务确认后再迁移。
13. 特调配置的配置标签、分配向导、统一版本升级、强制切换和停用规则采用[统一配置与配置标签](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-4f4a8fbe)至[配置版本、停用与引用约束](PRD.账单系统.第004篇.配置版本与客户引用.40A1257C97.md#doc-40A1257C97-config-version-67bb7ea2)；三类配置的引用关系相互独立。特调汇率配置切换和版本生效不发送客户账单配置变更邮件，只记录内部审计。

<a id="doc-72D3AF6045-rate-config-42cd9f89"></a>
### 1.5 账单生成命中与快照

账单生成前，系统必须按账单客户和账单内货币对命中客户级汇率配置。本章不设置`账单特调汇率日期`概念，账单生成时不支持按账期开始日、账期结束日或指定日期切换汇率口径。

命中顺序如下：

1. 新账单生成时，系统先读取该客户在任务执行快照中锁定的特调配置编号和准确版本，再按账单所需货币对查找启用规则。规则方向与账单所需方向相反时，按倒数规则推导默认汇率。
2. 命中特调固定汇率值时，直接作为账单默认汇率。
3. 命中特调百分比缩放或固定汇率差时，先按[基准汇率表](#doc-72D3AF6045-rate-config-09c87a60)的基准汇率命中规则取已确认生效的基准汇率；若特调货币对不是 `CNY` 锚点货币对，则允许通过[基准汇率表](#doc-72D3AF6045-rate-config-09c87a60)的财务本位币锚点规则先推导基准汇率，再按特调规则计算账单默认汇率。
4. 客户当前特调配置没有对应规则或规则无法产出有效默认汇率时，使用已确认生效的基准汇率作为下一优先级默认汇率。
5. 若账单所需货币对未直接命中基准汇率，但可通过财务本位币锚点汇率推导，系统允许按[基准汇率表](#doc-72D3AF6045-rate-config-09c87a60)的倒数或相除规则自动推导。
6. 若特调规则和基准汇率均不可用，系统使用店铺汇率表作为下一优先级默认汇率。
7. 若客户特调配置、基准汇率表和店铺汇率表均不可用，该货币对汇率固定按 `1` 处理；同币种换算同样固定按 `1` 处理。

账单生成成功后，系统必须把客户、配置编号、准确版本、客户引用记录编号、命中的货币对规则、基准汇率、店铺汇率、汇率来源、调整方式、调整方向、调整值、推导关系和计算后的默认汇率一起固化到账单特调汇率快照中。若命中的是固定汇率值，基准汇率和店铺汇率可记录为`不适用`，但固定汇率值、配置编号和准确版本必须进入快照。后续客户级汇率配置或店铺汇率表变化只影响后续新账单，不触发 BMS 任务，也不得回写历史账单；普通账单重算继续使用目标账单快照，显式账单级汇率调整另建新快照。

账单生成命中规则补充：

1. 账单内出现多个货币对时，必须逐一命中默认汇率；不能因为部分货币对命中成功，就忽略其它缺失货币对。
2. 倒数推导只用于同一人民币锚点货币对方向相反的场景。例如已维护`USD -> CNY`但账单需要`CNY -> USD`，或已维护`CNY -> USD`但账单需要`USD -> CNY`。
3. 未直接命中特调规则时，外币对外币兜底推导只允许通过财务本位币间接换算，不允许在两个无关货币对之间任意交叉推导。
4. 推导后的汇率必须保留推导来源，例如`由 USD -> CNY 倒数推导 CNY -> USD`，或`由 USD -> CNY 与 TWD -> CNY 相除推导 USD -> TWD`；若直接命中特调规则，则记录客户实际采用的配置编号和准确版本，不再额外要求经 `CNY` 推导。
5. 因缺少汇率兜底而按 `1` 处理时，系统必须在账单特调汇率快照中记录客户、货币对，以及客户特调配置、基准汇率表、店铺汇率表均未命中的结果，便于财务后续核对配置。
6. 缺少汇率兜底后按 `1` 处理的规则，同时适用于账单生成和财务在账单详情页触发的账单侧重算。
7. 系统不因汇率按 `1` 处理而增加独立二次确认，也不触发账单自动审核；账单必须由财务在审核环节确认金额和汇率口径无误后，才能进入后续流程。
8. 账单详情页允许在状态规则许可范围内进行账单级汇率调整；账单级调整只影响当前账单，不回写客户级汇率配置。

### 1.6 与金额汇兑的关系

客户级汇率配置负责决定账单生成前的默认汇率；金额汇兑负责定义账单生成后如何锁定快照、如何换算金额、如何汇总和核销。

1. 客户级汇率配置输出的是账单默认汇率。
2. 账单生成时，账单默认汇率被固化为账单特调汇率快照。
3. 基准汇率或特调规则变化后，可以重新计算后续账单默认汇率结果，但不会自动触发既有账单重跑；店铺汇率表变化不触发 BMS 任何动作。
4. 账单详情页允许在状态规则许可范围内进行账单级汇率调整；账单级调整只影响当前账单，不回写客户级汇率配置。
5. 账单费项明细中的汇率默认值取值优先级为：`账单级锁定汇率 > 客户引用的特调配置准确版本 > 基准汇率表 > 店铺汇率表 > 1`。
6. 历史账单始终以账单快照为准，不再读取最新客户级汇率配置。
7. 特调汇率与应收、返款账单配置的客户引用关系相互独立：三类配置分别校验客户引用唯一性，一个客户可以分别引用不同的配置编号；各类任务创建时分别解析并锁定当时生效的准确版本。

客户级账单配置提供出账范围和账期口径，客户级汇率配置提供生成前的默认汇率。两类前置配置都具备后，账单生成机制才能按稳定快照归集来源数据并形成账单结果。

<a id="doc-72D3AF6045-rate-config-fdd56741"></a>
### 1.7 内部审计

基准汇率和特调汇率的新增、导入、修改、移除、确认、停用等操作必须形成内部审计记录，统一见[内部审计](PRD.账单系统.第019篇.内部审计.38B07AC864.md#doc-38B07AC864-internal-audit-b4731bb9)。

1. 汇率配置页面及编辑弹窗不展示操作人、操作时间；操作人、操作时间、操作原因、变更前值和变更后值只在内部审计中查询。
2. 每次变更必须记录配置编号、准确版本、客户、货币对、变更前后汇率设置、客户分配与强制切换范围、操作原因、操作人、操作时间和逐客户执行结果。
3. 操作失败或被系统阻断时，也应记录阻断原因，不得只记录成功操作。
