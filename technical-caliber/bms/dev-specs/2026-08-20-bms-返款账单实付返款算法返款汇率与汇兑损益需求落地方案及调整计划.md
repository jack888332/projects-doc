### 1.3 核心结论摘要

1. 返款金额链路必须从“先换算、后扣减”改为“先扣减、后换算”：`应付返款 = 到付金额 - 到付附加费总额`，`实付返款（准） = 应付返款 - 返款账单指定扣减费项`，`实付返款 = 实付返款（准） × 返款汇率`。
2. `返款汇率 = 货款原始币种 → 货款结算币种`，生成账单时按汇率层级取得并随账单锁定；同币种固定为 `1`。
3. 订单费用报表后续只导入 `实收回款` 和 `回款汇率`，系统不再依赖 `sale_order_package_fee.type` 区分返款汇率和回款汇率。
4. 汇兑损益按 `实付返款（准） ×（标准化回款汇率 - 标准化返款汇率）` 计算，只展示在返款账单详情和财务内部导出中。
5. 历史 `collection` 和 `payment_collect` 存量原记录保留，但不参与新账单的币种、汇率、金额计算或核销。

## 2. 业务口径冻结

### 2.1 返款金额链路

按业务订单计算：

| 步骤 | 公式 | 币种 | 不满足时的处理 |
| --- | --- | --- | --- |
| 1. 匹配货款原始币种 | 按应付返款真实原始币种匹配明确规则，无明确规则时匹配 `其他` 兜底 | 货款原始币种 | 无匹配规则时，受影响订单不得进入本次返款账单 |
| 2. 确定货款结算币种 | 读取匹配规则的结算币种 | 货款结算币种 | 结算币种为空时不得保存配置或生成账单 |
| 3. 识别到付金额与到付附加费 | `到付金额 = cod_price`；`到付附加费总额 = dest_country_surcharge_amount`，属于非费项 | 货款原始币种 | 缺少到付金额或到付附加费总额时订单不得进入本次账单 |
| 4. 识别应付返款 | `应付返款 = 到付金额 - 到付附加费总额`，并与 OIS 订单级 `collection_price` 一致；BMS 直接读取 `collection_price` 作为应付返款本金 | 货款原始币种 | 缺少应付返款本金，或公式结果与 `collection_price` 不一致时，订单不得进入本次账单并记录差异 |
| 5. 汇总指定扣减费项 | 命中返款扣减配置的费项统一换算为货款原始币种后汇总 | 货款原始币种 | 缺少必要汇率时订单不得进入本次账单 |
| 6. 计算实付返款（准） | `实付返款（准） = 应付返款 - 返款账单指定扣减费项` | 货款原始币种 | 负数按 7.5 配置顺延或反向计入应收 |
| 7. 锁定返款汇率 | `货款原始币种 → 货款结算币种`，按 15.3.1 汇率层级取得并保存快照 | 返款汇率 | 缺少必要汇率时订单不得进入本次账单 |
| 8. 计算实付返款 | `实付返款 = 实付返款（准） × 返款汇率` | 货款结算币种 | 缺少必要汇率时订单不得进入本次账单 |
| 9. 校验收款账户 | 客户收款账户币种等于货款结算币种 | 货款结算币种 | 未配置同币种账户时配置不得保存，账单不得生成或执行返款 |

配置保存时还必须阻止：

1. 同一配置版本内相同 `货款原始币种` 映射到多个不同 `货款结算币种`；
2. `其他` 被当作真实币种参与换算；
3. `requiredAggregateFeeItems` 继续携带 `FEE0061 返款汇率`；
4. 客户收款账户币种与货款结算币种不一致。

生成时还应校验：

```text
cod_price - dest_country_surcharge_amount = collection_price
```

两者不一致的订单进入异常清单，不进入本次返款账单。

### 2.2 来源字段口径

| 来源字段 | 返款账单用途 | 约束 |
| --- | --- | --- |
| `sale_order_header.collection_price` | OIS 订单级应付返款本金 | BMS 只读取结果，不自行计算本金 |
| `sale_order_header.collection_premium_amount` | 订单级代收货款手续费 | 命中直接扣减配置时按订单计入一次 |
| `sale_order_header.cod_price` | 到付总额 | 用于核对到付金额，不等于应付返款 |
| `sale_order_header.dest_country_surcharge_amount` | 到付附加费总额 | 属于非费项，先从到付总额中扣除 |
| `sale_order_header.cod_amount` | 历史字段 | 不得仅凭中文名认定手续费，必须结合包裹侧事实 |
| `sale_order_package_fee.collection` | 历史包裹侧实付返款 | 停止新增，存量保留且不参与计算和展示 |
| `sale_order_package_fee.recovery_money` | 实收回款 | 当前版本直接读取导入值 |
| `sale_order_package_fee.receivable_collection_amount` | 包裹侧代收货款手续费 | 导入费项，按包裹挂靠归集 |
| `sale_order_package_fee.payment_collect` | 回款汇率 | 直接按导入值作为回款汇率；货币对固定为目的国币种 → 店铺币种，不再依赖 `type` 区分 |

### 2.3 汇兑损益算法

#### 2.3.1 计算公式

```text
汇兑损益金额 = 实付返款（准） ×（标准化回款汇率 - 标准化返款汇率）
```

约束：

1. 比较货币对以回款汇率的货币对和汇兑方向为准；回款汇率一旦录入，货币对固定为 `目的国币种 → 店铺币种`；
2. 两个汇率相减前必须有相同的左侧币种、右侧币种和方向；
3. 返款汇率与回款汇率货币对一致时直接作为标准化返款汇率；
4. 不一致时使用账单已锁定的汇率换算为回款汇率货币对，不得直接相减；由于两种外币对均经过店铺币种，原则上总能推导出中间汇率，不允许出现“缺少中间汇率”的业务常态；
5. 中间汇率方向相反时先取倒数再参与换算；
6. 货款原始币种与回款汇率左侧币种不一致时，先按账单锁定汇率把 `实付返款（准）` 换算为比较货币对左侧币种；
7. 汇兑损益币种为比较货币对右侧币种；
8. 缺少回款汇率或必要换算汇率时，字段显示 `--` 并说明缺失项，作为异常兜底，不作为正常业务路径；
9. 无回款汇率且实收回款继续使用货款原始币种时，标准化回款汇率按 `1` 处理；若返款也为同币种，汇兑损益为 `0`。

同一订单在同一次导入中出现多个不同回款汇率时，OIS 导入必须报错，不允许进入返款账单或汇兑损益计算。

#### 2.3.2 标准化返款汇率示例

场景一：回款汇率 `TWD → CNY`，返款汇率 `TWD → CNY`。

```text
标准化返款汇率 = 0.15
标准化回款汇率 = 0.2
汇兑损益 = 40 TWD × (0.2 - 0.15) = 2 CNY
```

场景二：回款汇率 `TWD → CNY`，返款汇率 `TWD → USD`，账单锁定 `USD → CNY = 7.2`。

```text
标准化返款汇率 = TWD → USD × USD → CNY = 0.021 × 7.2 = 0.1512
```

场景三：回款汇率 `TWD → CNY`，返款汇率 `TWD → USD`，只有 `CNY → USD`，方向相反。

```text
USD → CNY = 1 / (CNY → USD)
标准化返款汇率 = TWD → USD × (1 / (CNY → USD))
```

场景四：货款原始币种 `USD`，回款汇率 `TWD → CNY`。

```text
先按账单锁定 USD → TWD 把实付返款（准）换算为 TWD
再按回款汇率货币对 TWD → CNY 计算汇兑损益
```

### 2.4 展示边界

| 展示位置 | 是否展示汇兑损益 | 说明 |
| --- | --- | --- |
| 返款账单详情 | 是 | 展示完整金额链路和汇兑损益 |
| 面向财务的内部导出 | 是 | 增加回款汇率、返款汇率、标准化汇率、汇兑损益和缺失说明 |
| 回款管理 | 否 | 不重新计算返款金额、返款汇率或汇兑损益 |
| 客户页面 | 否 | 不得展示 |
| 客户邮件 | 否 | 不得展示 |
| 面向客户的对账报表 | 否 | 不得展示 |

回款管理可以继续读取关联返款账单的 `应付返款金额`、`实付返款（准）`、`返款汇率`、`实付返款` 用于包裹追踪，但页面不得重新计算这些结果，也不得展示汇兑损益。

## 3. 现状分析

### 3.1 后端生成逻辑现状

主要实现位于：

```text

```

关键方法：

| 方法 | 现状 |
| --- | --- |

| `resolveRefundPayableAmount()` | 直接取 `h_collection_price` 作为应付返款，未校验到付金额和到付附加费 |
| `buildRefundPrincipalFee()` | 本金费项按 `collection_price` 生成 |
| `buildStandaloneRefundFee()` | 先按 `sourceCurrency → billCurrency` 换算，再累计，等价于“先换算、后扣减” |

1. 当前顺序是先换算、后扣减；PRD 要求先扣减、后换算。

3. 当前包裹查询未取 `payment_collect`，回款汇率没有在生成时固化。
4. 当前缺失原始币种时兜底 `TWD`，PRD 要求阻断订单。
5. 当前 `FEE0061 返款汇率` 仍被前端默认配置带入 `requiredAggregateFeeItems`。
6. 当前币种规则 DTO 注释仍为“一期作为快照保存，不参与计算”，与 PRD 要求参与计算冲突。

### 3.3 数据库现状

已只读核对 `tmall_bms` 和 `ofp_ofdb1`，结论如下：

1. `ar_bill` 当前没有 `到付金额`、`到付附加费`、`应付返款原始币种`、`实付返款（准）`、`返款汇率快照`、`汇兑损益` 独立字段。
2. `ar_bill_currency_summary` 当前只有结算币种汇总，没有原始币种金额链路和返款汇率快照。
3. `fee_detail` 已具备 `amount_fee_currency`、`exchange_rate_to_bill`、`amount_bill_currency`、`source_extra_json` 等字段，可以承载部分金额链路，但缺少“返款汇率业务语义”和“回款汇率快照”的显式字段。
4. `bill_exchange_rate` 已具备 `FEE_TO_BILL`、`BILL_TO_FIN`、`hit_level`、`derivation_type` 等结构，可作为返款汇率锁定的落点，但需要补充“返款汇率专用语义”或业务类型标记。
5. `sale_order_package_fee` 没有币种字段，只有 `recovery_money`、`payment_collect`、`collection`、`receivable_collection_amount`、`type`。

### 3.4 线上样例数据

已执行只读查询，样例结论：

1. 存在 `cod_price = 980`、`collection_price = 950`、`dest_country_surcharge_amount = 30` 的订单，满足 `cod_price - dest_country_surcharge_amount = collection_price`，与确认口径一致。
2. 存在 `collection_price = 0`、`dest_country_surcharge_amount = cod_price` 的订单，说明无代收货款本金或全为到付附加费；这类订单不得进入应付返款计算。

## 4. 目标技术方案

### 4.1 总体设计原则

1. 返款账单生成、重算、详情、导出、回款管理统一消费同一份“订单级返款金额链路快照”，不允许各自推导。
2. 返款汇率只在生成或允许重算时锁定，锁定时保存来源、层级、表达式和快照值。
3. 回款汇率从源表 `payment_collect` 随任务或账单固化，不按金额相除推导。
4. 汇兑损益作为只读财务指标，独立存储、独立展示，不进入任何核销金额。
5. 已确认不处理历史数据：历史账单不自动改写、不批量重算，新算法只作用于新生成账单。

### 4.3 生成算法改造

#### 4.3.1 源数据读取

`queryRefundOrderRows()` 和包裹查询需要补充读取：

```text

```

#### 4.3.2 逐订单校验

生成前逐订单执行：

1. 缺少 `cod_price` 或 `collection_price` 时，订单不进入本次账单并记录原因。
2. 校验 `cod_price - dest_country_surcharge_amount = collection_price`，不一致时订单不进入本次账单并记录差异。
3. `resolveRefundSourceCurrency()` 缺失时，订单不进入本次账单，不再兜底 `TWD`。
4. 无法匹配货款原始币种规则且无 `其他` 兜底时，订单不进入本次账单。
5. 指定扣减费项缺少换算到货款原始币种的必要汇率时，订单不进入本次账单。
6. 返款汇率无法按 15.3.1 层级取得时，订单不进入本次账单。
7. 货款原始币种相同但映射多个不同结算币种时，配置保存即拒绝。
8. 客户收款账户币种不等于结算币种时，配置不得保存，账单不得生成或执行返款。
9. 同一订单在同一次导入中出现多个不同回款汇率时，导入报错，订单不进入返款账单。

#### 4.3.3 金额计算顺序

每张业务订单按以下顺序计算：

```text
到付附加费总额 = dest_country_surcharge_amount
应付返款 = 到付金额 - 到付附加费总额，并与 collection_price 一致
指定扣减费项合计 = Σ(命中配置的费项换算为货款原始币种)
实付返款（准） = 应付返款 - 指定扣减费项合计
实付返款 = 实付返款（准） × 返款汇率
```

指定扣减费项不是货款原始币种时，先按账单锁定汇率换算为货款原始币种再参与汇总，不得先换算到货款结算币种再相减。

#### 4.3.4 `fee_detail` 写入建议

本金费项：

```text
fee_currency = 货款原始币种
amount_fee_currency = 应付返款
exchange_rate_to_bill = 返款汇率
bill_currency = 货款结算币种
amount_bill_currency = 应付返款 × 返款汇率
```

扣减费项：

```text
fee_currency = 扣减费项换算前币种
amount_fee_currency = 扣减费项原始金额
exchange_rate_to_bill = 扣减费项币种 → 货款原始币种 → 货款结算币种的组合汇率
bill_currency = 货款结算币种
amount_bill_currency = 扣减费项换算到货款原始币种后的金额 × 返款汇率
```

汇总仍按：

```text
receivableAmount = Σ(principal.amount_bill_currency) - Σ(deduction.amount_bill_currency)
```

这样既满足“先扣减、后换算”，又避免重写整套汇总模型。但必须在 `fee_detail` 或专门快照中同时保存 `实付返款（准）` 和指定扣减费项原始币种合计，供汇兑损益和详情展示使用。

说明：本金费和扣减费各自先换算后，汇总相减得到 `(应付返款 - 指定扣减费项) × 返款汇率 = 实付返款`。详情展示的 `实付返款（准）` 必须来自原始币种金额链路，不能从结算币种差值反推。

#### 4.3.5 返款汇率锁定

推荐复用 `bill_exchange_rate` 的 `FEE_TO_BILL` 行，但补充：

1. 语义明确为 `货款原始币种 → 货款结算币种`；
2. 生成时写入 `rate_date`、`rate_source`、`source_type`、`hit_level`、`source_rate_value`、`derivation_type`；
3. 新生成账单锁定后不可随市场汇率变化；
4. 同币种固定写入 `1` 并记录 `FALLBACK_ONE` 或 `SAME_CURRENCY` 语义。

建议在 `bill_exchange_rate` 增加业务语义字段：

```text

  取值：REFUND_RATE / RECEIPT_RATE / NORMAL_FEE_RATE
```

### 4.4 汇兑损益实现方案

#### 4.4.1 回款汇率快照

`payment_collect` 在生成返款账单或回款管理刷新时随任务快照，建议落点：

已确认：新增独立表 `refund_receipt_rate_snapshot`，按 `bill_no + tail_way_bill_no` 保存：

```text

shop_currency                     店铺币种
source_type
type
snapshot_at
```

选择独立表的原因：

1. `fee_detail` 是费项行，回款汇率不是费项；
2. 回款汇率需要按包裹追溯、不可变快照和缺失原因；
3. 独立表不会污染费项核销语义。

同一订单同一次导入中，回款汇率必须唯一；出现多个不同值时报错，不写入快照。

#### 4.4.2 标准化汇率计算

实现函数建议：

```text
standardizeRefundRate(refundRate, refundPair, receiptPair, lockedRates)

1. 若 refundPair == receiptPair，直接返回 refundRate。
2. 若 refundPair 右侧 == receiptPair 右侧，仅需补左侧币种换算。
3. 若 refundPair 左侧 == receiptPair 左侧，补右侧汇率换算。
4. 左侧和右侧都不一致时，先补右侧，再补左侧。
5. 每一步优先使用账单锁定汇率；方向相反先取倒数。
6. 缺少任一必要汇率，返回缺失标记。
```

已确认口径：由于回款汇率和返款汇率都可经过店铺币种推导，任何两种外币对之间的换算汇率都可由两个“外币与店铺币种”汇率推算；业务上不允许出现缺少中间汇率的常态。代码仍保留缺失标记和 `--` 展示，作为脏数据兜底。

金额基础换算：

```text
若 sourceCurrency == compareLeftCurrency，baseCompareLeft = 实付返款（准）
否则 baseCompareLeft = 实付返款（准） × 账单锁定(sourceCurrency → compareLeftCurrency)
```

#### 4.4.3 缺失处理

| 场景 | 处理 |
| --- | --- |
| 无回款汇率且实收回款仍为货款原始币种 | 标准化回款汇率按 `1`；若返款也同币种，汇兑损益为 `0` |
| 无回款汇率且实收回款已换算 | 显示 `--`，说明缺失回款汇率 |
| 返款汇率缺少必要换算汇率 | 显示 `--`，说明缺失的货币对 |
| 货款原始币种与比较左侧不一致且缺少锁定汇率 | 显示 `--`，说明缺失换算汇率 |
| 数值计算完成 | 展示金额和币种 |

## 6. 疑问点与确认结论

### 6.1 已确认口径（2026-08-21）

| 序号 | 疑问点 | 确认结论 | 对方案的影响 |
| --- | --- | --- | --- |
| 1 | 到付附加费总额来源 | `sale_order_header.dest_country_surcharge_amount`，属于非费项 | 生成、快照、详情、导出均读取该字段，不进入费项明细 |
| 2 | `collection_price` 是否即应付返款本金 | 是 | 应付返款直接读取 `collection_price`，并校验 `cod_price - dest_country_surcharge_amount = collection_price` |
| 3 | 一票多件汇兑损益粒度 | 按业务订单计算一次 | 回款汇率取该订单同次导入的唯一值；同一订单多个不同回款汇率时导入报错 |
| 4 | 缺少中间锁定汇率 | 不允许存在，可通过两个“外币与店铺币种”汇率推算 | 代码仍保留 `--` 兜底，但正常路径应总能标准化 |
| 5 | `payment_collect` 语义 | 汇率 | 直接作为回款汇率快照，不再按金额关系推导 |
| 6 | 回款汇率货币对 | 目的国币种 → 店铺币种 | 比较货币对固定为 `目的国币种 → 店铺币种` |
| 7 | 回款汇率快照落点 | 独立表 `refund_receipt_rate_snapshot` | 按包裹保存回款汇率、货币对、店铺币种和快照时间 |
| 8 | 返款汇率快照落点 | 复用 `bill_exchange_rate` | 增加 `rate_business_type` 标记返款汇率语义 |
| 9 | 汇总表补充金额链路 | 是 | `ar_bill_currency_summary` 增加原始币种、到付金额、到付附加费、应付返款、指定扣减、实付返款（准）、返款汇率字段 |
| 10 | 历史未发出账单重算 | 无需处理历史数据 | 新算法只影响新生成账单，不批量重算 |
| 11 | 存量配置 `FEE0061` 清理 | 无需处理历史数据 | 存量快照保留，新代码对新账单强制忽略该费项 |
| 12 | 缺少货款原始币种 | 按 PRD 阻断订单 | 不沿用 `TWD` 或 `CNY` 兜底 |

## 7. 风险与验证

### 7.1 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| `payment_collect` 存量样例量级异常 | 回款汇率快照失真，汇兑损益错误 | 口径已确认为汇率；实施时按导入模板校验，脏数据阻断或清洗 |
| `cod_price - dest_country_surcharge_amount ≠ collection_price` | 应付返款、实付返款（准）错算 | 生成前校验，差异订单进入异常清单 |

| 前端继续推导汇率 | 展示值与账单快照不一致 | 删除前端推导，全部由后端返回 |
| 历史账单被误重算 | 已发出、已结清结果变化 | 已确认不处理历史数据；上线回归仅验证历史账单不变 |
| 19.6.2 与 11.8 冲突 | 验收口径不一致 | 已确认返款账单支持财务内部导出；实施前同步修订 PRD 19.6.2 |
| 配置快照旧值残留 | 新账单继续带入 FEE0061 | 代码强制忽略并阻断保存 |
