# 线路报价配置 PRD

## 1. 产品定位与范围

### 1.1 产品定位

线路报价是供应链系统为业务订单选择运输服务并计算客户费用的规则配置。订单侧根据报价形成线路、承运商、计费结果和费用明细；财务系统中的 BMS 只读取这些已经形成的结果，不重新计算线路报价。相关系统边界见[账单系统 PRD](./PRD.账单系统.md)中的业务系统基本面。

本 PRD 只描述`线路报价管理`页面及其配置逻辑，重点说明一条报价适用于哪些订单、如何确定承运商和线路产品、如何计算费用，以及配置发生变化后如何生效和追溯。

### 1.2 本期范围

本期包含以下能力：

1. 新增、编辑、复制新增、启用、禁用、删除线路报价，以及查看历史版本。
2. 配置报价基础信息、报价分组、业务类型和产品展示信息。
3. 配置目的地、货物类型、运输方式、适用仓库和承运商。
4. 配置承运商及线路产品的分配策略。
5. 配置计费维度、计算方式、重量处理、费用取整、价格区间和地区报价。
6. 按尾程派送商和代收货款金额区间配置`代收货款手续费报价`，并将命中结果形成订单费用。
7. 查询、选择列表表头、导出报价，以及批量修改报价和禁运规则。

### 1.3 不在本期范围

1. 业务订单的创建、拆单、出库和实际运输执行。
2. 承运商自身的运价维护、物流轨迹维护和承运商产品运营。
3. BMS 费项池归集、账单生成、账单重算和对账报表导出。
4. 产品优先级方向、地区报价运行时覆盖关系等尚未形成唯一口径的规则。相关问题统一列入[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)，确认前不得自行补充实现规则。

## 2. 业务对象与配置关系

### 2.1 一条线路报价由什么组成

一条线路报价由基础信息、适用条件、线路分配策略和计费规则组成。订单只有同时满足报价的适用条件，且报价本身可用时，才能将该报价作为候选报价。

同一报价可以配置多个目的地、货物类型、运输方式、仓库或报价分组。同一维度内，订单命中任意一个已配置值即可；不同维度之间必须同时命中。

报价至少需要明确以下关系：

| 关系维度 | 业务含义 |
| --- | --- |
| 店铺 | 报价所属的业务入口。报价分组和适用仓库等选项依赖店铺加载。 |
| 报价分组 | 报价适用的客户、会员或同行分组，支持多选。 |
| 业务类型 | 报价适用的业务场景，例如集运、重出订单或电商订单。 |
| 目的地 | 订单收货国家或地区。 |
| 货物类型 | 订单货物所属的计价或禁运分类。 |
| 运输方式 | 空运、陆运、海快等运输方式。 |
| 适用仓库 | 报价可被哪些发货仓使用。 |
| 承运商及产品 | 订单最终使用的运输服务提供方及其产品。 |
| 计费规则 | 将订单的重量、体积、长度、周长、数量或材积转换为费用的规则。 |
| 代收货款手续费报价 | 订单已经确定尾程派送商后，按单个尾程包裹的代收货款金额区间确定固定手续费。一份报价可以同时关联多个派送商，所有已关联派送商共用同一套金额区间和固定手续费。 |

### 2.2 报价、报价版本和订单费用的关系

1. 报价保存后形成可供订单使用的报价记录；编辑报价时必须保留历史版本，供后续查看和对比。
2. 新订单只能使用同时满足启用状态、生效时间和适用范围的报价。
3. 订单一旦形成线路和费用结果，后续账单直接使用订单侧已形成的结果，不因 BMS 再次执行而重新推导线路报价。
4. 报价变更是否影响已经形成但尚未出库的订单，按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)处理；规则确认前，不得假设历史订单会自动改价。

### 3.2 不同报价怎样共用同一详情页？

原型列表至少同时演示以下组合，财务可以分别进入详情页，直观看到普通报价与代收货款手续费报价的配置差异：

| 报价类型示例 | 计费模式示例 | 详情页呈现重点 |
| --- | --- | --- |
| `派送报价` | `实重于抛重二者取其大` | 计费模式、计算方式、舍入、进位、默认抛比、默认抛重公式和价格区间均按适用规则开放配置。 |
| `派送附加费报价` | `仅按重量计费(KG)` | 重量计费和价格区间开放配置；默认抛比、默认抛重公式因不参与纯重量计费而显示为禁用态。 |
| `超材报价` | `按材积(材)` | 计费模式、计算方式、舍入、进位和价格区间开放配置；按材积专属规则按[7.5 按材积计费的专属配置](#75-按材积计费的专属配置)处理。 |
| `系统服务报价` | `按数量（个）` | 计算方式只提供`订单个数`和`包裹个数`，重量、抛重相关字段不适用。 |
| `代收货款手续费报价` | `按代收货款金额分档` | 计费模式和计算方式采用固定值；普通线路计费字段显示为禁用态，尾程派送商集合、报价币种和代收货款金额区间保持可编辑。 |

字段状态必须遵守以下统一口径：

1. 当前报价类型适用且允许财务调整的字段保持可编辑，不得为了突出差异而禁用。
2. 当前报价类型适用但只能采用一个固定值的字段显示该值并禁用，避免形成实际不存在的可选范围。
3. 当前报价类型不参与该字段对应业务计算时，字段显示`不适用`并禁用；已有旧值也不得参与费用计算。
4. `默认价格区间`由各报价类型复用；代收货款手续费报价把区间指标固定为`代收货款金额`，并把价格类型固定为`一口价`。

### 3.3 配置主流程

1. 进入`线路报价管理`，通过店铺、目的地、运输方式、货物类型或报价名称定位已有报价。
2. 新增报价时，先选择店铺，再填写报价名称、报价分组、业务类型、报价类型和生效范围。
3. 配置目的地、货物类型、运输方式和适用仓库，确定报价可服务的订单范围。
4. 选择渠道线路分配策略并配置承运商；策略要求指定承运商产品时，还必须完成产品关联。
5. 普通线路报价选择计费模式和多包裹计算方式，再配置重量、体积、长度、数量或材积处理规则；`代收货款手续费报价`改为选择一个或多个尾程派送商，并配置报价币种。
6. 各报价均在原有`默认价格区间`区域维护价格规则；代收货款手续费报价的区间指标固定为`代收货款金额`，价格类型固定为`一口价`，区间价格即固定手续费。需要按地区区别定价的普通报价仍可新增地区报价；代收货款手续费报价不使用地区报价。
7. 保存报价。保存成功后，只有状态、时间和适用范围均满足条件的报价才参与订单报价。
8. 调整已有报价时，优先使用`复制新增`创建新报价；直接编辑时应先确认影响范围。每次变更都必须保留历史版本。

## 4. 报价基础信息：先定义这条报价

### 4.1 基础字段

| 字段 | 是否必填 | 默认值或枚举 | 业务规则 |
| --- | --- | --- | --- |
| 店铺 | 是 | 无默认值 | 报价必须归属于一个店铺。选择店铺后，系统按店铺加载可用的报价分组和仓库。 |
| 报价名称 | 是 | 无默认值 | 用于在列表、订单和历史版本中识别报价。同一店铺下不应使用无法区分的重复名称。 |
| 报价分组 | 是 | 随店铺加载 | 支持多选；报价只对所选分组中的客户生效。 |
| 业务类型 | 是 | 当前页面默认`集运` | 支持多选。可选值包括`集运`、`中转/预报`、`袋中袋`、`电商订单`、`重出订单`、`取件退回`。 |
| 启用时间 | 条件必填 | 非永久报价需填写 | 由开始时间和到期时间组成。非永久报价必须填写完整时间范围，且开始时间不得晚于到期时间。 |
| 永久启用 | 否 | 当前新增页面默认未勾选 | 勾选后不设置到期时间；取消勾选时必须补充有效的开始和到期时间。 |
| 启用状态 | 否 | 当前新增页面默认关闭 | 只有状态为启用且当前时间处于有效期内的报价才可参与匹配。 |
| 报价类型 | 是 | 当前页面默认`派送报价` | 可选值包括`派送报价`、`自提报价`、`包税报价`、`保价报价`、`超重报价`、`超长报价`、`超材报价`、`打包报价`、`落地派送报价`、`系统服务报价`、`预扣报价`、`派送附加费报价`、`代收货款手续费报价`。 |
| 产品优先级 | 否 | 0 | 只能填写非负数，用于多个报价同时命中时的排序或选择。优先级方向和同优先级处理方式见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。 |
| 时效 | 否 | 空 | 用于展示或业务选择，不改变价格区间计算。 |
| 最低价格 | 否 | 空 | 报价级别的最低收费。它与价格规则中的`最低收费`不是同一个配置项，二者如何叠加见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。 |
| 推荐标签 | 否 | 空 | 支持`高性价比，低价平衡之选`、`强烈推荐，精选线路`等标签，用于前端推荐展示。 |
| 产品描述 | 否 | 空 | 用于展示线路服务说明。 |
| 商品禁寄品类 | 否 | 空 | 支持多选禁寄品类，例如儿童用品、食品、粉面、玩具等。该字段只表达本报价的商品限制，不替代全局禁运规则。 |
| 商品禁寄描述 | 否 | 空 | 用文字补充禁寄限制或特殊说明。 |

`派送附加费报价`只能配置为`中转/预报`业务类型，且至少选择一个业务类型。新增、编辑和批量修改时都必须校验这一限制；选择其他业务类型时不得保存。除这一已确认限制外，其他报价类型与业务类型是否存在专属组合规则，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。

#### 4.1.1 列表和详情页统一使用哪些枚举？

列表筛选、列表展示和详情页控件必须使用同一套枚举口径，不得因为页面区域不同而出现漏项、别名或同义值。店铺、报价分组、仓库、目的地和承运商属于业务主数据，由系统按当前店铺、仓库、目的地或线路配置动态加载，不在下表中虚构固定枚举。

| 枚举字段 | 可选值 |
| --- | --- |
| 业务类型 | `集运`、`中转/预报`、`袋中袋`、`电商订单`、`重出订单`、`取件退回` |
| 报价类型 | `派送报价`、`自提报价`、`包税报价`、`保价报价`、`超重报价`、`超长报价`、`超材报价`、`打包报价`、`落地派送报价`、`系统服务报价`、`预扣报价`、`派送附加费报价`、`代收货款手续费报价` |
| 货物类型 | `普货`、`药品保健品`、`食品专线`、`粉面专线`、`易碎品`、`敏感品`、`特A`、`特B`、`特C` |
| 运输方式 | `空运`、`陆运`、`海快`、`加强包装`、`海运` |

## 5. 报价适用范围：哪些订单可以使用

### 5.1 目的地国家或地区

1. `目的地国家/地区`为必填，支持选择国家、地区和特殊目的地节点，并提供全选能力。
2. 只有订单目的地命中已配置范围时，报价才进入候选集合。
3. 国家和地区按层级生效：选择上级节点表示覆盖其下属节点；业务要求限定到具体地区时，应选择具体地区，不应只选择上级节点。

### 5.2 货物类型

支持多选以下货物类型：`普货`、`药品保健品`、`食品专线`、`粉面专线`、`易碎品`、`敏感品`、`特A`、`特B`、`特C`。

货物类型用于筛选报价和确定计费适用范围，不等于商品禁寄品类。一个报价可以适用于多个货物类型；订单货物类型未命中时，不得使用该报价。

### 5.3 运输方式

支持多选`空运`、`陆运`、`海快`、`加强包装`、`海运`。运输方式既是报价匹配条件，也影响承运商和线路产品的可选范围。

### 5.4 适用仓库

1. `适用仓库`为必填，支持多选。
2. 仓库选项随店铺加载，只能选择当前店铺可用的仓库。
3. 订单实际发货仓必须命中适用仓库；即使店铺、目的地和运输方式均匹配，只要仓库不匹配，也不得使用该报价。

### 5.5 报价分组与店铺依赖

1. 报价分组为必填且支持多选，选项随店铺加载。
2. 切换店铺后，报价分组和适用仓库必须重新加载，不得沿用上一店铺的选项。
3. 保存前，所选报价分组必须属于当前店铺可用的分组。

### 5.6 订单规模门槛

页面还提供两个可选的订单规模门槛，用于进一步限制报价的适用范围：

| 字段 | 是否必填 | 单位 | 录入要求 | 配置含义 |
| --- | --- | --- | --- | --- |
| 最小包裹数 | 否 | 个 | 只能填写非负整数。 | 限制达到指定包裹数量的订单使用本报价。 |
| 包裹最小重量 | 否 | KG | 只能填写非负数，最多保留 1 位小数。 | 限制达到指定重量门槛的包裹或订单使用本报价。 |

未填写某个字段，表示本报价不受该门槛限制。两个字段同时填写时是同时满足还是满足其一、`包裹最小重量`比较单个包裹还是订单汇总重量，以及等于门槛时是否命中，现有报价匹配逻辑尚不能证明，必须先按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)明确。

## 6. 承运商与线路分配：订单最终使用哪条线路

### 6.1 渠道线路分配策略

`渠道线路分配策略`为必填。当前页面提供以下五种方式：

| 策略 | 业务含义 | 承运商由谁选择 | 是否指定承运商产品 |
| --- | --- | --- | --- |
| 当前线路报价指定唯一的承运商，承运商产品为默认产品 | 固定承运商，使用该承运商的默认产品 | 系统 | 不指定具体产品 |
| 当前线路报价指定唯一的承运商及产品 | 固定承运商和具体产品 | 系统 | 指定具体产品 |
| 客户自行选择承运商，承运商产品为默认产品 | 由客户选择承运商，使用所选承运商的默认产品 | 客户 | 不指定具体产品 |
| 客户自行选择承运商及其产品 | 由客户同时选择承运商和产品 | 客户 | 指定可选产品范围 |
| 系统根据履约规则自动分配承运商和产品 | 系统按履约规则确定承运商和产品 | 系统 | 按履约规则确定 |

该策略决定订单中的承运商和线路产品由谁确定。保存时必须校验策略与承运商、产品配置一致：固定承运商的策略不得缺少承运商；要求指定产品的策略不得只配置承运商而不配置产品。

订单命中报价后，系统按所选策略写入承运商和产品：

1. 指定唯一承运商时，订单使用报价中配置的承运商，并带入该承运商在当前仓库和店铺下的默认产品。
2. 指定唯一承运商及产品时，订单使用报价中配置的承运商和产品；任一配置缺失，都不得继续创建订单线路。
3. 客户自行选择承运商时，订单保留客户所选承运商，并带入该承运商的默认产品。
4. 客户自行选择承运商及产品时，订单保留客户所选承运商和产品。
5. 系统自动分配时，系统先按履约规则确定承运商，再带入该承运商的默认产品。

### 6.2 承运商配置

1. 固定承运商和客户选择承运商的策略必须配置可用承运商，页面支持新增和移除。系统自动分配时不要求人工选择承运商，但必须存在可执行的履约规则。
2. 一个报价可以配置多个承运商；实际使用哪一个，由所选策略以及订单侧选择或履约规则共同决定。
3. 承运商选项受店铺、目的地、货物类型、运输方式和适用仓库限制，只展示当前报价场景可用的承运商。
4. 选择“指定承运商及产品”类策略时，页面必须提供承运商产品配置入口；任一已选承运商没有选择产品时，报价不得保存。

## 7. 计费规则：如何把订单指标算成费用

### 7.1 计费模式

`计费模式`为必填。当前页面提供以下选项：

1. `仅按重量计费(KG)`。
2. `实重于抛重二者取其大`。
3. `按体积（立方米）`。
4. `自定义两者取其大`。
5. `仅按抛重计费（KG）`。
6. `最长长度（CM）`。
7. `周长（CM）`。
8. `三边之和（CM）`。
9. `按数量（个）`。
10. `按材积(材)`。

计费模式决定费用使用哪一种计费量计算。一个报价只能选择一个计费模式；计费模式必须与末级价格规则的价格类型和计量单位一致。价格区间中的`规则类型`只负责判断订单命中哪条规则，可以与计费模式相同，也可以在嵌套规则中作为额外筛选条件，详见[8.2 规则类型：区间按什么数据判断？](#82-规则类型区间按什么数据判断)。

选择`按材积(材)`后，还必须完成[7.4 按材积(材)的专属配置：先算材积，再处理超材费用](#74-按材积材的专属配置先算材积再处理超材费用)。否则，系统无法根据包裹尺寸得到有效材积，也无法完整处理超材费用。

选择`自定义两者取其大`后，页面额外展示`自定义最小长宽高之和`。系统先计算当前包裹的三边之和：低于门槛时按实重计费；高于门槛时，计算抛重并取实重与抛重中的较大值。门槛单位与边长单位一致，配置值必须为非负数。等于门槛时如何处理，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。

### 7.2 计算方式：按合并、单独还是数量算费

`计算方式`由`计费模式`决定可选范围。不同计费模式不得使用互相不兼容的计算方式：

| 计费模式 | 可选计算方式 | 业务含义 |
| --- | --- | --- |
| 除`按数量（个）`外的计费模式 | 多包裹合并算费 | 先汇总同一业务订单下参与算费的多个包裹，再用汇总后的计费指标匹配价格区间并计算一次费用。 |
| 除`按数量（个）`外的计费模式 | 多包裹单独算费 | 每个包裹分别匹配价格区间并计算费用，再汇总同一业务订单的费用。 |
| `按数量（个）` | 订单个数 | 以参与本次算费的业务订单数量作为计费数量。 |
| `按数量（个）` | 包裹个数 | 以参与本次算费的包裹数量作为计费数量。 |

切换计费模式时，系统必须同步检查当前计算方式：切换为`按数量（个）`且原计算方式不兼容时，自动改为`订单个数`；从`按数量（个）`切换到其他计费模式且原计算方式为`订单个数`或`包裹个数`时，自动改为`多包裹合并算费`。页面只展示当前计费模式允许的计算方式，避免保存冲突组合。

### 7.3 费用取整、舍入和进位

1. `费用取整`当前提供`实际费用`，表示价格计算结果按实际金额保留，不在本配置中额外截断为整数。
2. `舍入模式`支持 `无舍入`、`0.1舍入`、`0.2舍入`、`0.3舍入`、`0.5舍入`。
3. `进位模式`支持 `无进位`、`0.5进位`、`1进位`、`0.1进位`、`0.2进位`、`0.3进位`、`按区间进位`。
4. 计费量的处理顺序是先舍入、后进位。规则类型为`计费重量`时，处理后的计费重量用于匹配价格区间；规则类型为其他指标时，先按该指标命中价格规则，再用处理后的计费量计算费用。
5. `费用取整=实际费用`只作用于价格计算完成后的金额，不改变前面的计费指标处理过程；金额计算完成后按实际金额保留，不额外截断为整数。

以下示例只用于说明计算顺序。舍入值表示小数部分的保留门槛：小数部分小于该值时，舍去全部小数；达到该值时，保留原始计费指标，再执行进位。进位表示向上取到指定步长的最近值。以`0.3进位`为例，每个整数都是一个起点，按`0.3`递增形成步长点：`3.0`、`3.3`、`3.6`、`3.9`、`4.2`……因此，`3.3487`位于`3.3`和`3.6`之间，向上取为`3.6`；已经落在步长点上的`3.0`保持不变。

| 示例组 | 舍入设置 | 进位设置 | 原始计费指标 | 舍入过程及结果 | 进位过程及结果 | 最终计费指标 |
| --- | --- | --- | ---: | --- | --- | ---: |
| 1 | 0.1舍入 | 0.5进位 | 1.0937 | 小数部分 0.0937 < 0.1，舍去小数，得到 1.0 | 1.0 已落在 0.5 的步长点上，保持 1.0 | 1.0 |
| 1 | 0.1舍入 | 0.5进位 | 1.1462 | 小数部分 0.1462 >= 0.1，保留 1.1462 | 向上取到最近的 0.5 步长点，得到 1.5 | 1.5 |
| 2 | 0.2舍入 | 1进位 | 2.1847 | 小数部分 0.1847 < 0.2，舍去小数，得到 2.0 | 2.0 已是整数，保持 2.0 | 2.0 |
| 2 | 0.2舍入 | 1进位 | 2.2639 | 小数部分 0.2639 >= 0.2，保留 2.2639 | 向上取整，得到 3.0 | 3.0 |
| 3 | 0.3舍入 | 0.3进位 | 3.2746 | 小数部分 0.2746 < 0.3，舍去小数，得到 3.0 | 3.0 已落在 0.3 的步长点上，保持 3.0 | 3.0 |
| 3 | 0.3舍入 | 0.3进位 | 3.3487 | 小数部分 0.3487 >= 0.3，保留 3.3487 | 向上取到最近的 0.3 步长点，得到 3.6 | 3.6 |
| 4 | 0.5舍入 | 0.1进位 | 4.4827 | 小数部分 0.4827 < 0.5，舍去小数，得到 4.0 | 4.0 已落在 0.1 的步长点上，保持 4.0 | 4.0 |
| 4 | 0.5舍入 | 0.1进位 | 4.5639 | 小数部分 0.5639 >= 0.5，保留 4.5639 | 向上取到最近的 0.1 步长点，得到 4.6 | 4.6 |

`按区间进位`需要先维护每个区间对应的进位方式，不能脱离区间规则单独计算，因此不能与固定步长进位同时使用。每条区间规则包含`重量大于`、`小于等于`和`进位方式`三个字段，区间口径固定为`下限 < 包裹重量 <= 上限`。进位方式可选`不进位`、`0.5进位`、`1进位`、`取对方计费重量标识`、`0.1进位`、`0.2进位`、`0.3进位`。订单命中区间后，采用该区间的进位方式。

各区间必须明确下限、上限和进位方式。区间是否需要完整覆盖所有可能重量、重叠或空档是否阻止保存，以及`取对方计费重量标识`中的“对方”具体指谁、计费重量从哪里取得、来源缺失时如何处理，均须按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)明确。

价格区间命中后，系统再按该区间的价格类型计算金额。例如，最终计费指标为 `1.5kg`，价格类型为 `每千克`，单价为 `8 CNY/kg`，则运算过程如下：

| 运算步骤 | 运算内容 | 结果 |
| --- | --- | ---: |
| 1 | 原始计费指标为 `1.1462kg`，小数部分 `0.1462 >= 0.1` | 保留 `1.1462kg` |
| 2 | `1.1462kg` 按 `0.5进位` | 向上取为 `1.5kg` |
| 3 | 用 `1.5kg` 匹配价格区间 | 命中 `每千克` 规则 |
| 4 | `1.5kg × 8 CNY/kg` | `12 CNY` |
| 5 | `费用取整=实际费用` | 保留 `12 CNY`，不再额外取整 |

因此，舍入和进位处理的是计费指标，费用取整处理的是金额；三者不能混用，也不能调换顺序。

### 7.4 按材积(材)的专属配置：先算材积，再处理超材费用

只有当`计费模式`选择`按材积(材)`时，页面才展示本节配置区。本节配置不属于其他计费模式；切换到其他计费模式后，箱型材积、超材收款和超材手续费规则均不参与费用计算。按材积报价时，系统按以下顺序处理：

1. 读取包裹长、宽、高，并统一确定三边角色：最长边为`L`，次长边为`W`，最短边为`H`。不得直接把业务系统原始字段的排列顺序当作长、宽、高。
2. 按`按箱型配置材积`表格从上到下匹配第一条满足条件的箱型规则。
3. 使用命中规则的`材积公式`计算材积，再乘以该规则的`材积比`，得到本包裹参与报价的材积。
4. 使用材积匹配[8.2 规则类型：区间按什么数据判断？](#82-规则类型区间按什么数据判断)中的`材积`规则，并按命中的末级价格规则计算基础费用。
5. 包裹满足超材条件时，再按`超材收款规则`和`超材手续费规则`确定超材费用及收款方式。

#### 7.4.1 按箱型配置材积：同一包裹只命中第一条规则

`按箱型配置材积`通过多行规则描述不同包裹形状的材积算法。页面支持`新增配置`和`删除`，每行包含以下字段：

| 字段 | 业务含义 | 配置要求 |
| --- | --- | --- |
| 箱型名称 | 当前规则的可读名称，例如`不计算超材`、`箱型`、`扁形`、`长条形`。 | 必填；仅用于识别规则，不参与数值计算。 |
| 边长条件 | 判断包裹有多少条边满足某个长度条件，例如`< 30cm`或`>= 30cm`。 | 必须选择比较符号并填写长度值，单位固定为`cm`。 |
| 边数量条件 | 判断满足边长条件的边数，例如`= 3`、`>= 1`或`>= 2`。 | 必须选择比较符号并填写边数；边数只能在 1 至 3 范围内取值。 |
| 材积公式 | 将`L`、`W`、`H`转换为材积的运算规则。 | 必填；只能使用`L`、`W`、`H`、数字、加减乘除和括号，结果必须为不小于零的数值。 |
| 材积比 | 对材积公式结果进行比例修正。 | 默认值为`1.00`；最终材积=`公式结果 × 材积比`，材积比不得小于零。 |
| 操作 | 删除当前箱型规则。 | 删除后必须重新检查剩余规则能否覆盖需要报价的包裹。 |

页面内置的常用箱型规则及公式含义如下：

| 箱型规则 | 条件示例 | 材积公式 | 业务含义 |
| --- | --- | --- | --- |
| 不计算超材 | 三条边均 `< 30cm` | `0` | 包裹不按材积收取超材费用，材积结果为`0`。 |
| 箱型 | 三条边均 `>= 30cm` | `L × W × H ÷ 27000` | 三边均达到箱型门槛，按立体箱型材积计算。 |
| 扁形 | 至少一条边 `< 30cm` | `L × W ÷ 900` | 包裹存在较短边，按长与宽的二维材积计算。 |
| 长条形 | 至少两条边 `< 30cm` | `L ÷ 30` | 包裹有两条明显较短的边，按最长边的长条形材积计算。 |

表格按从上到下匹配，命中第一条后停止，不再尝试后续规则。因此，更严格的规则必须排在覆盖范围更大的规则之前。例如，`至少两条边 < 30cm`的长条形规则会被`至少一条边 < 30cm`的扁形规则覆盖，必须把长条形规则排在扁形规则之前，否则长条形规则永远不会命中。`三边均 < 30cm`的不计算超材规则也必须排在其他包含`< 30cm`的规则之前。

系统应在保存时校验以下内容：

1. 至少存在一条箱型规则；每条规则的箱型名称、边长条件、边数量条件、材积公式和材积比均完整有效。
2. 箱型规则按页面顺序参与匹配；存在包含关系时，应提示用户确认顺序，避免前面的宽泛规则完全遮蔽后续规则。
3. 材积公式只能引用当前包裹的`L`、`W`、`H`，不能引用未定义字段、函数、文字或其他报价字段；公式解析失败时不允许保存。
4. 包裹三边缺失、无法计算或材积公式结果异常时，本次报价不得静默按零费用处理，必须返回无法计算材积的业务错误。
5. 箱型规则没有命中时，本次报价不得继续生成缺少材积依据的费用结果；必须补充能覆盖该包裹的规则后再报价。

#### 7.4.2 报价币种和店铺币种结算汇率

按材积报价必须同时明确报价金额使用的`报价币种`和回写店铺订单时使用的`店铺币种`。页面中的`店铺币种结算汇率`表示：`1 单位报价币种 = N 单位店铺币种`，换算方向固定为`报价币种 -> 店铺币种`。

1. `报价币种`决定材积基础费用、超材费用和超材手续费的录入、计算及展示币种。示例中报价币种为`台币/TWD`，因此价格规则和手续费金额均按`TWD`维护。
2. `店铺币种`由当前店铺默认币种确定，不在本配置区手动修改。页面应同时展示报价币种和店铺币种，避免误认为两者相同。
3. `店铺币种结算汇率`用于将报价币种金额换算为店铺币种金额。例如报价币种为`TWD`、店铺币种为`CNY`、汇率为`0.45`时，`100 TWD × 0.45 = 45 CNY`。
4. 报价币种与店铺币种相同时，结算汇率为`1`；币种不同时，汇率必须是大于`0`的有效数值。缺少汇率时，不允许保存按材积报价。
5. 币种或汇率变更后，应重新换算预览金额，并以保存后的配置参与后续订单报价；已形成的订单费用是否重算，按报价版本和账单重算规则处理，本配置不自动回溯。

#### 7.4.3 超材收款规则：先确定谁付款、何时收款

`超材收款规则`分别配置`收方`和`寄方`作为超材费用付款方时的收款方式。两行规则彼此独立；系统按实际确定的付款方读取对应规则，不得将收方规则套用于寄方。

| 超材付款方 | 可选收款方式 | 业务结果 |
| --- | --- | --- |
| 收方 | `到付`、`人工确认后收款` | 超材费用由收方承担；到付表示随收方收货环节收取，人工确认后收款表示经人工确认后再收取。 |
| 寄方 | 除`到付`外的收款方式 | 超材费用由寄方承担；不得配置`到付`，因为到付收款对象是收方。 |

页面提示“建议超材付款方为收方时选择到付，避免漏收款；如需人工确认后收取请选择人工确认后收款”只是收款操作提示。财务仍可按业务约定选择其他可用方式，但收款方式必须与付款方匹配。

#### 7.4.4 超材手续费规则：按收款方式分别收取

`超材手续费规则`用于在超材费用之外，按收款方式配置是否加收固定手续费。点击`添加`新增一行。每行包含：

| 字段 | 业务含义 | 配置要求 |
| --- | --- | --- |
| 收款方式 | 该行手续费对应的收款方式。 | 同一种收款方式最多配置一条，重复选择时不允许保存。 |
| 是否收手续费 | 控制该收款方式是否追加手续费。 | 开启时才追加手续费；关闭时即使保留金额，也不得计入费用。 |
| 手续费金额 | 该收款方式下的固定手续费金额。 | 开启收手续费时必填，不能为负数，币种与`报价币种`一致。 |
| 操作 | 删除该收款方式的手续费规则。 | 删除后，该收款方式不再按本报价收取超材手续费。 |

超材手续费与材积基础费用是两笔独立费用：材积基础费用由材积命中价格规则后计算；只有命中对应收款方式且开关开启时，才追加超材手续费。删除或关闭手续费规则，不影响材积基础费用和超材付款方配置。

#### 7.4.5 按材积配置的整体保存和生效约束

1. 只有`计费模式=按材积(材)`时，箱型材积配置、报价币种与汇率、超材收款规则和超材手续费规则才作为本报价的有效配置。
2. 保存时必须同时校验材积规则、报价币种、结算汇率和超材收款/手续费配置；任一专属配置不完整或不合法，整条报价不得保存为启用状态。
3. 规则生效后，系统必须能够从订单的包裹尺寸追溯到命中的箱型名称、材积公式、材积比、报价币种、超材付款方、收款方式和手续费金额，便于财务核对费用来源。
4. 编辑报价并切换为其他计费模式后，原有按材积专属配置不得继续参与新订单计算；若再次切换回`按材积(材)`，只有通过完整校验的配置才能重新生效。

### 7.5 默认抛重与地区抛重

`默认抛比`和`默认抛重公式`用于把包裹体积换算为抛重，只适用于需要抛重参与计费的模式：`实重于抛重二者取其大`、`自定义两者取其大`和`仅按抛重计费（KG）`。`仅按重量计费`、`按体积（立方米）`、按长度或数量计费以及`按材积(材)`不使用本节配置；其中`按材积(材)`使用[7.4 按材积(材)的专属配置：先算材积，再处理超材费用](#74-按材积材的专属配置先算材积再处理超材费用)。

#### 7.5.1 抛重公式可以使用哪些字段？

抛重公式只能使用以下字段，且计算结果单位必须为`kg`：

| 字段 | 含义 | 单位 | 取值说明 |
| --- | --- | --- | --- |
| `L` | 包裹长度 | `cm` | 订单包裹记录中的长度。 |
| `W` | 包裹宽度 | `cm` | 订单包裹记录中的宽度。 |
| `H` | 包裹高度 | `cm` | 订单包裹记录中的高度。 |
| `V` | 包裹体积 | `cm³` | 包裹长、宽、高相乘所得体积，即`长 × 宽 × 高`。 |
| `Z` | 包裹实重 | `kg` | 包裹称重得到的实际重量，不含抛重换算、舍入或进位。 |
| `K` | 抛比 | `cm³/kg` | 每 `K` 立方厘米体积折算为 `1kg` 抛重的换算系数。必须大于 `0`，不能作为除数取 `0`。 |

默认抛重公式为`V/K`时，系统用包裹体积除以抛比计算抛重。以默认抛比`9000`为例，包裹尺寸为`60cm × 40cm × 30cm`，则`V=72,000cm³`，`V/K=72,000÷9,000=8kg`，抛重为`8kg`。若计费模式为`实重于抛重二者取其大`，且包裹实重`Z=2.3kg`，则取`8kg`进入后续舍入、进位和价格计算。

`V/K`只是最常用的写法。公式也可以直接引用`L`、`W`、`H`，例如`(L×W×H÷K+Z)÷2`。公式只能引用`L`、`W`、`H`、`V`、`Z`、`K`、数字、加减乘除和括号，且必须计算出非负的千克数；引用其他字段、公式语法错误、`K`为空或为零时，报价不得保存为启用状态。

抛重公式和按材积配置都可以使用`L`、`W`、`H`，但字段含义和计算结果不同：抛重公式直接使用包裹记录中的长、宽、高字段，结果必须是`kg`；按材积配置先把三边按长度排序为`L`、`W`、`H`，结果是`材`。两类公式不得互相复制后直接作为同一种计费结果使用。

#### 7.5.2 默认配置和指定地区配置怎样配合？

`默认抛比`和`默认抛重公式`是整条报价的兜底规则。`指定地区抛重配置`用于为部分目的地设置不同的抛比或公式；页面支持新增、编辑和删除地区规则，同一条地区规则可以选择多个采用相同口径的地区。

计算时按以下顺序确定抛重规则：

1. 根据订单目的地检查是否命中指定地区抛重配置。
2. 命中时，完整使用该地区规则的`抛重公式`和`抛比`；两项均为必填，不能只覆盖其中一项。
3. 未命中地区规则时，使用默认抛重公式和默认抛比。
4. 地区规则中的地区必须属于当前报价目的地范围；目的地范围变更后，系统应重新校验已有地区规则是否仍然有效。

同一目的地不能同时属于两条指定地区抛重规则。重复既包括选择相同地区，也包括把父级地区和子级地区分别配置在不同规则中的情形。发生重叠时，系统应阻止保存，不得依赖隐含顺序决定使用哪条规则。

#### 7.5.3 抛重进入费用计算前还要经过什么处理？

抛重公式得到的只是抛重原值，系统还要结合计费模式确定实际计费量：

| 计费模式 | 抛重的使用方式 |
| --- | --- |
| 仅按抛重计费（KG） | 直接使用抛重作为计费量。 |
| 实重于抛重二者取其大 | 比较`Z`与抛重，取较大值作为计费量。 |
| 自定义两者取其大 | 依照该模式配置的自定义比较逻辑，使用抛重参与比较。 |

确定计费量后，再按[7.3 费用取整、舍入和进位](#73-费用取整舍入和进位)处理，并使用处理后的计费量匹配价格规则和计算费用。订单费用明细应保留抛重原值、命中的默认或地区规则、公式、抛比及处理后的计费量，供财务核对。

#### 7.5.4 保存约束

1. 使用抛重的计费模式必须填写有效的默认抛比和默认抛重公式；默认抛比必须大于`0`，公式必须返回非负的`kg`数值。
2. 每条地区规则必须至少选择一个地区，并完整填写抛重公式和抛比；删除地区规则后，该地区自动回退到默认配置。
3. 包裹尺寸缺失，或地区规则、默认规则无法计算抛重时，系统不得将抛重默认为`0kg`继续计费，必须返回明确的无法计算抛重提示。
4. 修改抛比、公式或地区规则只影响后续按新报价生成的订单费用；已有订单费用是否重算，按报价变更和重算流程触发，保存配置时不得静默改写。

## 8. 价格区间：命中哪条规则、如何计算金额

### 8.1 默认价格区间

默认价格区间是报价的基础价格规则。页面通过可编辑规则表维护，支持新增和删除规则。

每条价格规则至少要表达以下内容：

| 规则要素 | 说明 |
| --- | --- |
| 规则类型 | 当前规则节点用于匹配区间的业务指标，例如包裹重量、月发货量或保价金额。它决定区间的比较单位，不一定等于费用的计费量。 |
| 区间下限及边界 | 支持`大于`和`大于等于`。 |
| 区间上限及边界 | 支持`小于`和`小于等于`。 |
| 价格 | 该区间的固定价格或单位价格。 |
| 价格类型 | 例如每千克、一口价、每 0.1 千克、每 0.5 千克、每立方米、每个或每材。 |
| 费用性质 | 用于表达附加费用、最低收费、最高收费或增值基础等规则。 |
| 计量单位 | 明确价格是按什么单位计算。 |

命中规则后，价格类型决定金额如何计算：

1. `一口价`表示命中区间后直接取该价格。
2. `每千克`、`每 0.1 千克`、`每 0.5 千克`、`每立方米`、`每个`和`每材`表示用处理后的计费指标乘以单位价格。
3. `最低收费`和`最高收费`用于限制最终费用；它们与报价基础价格、附加费用如何叠加，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。
4. `附加费用`表示在基础报价之外追加的费用，不得当作基础价格使用。

### 8.2 规则类型：区间按什么数据判断？

`规则类型`是每条价格规则必须选择的判断指标。系统先取得订单对应的指标值，再与规则的最小值、最大值及边界符号比较，判断订单是否命中。三者分工如下，不能互相替代：`规则类型`回答“什么条件下命中”，`计费模式`回答“使用什么计费量”，`价格类型`回答“命中后如何计算价格”。

例如，报价可以先按`包裹重量`区间选择价格，再在某个重量区间下按`月发货量`选择子规则；最终仍按报价的计费模式和末级规则的价格类型计算费用。页面应根据规则类型自动带出单位，区间上下限必须使用该单位。

| 指标类别 | 规则类型 | 匹配数值与单位 | 详细解释与适用方式 |
| --- | --- | --- | --- |
| 单票或包裹指标 | 包裹重量 | 包裹实重，`kg` | 指包裹称重得到的实际重量，不包含抛重比较、舍入或进位。报价采用`多包裹合并算费`时，按同一业务订单内需合并算费的包裹实重汇总；采用`多包裹单独算费`时，按当前包裹的实重判断。适用于按实际重量分档报价。 |
| 单票或包裹指标 | 计费重量 | 处理后的重量，`kg` | 指按当前报价的计费模式、抛重规则、舍入和进位处理后得到的重量。它与`包裹重量`的差异在于：前者可以受体积重、抛比和进位影响，后者只是原始实重。适用于价格区间必须跟最终算费重量保持一致的场景。 |
| 累计统计指标 | 月均重 | 当月平均计费重量，`kg` | 指同一统计主体在当前自然月内已出库包裹的计费重量总和，除以已出库包裹数。用于按客户当月平均包裹重量区间执行差异化报价。没有已出库包裹时，月均重按 `0kg` 参与区间判断。 |
| 累计统计指标 | 月发货量 | 当月已出库包裹数，`单` | 指同一统计主体在当前自然月内已出库的包裹数量，不是订单商品件数。适用于按客户当月累计发货量分档报价。 |
| 累计统计指标 | 日发货量 | 当日已出库包裹数，`单` | 指同一统计主体在当前自然日内已出库的包裹数量，不是订单商品件数。适用于按当日发货规模执行阶梯价格。 |
| 累计统计指标 | 月运费总额 | 当月累计运费，`元` | 指同一统计主体在当前自然月内，已出库包裹按线路报价计算出的基础运费累计金额，不含保价费、税费及其他独立附加费用。金额区间必须以报价币种比较；存在不同币种的来源金额时，系统不得直接比较，应先换算为报价币种。 |
| 单票或包裹指标 | 保价金额 | 申报保价金额，`元` | 指订单或包裹申报的保价本金，不是由此计算出的保价费。金额区间按报价币种比较；来源金额币种与报价币种不一致时，应先换算后再命中区间。适用于高价值货物收取不同保价费或服务费的场景。 |
| 单票或包裹指标 | 代收货款金额 | 尾程包裹的代收货款原始金额 | 指该尾程包裹交给派送商收取的代收货款金额，只用于命中`代收货款手续费报价`的金额区间，不参与手续费乘法计算。金额必须使用报价配置的`报价币种`比较。 |
| 单票或包裹指标 | 体积 | 长 × 宽 × 高，`cm³` | 指包裹的几何体积，按长、宽、高相乘得到。它是体积本身，不是将体积换算后的抛重或材积。适用于按立方体积划分价格区间的线路。 |
| 单票或包裹指标 | 包裹长度 | 包裹最长边，`cm` | 指包裹长、宽、高中的最大值，不是周长，也不是三边之和。适用于超长包裹的价格分档或附加收费。 |
| 单票或包裹指标 | 数量 | 当前算费对象数量，`个` | 指当前报价计算对象的数量。多包裹合并算费时为参与合并的包裹数；多包裹单独算费时为当前包裹对应的数量。它不等于月发货量、日发货量等累计统计指标。适用于按件数分档的报价。 |
| 单票或包裹指标 | 材积 | 按材积规则换算的值，`材` | 指根据箱型、材积公式和材积比换算得到的材积值，不等于几何体积。适用于报价计费模式为`按材积(材)`，或需要按材积区间再细分价格的场景。 |

统计类规则类型统一遵守以下口径：

1. 统计主体固定为当前报价命中的店铺和客户，不得跨店铺、跨客户汇总，也不得混入其他线路报价下的业务数据。
2. `月均重`、`月发货量`、`日发货量`和`月运费总额`按包裹出库时间归属自然日或自然月；月度统计在每月第一日重新开始累计。
3. 统计值只累计当前待报价包裹之前已经出库的包裹，当前包裹不计入自身的统计条件，避免同一笔费用因计算先后不同而产生不同结果。
4. 当前自然日或自然月没有符合范围的已出库包裹时，数量和金额按`0`参与判断，`月均重`按`0kg`参与判断。使用统计类规则类型时，价格区间应覆盖零值，或提供明确的默认规则。

配置规则类型时，还必须遵守以下约束：

1. 规则类型为必填项。页面应根据所选规则类型展示正确单位；用户不得把重量、金额、体积、长度、数量或材积填入错误单位的区间。
2. 同一父规则下的同级规则必须使用同一种规则类型，才能校验区间是否重叠、连续或存在空档；不同层级可以使用不同规则类型，以表达多条件报价。
3. 规则类型只用于选择规则。最终费用仍按报价的计费模式和末级规则价格类型计算；例如按`月发货量`命中子规则后，末级规则仍可按`每千克`对计费重量计算费用。
4. 普通线路报价中的`包裹重量`、`计费重量`、`体积`、`包裹长度`、`数量`和`材积`取自本次报价的算费对象；`代收货款手续费报价`中的`代收货款金额`取自已经确定尾程派送商的单个尾程包裹，不受普通线路报价的多包裹合并或单独算费设置影响。

### 8.3 区间边界和嵌套规则

1. 每条区间规则都必须明确下限、上限及边界符号。区间是否必须完整覆盖全部可能值，以及发生重叠或空档时是否阻止保存，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。
2. 相邻区间应通过边界符号明确衔接，例如`0kg < 包裹重量 <= 10kg`和`10kg < 包裹重量 <= 999kg`。
3. 需要在一个区间内继续按子条件计算时，可以在该区间下维护子规则；子规则也可以继续嵌套，直到规则节点可以直接计算费用。
4. 页面应同时展示区间、价格类型和价格，避免只显示一个无法理解的数字。
5. 保存时必须校验单条规则的区间上下限、边界关系、价格类型和计量单位；校验失败时不得保存。同级规则之间的重叠和空档校验按第 1 项引用的待确认规则处理。
6. 区间最大值填写`0`时，表示没有上限，即无穷大。页面应展示“无穷大”或“无上限”，不能让用户误解为上限数值为 0。
7. 任意层级的规则节点只有在未填写单价时，才可以作为父规则继续添加子规则；填写单价后，该节点表示直接计费，不得再下挂子规则。
8. 当前规则操作菜单中的`+`按钮表示`添加子规则`。只有当前节点未填写单价时，该按钮才可用；新增子规则必须位于当前节点的区间范围内。
9. 子规则可以继续嵌套。系统从上到下逐级匹配，直到命中填写单价的末级规则；末级规则不能再添加子规则。
10. 子规则不得超出父规则范围。同一父规则下的子规则是否必须互斥且连续，按第 1 项引用的待确认规则处理。
11. 将已有规则移动到新的父规则下时，如果新父规则原本填写了单价，系统应先清除其单价和价格类型，再将其转为条件节点。移动后，父规则必须重新按子规则完整匹配，不能同时表示直接计费和继续分层。

### 8.4 地区报价

`地区报价`用于为特定地区维护独立的价格区间。每个地区报价卡至少包含：

1. `选择地区`。
2. `地址分类`，可选且支持多选。
3. 该地区的价格区间规则。
4. 删除地区报价、保存和关闭操作。

一张地区报价卡可以选择多个地区，也可以选择多个地址分类。地址分类为空表示该卡不限定地址分类，但运行时适用范围仍须按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)确认。地区必须属于本报价已配置的目的地范围；同一张卡选择父级地区后，页面会清理该父级及其下级节点的重复选择，避免保留父子重叠节点。

地区报价命中后是完全替代默认价格区间还是叠加费用、多个地区报价卡同时命中时如何选择、未配置地址分类时如何回退，仍须按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)明确。不得根据地区报价卡在页面中的排列顺序自行推定优先级。

### 8.5 代收货款手续费报价：先锁定派送商，再按货款金额分档

#### 8.5.1 这类报价解决什么问题？

尾程派送商可能按照包裹代收货款金额分档收取手续费。同一目的地、不同派送商的分档金额和手续费并不相同，不能把它们压缩成一条通用的重量或体积价格规则。

`代收货款手续费报价`是线路报价中的一种独立报价类型。它不负责选择线路或派送商，而是在订单已经确定尾程派送商后，为每个尾程包裹按代收货款金额找到对应的固定手续费。订单包含多个尾程包裹时，每个包裹分别命中区间，最后汇总为该业务订单的代收货款手续费。

本报价类型只处理客户侧的代收货款手续费，不处理尾程派送商的其他运输费用，也不替代普通线路报价、到付附加费报价或返款业务。

#### 8.5.2 页面需要配置哪些内容？

选择报价类型为`代收货款手续费报价`后，页面沿用普通报价的公共详情结构，但必须根据字段是否适用切换控件状态：仍需财务配置的字段保持可编辑；业务值唯一的字段显示固定值并禁用；不参与本报价计算的公共字段显示`不适用`并禁用。箱型材积、超材收款、超材手续费及普通线路地区价格规则等专属区域不显示，不能因为这些字段存在旧值而影响代收货款手续费计算。

本报价仍沿用店铺、报价分组、业务类型、目的地、启用时间、启用状态和版本管理等通用属性；其中尾程派送商集合由本报价固定指定，不使用`渠道线路分配策略`为订单重新选择派送商。一份报价可以同时指定多个独立的尾程派送商，所有已指定派送商共用同一套金额区间和固定手续费；派送商主数据仍保持独立，不因共用报价而合并。

代收货款手续费报价不得新增独立的纵向金额区间表，必须复用原有`默认价格区间`区域及其新增、编辑、删除交互。该区域的规则类型固定为`代收货款金额`，价格类型固定为`一口价`且不可切换；每个区间填写的价格就是该区间的固定手续费。报价币种同时作为区间金额和手续费的币种。

| --- | --- | --- | --- |

| 计费模式 | 按完整计费模式枚举选择 | 固定为`按代收货款金额分档` | 普通报价可编辑；本报价显示固定值并禁用。 |
| 计算方式 | 根据计费模式展示兼容枚举 | 固定为`多包裹单独算费` | 普通报价可编辑；本报价显示固定值并禁用。 |
| 费用取整、舍入模式、进位模式 | 按普通费用规则配置 | 不参与固定手续费计算 | 普通报价可编辑；本报价显示`不适用`并禁用。 |
| 默认抛比、默认抛重公式 | 仅在使用抛重的计费模式下参与计算 | 不参与手续费计算 | 普通报价仅在适用计费模式下可编辑；其他计费模式和本报价均显示`不适用`并禁用。 |
| 默认价格区间 | 用于按计费量确定价格 | 用于按代收货款金额确定固定手续费 | 两类报价均显示；本报价的规则类型固定为`代收货款金额`，价格类型固定为`一口价`。 |
| 报价币种 | 不属于普通报价 | 同时用于解释区间金额和手续费金额 | 普通报价不显示；本报价显示并保持可编辑。 |

#### 8.5.3 系统怎样为包裹计算代收货款手续费？

系统按以下顺序处理，不得跳过派送商匹配或将未命中结果默认为`0`：

1. 判断尾程包裹是否存在代收货款业务；没有代收货款或代收货款金额为`0`时，不产生代收货款手续费。
2. 读取该尾程包裹已经确定的尾程派送商、订单所属店铺、客户报价分组、业务类型、目的地和代收货款原始币种。
3. 在启用且有效的`代收货款手续费报价`中，筛选通用适用范围和报价币种均匹配、且尾程派送商集合包含订单派送商的一条报价。
4. 读取该包裹的代收货款金额，按报价中的金额边界命中一条区间。
5. 直接取命中区间的固定手续费金额，并使用该报价配置的`报价币种`形成一条`代收货款手续费`费用明细。
6. 订单包含多个尾程包裹时，分别计算每个包裹的手续费，再汇总到业务订单；明细仍保留尾程运单号、派送商、代收货款金额、命中区间、手续费金额、报价币种和报价版本，供后续对账追溯。

`代收货款金额`只用于命中区间，不参与手续费乘法计算。例如命中`5,001至10,000 TWD`区间且手续费配置为`35 TWD`时，无论包裹代收货款实际为`5,100 TWD`还是`9,900 TWD`，手续费都为`35 TWD`。

对报价中的每个尾程派送商分别校验唯一性：同一适用范围、同一报价币种、同一尾程派送商的有效报价在有效时间上不得重叠。两个报价的派送商集合只要存在交集，且其他适用范围和有效时间也重叠，即构成冲突；系统应在保存或启用时阻止形成无法唯一选择的报价。订单无法找到报价、代收货款币种不匹配或金额没有命中区间时，系统返回明确的`未配置可用的代收货款手续费报价`原因，不得产生无币种或金额为`0`的手续费明细，也不得静默使用其他派送商的报价。

#### 8.5.4 金额区间如何表达和校验？

金额区间采用“下限不包含、上限包含”的连续表达，例如`0 < 代收货款金额 <= 5,000`和`5,000 < 代收货款金额 <= 10,000`。对于没有小数的币种，页面可按财务习惯显示为`1至5,000`和`5,001至10,000`；实际判断仍以边界关系为准，避免因币种精度不同产生空档。

1. 第一条区间必须从`0`以上开始，最后一条区间必须覆盖本报价允许的最大代收货款金额；最大值为`0`时按无上限处理。
2. 同一报价内的区间不得重叠、不得存在空档，后一条区间必须从前一条区间的上限连续开始。
3. 区间下限和上限必须符合边界关系，手续费金额必须为非负数；手续费为`0`表示该金额范围免收手续费，不表示未配置。
4. 报价币种必须填写；订单金额和固定手续费均使用该币种，不存在两种币种之间的换算，也不自动套用汇率。
5. 每条报价必须至少有一条完整区间；删除最后一条区间或删除后形成空档时，不得保存或启用。
6. 一份代收货款手续费报价至少关联一个尾程派送商，也可以关联多个尾程派送商。关联关系只表示这些派送商共同引用同一套规则，不合并派送商主数据；所有关联派送商必须共用报价币种、金额区间和固定手续费。若任一派送商需要不同费率，必须拆分为另一份报价。

#### 8.5.6 费用结果怎样生效和追溯？

1. 报价保存后形成独立版本；后续编辑、复制新增、启用、停用和删除遵循[9. 报价如何生效、变更和追溯](#9-报价如何生效变更和追溯)。
2. 订单费用结果必须记录命中的报价版本和金额区间，后续查看订单费用时能还原“哪个派送商、哪个代收货款金额、哪个区间、哪份报价版本产生了手续费”。
3. 已形成的订单费用不因报价后续编辑而静默改写；只有订单侧明确触发费用重算时，才按重算时适用的报价版本重新计算，并保留新旧结果的业务追溯关系。
4. 该费用形成后作为客户侧费用结果，继续进入后续账单和对账流程；BMS读取已经形成的费用结果，不在账单生成时重新匹配派送商或代收货款金额区间。

## 9. 报价如何生效、变更和追溯

### 9.1 生效条件

报价同时满足以下条件时，才可被订单使用：

1. 报价状态为启用。
2. 当前时间不早于启用时间。
3. 报价为永久启用，或当前时间不晚于到期时间。
4. 订单的店铺、报价分组、业务类型、目的地、货物类型、运输方式和仓库均命中报价范围。
5. 承运商、线路产品和计费规则均完整可用。

### 9.2 新增、编辑和复制新增

1. `新增报价`创建一条新的线路报价，填写完整必填项后才能保存。
2. `编辑`修改当前报价的基础信息、适用范围或计费规则；保存前必须重新校验所有相关依赖。
3. `复制新增`以已有报价为基础创建新报价。新报价必须拥有独立的报价名称和生效配置，不能覆盖原报价。
4. 编辑或复制新增时，必须明确复制范围，尤其是报价分组、仓库、承运商、地区报价和价格区间，避免只复制基础信息而缺少计费规则。

### 9.3 启用、禁用和删除

1. 禁用报价后，新订单不得再使用该报价；已经形成的订单费用是否回溯调整，不在本页面自动处理。
2. 启用报价前必须校验有效期、适用范围、承运商和计费规则完整性。
3. 未被订单、费用或历史记录引用的报价可以删除。已被引用的报价采用禁用、逻辑删除还是其他处理方式，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。
4. 删除、禁用和启用都必须二次确认，并说明对后续订单的影响。

### 9.4 历史版本

1. `历史版本`展示报价的版本号、变更时间、操作人和查看入口。
2. `查看`以只读方式展示该版本的基础信息、适用范围、承运商、计费模式、价格区间和地区报价；`代收货款手续费报价`还应展示报价币种及各金额区间的手续费。
3. `对比当前`展示历史版本与当前版本的差异；查看和对比都不得改变当前配置。
4. 历史版本至少应追溯报价名称、报价分组、业务类型、目的地、运输方式、仓库、承运商、计费模式和价格规则的变化；代收货款手续费报价还应追溯尾程派送商集合、报价币种和金额区间规则的变化。

## 10. 报价列表与批量操作

### 10.1 列表展示

列表至少支持展示以下信息：

1. 序号、店铺、报价名称、所属仓库、状态、业务类型、报价类型、报价分组。
2. 关联方案名、最新发布报价方案、最新方案发布时间、关联方案数量。
3. 货物类型、运输方式、承运商、目的地、产品描述。
4. 修改人、修改时间、创建人、创建时间、启用时间、到期时间、永久启用。
5. 产品优先级、计费模式、舍入模式、进位模式、超材手续费配置、超材费配置、推荐标签。
6. 报价类型为`代收货款手续费报价`时，还应展示尾程派送商集合、报价币种、代收货款金额范围、区间数量和手续费范围；普通线路报价不显示空的手续费专属字段。

列表支持选择表头、分页和横向滚动。选择表头只改变列表展示，不得改变报价配置。

### 10.2 批量修改报价

批量修改采用“勾选字段后才覆盖”的方式：未勾选字段保持每条报价原值，避免误覆盖无关配置。

批量修改支持以下范围：

| 批量修改区域 | 可修改内容 | 约束 |
| --- | --- | --- |
| 使用时间 | 永久启用或指定时间范围 | 勾选后才生效；指定时间必须完整。 |
| 服务属性 | 服务级别、服务类别、服务项内容 | 三项必须完整选择，不允许只修改其中一项。 |
| 币种与计量单位 | 币种、计量单位 | 应用到全部选中报价，并校验价格规则单位一致。 |
| 适用仓库 | 重设、新增或移除仓库 | `重设`完全替换原值；`重设`不能与`新增`或`移除`同时提交。当前页面不提供清空原有仓库的操作。 |
| 报价分组 | 按店铺分别重设、新增或移除分组 | `重设`完全替换原值；`重设`不能与`新增`或`移除`同时提交。多店铺批量修改时，分组按各店铺可用选项处理，不得跨店铺复用无效分组。 |
| 客户提醒说明 | 弹框提醒说明 | 用于客户端展示服务内容、规则或收费说明。 |
| 内容要求 | 以标签形式维护客户需要准备的内容 | 回车生成标签；未勾选时保留原值。 |
| 计费规则 | 计费模式、重量处理、价格区间等 | 只有勾选`应用计费设置`后才覆盖选中报价；可从已选报价中选择一条已有计费规则作为快速填充模板。 |

提交批量修改前，页面必须显示选中报价数量、将被覆盖的字段及各字段新值；提交成功后刷新列表并保留历史版本。

业务类型、目的地、运输方式、货物类型、适用仓库和承运商等多值字段，统一使用以下批量操作语义：

1. `重设`：用本次选择的值完全替换每条报价的原值。
2. `新增`：在每条报价原值中加入本次选择的值。
3. `移除`：从每条报价原值中移除本次选择的值。
4. `重设`不能与`新增`或`移除`同时提交；未选择任何值的字段不提交，因此不表示清空。
5. 批量修改承运商时，必须同时选择渠道线路分配策略。批量页面仅提供“指定唯一承运商，产品为默认产品”和“客户自行选择承运商，产品为默认产品”两种策略。

### 10.3 批量修改禁运规则

`批量修改禁运规则`当前是辅助处理入口，不提供`重设`、`新增`、`移除`或`清空`等确定性的字段操作。选中报价后，系统按店铺分组提交处理请求；每个店铺形成一项后台处理请求，且必须填写不少于 10 个字符的`集运清单描述`。

该入口与价格规则、承运商、目的地和生效时间相互独立。当前实现尚不能证明后台处理会如何改写禁运品类或禁寄描述，因此上线前必须补充处理结果的写入范围、覆盖方式、失败反馈和人工复核规则；规则明确前，不得把该入口解释为已具备确定性的批量禁运规则修改能力。

## 11. 报价匹配与保存边界

### 11.1 订单如何找到候选报价

订单请求报价时，系统至少按以下条件筛选：

1. 店铺。
2. 客户所属报价分组。
3. 业务类型。
4. 目的地国家或地区。
5. 货物类型。
6. 运输方式。
7. 实际发货仓。
8. 报价启用状态和有效期。

筛选结果再结合报价类型、承运商线路分配策略、产品优先级和价格规则形成可用报价。不存在满足全部条件的报价时，不得静默改用其他店铺、仓库或报价分组的报价。

`代收货款手续费报价`不参与普通线路和派送商选择。订单先由普通线路报价确定尾程派送商，再按[8.5 代收货款手续费报价：先锁定派送商，再按货款金额分档](#85-代收货款手续费报价先锁定派送商再按货款金额分档)匹配手续费报价。

### 11.2 必须阻止保存的情况

以下情况不得保存：

1. 缺少店铺、报价名称、报价分组、报价类型、业务类型、目的地、货物类型、运输方式、适用仓库或渠道线路分配策略；非自动分配策略缺少承运商。
2. 非永久报价缺少完整启用时间，或开始时间晚于到期时间。
3. 策略要求指定承运商产品，但没有配置可用的承运商产品。
4. 计费模式与价格区间计量单位不一致。
5. 单条价格规则的区间上下限关系错误、价格为空或价格为非法负值。同级区间重叠或存在空档时是否阻止保存，见[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)。
6. 地区抛重规则缺少地区、抛重公式或抛比。
7. 地区报价缺少地区或价格区间。
8. `最小包裹数`不是非负整数，或`包裹最小重量`不是最多保留 1 位小数的非负数。
9. 批量修改时，选中的新值会使任一报价失去必填的店铺、分组、仓库、承运商或计费规则。
10. `代收货款手续费报价`未配置至少一个尾程派送商、缺少报价币种、没有完整金额区间、区间重叠或存在空档、手续费为负数，或会与相同适用范围内且派送商集合存在交集的其他有效报价形成无法唯一选择的时间重叠。

### 11.3 报价无法使用时如何反馈

1. 订单没有找到可用报价时，页面或调用报价的业务流程必须明确提示“没有匹配的线路报价”，不得返回不符合适用范围的报价。
2. 多个报价同时命中时，系统按[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)中最终确认的产品优先级规则选择；规则确认前，不得自行决定优先级方向或同优先级处理方式。
3. 订单已使用的报价在后续配置变更后是否重新匹配，由订单状态和[12.1 仍待确认的运行时规则](#121-仍待确认的运行时规则)决定，不得由 BMS 账单任务自行决定。
4. 代收货款包裹没有找到可用的手续费报价，或金额没有命中区间时，必须返回`未配置可用的代收货款手续费报价`及未命中的尾程派送商、币种和金额；不得默认手续费为`0`或改用其他派送商报价。

## 12. 待确认业务规则

本章只保留尚未确认、且不能仅根据页面配置确定结果的运行时规则。已经确认的配置规则直接写入对应业务章节，本章不重复说明。

### 12.1 仍待确认的运行时规则

以下问题会直接影响报价命中、费用计算或历史订单处理，确认前不得自行推断：

1. 多条报价同时命中时，`产品优先级`是数值越大越优先还是越小越优先；优先级相同且其他条件仍无法区分时，是阻止下单、返回冲突，还是按其他明确字段继续决策。
2. 除`派送附加费报价`外，其他报价类型是否存在只允许用于特定业务类型的组合限制。
3. 地区报价命中后，是替代默认价格区间还是追加费用；多个地区报价卡同时命中时如何选择；订单没有地址分类时，是否可以回退到未限定地址分类的地区报价或默认价格区间。
4. `最低收费`、`最高收费`、`附加费用`和`增值基础`同时命中时的计算顺序、适用范围和叠加关系。当前资料只能确认这些配置项存在，尚不能确认最终金额计算顺序。
5. 报价配置、报价币种、汇率、启用状态或到期时间变更后，已下单未出库、已出库未结单、已产生客户费用的订单是否重新匹配或重算；需要重算时，由谁发起，以及保留哪个报价版本。
6. 已被订单或历史记录引用的报价，在删除、禁用或到期后如何处理；删除采用物理删除还是逻辑删除；历史版本是否支持恢复为当前版本。
7. 客户自行选择承运商或承运商产品时，订单提交侧如何校验所选项属于当前报价的可用范围；客户可见范围是否还受报价分组、仓库或其他权限限制。
8. 报价币种和计量单位由哪里维护；未来是否需要将币种配置扩展到当前页面未展示该配置的报价类型和业务类型。
9. `批量修改禁运规则`后台处理完成后，禁运品类和禁寄描述具体写入哪些对象、采用覆盖还是追加、失败如何反馈和是否需要人工复核。
10. `最小包裹数`和`包裹最小重量`同时配置时，是同时满足还是满足任一项；`包裹最小重量`比较单个包裹、任一包裹、全部包裹汇总重量还是其他指标；等于门槛时是否命中。
11. `自定义两者取其大`中，包裹三边之和等于`自定义最小长宽高之和`时，是按实重计费，还是进入实重与抛重取大逻辑。
12. `按区间进位`是否要求完整覆盖所有可能重量；区间重叠或存在空档时是否阻止保存；`取对方计费重量标识`中的“对方”具体指谁、使用哪一项计费重量、来源缺失时如何处理。
13. 非永久报价的结束日期是否覆盖当天全天。若结束日当天仍有效，保存值必须覆盖结束日最后时刻，不能因保存为`00:00:00`而只在当天零点命中。

在上述规则确认前，不得在产品文档、接口或数据处理中自行补充未确认的优先级、回退或金额叠加逻辑。
