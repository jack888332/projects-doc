# 2026-07-23 BMS 成本费项索引需求落地方案及调整计划

## 1. 文档目的

本文只设计本期“成本费项索引”功能，作为开发、联调和验收依据。

设计依据：

1. 成本中心原型：`http://192.168.2.2:10100/`。
2. PRD：`aidocs/product-caliber/bms/prd/财务系统.PRD.md` 的 `13.5.2 成本费项索引`。
3. 实体关系图：`aidocs/product-caliber/bms/prd/derivant/概念实体关系图.md`。
4. 当前 `bms`、`platform-admin`、`admin_shell` 代码及开发库 `tmall_bms` 实际结构。

本文是实施方案，不直接变更业务代码和数据库。

## 2. 本期范围

### 2.1 本期实现

1. 按五大成本板块浏览标准成本费项。
2. 按关键词、状态查询当前板块的成本费项。

## 3. 需求口径

### 3.1 业务定义

成本费项索引是 BMS 内部统一使用的标准成本费项主档，用于归一供应商收费含义。

成本费项索引与现有客户侧费项索引是两个独立业务域：

| 对比项 | 客户侧费项索引 | 成本费项索引 |
| --- | --- | --- |
| 当前表 | `fee_index` | 本期新增 `cost_fee_index` |
| 服务对象 | 应收账单、返款账单 | 成本业务 |
| 费项类型 | 多种类型 | 固定为 `AP`（应付类） |
| 分组方式 | 业务场景、挂靠对象等 | 单一成本板块 |
| 名称唯一性 | 客户侧规则 | 同一成本板块内唯一 |

不得通过给现有 `fee_index` 增加“成本类型”筛选来混合维护两个业务域。

### 3.2 五大成本板块

| 编码 | 页面名称 |
| --- | --- |
| `DELIVERY` | 派送成本 |
| `CUSTOMS` | 清关成本 |
| `SEA_FREIGHT` | 海运成本 |
| `AIR_FREIGHT` | 空运成本 |
| `TRUCKING` | 租车成本 |

每个成本费项必须且只能归属一个成本板块。

### 3.3 核心规则

1. 成本费项编码由系统自动生成，在成本中心内全局唯一。
2. 同一成本板块内，标准成本费项名称不允许重复。
3. 不同成本板块允许使用相同名称，但必须使用不同编码。
4. 费项类型固定为 `AP`，页面不提供选择。
5. 业务定义必填，必须说明该费项包含和不包含的收费内容。
6. 状态只有启用、停用。
7. 停用只影响后续业务选择，不改变历史数据。
8. 不提供删除操作。
9. 本期尚无成本账单、成本明细和分摊规则引用，因此不实现引用校验。
10. 成本费项编码创建后不可修改；名称、业务定义、备注和状态可修改。
11. 成本费项索引是全平台共享的全局配置，不按供应链、店铺或用户隔离。
12. 标准名称保存前去除首尾空格，同一板块内按不区分大小写的规则校验唯一性。
13. 本期不增加菜单权限、按钮权限或后端操作权限控制。
14. 成本费项可维护多个全局别名，用于成本账单导入时按原始费项名称推荐标准成本费项；最终导入结果仍需由财务确认。

### 4.3 查询规则

1. 页面首次进入不传成本板块条件，默认查询全部成本费项。
2. 切换板块后，保留关键词和状态条件，页码重置为 1。
3. 关键词去除首尾空格后，模糊匹配 `fee_code`、`fee_name` 或 `fee_aliases`。
4. 状态默认为全部。
5. 点击重置时清空关键词和状态，保留当前板块标签。
6. 默认按更新时间倒序、主键倒序排列。
7. 无数据时展示“当前成本板块暂无标准成本费项”。

### 4.4 新增与编辑

使用弹窗表单：

| 字段 | 新增 | 编辑 | 校验 |
| --- | --- | --- | --- |
| 成本板块 | 必填、可选 | 只读 | 五大板块之一 |
| 成本费项编码 | 系统生成、只读 | 只读 | 用户不可输入或修改 |
| 标准成本费项名称 | 必填 | 可修改 | 去除首尾空格；最长 128；当前板块内唯一 |
| 费项类型 | 只读展示 | 只读展示 | 固定为应付类（`AP`） |
| 成本费项别名 | 选填 | 可修改 | 多个别名使用逗号、分号或换行分隔；合计最长 1000 |
| 业务定义 | 必填 | 可修改 | 最长 1000 |
| 状态 | 必填 | 可修改 | 启用或停用；新增默认启用 |
| 备注 | 选填 | 可修改 | 最长 500 |

提交规则：

1. 点击保存后按钮进入加载状态，禁止重复提交。
2. 保存成功后关闭弹窗、提示成功并刷新当前页。
3. 名称唯一性冲突时明确提示“当前成本板块已存在同名费项”。
4. 保存失败时保留用户已填写内容。

成本费项编码生成规则：

1. 新增时由 BMS 后端生成，前端和 Platform Admin 均不传编码。
2. 格式为 `CFI_{板块缩写}_{yyyyMMddHHmmss}_{6位大写随机串}`。
3. 板块缩写分别为：`DELIVERY -> DEL`、`CUSTOMS -> CUS`、`SEA_FREIGHT -> SEA`、`AIR_FREIGHT -> AIR`、`TRUCKING -> TRK`。
4. 示例：`CFI_DEL_20260723153045_A1B2C3`。
5. 数据库唯一索引作为并发兜底；发生极小概率的编码冲突时，后端重新生成后再保存，最多重试 3 次，仍失败则返回“成本费项编码生成失败，请重试”。
6. 编码生成逻辑封装在成本费项 Service 内，不依赖前端，也不新增独立编码服务或序列表。

### 4.5 启用与停用

1. 启用操作直接提交，成功后刷新当前页。
2. 停用前二次确认，文案为：“停用后，该成本费项将不能被后续成本业务选择，是否继续？”
3. 本期不存在成本业务引用，停用无需检查引用关系。
4. 不提供删除按钮。

## 5. 数据库设计

### 5.1 设计结论

新增独立表 `cost_fee_index`，不修改、不复用现有 `fee_index`。

原因：

1. PRD 明确要求客户侧与成本侧费项索引分域。
2. 现有 `fee_index` 已有 55 条数据，并被客户侧费项、来源规则和账单功能使用。
3. 现有表字段围绕场景标签、挂靠对象和订单来源设计，不符合成本板块模型。
4. 独立表可以避免成本侧改动影响已上线的客户侧费项链路。

### 5.2 建议表结构

```sql
CREATE TABLE `cost_fee_index` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `fee_code` varchar(64) NOT NULL COMMENT '成本费项编码，成本中心内全局唯一',
  `fee_name` varchar(128) NOT NULL COMMENT '内部标准成本费项名称',
  `fee_aliases` varchar(1000) DEFAULT NULL COMMENT '成本费项别名，多个别名使用英文逗号分隔，用于成本账单导入名称映射',
  `cost_board` varchar(32) NOT NULL COMMENT '成本板块：DELIVERY/CUSTOMS/SEA_FREIGHT/AIR_FREIGHT/TRUCKING',
  `fee_type` varchar(16) NOT NULL DEFAULT 'AP' COMMENT '费项类型，固定为AP应付类',
  `business_definition` varchar(1000) NOT NULL COMMENT '业务定义，说明包含和不包含的收费内容',
  `enabled` tinyint(1) NOT NULL DEFAULT '1' COMMENT '是否启用：1启用，0停用',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_fee_code` (`fee_code`),
  UNIQUE KEY `uk_cost_board_fee_name` (`cost_board`, `fee_name`),
  KEY `idx_cost_board_enabled_updated` (`cost_board`, `enabled`, `updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci ROW_FORMAT=DYNAMIC COMMENT='成本费项索引';
```

### 5.3 字段说明

1. `fee_type` 固定保存 `AP`，用于明确成本费项的业务性质；前端不传，后端统一赋值。
2. `cost_board` 使用枚举校验，禁止保存枚举外值。
3. `fee_aliases` 保存成本费项的全局别名，后端去除空值和重复值后统一使用英文逗号分隔；供应商专属映射仍由后续导入设置快照承载。
4. 本期不增加逻辑删除字段，因为产品不提供删除能力。
5. 本期不增加版本字段；单行更新由数据库事务保证。
6. 成本费项是全平台共享的 BMS 全局配置，不增加 `sc_id/shop_id/user_id` 数据隔离列；操作人使用 `created_by/updated_by` 记录。

### 5.4 SQL 实现约束

1. 列表使用数据库分页：先 `COUNT`，再 `LIMIT #{offset}, #{limit}`。
2. 选择具体成本板块时按 `cost_board` 精确筛选；选择“全部”时不增加板块条件。
3. 关键词条件使用 `fee_code LIKE` 或 `fee_name LIKE`，不对列使用 SQL 函数。
4. 写操作统一使用 `@Transactional(rollbackFor = Exception.class)`。
5. 新增和更新前在 Service 层做非空、枚举和唯一性提示校验，数据库唯一键作为并发兜底。
6. 更新语句不更新 `fee_code` 和 `created_by`。
7. 开发时需将完整 `CREATE TABLE` 同步到 `aidocs/technical-caliber/sql/ar_bill.sql`。
8. 标准名称在后端去除首尾空格后保存；表使用 `utf8mb4_general_ci` 字符排序规则，唯一性校验与数据库唯一索引均不区分大小写。

### 6.5 后端校验

新增时：

1. 成本板块、名称、业务定义、状态必填。
2. 后端按已确认格式自动生成编码。
3. 状态只允许 0 或 1。
4. 校验板块内名称唯一。
5. 费项类型由后端固定写入 `AP`，不接受前端修改。
6. 别名按中英文逗号、分号或换行拆分，去除空值和重复值后统一保存。

编辑时：

1. 记录必须存在。
2. 保存 DTO 不包含编码，不接受对编码的修改。
3. 成本板块不可修改。
4. 校验修改后的板块内名称唯一，并排除当前 ID。

状态变更时：

1. 记录必须存在。
2. 状态只允许 0 或 1。
3. 重复提交相同状态按幂等成功处理。

## 11. 最终落地结论

本期仅建设一套独立、可维护的成本费项标准主档：

1. 新增一张 `cost_fee_index` 表。
2. 新增一组独立的成本费项后端接口。
3. 将现有成本费项索引静态页面接成真实的查询和维护页面。
4. 不修改现有客户侧 `fee_index` 及其业务链路。
5. 不提前建设任何成本账单、供应商映射或分摊能力。

该范围可以独立开发、独立验收，并为后续成本账单导入提供标准费项基础，但不把后续功能带入本期。
