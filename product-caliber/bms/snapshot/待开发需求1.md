# 待开发需求：客户与会员统一主体及店铺归属约束

## 1. 需求摘要

| 项目 | 内容 |
|---|---|
| 目的 | 统一 BMS 与集运客门户中的主体认知，避免把同一客户 / 会员建模为多账号或多个当前店铺，并消除配置、任务和账单页面中的多归属歧义。 |
| 范围 | 核心对象关系、客户组归属、配置分配与查询、生成任务快照、账单来源店铺快照。 |
| 来源 | 2026-08-28 产品澄清；同步纳入《PRD.账单系统》7.2.1、19.2.1 及相关任务和列表字段。 |
| 阅读说明 | 本文仅记录相对当前已实现方案的新增与修改，不重复共享 / 独享配置、配置版本等既有规则。 |

## 2. 变更需求

### 2.1 客户与会员统一为同一业务主体

1. `客户`和`会员`不是上下级或一对多关系，而是同一业务主体在不同系统语境下的称谓：
   - WMS 从货主关系称为`客户`或`货主`，使用客户编码；
   - 集运客门户从账号关系称为`会员`，使用会员编码。
2. 一个客户主数据必须且只能对应一个会员身份。BMS 同时保留客户编码和会员编码，用于跨系统定位同一主体，不得再展示或存储同一客户对应多个`关联会员`的当前关系。
3. 客户 / 会员是配置引用、订单下单、账单结算和财务对账的共同主体。配置引用仍直接下挂客户 / 会员，不因店铺或客户组归属形成配置层级。

### 2.2 店铺和客户组归属约束

1. 一个会员在同一时点只能从属一个店铺；店铺为会员的唯一当前所属店铺。
2. 客户组必须在店铺内创建，一个客户组只能属于一个店铺，不得跨店铺包含会员。
3. 一个会员在同一时点至多加入其当前所属店铺下的一个客户组；未加入客户组时允许为空。
4. 会员转店或改组由 OIS 管理。BMS 读取当前关系，不反向维护店铺或客户组归属；转店或改组不自动改变客户当前引用的配置编号和版本。
5. OIS 提供给 BMS 的关系数据至少包含：客户主数据编号及名称、会员编号及名称、当前所属店铺、当前所属客户组、客户组所属店铺、关系状态和更新时间。
6. 出现以下任一数据问题时，该客户不得进入配置分配候选清单，并须返回具体原因：
   - 客户与会员不能一一对应；
   - 同一会员同时存在多个当前所属店铺；
   - 客户组不属于会员当前所属店铺；
   - 必需关系字段缺失。

### 2.3 配置分配与查询调整

| 场景 | 修改后规则 |
|---|---|
| 客户配置列表 | 每个客户只展示一组当前身份与归属字段：客户编码、客户名称、会员编码、所属店铺、所属客户组。字段名称使用`所属店铺`和`所属客户组`，不再使用`关联会员`或多值归属表达。 |
| 分配向导 | 店铺、客户组和指定客户仍仅用于批量选客。选择店铺后，客户组选项只显示所选店铺下的客户组；选择客户组时只能命中该客户组所属店铺内的会员。 |
| 条件组合 | 店铺与客户组必须属于同一条当前归属关系。跨店铺的无效组合不得命中客户，也不得依靠不同关系的字段拼接形成命中。 |
| 列表结果 | 删除`全部当前归属`、`本次命中归属`等多关系列，分别展示唯一的会员编码、所属店铺和所属客户组。 |
| 引用审计 | 创建或切换配置引用时，审计记录固化当时的客户编码、会员编码、所属店铺和所属客户组，便于追溯；这些字段不参与运行时配置匹配。 |

### 2.4 任务与账单快照调整

1. 按客户生成账单或批量创建任务时，每个客户任务只固化一组当前主体快照：客户编码、会员编码、所属店铺、所属客户组、配置编号和准确版本。
2. 任务列表和详情使用`会员编码`、`所属店铺快照`、`所属客户组快照`，不再显示多个当前会员、多个当前店铺或多个当前客户组。
3. 当前归属与历史订单来源必须区分：会员转店后，新订单使用新店铺，已生成订单继续保留原`所属店铺快照`。
4. 同一客户 / 会员在同一账期内存在不同来源订单店铺快照时，可以继续读取同一份客户配置引用，但账单必须按来源订单的店铺快照拆分，不得跨店铺归集。

## 3. 影响范围

1. 账单配置与汇率配置的客户引用列表、查询条件和分配向导。
2. 按客户生成任务、任务列表、任务详情和批次详情中的主体归属快照。
3. 客户 / 会员关系接口或数据视图，以及关系异常的候选客户排除与提示。
4. 账单生成时来源订单店铺快照的拆单逻辑；既有历史订单快照不得被当前归属覆盖。
