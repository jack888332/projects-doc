## 1. PRD 变更整理

目标提交修改了 `product-caliber/bms/prd/CERD.md` 与 `product-caliber/bms/prd/PRD.账单系统.md`，核心是引入「虚拟业务订单」概念，并把 `ofp_ofdb1.sale_order_additional_matter` 的附加费来源拆分为两个导入入口。

### 1.1 虚拟业务订单（CERD 新增约束）

| 要点 | 内容 |
| --- | --- |
| 识别方式 | `ofp_ofdb1.sale_order_header.order_type = "BILL"` 表示虚拟业务订单；是否虚拟**不得再由其它字段重复表达**。 |
| 业务含义 | 只承载来源和客户归属，不代表客户真实下单；不发生核价、核重、出库、运输或签收等履约流程。 |
| 用途 | 【记账单导入】形成的直接客户附加费挂靠该虚拟业务订单。 |
| 快照要求 | `业务主单快照.订单类型`由 `sale_order_header.order_type` 同步；取 `BILL` 时表示虚拟业务订单。 |

### 1.2 附加事项表两个导入入口（19.2.3.5）

| 导入入口 | 记录什么费用 | 挂靠对象 | 可用的时间事实 |
| --- | --- | --- | --- |
| `附加费用报表导入` | 归属于真实尾程包裹的附加费 | 真实业务订单下由尾程运单号对应的尾程包裹 | 沿包裹归属读取真实业务订单的出库时间或订单完结时间 |
| `记账单导入` | 直接向客户收取、但不归属于真实业务订单的附加费 | `order_type = "BILL"` 的虚拟业务订单 | 虚拟订单无出库/完结时间；使用附加事项记录自身 `create_time` |

### 1.3 记账单导入附加费的归集规则（9.4 / 9.5.4）

1. **筛选口径**：不校验订单履约节点，按 `ofp_ofdb1.sale_order_additional_matter.create_time` 筛选。
2. **收取方式过滤**：按 `sale_order_additional_matter.fee_pay_method`（收取方式）过滤，仅 `fee_pay_method = 'account_period_payment'`（账期支付）的附加费才可作为客户应收费项写入 `BMS费项池` 并参与应收账单计算；其它收取方式不得进入应收归集范围（Q-01 已确认：以代码现有字段 `fee_pay_method` 为准，PRD 中 `payment_method` 表述按该字段理解）。
3. **归账要求**：必须归入客户应收账单，并使用客户应收账单配置的**默认方案**；来源创建时间落入默认方案的实际账期，同时满足客户、店铺、费项范围、金额、币种和防重条件时，由系统自动发起的`费项入池`任务或`账单生成`任务写入费项池。
4. **入池后承接**（9.5.4 规则 8）：
   - 对应账期尚无账单 → 参与**首次生成**；
   - 对应账单尚未发出且允许补充 → 参与**补充生成**；
   - 其它情形 → 按 9.8（调账、冲正或本期/后续账单承接），**不得重复形成应收费项**。
5. **识别约束**：以 `order_type = "BILL"` 识别虚拟业务订单，不得伪造虚拟订单的出库或完结数据来满足归集条件。

### 1.4 防重与留痕（9.5.5）

- PRD 原文要求保留导入入口、导入批次、原始行、挂靠对象、导入人员，并按 `导入入口 + 文件校验值 + 工作表 + 原始行号` 防重。
- **已确认（Q-03）：BMS 不做文件导入防重**（导入入口/文件校验值/工作表/原始行号均不由 BMS 采集和校验）；采集字段回填**参考原有附加费采集**，OFP 侧已有回填标识字段（`bms_billed_flag` / `bms_bill_no` / `bms_after_bill_added_flag`），BMS 按原有逻辑回填即可。
- 更正已入池金额按 9.5.2（更正费项、调账或冲正）处理。

### 1.5 其它相关变更

1. `sale_order_package_fee`（订单费项报表导入的包裹级回款明细）作为**非费项**回款核对事实进入归集视野（本次只影响回款管理口径说明，不影响应收采集 SQL）。
2. 费项类型由费项索引定义（应收类/应收扣减类/应付类/代收类/代付类/非费项），应收计算时：`应收扣减类`和`代收类`按负数参与汇总，`代付类`按正数参与汇总。
3. 来源未明确币种时默认币种顺序：代收货款→目的国币种；附加费 `payment_method=货到付款`→目的国币种；其它→店铺币种；目的国币种读 `sale_order_header.dest_country_currency_code`。

> 记账单场景已确认（Q-06）：记账单附加费都不是到付费项，**原始币种直接取 `ofp_ofdb1.sale_order_additional_matter.fee_amount_currency`**，不进入目的国/店铺币种兜底链。

## 3. 总体技术方案

### 3.1 虚拟业务订单识别（common 层）

在 `BmsConstants` 新增：

```java
/** OFP 销售订单类型：虚拟业务订单（记账单），仅承载来源与客户归属，不参与履约 */
public static final String SALE_ORDER_TYPE_BILL = "BILL";
```

### 3.2 记账单附加费采集分支（biz 层，核心）

在 `BillGenerateServiceImpl` 新增记账单附加费查询与归集分支，与现有三条附加费路径并列：

```
MEMBER_AR 任务执行
 ├─ 订单主查询（现有，排除 BILL 见 3.3）
 ├─ 附加费随订单查询（现有，仅真实订单）
 ├─ 附加费增量查询（现有，显式排除 BILL）
 ├─ 理赔查询（现有）
 └─ ★ 记账单附加费查询（新增）
      条件：h.order_type = 'BILL'
            AND h.member_code = ? AND h.shop_id = ? AND (h.sc_id = ? OR h.sc_id IS NULL)
            AND a.fee_amount IS NOT NULL AND a.fee_amount <> 0
            AND a.fee_pay_status IN ('waiting_pay','waiting_settlement')
            AND a.fee_pay_method = 'account_period_payment'   -- Q-01 已确认：沿用现有字段
            AND a.create_time >= ? AND a.create_time < ?       -- 固化 create_time
            AND COALESCE(a.bms_billed_flag, 0) = 0
            AND (a.bms_bill_no IS NULL OR a.bms_bill_no = '')
            AND COALESCE(a.bms_after_bill_added_flag, 0) = 0
      ORDER BY a.id LIMIT ? OFFSET ?
```

要点：

1. **触发范围**：仅在 `billConfig.configType = DEFAULT`（默认方案）时执行本分支；分支方案（BRANCH）不采集记账单（PRD：归入客户应收账单默认方案）。
2. **独立成批查询，不依赖 orderIds**：以 `h.order_type='BILL'` 直接定位虚拟订单，避免对 BILL 订单重复走订单主扫描。
3. **挂靠对象固定为业务订单（ORDER）**：记账单分支生成的 `fee_detail` 写 `attachedObject = FEE_ATTACHED_OBJECT_ORDER`，`businessOrderNo` 取虚拟订单 `h.order_code`，`sourceTable = sale_order_additional_matter`，`sourceId = a.id`。
4. **规则匹配**：复用 `matchesAdditionalRule`，按 `filter_params_json.feeItemType` 与 `a.fee_item_type` 匹配；未命中启用规则的行跳过（不采集、不打标）。
5. **快照同步**：记账单分支同样生成 `main_order` 快照（`orderType = 'BILL'`，现有 :3275 已写 `orderType`，虚拟订单直接复用该写入路径，但不走履约时间字段）。
6. **任务快照**：在 `bill_generate_task` 的源 SQL 快照中追加 `ledger_additional_source` 段（`appendTaskAdditionalSourceSql` 拼接进 `additional_source_sql`），复用现有 `appendSqlSectionHeader` 机制；任务详情弹窗「附加费/记账单拉取 SQL」区块整段展示。

### 3.3 现有附加费 SQL 的隔离调整

| 位置 | 调整 |
| --- | --- |
| `buildAdditionalRowsQuerySql`（:5066） | 追加 `AND h.order_type <> 'BILL'`（防御：若 OFP 虚拟订单被外部误写入 orderIds 场景）。 |
| `buildIncrementalAdditionalQuerySql`（:5099） | 追加 `AND h.order_type <> 'BILL'`，将 BILL 订单附加费完全隔离到记账单分支，防止与记账单分支按 `create_time` 重复采集。 |
| `buildOrderWideQuerySql`（:5003） | 追加 `AND COALESCE(h.order_type,'') <> 'BILL'`，确保虚拟订单永不进入订单主扫描（防止未来 OFP 侧给 BILL 订单补了履约时间字段后被误采）。 |

### 3.4 记账单来源打标与留痕

1. **新增 collect_type**：`BmsConstants` 新增 `SOURCE_COLLECT_TYPE_LEDGER_ADDITIONAL_FEE = "LEDGER_ADDITIONAL_FEE"`（记账单附加费）。`bill_source_collect_mark.collect_type` 注释同步补充。
2. **打标路径**：复用 `markAdditionalSource(billConfig, row, orderRow, billId, billNo, taskId, collectType)`（:4387-4400），记账单分支传入新 collect_type；`source_snapshot_json` 保留原有附加费一致的关键字段快照（Q-03 已确认：不采集导入入口/文件校验值/工作表/原始行号）。
3. **源表回写**：复用 `markAdditionalFromSource` → `UPDATE sale_order_additional_matter SET bms_billed_flag=1, bms_bill_no=? WHERE id=?`，与现有附加费一致（OFP 侧已有回填标识字段）。

### 3.5 防重设计

**已确认（Q-03）：BMS 不做文件导入防重，防重口径与原有附加费采集完全一致。**

1. **来源行防重**：`uk_source_collect(source_system,source_table,source_id,collect_type,bill_type)` 保证同一来源行同一归集类型只打标一次；记账单分支使用新 collect_type 后天然与报表导入（ADDITIONAL_FEE）互不冲突。
2. **源表回填标识防重**：沿用 `bms_billed_flag` / `bms_bill_no` / `bms_after_bill_added_flag` 三个 OFP 侧回填标识字段，与现有 `sale_order_header` / `sale_order_additional_matter` 采集逻辑一致（Q-03/Q-04/Q-05 已确认）。
3. 重复导入同一文件不得形成第二条有效费项：由 OFP 侧导入与回填标识机制保证，BMS 不做文件级去重。

### 3.6 入池后承接（首次生成 / 补充生成 / 9.8）

- **首次生成**：记账单附加费随默认方案任务按 `create_time` 落入账期窗口，与现有订单/附加费同批写入费项池并生成账单——现有链路天然支持。
- **补充生成**：记账单附加费若在账单生成后导入，复用现有「出账后新增附加费」增量机制（`bms_after_bill_added_flag=1` 路径）；**该标记的维护方式与原有 `sale_order_header` 采集逻辑一致（Q-05 已确认），BMS 不做额外处理**，仅确保增量 SQL 按 Q-08 口径隔离。
- **9.8 承接**：对已发出或不允许补充的账单，记账单附加费不自动重复入池；需按现有调账/冲正链路承接（本次不新增，仅确保不打标不重复采集）。

### 3.7 币种（记账单场景）

**已确认（Q-06）：记账单附加费都不是到付费项，原始币种直接取 `ofp_ofdb1.sale_order_additional_matter.fee_amount_currency`。**

BMS 侧记账单分支的币种解析简化：优先规则配置的币种列 → `a_fee_amount_currency` → `a_convert_fee_amount_currency`（与现有 `resolveSourceCurrency` 前两步一致，:3545-3562）；**不进入目的国币种 / 店铺币种默认链**（虚拟订单无目的国事实，记账单费项非到付）。`fee_amount_currency` 为空时按缺失币种处理，不入池并记录币种缺失原因。

## 7. 风险与注意事项

1. **回填标识依赖 OFP**：`bms_billed_flag` / `bms_bill_no` / `bms_after_bill_added_flag` 由 OFP 侧维护（Q-03/Q-05 确认）；若上游记账单导入未按原有逻辑写回填标识，补充生成与防重会失效，需在联调阶段与 OFP 侧对表验证。
2. **防重边界**：`uk_source_collect` 防重粒度为来源行 + collect_type；若记账单分支与增量分支隔离不彻底（§3.3），同一附加费行可能产生重复费项。§3.3 的 `order_type <> 'BILL'` 隔离必须与新增分支同步上线。
3. **历史数据**：虚拟业务订单与记账单附加费为 OFP 侧新增数据形态，历史库无此类数据；本次不处理存量迁移。
4. **币种缺失**：记账单附加费 `fee_amount_currency` 为空时不入池并记录币种缺失原因（Q-06），需在联调时准备缺失币种用例确认提示链路。
5. **不做越界**：记账单导入页面、文件解析、工作表读取、文件级防重均属 OFP 侧职责，BMS 只负责采集、归集、打标与回填。
