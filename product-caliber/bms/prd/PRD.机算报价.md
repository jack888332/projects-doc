# 线路报价配置 PRD

## 1. 产品定位与范围

### 1.1 产品定位

线路报价是供应链系统中为业务订单选择运输服务并计算客户侧费用的配置。财务系统中的 BMS 不重新计算线路报价，只读取订单侧已经形成的线路、承运商、计费结果和费用明细；相关边界见 [账单系统 PRD](./PRD.账单系统.md) 的业务系统基本面。

本 PRD 只描述 `线路报价管理` 页面及其配置逻辑，目标是让业务人员可以按照店铺、客户分组、仓库、目的地、货物类型和运输方式维护可复用的报价规则，并明确报价的适用范围、承运商分配方式、计费公式和价格区间。

### 1.2 本期范围

本期包含：

1. 线路报价的新增、编辑、复制新增、启用、禁用、删除和历史版本查看。
2. 报价基础信息、客户分组、业务类型和产品展示信息的配置。
3. 目的地、货物类型、运输方式、适用仓库和承运商的配置。
4. 承运商及线路产品的分配策略配置。
5. 计费维度、计费方式、重量处理、价格取整、价格区间和地区报价的配置。
6. 报价列表查询、表头选择、导出以及批量修改报价和批量修改禁运规则。

### 1.3 不在本期范围

1. 业务订单的创建、拆单、出库和实际运输执行。
2. 承运商自身的运价维护、物流轨迹维护和承运商产品的运营管理。
3. BMS 费项池的归集、账单生成、账单重算和对账报表导出。
4. 对产品优先级方向、地区报价运行时覆盖关系等当前实现无法证明的最终决策规则，统一列入[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)，在规则确认前不应由实现方自行推断。

## 2. 业务对象与配置关系

### 2.1 什么是一条线路报价

一条线路报价由一个报价名称和一组适用条件组成。适用条件全部满足时，该报价才可以作为订单的候选报价。

一条报价可以同时覆盖多个值，例如多个目的地、多个货物类型、多个运输方式、多个仓库和多个客户分组。多个值表示“满足其中任意一个即可”，不同维度之间仍然是“同时满足”。

报价至少需要明确以下关系：

| 关系维度 | 业务含义 |
| --- | --- |
| 店铺 | 报价所属的业务入口。报价分组和适用仓库等选项依赖店铺加载。 |
| 客户分组 | 报价适用的客户、会员或同行分组。报价分组为多选。 |
| 业务类型 | 报价适用的业务场景，例如集运、重出订单或电商订单。 |
| 目的地 | 订单收货国家或地区。 |
| 货物类型 | 订单货物所属的计价或禁运分类。 |
| 运输方式 | 空运、陆运、海快等运输方式。 |
| 适用仓库 | 报价可被哪些发货仓使用。 |
| 承运商及产品 | 订单最终使用的运输服务提供方及其产品。 |
| 计费规则 | 将订单的重量、体积、长度、周长、数量或材积转换为费用。 |

### 2.2 报价、报价版本和订单费用的关系

1. 报价配置保存后形成可供订单使用的报价记录；编辑报价时，系统需要保留历史版本，便于查看某个时点的配置内容。
2. 新订单只能使用满足生效时间、启用状态和适用范围的报价。
3. 订单一旦形成线路和费用结果，后续账单应以订单侧已形成的结果为准，不因 BMS 重新执行而重新推导线路报价。
4. 报价配置的修改是否影响已经形成但尚未出库的订单，需要以[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)为准；在规则确认前，不得假设历史订单会自动改价。

### 3.2 配置主流程

1. 业务人员进入 `线路报价管理`，通过店铺、目的地、运输方式、货物类型或报价名称定位已有报价。
2. 新增报价时，先选择店铺，再配置报价名称、报价分组、业务类型、报价类型和生效范围。
3. 配置目的地、货物类型、运输方式和适用仓库，限定报价可以服务的订单范围。
4. 选择渠道线路分配策略并配置承运商；若策略要求指定承运商产品，还需要完成承运商产品关联。
5. 选择计费模式和多包裹算费方式，再配置重量、体积、长度、数量或材积相关处理规则。
6. 维护默认价格区间；存在地区差异时，新增地区报价并维护该地区的价格区间。
7. 保存报价。保存成功后，报价按启用状态和生效时间参与订单报价；未启用或尚未到生效时间的报价不得被使用。
8. 已有报价需要调整时，优先使用 `复制新增` 创建新的报价，或在确认影响范围后编辑现有报价；系统必须保留历史版本。

## 4. 报价基础信息怎么配置

### 4.1 基础字段

| 字段 | 是否必填 | 默认值或枚举 | 业务规则 |
| --- | --- | --- | --- |
| 店铺 | 是 | 无默认值 | 选择店铺后，系统按店铺加载可用的报价分组和仓库；报价必须归属于一个店铺。 |
| 报价名称 | 是 | 无默认值 | 用于在列表、订单和历史版本中识别报价；同一店铺下应避免使用无法区分的重复名称。 |
| 报价分组 | 是 | 依店铺加载 | 支持多选；报价仅对所选客户分组生效。 |
| 业务类型 | 是 | 当前页面默认 `集运` | 支持多选。可选值包括 `集运`、`中转/预报`、`袋中袋`、`电商订单`、`重出订单`、`取件退回`。 |
| 启用时间 | 条件必填 | 非永久报价需填写 | 由开始时间和到期时间组成；非永久报价必须填写完整时间范围，开始时间不得晚于到期时间。 |
| 永久启用 | 否 | 当前新增页面默认未勾选 | 勾选后不设置到期时间；取消勾选时必须填写有效时间范围。 |
| 启用状态 | 否 | 当前新增页面默认关闭 | 只有状态为启用且当前时间处于有效期内的报价才可参与匹配。 |
| 报价类型 | 是 | 当前页面默认 `派送报价` | 可选值包括 `派送报价`、`自提报价`、`包税报价`、`保价报价`、`超重报价`、`超长报价`、`超材报价`、`打包报价`、`落地派送报价`、`系统服务报价`、`预扣报价`、`派送附加费报价`。 |
| 产品优先级 | 否 | 0 | 只能填写非负数，用于多个报价同时满足条件时的排序或选择；优先级方向和同优先级处理方式见[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)。 |
| 时效 | 否 | 空 | 用于展示或业务选择的运输时效，不改变价格区间计算。 |
| 最低价格 | 否 | 空 | 用于配置报价的最低收费；与价格区间中的最低收费规则如何叠加，需要遵循统一的价格计算规则。 |
| 推荐标签 | 否 | 空 | 支持 `高性价比，低价平衡之选`、`强烈推荐，精选线路` 等标签，用于前端推荐展示。 |
| 产品描述 | 否 | 空 | 用于展示线路服务说明。 |
| 商品禁寄品类 | 否 | 空 | 支持多选禁寄品类，例如儿童用品、食品、粉面、玩具等；只表达该报价的商品限制，不替代全局禁运规则。 |
| 商品禁寄描述 | 否 | 空 | 用文字补充禁寄限制或特殊说明。 |

`派送附加费报价`只能配置为`中转/预报`业务类型，且至少选择一个业务类型。新增、编辑和批量修改均须执行此校验；选择其他业务类型时不得保存。除这一已实现的限制外，其他报价类型与业务类型之间是否还存在专属组合规则，见[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)。

### 4.2 系统保存时必须具备的业务属性

除页面基础字段外，报价还必须具备以下业务属性，才能被完整识别和展示：

| 业务属性 | 说明 |
| --- | --- |
| 服务级别 | 报价所属的服务层级。 |
| 服务类别 | 报价所属的服务类别。 |
| 服务项内容 | 具体服务项或产品内容。 |
| 币种 | 价格的计价币种。 |
| 计量单位 | 价格区间使用的重量、体积、长度、数量或材积单位。 |
| 客户提醒说明 | 在客户端展示的服务内容、规则或收费说明。 |

这些属性属于报价定义的一部分，不能在保存时缺失。它们在不同页面版本中可能通过服务分类、计费规则或展示配置区域维护，但不得因页面折叠或未展开而跳过校验。

## 5. 报价适用范围：哪些订单可以使用这条报价

### 5.1 目的地国家或地区

1. `目的地国家/地区`为必填，支持选择国家、地区和特殊目的地节点，页面提供全选能力。
2. 订单目的地必须命中报价配置的国家或地区范围，报价才进入候选集合。
3. 国家与地区的层级关系应保持清晰：选择上级节点表示覆盖其下属节点；若业务只允许具体地区，应选择具体地区而不是笼统选择上级节点。

### 5.2 货物类型

支持多选以下货物类型：`普货`、`药品保健品`、`食品专线`、`粉面专线`、`易碎品`、`敏感品`、`特A`、`特B`、`特C`。

货物类型用于筛选报价和决定计费适用范围，不等于商品禁寄品类。一个报价可以同时适用于多个货物类型；订单货物类型未命中时，不得使用该报价。

### 5.3 运输方式

支持多选 `空运`、`陆运`、`海快`、`加强包装`、`海运`。运输方式是报价匹配条件之一，也影响承运商和线路产品的可选范围。

### 5.4 适用仓库

1. `适用仓库`为必填，支持多选。
2. 仓库选项随店铺加载；当前页面示例包括东莞仓、深圳仓、上海仓、台湾仓、东风台湾仓、台湾 2 仓、义乌仓等。
3. 订单的实际发货仓必须命中适用仓库；仅店铺、目的地和运输方式匹配但仓库不匹配时，不得使用该报价。

### 5.5 报价分组与店铺依赖

1. 报价分组为必填且支持多选，选项随店铺加载。
2. 店铺切换后，报价分组和适用仓库必须重新加载，不能沿用上一店铺的选项。
3. 报价保存前，所选分组必须属于当前店铺可用的客户分组。

## 6. 承运商与线路分配：订单最终走谁的线路

### 6.1 渠道线路分配策略

`渠道线路分配策略`为必填，当前页面提供以下五种方式：

| 策略 | 业务含义 | 客户或系统是否选择承运商 | 是否指定承运商产品 |
| --- | --- | --- | --- |
| 当前线路报价指定唯一的承运商，承运商产品为默认产品 | 报价固定承运商，产品使用该承运商默认产品 | 不选择 | 不指定具体产品 |
| 当前线路报价指定唯一的承运商及产品 | 报价固定承运商和具体产品 | 不选择 | 指定 |
| 客户自行选择承运商，承运商产品为默认产品 | 客户选择承运商，产品使用所选承运商默认产品 | 客户选择 | 不指定具体产品 |
| 客户自行选择承运商及其产品 | 客户同时选择承运商和产品 | 客户选择 | 指定产品范围 |
| 系统根据履约规则自动分配承运商和产品 | 系统按履约规则确定承运商和产品 | 系统选择 | 按履约规则确定 |

策略是报价的核心行为设置。保存时必须保证策略与承运商及产品配置相互一致：固定承运商的策略不能缺少承运商；要求指定产品的策略不能只配置承运商而不配置产品。

订单使用报价后，系统按策略写入承运商和产品：

1. 指定唯一承运商时，订单使用报价中配置的承运商，并带入该承运商在当前仓库和店铺下的默认产品。
2. 指定唯一承运商及产品时，订单使用报价中配置的承运商和产品；任一配置缺失时不得继续创建订单线路。
3. 客户自行选择承运商时，订单保留客户选择的承运商，并带入该承运商的默认产品。
4. 客户自行选择承运商及产品时，订单保留客户选择的承运商和产品。
5. 系统自动分配时，系统先按履约规则选出承运商，再带入该承运商的默认产品。

### 6.2 承运商配置

1. 固定承运商和客户选择承运商的策略必须配置可用承运商，页面支持新增和移除；系统按履约规则自动分配时，不要求人工选择承运商，但必须具备可执行的履约规则。
2. 一个报价可以配置多个承运商；实际使用哪一个承运商，取决于上表所选策略和订单侧选择或履约规则。
3. 承运商选项应受店铺、目的地、货物类型、运输方式和适用仓库限制，只展示当前报价场景可用的承运商。
4. 选择“指定承运商及产品”类策略时，页面必须提供承运商产品的配置入口；任一已选承运商未选择产品时，报价不可保存。

## 7. 计费规则：重量、体积和数量如何变成费用

### 7.1 计费模式

`计费模式`为必填，当前页面提供：

1. `仅按重量计费(KG)`。
2. `实重于抛重二者取其大`。
3. `按体积（立方米）`。
4. `自定义两者取其大`。
5. `仅按抛重计费（KG）`。
6. `最长长度（CM）`。
7. `周长（CM）`。
8. `三边之和（CM）`。
9. `按数量（个）`。
10. `按材积(材)`。

计费模式决定费用按什么计费量计算。一个报价只能选择一个计费模式；计费模式与末级价格规则的价格类型、计量单位必须一致。价格区间中的`规则类型`用于判断订单应命中哪一条价格规则；它可以与计费模式一致，也可以在嵌套规则中作为额外的筛选条件，详见[8.2 规则类型：区间按什么数据判断？](#82-规则类型区间按什么数据判断)。

选择`按材积(材)`后，还必须完成[7.4 按材积(材)的专属配置：先识别材积，再确定超材费用](#74-按材积材的专属配置先识别材积再确定超材费用)，否则系统无法根据包裹尺寸得到有效材积，也无法完整处理超材费用。

### 7.2 多包裹如何算费

`计算方式`提供两种选择：

| 方式 | 业务含义 |
| --- | --- |
| 多包裹合并算费 | 先按报价规则汇总同一业务订单下的多个包裹，再用汇总后的计费指标匹配价格区间。 |
| 多包裹单独算费 | 每个包裹分别匹配价格区间并计算费用，再汇总同一业务订单的费用。 |

该选择会直接影响计费结果，修改时应在报价名称、产品说明或客户沟通中明确其含义。

### 7.3 费用取整、舍入和进位

1. `费用取整`当前提供 `实际费用`，表示价格计算结果按实际金额保留，不在本配置中额外截断为整数。
2. `舍入模式`支持 `无舍入`、`0.1舍入`、`0.2舍入`、`0.3舍入`、`0.5舍入`。
3. `进位模式`支持 `无进位`、`0.5进位`、`1进位`、`0.1进位`、`0.2进位`、`0.3进位`、`按区间进位`。
4. 计费量的处理顺序为：先按舍入模式处理，再按进位模式处理。规则类型为`计费重量`时，处理后的计费重量用于匹配价格区间；规则类型为其他指标时，先按该指标命中价格规则，再使用处理后的计费量计算费用。
5. `费用取整=实际费用`只作用于价格计算完成后的金额，不改变前面的计费指标处理过程。金额计算完成后按实际费用保留，不额外截断为整数。

以下示例仅用于说明运算顺序。舍入值是小数部分的保留门槛：小数部分小于舍入值时，舍去全部小数；小数部分达到舍入值时，保留原始计费指标并继续执行进位。进位表示向上取到指定步长的最近值。以 `0.3进位`为例，每个整数都是一个起点，按 `0.3`递增形成步长点：`3.0`、`3.3`、`3.6`、`3.9`、`4.2`……因此，`3.3487`位于 `3.3`和 `3.6`之间，向上取到 `3.6`；已经落在步长点上的 `3.0`则保持不变。

| 示例组 | 舍入设置 | 进位设置 | 原始计费指标 | 舍入过程及结果 | 进位过程及结果 | 最终计费指标 |
| --- | --- | --- | ---: | --- | --- | ---: |
| 1 | 0.1舍入 | 0.5进位 | 1.0937 | 小数部分 0.0937 < 0.1，舍去小数，得到 1.0 | 1.0 已落在 0.5 的步长点上，保持 1.0 | 1.0 |
| 1 | 0.1舍入 | 0.5进位 | 1.1462 | 小数部分 0.1462 >= 0.1，保留 1.1462 | 向上取到最近的 0.5 步长点，得到 1.5 | 1.5 |
| 2 | 0.2舍入 | 1进位 | 2.1847 | 小数部分 0.1847 < 0.2，舍去小数，得到 2.0 | 2.0 已是整数，保持 2.0 | 2.0 |
| 2 | 0.2舍入 | 1进位 | 2.2639 | 小数部分 0.2639 >= 0.2，保留 2.2639 | 向上取整，得到 3.0 | 3.0 |
| 3 | 0.3舍入 | 0.3进位 | 3.2746 | 小数部分 0.2746 < 0.3，舍去小数，得到 3.0 | 3.0 已落在 0.3 的步长点上，保持 3.0 | 3.0 |
| 3 | 0.3舍入 | 0.3进位 | 3.3487 | 小数部分 0.3487 >= 0.3，保留 3.3487 | 向上取到最近的 0.3 步长点，得到 3.6 | 3.6 |
| 4 | 0.5舍入 | 0.1进位 | 4.4827 | 小数部分 0.4827 < 0.5，舍去小数，得到 4.0 | 4.0 已落在 0.1 的步长点上，保持 4.0 | 4.0 |
| 4 | 0.5舍入 | 0.1进位 | 4.5639 | 小数部分 0.5639 >= 0.5，保留 4.5639 | 向上取到最近的 0.1 步长点，得到 4.6 | 4.6 |

`按区间进位`需要先维护各区间对应的进位结果，无法脱离区间规则单独计算，因此不与固定步长进位混用。订单命中某个进位区间后，直接采用该区间配置的进位规则。

价格区间命中后，系统再按该区间的价格类型计算金额。例如，最终计费指标为 `1.5kg`，价格类型为 `每千克`，单价为 `8 CNY/kg`，则运算过程如下：

| 运算步骤 | 运算内容 | 结果 |
| --- | --- | ---: |
| 1 | 原始计费指标为 `1.1462kg`，小数部分 `0.1462 >= 0.1` | 保留 `1.1462kg` |
| 2 | `1.1462kg` 按 `0.5进位` | 向上取为 `1.5kg` |
| 3 | 用 `1.5kg` 匹配价格区间 | 命中 `每千克` 规则 |
| 4 | `1.5kg × 8 CNY/kg` | `12 CNY` |
| 5 | `费用取整=实际费用` | 保留 `12 CNY`，不再额外取整 |

因此，舍入和进位处理的是计费指标，费用取整处理的是金额；两者不能混用，也不能调换顺序。

### 7.4 按材积(材)的专属配置：先识别材积，再确定超材费用

当`计费模式`选择`按材积(材)`时，页面才展示本节配置区。该配置区不是所有计费模式共用的附加配置；切换到其他计费模式后，箱型材积、超材收款和超材手续费规则均不参与费用计算。按材积报价的完整计算顺序是：

1. 读取包裹长、宽、高，并统一确定三边的角色：最长边为`L`（长），次长边为`W`（宽），最短边为`H`（高）。不使用业务系统原始字段的排列顺序直接代替长、宽、高。
2. 按`按箱型配置材积`表格从上到下匹配第一条满足条件的箱型规则。
3. 使用命中规则的`材积公式`计算材积值，再乘以该规则的`材积比`，得到本包裹参与报价的材积。
4. 使用材积值匹配[8.2 规则类型：区间按什么数据判断？](#82-规则类型区间按什么数据判断)中的`材积`规则，并按末级价格规则计算基础费用。
5. 若包裹满足超材条件，再按`超材收款规则`和`超材手续费规则`确定超材费用及收款方式。

#### 7.4.1 按箱型配置材积：同一包裹只命中第一条规则

`按箱型配置材积`通过多行规则描述不同包裹形状的材积算法。页面支持`新增配置`和`删除`，每行包含以下字段：

| 字段 | 业务含义 | 配置要求 |
| --- | --- | --- |
| 箱型名称 | 当前规则的人类可读名称，例如`不计算超材`、`箱型`、`扁形`、`长条形`。 | 必填；名称用于识别规则，不参与数值计算。 |
| 边长条件 | 判断包裹有多少条边满足某个长度条件，例如`< 30cm`或`>= 30cm`。 | 必须选择比较符号并填写长度值，长度单位固定为`cm`。 |
| 边数量条件 | 判断满足边长条件的边数，例如`= 3`、`>= 1`或`>= 2`。 | 必须选择比较符号并填写边数；边数只能在三条边范围内取值。 |
| 材积公式 | 将`L`、`W`、`H`转换为材积的运算规则。 | 必填；只能使用`L`、`W`、`H`、数字、加减乘除和括号，计算结果必须为不小于零的数值。 |
| 材积比 | 对材积公式结果进行比例修正。 | 默认值为`1.00`；最终材积=`公式结果 × 材积比`，材积比不得小于零。 |
| 操作 | 删除当前箱型规则。 | 删除后应重新检查规则是否仍能覆盖需要报价的包裹。 |

页面内置的常用箱型规则及公式含义如下：

| 箱型规则 | 条件示例 | 材积公式 | 业务含义 |
| --- | --- | --- | --- |
| 不计算超材 | 三条边均 `< 30cm` | `0` | 包裹不按材积收取超材费用，材积结果为`0`。 |
| 箱型 | 三条边均 `>= 30cm` | `L × W × H ÷ 27000` | 三边均达到箱型门槛，按立体箱型材积计算。 |
| 扁形 | 至少一条边 `< 30cm` | `L × W ÷ 900` | 包裹存在较短边，按长与宽的二维材积计算。 |
| 长条形 | 至少两条边 `< 30cm` | `L ÷ 30` | 包裹有两条明显较短的边，按最长边的长条形材积计算。 |

表格按从上到下的顺序匹配，命中第一条后停止，不会继续尝试后续规则。因此，具有更严格条件的规则必须放在覆盖范围更大的规则之前。例如，`至少两条边 < 30cm`的长条形规则会被`至少一条边 < 30cm`的扁形规则覆盖，长条形规则必须排在扁形规则之前；否则长条形永远不会被命中。`三边均 < 30cm`的不计算超材规则也必须优先于其他包含`< 30cm`的规则。

系统应在保存时校验以下内容：

1. 至少存在一条箱型规则；每条规则的箱型名称、边长条件、边数量条件、材积公式和材积比均完整有效。
2. 箱型规则按页面顺序参与匹配；规则存在包含关系时，应提示用户确认先后顺序，避免后面的规则被前面的宽泛规则完全遮蔽。
3. 材积公式只能引用当前包裹的`L`、`W`、`H`，不能引用未定义字段、函数、文字或其他报价字段；公式解析失败时不允许保存。
4. 包裹三边缺失、无法计算或材积公式结果异常时，本次报价不得静默按零费用处理，应返回无法计算材积的业务错误。
5. 箱型规则没有命中时，本次报价不得继续生成一个没有材积依据的费用结果；财务应补充能覆盖该包裹的规则后再报价。

#### 7.4.2 报价币种和店铺币种结算汇率

按材积报价需要同时明确报价金额使用的`报价币种`和回写店铺订单时使用的`店铺币种`。页面展示的`店铺币种结算汇率`表示：`1 单位报价币种 = N 单位店铺币种`，换算方向固定为`报价币种 -> 店铺币种`。

1. `报价币种`决定材积基础费用、超材费用和超材手续费的录入及展示币种。截图示例中报价币种为`台币/TWD`，因此价格规则和手续费金额均按`TWD`维护。
2. `店铺币种`由当前店铺的默认币种确定，不在本配置区手动修改。页面应明确展示报价币种与店铺币种，避免财务误把二者当成同一币种。
3. `店铺币种结算汇率`用于将报价币种金额换算为店铺币种金额。示例中报价币种为`TWD`、店铺币种为`CNY`、汇率为`0.45`时，`100 TWD × 0.45 = 45 CNY`。
4. 报价币种与店铺币种相同时，结算汇率应为`1`；币种不同时，汇率必须为大于`0`的有效数值。缺少汇率时不允许保存按材积报价。
5. 币种或汇率发生变化时，应重新换算预览金额，并以保存时的配置参与后续订单报价；已经形成的订单费用是否重算，遵循报价版本和账单重算规则，不由本配置自动回溯。

#### 7.4.3 超材收款规则：先确定谁付款、何时收款

`超材收款规则`用于分别配置`收方`和`寄方`作为超材费用付款方时的收款方式。两行规则彼此独立，系统按实际确定的超材付款方读取对应行，不得将收方的收款方式套用到寄方。

| 超材付款方 | 可选收款方式 | 业务结果 |
| --- | --- | --- |
| 收方 | `到付`、`人工确认后收款` | 超材费用由收方承担；到付表示随收方收货环节收取，人工确认后收款表示经人工确认后再收取。 |
| 寄方 | 除`到付`外的收款方式 | 超材费用由寄方承担；不得配置`到付`，因为到付收款对象是收方。 |

页面提示“建议超材付款方为收方时选择到付，避免漏收款；如需人工确认后收取请选择人工确认后收款”属于收款操作提示。财务仍可根据业务约定选择其他可用方式，但收款方式必须与付款方匹配。

#### 7.4.4 超材手续费规则：按收款方式分别收取

`超材手续费规则`用于在超材费用之外，按收款方式配置是否加收固定手续费。点击`添加`新增一行，每行包含：

| 字段 | 业务含义 | 配置要求 |
| --- | --- | --- |
| 收款方式 | 该行手续费对应的收款方式。 | 同一种收款方式最多配置一条，重复选择时不允许保存。 |
| 是否收手续费 | 控制该收款方式是否追加手续费。 | 开启时才追加手续费；关闭时即使保留金额，也不得计入费用。 |
| 手续费金额 | 该收款方式下的固定手续费金额。 | 开启收手续费时必填，不能为负数，币种与`报价币种`一致。 |
| 操作 | 删除该收款方式的手续费规则。 | 删除后，该收款方式不再按本报价收取超材手续费。 |

超材手续费与材积基础费用是两笔不同的费用：材积基础费用由材积值命中价格规则后计算，超材手续费只有在命中对应收款方式且开关开启时才追加。删除或关闭手续费规则，不影响材积基础费用和超材付款方配置。

#### 7.4.5 按材积配置的整体保存和生效约束

1. 只有`计费模式=按材积(材)`时，箱型材积配置、报价币种与汇率、超材收款规则和超材手续费规则才作为本报价的有效配置。
2. 保存时必须同时校验材积规则、报价币种、结算汇率和超材收款/手续费配置；任一专属配置不完整或不合法，整条报价不得保存为启用状态。
3. 规则生效后，系统必须能够从订单的包裹尺寸追溯到命中的箱型名称、材积公式、材积比、报价币种、超材付款方、收款方式和手续费金额，便于财务核对费用来源。
4. 编辑报价并切换为其他计费模式后，原有按材积专属配置不得继续参与新订单计算；若再次切换回`按材积(材)`，只有通过完整校验的配置才能重新生效。

### 7.5 默认抛重与地区抛重


`默认抛比`和`默认抛重公式`用于将包裹体积换算为抛重。它们只适用于需要抛重参与计费的模式：`实重于抛重二者取其大`、`自定义两者取其大`和`仅按抛重计费（KG）`。`仅按重量计费`、`按体积（立方米）`、按长度或数量计费以及`按材积(材)`均不使用本节配置；其中`按材积(材)`应使用[7.4 按材积(材)的专属配置：先识别材积，再确定超材费用](#74-按材积材的专属配置先识别材积再确定超材费用)。

#### 7.5.1 抛重公式中的 `V`、`Z`、`K` 分别是什么？

抛重公式可使用以下配置字段，并且计算结果的单位必须为`kg`：

| 字段 | 含义 | 单位 | 取值说明 |
| --- | --- | --- | --- |
| `V` | 包裹体积 | `cm³` | 包裹长、宽、高相乘所得体积，即`长 × 宽 × 高`。 |
| `Z` | 包裹实重 | `kg` | 包裹称重得到的实际重量，不含抛重换算、舍入或进位。 |
| `K` | 抛比 | `cm³/kg` | 每 `K` 立方厘米体积折算为 `1kg` 抛重的换算系数。必须大于 `0`，不能作为除数取 `0`。 |

默认抛重公式为`V/K`时，系统用包裹体积除以抛比计算抛重。以默认抛比`9000`为例：包裹尺寸为`60cm × 40cm × 30cm`，则`V=72,000cm³`，`V/K=72,000÷9,000=8kg`，该包裹的抛重为`8kg`。若计费模式为`实重于抛重二者取其大`，且包裹实重`Z=2.3kg`，则取`8kg`进入后续舍入、进位和价格计算。

`V/K`只是最常用的公式写法。页面应提示财务：公式只能引用`V`、`Z`、`K`、数字、加减乘除和括号，且必须能计算出非负的千克数；引用其他字段、公式语法错误、`K`为空或为零时，报价不得保存为启用状态。抛重公式与按材积配置中的`L`、`W`、`H`材积公式不是同一套规则，不能混用。

#### 7.5.2 默认配置和指定地区配置怎样配合？

`默认抛比`和`默认抛重公式`是全报价的兜底规则。`指定地区抛重配置`用于在部分目的地使用不同的抛比或公式，页面支持新增、编辑和删除地区规则；同一条地区规则可以选择多个采用相同口径的地区。

计算时按以下顺序确定抛重规则：

1. 先根据订单目的地检查是否命中指定地区抛重配置。
2. 命中时，完整使用该地区规则的`抛重公式`和`抛比`；地区规则两项均为必填，不能只覆盖其中一项。
3. 未命中任何地区规则时，使用默认抛重公式和默认抛比。
4. 地区规则配置的地区必须属于当前报价的目的地范围；目的地范围变更后，系统应校验已有地区规则仍然有效。

同一目的地不能同时属于两条指定地区抛重规则。这里的重复不仅包括相同地区，也包括父级地区和其子级地区同时被不同规则选择的情形。出现重叠时，系统应阻止保存，而不是依赖隐含的先后顺序决定采用哪条规则。

#### 7.5.3 抛重进入费用计算前还要经过什么处理？

抛重公式计算得到的数值只是抛重原值，仍需结合计费模式确定实际使用的计费量：

| 计费模式 | 抛重的使用方式 |
| --- | --- |
| 仅按抛重计费（KG） | 直接使用抛重作为计费量。 |
| 实重于抛重二者取其大 | 比较`Z`与抛重，取较大值作为计费量。 |
| 自定义两者取其大 | 依照该模式配置的自定义比较逻辑，使用抛重参与比较。 |

确定计费量后，再按[7.3 费用取整、舍入和进位](#73-费用取整舍入和进位)处理，并使用处理后的计费量匹配价格规则、计算费用。抛重原值、命中的默认或地区抛重规则、公式、抛比及处理后的计费量都应保留在订单费用明细中，供财务核对。

#### 7.5.4 保存约束

1. 使用抛重的计费模式必须填写有效的默认抛比和默认抛重公式；默认抛比必须大于`0`，公式必须能返回非负的`kg`数值。
2. 每条地区规则必须选择至少一个地区，并完整填写抛重公式与抛比；删除地区规则后，该地区自动回退使用默认配置。
3. 包裹尺寸缺失、地区规则或默认规则无法计算抛重时，系统不得将抛重默认为`0kg`继续计费，应返回明确的无法计算抛重提示。
4. 更改抛比、公式或地区规则只影响后续按新报价生成的订单费用；已有订单费用是否重算，应由报价变更和重算流程明确触发，不能在保存时静默改写。

## 8. 价格区间与地区报价

### 8.1 默认价格区间

默认价格区间是报价的基础价格规则。页面通过可编辑规则表维护价格区间，支持新增和删除规则。

每条价格规则至少需要表达：

| 规则要素 | 说明 |
| --- | --- |
| 规则类型 | 当前规则节点用于匹配区间的业务指标，例如包裹重量、月发货量或保价金额。它决定区间的比较单位，不直接等同于费用的计费量。 |
| 区间下限及边界 | 支持“大于”和“大于等于”。 |
| 区间上限及边界 | 支持“小于”和“小于等于”。 |
| 价格 | 该区间的固定价格或单位价格。 |
| 价格类型 | 例如每千克、一口价、每 0.1 千克、每 0.5 千克、每立方米、每个、每材。 |
| 费用性质 | 可表达附加费用、最低收费、最高收费或增值基础等规则。 |
| 计量单位 | 明确价格是按什么单位计算。 |

价格类型决定金额计算方式：

1. `一口价`表示命中区间后直接取该价格。
2. `每千克`、`每 0.1 千克`、`每 0.5 千克`、`每立方米`、`每个`、`每材`表示按处理后的计费指标乘以单位价格。
3. `最低收费`和`最高收费`用于对最终费用设置边界；与报价基础价格和附加费用的叠加方式必须在价格规则中明确。
4. `附加费用`表示在基础报价之外追加的费用，不应被误当作基础价格。

### 8.2 规则类型：区间按什么数据判断？

`规则类型`是每条价格规则必须选择的判断指标。系统先取得订单对应的规则类型数值，再与该规则的最小值、最大值及边界符号比较，以确定订单是否命中该规则。它回答的是“这条价格规则在什么条件下生效”；`计费模式`回答的是“费用按什么量计算”；`价格类型`回答的是“命中后怎样计算价格”。三者不能互相替代。

例如，报价可以先按`包裹重量`区间选择价格，再在某一重量区间下按`月发货量`选择子规则；最终仍按报价的计费模式和末级规则的价格类型计算费用。下表中的单位由页面随规则类型自动带出，配置的区间上下限必须使用对应单位。

| 指标类别 | 规则类型 | 匹配数值与单位 | 详细解释与适用方式 |
| --- | --- | --- | --- |
| 单票或包裹指标 | 包裹重量 | 包裹实重，`kg` | 指包裹称重得到的实际重量，不包含抛重比较、舍入或进位。报价采用`多包裹合并算费`时，按同一业务订单内需合并算费的包裹实重汇总；采用`多包裹单独算费`时，按当前包裹的实重判断。适用于按实际重量分档报价。 |
| 单票或包裹指标 | 计费重量 | 处理后的重量，`kg` | 指按当前报价的计费模式、抛重规则、舍入和进位处理后得到的重量。它与`包裹重量`的差异在于：前者可以受体积重、抛比和进位影响，后者只是原始实重。适用于价格区间必须跟最终算费重量保持一致的场景。 |
| 累计统计指标 | 月均重 | 当月平均计费重量，`kg` | 指同一统计主体在当前自然月内已出库包裹的计费重量总和，除以已出库包裹数。用于按客户当月平均包裹重量区间执行差异化报价。没有已出库包裹时，月均重按 `0kg` 参与区间判断。 |
| 累计统计指标 | 月发货量 | 当月已出库包裹数，`单` | 指同一统计主体在当前自然月内已出库的包裹数量，不是订单商品件数。适用于按客户当月累计发货量分档报价。 |
| 累计统计指标 | 日发货量 | 当日已出库包裹数，`单` | 指同一统计主体在当前自然日内已出库的包裹数量，不是订单商品件数。适用于按当日发货规模执行阶梯价格。 |
| 累计统计指标 | 月运费总额 | 当月累计运费，`元` | 指同一统计主体在当前自然月内，已出库包裹按线路报价计算出的基础运费累计金额，不含保价费、税费及其他独立附加费用。金额区间必须以报价币种比较；存在不同币种的来源金额时，系统不得直接比较，应先换算为报价币种。 |
| 单票或包裹指标 | 保价金额 | 申报保价金额，`元` | 指订单或包裹申报的保价本金，不是由此计算出的保价费。金额区间按报价币种比较；来源金额币种与报价币种不一致时，应先换算后再命中区间。适用于高价值货物收取不同保价费或服务费的场景。 |
| 单票或包裹指标 | 体积 | 长 × 宽 × 高，`cm³` | 指包裹的几何体积，按长、宽、高相乘得到。它是体积本身，不是将体积换算后的抛重或材积。适用于按立方体积划分价格区间的线路。 |
| 单票或包裹指标 | 包裹长度 | 包裹最长边，`cm` | 指包裹长、宽、高中的最大值，不是周长，也不是三边之和。适用于超长包裹的价格分档或附加收费。 |
| 单票或包裹指标 | 数量 | 当前算费对象数量，`个` | 指当前报价计算对象的数量。多包裹合并算费时为参与合并的包裹数；多包裹单独算费时为当前包裹对应的数量。它不等于月发货量、日发货量等累计统计指标。适用于按件数分档的报价。 |
| 单票或包裹指标 | 材积 | 按材积规则换算的值，`材` | 指根据箱型、材积公式和材积比换算得到的材积值，不等于几何体积。适用于报价计费模式为`按材积(材)`，或需要按材积区间再细分价格的场景。 |

统计类规则类型的共同口径如下：

1. 统计主体固定为当前报价命中的店铺和客户；不得跨店铺、跨客户汇总，也不得把其他线路报价下的业务数据混入统计。
2. `月均重`、`月发货量`、`日发货量`和`月运费总额`均以包裹出库时间归属自然日或自然月；月度统计在每月第一日重新开始累计。
3. 统计值仅累计当前待报价包裹之前已经出库的包裹，当前包裹不计入其自身的统计条件，避免同一笔费用因是否先计算而得到不同结果。
4. 当前自然日或自然月没有符合范围的已出库包裹时，数量和金额按 `0` 参与判断；`月均重`也按 `0kg` 参与判断。使用统计类规则类型时，价格区间应覆盖零值，或提供明确的默认规则。

配置规则类型时，还必须遵守以下约束：

1. 规则类型为必填项。页面应根据所选规则类型展示正确的单位；用户不得把重量、金额、体积、长度、数量或材积填入错误单位的区间。
2. 同一父规则下的同级规则必须选择同一种规则类型，才能校验区间是否重叠、连续或存在空档；不同层级可以选择不同规则类型，以表达多条件报价。
3. 规则类型仅用于选择规则。最终费用仍应按报价的计费模式及末级规则的价格类型计算；例如按`月发货量`命中子规则后，末级规则仍可按`每千克`对计费重量计算费用。
4. `包裹重量`、`计费重量`、`体积`、`包裹长度`、`数量`和`材积`取自本次报价的算费对象；其合并或单独计算方式遵循[7.2 多包裹如何算费](#72-多包裹如何算费)。

### 8.3 区间边界和嵌套规则

1. 区间必须能明确判断一条订单数据是否命中，不能出现同时命中两条基础规则或无法命中的空档。
2. 相邻区间应通过边界符号明确衔接，例如 `0kg < 包裹重量 <= 10kg` 和 `10kg < 包裹重量 <= 999kg`。
3. 需要在一个区间内继续按子条件计算时，可以在该区间下维护子规则；子规则本身也可以继续嵌套下一层子规则，直到规则节点可以直接计算费用。
4. 页面展示应同时呈现区间、价格类型和价格，避免只展示一个无法理解的数字。
5. 保存时应校验区间上下限、边界关系、价格类型和计量单位；校验失败时不允许保存。
6. 区间的最大值填写 `0`时，表示该区间没有上限，即最大值为无穷大；页面展示时应使用“无穷大”或“无上限”表达，不能让用户误解为区间上限是数值 0。
7. 任意层级的规则节点不填写单价时，才可以作为父规则继续添加子规则；规则节点已经填写单价时，表示该节点直接参与计费，不允许再下挂子规则。
8. 当前规则操作菜单中的 `+`按钮是`添加子规则`按钮。只有当前规则节点未填写单价时，该按钮才可用；点击后新增的子规则必须位于当前规则节点的区间范围内。
9. 子规则可以继续嵌套子规则，系统从上到下逐级匹配，直到命中填写了单价的末级规则；末级规则不能再添加子规则。
10. 同一父规则下的子规则仍需遵守区间互斥和连续原则，不能出现重叠、空档或超出父规则范围的情况。

### 8.4 地区报价

`地区报价`用于为特定地区维护单独的价格区间。每个地区报价卡至少包含：

1. `选择地区`。
2. `地址分类`，可选且支持多选。
3. 该地区的价格区间规则。
4. 删除此区域报价、保存和关闭操作。

页面支持在一张地区报价卡中选择多个地区，并可按需选择多个地址分类；地址分类为空时表示该卡未限定地址分类，但其运行时适用范围仍须按[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)确认。地区必须属于本报价已配置的目的地范围；同一张卡选择父级地区后，页面会清理该父级及其下级节点的重复选择，避免在单张卡内同时保留父子重叠节点。

地区报价命中后是完全替代默认价格区间还是叠加费用、不同地区报价卡同时命中时的选择顺序、未配置地址分类时的回退方式，现有本地代码没有提供计算依据，必须按[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)明确后实现。不得根据地区报价卡在页面中的排列顺序自行推定优先级。

## 9. 报价生效、变更和历史版本

### 9.1 生效条件

报价只有同时满足以下条件，才可被订单使用：

1. 报价状态为启用。
2. 当前时间不早于启用时间。
3. 报价为永久启用，或当前时间不晚于到期时间。
4. 订单的店铺、客户分组、业务类型、目的地、货物类型、运输方式和仓库均命中报价范围。
5. 承运商、线路产品和计费规则完整可用。

### 9.2 新增、编辑和复制新增

1. `新增报价`创建一条新的线路报价，必须完整填写必填项后才能保存。
2. `编辑`修改当前报价的基础信息、适用范围或计费规则；保存前必须重新校验相关依赖关系。
3. `复制新增`以已有报价为基础创建新报价，但新报价必须拥有独立的报价名称和生效配置，不能因为复制而覆盖原报价。
4. 编辑或复制新增时，应明确哪些字段被复制，尤其是客户分组、仓库、承运商、地区报价和价格区间，避免只复制基础信息导致新报价缺少计费规则。

### 9.3 启用、禁用和删除

1. 禁用报价后，新订单不得再使用该报价；已经形成的订单费用是否回溯调整，不在本页面自动处理。
2. 启用报价前必须校验有效期、适用范围、承运商和计费规则完整性。
3. 删除仅适用于没有被业务事实依赖，或业务允许删除的报价；已经产生订单费用或被历史版本引用的报价，不应直接物理删除，页面应改为禁用或保留历史记录。
4. 删除、禁用和启用都必须有明确的二次确认，确认内容应说明对后续订单的影响。

### 9.4 历史版本

1. `历史版本`展示报价的版本号、变更时间、操作人和查看入口。
2. `查看`以只读方式展示该版本的基础信息、适用范围、承运商、计费方式、价格区间和地区报价。
3. `对比当前`用于查看历史版本与当前版本的差异；查看或对比不改变当前配置。
4. 历史版本至少要能追溯报价名称、报价分组、业务类型、目的地、运输方式、仓库、承运商、计费模式和价格规则的变化。

## 10. 列表和批量操作

### 10.1 列表展示

列表至少支持展示以下信息：

1. 序号、店铺、报价名称、所属仓库、状态、业务类型、报价类型、报价分组。
2. 关联方案名、最新发布报价方案、最新方案发布时间、关联方案数量。
3. 货物类型、运输方式、承运商、目的地、产品描述。
4. 修改人、修改时间、创建人、创建时间、启用时间、到期时间、永久启用。
5. 产品优先级、计费模式、舍入模式、进位模式、超材手续费配置、超材费配置、推荐标签。

列表支持选择表头、分页和横向滚动。表头选择只改变展示字段，不得改变报价配置。

### 10.2 批量修改报价

批量修改必须采用“勾选字段后才覆盖”的方式，未勾选的字段保持每条报价原值，避免批量操作误覆盖无关配置。

批量修改支持以下范围：

| 批量修改区域 | 可修改内容 | 约束 |
| --- | --- | --- |
| 使用时间 | 永久启用或指定时间范围 | 勾选后才生效；指定时间必须完整。 |
| 服务属性 | 服务级别、服务类别、服务项内容 | 三项必须完整选择，不能只修改其中一项。 |
| 币种与计量单位 | 币种、计量单位 | 选择后应用到全部选中报价，并校验价格规则单位一致。 |
| 适用仓库 | 重设、新增或移除仓库 | 重设表示完全替换原值；重设与新增、移除不能同时提交。当前页面不提供清空原有仓库的操作。 |
| 报价分组 | 按店铺分别重设、新增或移除分组 | 重设表示完全替换原值；重设与新增、移除不能同时提交。多店铺批量修改时，分组按各自店铺的选项处理，不能跨店铺复用无效分组。 |
| 客户提醒说明 | 弹框提醒说明 | 适用于客户端展示的服务内容、规则或收费说明。 |
| 内容要求 | 以标签形式维护客户需要准备的内容 | 回车生成标签；未勾选时保留原值。 |
| 计费规则 | 计费模式、重量处理、价格区间等 | 只有勾选 `应用计费设置` 后才覆盖选中报价；可从已选报价中选择一个已有计费规则作为快速填充模板。 |

批量修改提交前必须显示选中报价数量、将被覆盖的字段和每个字段的新值；提交成功后刷新列表并保留历史版本。

对业务类型、目的地、运输方式、货物类型、适用仓库和承运商等多值字段，批量操作统一使用以下语义：

1. `重设`：以本次选择的值完全替换每条报价的原值。
2. `新增`：在每条报价原值中增加本次选择的值。
3. `移除`：从每条报价原值中移除本次选择的值。
4. `重设`不能与`新增`或`移除`同时提交；未选择任何值的字段不提交，因此不表示清空。
5. 批量修改承运商时，必须同时选择渠道线路分配策略；批量页面仅提供“指定唯一承运商，产品为默认产品”和“客户自行选择承运商，产品为默认产品”两种策略。

### 10.3 批量修改禁运规则

`批量修改禁运规则`当前是辅助处理入口，不提供“重设、新增、移除”或“清空”的确定性字段操作。用户选中报价后，系统按店铺分组提交处理请求；每个店铺形成一项后台处理请求，且必须填写不少于 10 个字符的`集运清单描述`。

该入口与价格规则、承运商、目的地和生效时间分离。当前本地代码无法证明后台处理会如何改写禁运品类或禁寄描述，因此上线前必须补充处理结果的写入范围、覆盖方式、失败反馈和人工复核规则；在规则明确前，不得把该入口解释为已具备确定性的批量禁运规则修改能力。

## 11. 报价匹配与异常边界

### 11.1 订单如何找到候选报价

订单生成报价时，系统至少按以下条件筛选：

1. 店铺。
2. 客户所属报价分组。
3. 业务类型。
4. 目的地国家或地区。
5. 货物类型。
6. 运输方式。
7. 实际发货仓。
8. 报价启用状态和有效期。

筛选结果再结合报价类型、承运商线路分配策略、产品优先级和价格规则形成可用报价。不存在满足全部条件的报价时，不得静默使用其他店铺、其他仓库或其他客户分组的报价。

### 11.2 必须阻止保存的情况

以下情况不允许保存：

1. 缺少店铺、报价名称、报价分组、报价类型、目的地、货物类型、运输方式、适用仓库或渠道线路分配策略；非自动分配策略缺少承运商。
2. 非永久报价缺少完整启用时间，或开始时间晚于到期时间。
3. 策略要求指定承运商产品，但没有配置可用的承运商产品。
4. 计费模式与价格区间计量单位不一致。
5. 价格区间上下限关系错误、价格为空、价格为非法负值，或区间发生无法判定的重叠。
6. 地区抛重规则缺少地区、抛重公式或抛比。
7. 地区报价缺少地区或价格区间。
8. 批量修改时，选中的新值会使任一报价失去必填的店铺、分组、仓库、承运商或计费规则。

### 11.3 报价无法使用时的处理

1. 如果订单没有找到可用报价，页面或调用报价的业务流程必须明确提示“没有匹配的线路报价”，不能返回一条不符合适用范围的报价。
2. 如果多个报价同时命中，系统必须按已确认的产品优先级规则选择；如果优先级仍无法区分，应提示配置冲突并要求业务人员调整报价。
3. 订单已使用的报价在后续配置变更后是否重新匹配，应由订单状态和[12.2 仍待确认的运行时规则](#122-仍待确认的运行时规则)决定，不得由 BMS 账单任务自行决定。

## 12. 待确认业务规则

本章只保留现有页面和本地服务代码无法证明的运行时规则。已能从实现确认的规则，已分别回填至[4.1 基础字段](#41-基础字段)、[6.1 渠道线路分配策略](#61-渠道线路分配策略)、[8.4 地区报价](#84-地区报价)和[10.2 批量修改报价](#102-批量修改报价)。

### 12.1 已由现有实现确认的边界

1. `产品优先级`默认值为`0`，且只能填写非负数；现有实现没有给出数值越大或越小优先的订单匹配逻辑。
2. `派送附加费报价`仅支持`中转/预报`业务类型；保存、编辑和批量修改均校验这一限制。
3. 固定承运商、客户选承运商、客户选承运商及产品、系统自动分配五种策略的承运商和产品带入方式，按[6.1 渠道线路分配策略](#61-渠道线路分配策略)执行。
4. 地区报价支持地区多选和可选的地址分类多选；单张地区报价卡会避免父级地区与其下级地区重复选择，但未发现跨卡冲突校验或订单运行时的命中顺序。
5. 多值字段的批量修改支持`重设`、`新增`、`移除`，其中`重设`与`新增`、`移除`互斥；空操作不表示清空。禁运规则的批量入口目前仅提交按店铺拆分的后台处理请求，不具备可由页面确定的覆盖语义。
6. 报价导出使用当前查询条件；勾选报价时，页面将所选报价名称作为筛选条件，未勾选时导出当前查询结果。导出列取当前表头的已展示字段并排除操作列，前端按每批`1000`条拉取数据，导出操作沿用报价编辑权限。由于勾选记录按报价名称而不是报价 ID 筛选，存在重名报价时，现有逻辑不能保证结果严格等同于所勾选记录。
7. 报价币种配置会与店铺默认币种建立换算关系：报价币种等于店铺币种时，换算汇率自动为`1`；不相等时，页面从店铺币种汇率记录中带入可用汇率。常规报价仅在`派送报价`且业务类型均为`重出订单`或`取件退回`时显示该配置；按材积报价也显示该配置。现有页面未强制在币种变更后重填价格区间。
8. 当前实现提供启用、禁用、删除和按报价 ID 查询历史版本的入口；历史版本页面为只读查看和与当前版本对比，未发现恢复历史版本为当前版本的操作入口。

### 12.2 仍待确认的运行时规则

1. 多条报价同时命中时，`产品优先级`是数值越大优先还是越小优先；优先级相同且其他条件也无法区分时，系统是阻止下单、返回冲突，还是按其他明确字段决策。
2. 除`派送附加费报价`外，其他报价类型是否存在只允许用于特定业务类型的专属组合规则。
3. 地区报价命中后是替代默认价格区间还是追加费用；多个地区报价卡同时命中时如何选择；订单没有地址分类时是否可回退到未配置地址分类的地区报价或默认价格区间。
4. `最低收费`、`最高收费`、`附加费用`和`增值基础`同时命中时的计算顺序、适用范围和叠加关系。现有页面仅能看到配置项及保存顺序，不能证明最终金额计算顺序。
5. 报价配置、报价币种、汇率、启用状态或到期时间变更后，已下单未出库、已出库未结单、已产生客户费用的订单是否重新匹配或重算；如需重算，应由谁发起并保留何种报价版本。
6. 删除、禁用、到期对已被订单或历史记录引用的报价如何处理；删除是否物理删除或逻辑删除；历史版本是否需要提供恢复为当前版本的能力。
7. 客户自行选择承运商或承运商产品时，订单提交侧如何校验客户所选项属于该报价可用范围；客户可见范围是否还受客户分组、仓库或其他权限约束。
8. 报价币种可选范围、计量单位的最终维护来源，以及未来是否需要将币种配置扩展到当前未展示该配置的报价类型和业务类型。
9. `批量修改禁运规则`后台处理完成后，禁运品类和禁寄描述的具体写入规则、覆盖范围、失败重试和人工复核方式。

在上述规则确认前，页面可以继续展示已确认的配置字段，但不得在产品文档、接口或数据处理中自行补充未确认的优先级、回退或金额叠加逻辑。
