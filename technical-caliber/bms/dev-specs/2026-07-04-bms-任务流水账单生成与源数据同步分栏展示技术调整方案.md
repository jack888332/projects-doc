# BMS 任务流水分栏展示技术调整方案

## 1. 背景

本方案用于承接 `财务系统.PRD.md` 中对任务流水页面的调整要求：原页面从单一“账单生成任务”视角，调整为“任务流水”视角，并在任务流水内分栏展示两类任务。

本期最终口径如下：

1. 底层任务表仍为 `bill_generate_task`。
2. 跑了任务且产生账单的记录，展示为 `账单生成任务`。
3. 跑了任务但没有产生账单的记录，展示为 `源数据同步任务`。
4. 两类任务都基于账单配置执行。
5. 本期不调整表结构，不新增独立源数据同步任务表，不新增生成金额字段。
6. 页面标题更正为 `任务流水`。

## 2. 页面口径

### 2.1 页面名称

页面标题从 `账单生成任务` 调整为 `任务流水`。

路由和权限码本期可沿用现有配置：

```text
路由：/billing/billGenerateTask
权限码：bill_generate_task
```

### 2.2 页面分栏

任务流水页保留现有外层结构，并在任务流水区域增加二级页签：

1. `账单生成任务`
2. `源数据同步任务`

切换二级页签时：

1. 保留当前筛选条件。
2. 重置页码为第 1 页。
3. 按当前页签重新查询统计和列表。

### 2.3 分栏判断

两类任务都来自 `bill_generate_task`：

| 页签 | 判断口径 |
| --- | --- |
| 账单生成任务 | 当前任务已产出账单 |
| 源数据同步任务 | 当前任务未产出账单 |

后端需要基于现有关联关系判断任务是否产出账单，例如通过账单表中的 `generate_task_id`、任务与账单的可追溯字段，或现有 Mapper 中已经使用的关联关系。本期不通过新增字段解决。

## 3. 枚举口径

### 3.1 任务状态

账单生成任务和源数据同步任务共用一套任务状态枚举。

本期展示口径：

| 后端值 | 展示文案 |
| --- | --- |
| `PENDING` | 待执行 |
| `RUNNING` | 运行中 |
| `SUCCESS` | 成功 |
| `FAILED` | 失败 |
| `NEED_RETRY` | 待重试 |
| `CANCELED` | 已取消 |

`漏执行` 本期不作为任务流水真实状态。排队执行过程中因技术原因中断排队的场景，可回落展示为 `待执行`。

### 3.2 触发方式

本期先保持现有触发方式展示，不强制映射历史值。

现有历史值如 `MANUAL_TEST`、`AUTO` 先保持现有展示。

`CONFIG_CHANGE`、`FINANCE_ADJUST` 等触发方式先预留枚举，完整定义在后续账单重跑机制完善时落实。

### 3.3 数据拉取类型和配置类型

两类任务共用一套数据拉取类型和配置类型枚举：

| 后端值 | 展示文案 |
| --- | --- |
| `FULL` | 全量 |
| `INCREMENTAL` | 增量 |
| `DEFAULT` | 默认配置 |
| `BRANCH` | 分支配置 |

## 4. 后端调整方案

### 4.1 请求参数

在现有任务流水分页请求中增加展示分类参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `taskCategory` | `String` | `BILL_GENERATE` / `SOURCE_SYNC`，为空默认 `BILL_GENERATE` |

建议新增枚举：

```text
BILL_GENERATE：账单生成任务
SOURCE_SYNC：源数据同步任务
```

### 4.2 分页查询

现有接口保持不变：

```text
POST /api/bms/bill-generate-task/page
POST /portal/bms/billGenerateTask/page
```

查询分派口径：

1. `taskCategory = BILL_GENERATE`：查询已产出账单的 `bill_generate_task`。
2. `taskCategory = SOURCE_SYNC`：查询未产出账单的 `bill_generate_task`。

筛选条件继续使用现有任务编号、配置编号、客户、店铺、任务状态、触发方式、账期、创建时间等字段。

### 4.3 详情查询

现有详情接口保持不变，并透传 `taskCategory`：

```text
GET /api/bms/bill-generate-task/detail
GET /portal/bms/billGenerateTask/detail
```

详情内容本期复用现有任务详情结构：

1. 基础信息。
2. 错误信息。
3. 账单配置快照。
4. 费项规则快照。
5. 主订单拉取 SQL。
6. 附加费拉取 SQL。

源数据同步任务同样基于账单配置执行，因此仍可展示账单配置快照和费项规则快照。本期不新增源数据同步专属快照字段。

### 4.4 统计口径

统计区按当前筛选条件和当前 `taskCategory` 计算：

1. 任务总数。
2. 成功任务数。
3. 失败任务数。
4. 待重试任务数。
5. 运行中任务数。

本期不展示生成金额统计字段；若后端响应仍保留历史 `receivableAmount`，前端不在任务流水统计区展示。

### 4.5 数据库

本期不调整数据库结构：

1. 不新增 `source_data_sync_task`。
2. 不新增 `bill_generate_task.task_category`。
3. 不新增生成金额字段。
4. 不修改 `aidocs/technical-caliber/sql/ar_bill.sql`。

## 5. 前端调整方案

### 5.1 页面结构

文件：

```text
admin_shell/src/views/billing/billGenerateTask/index.vue
```

调整点：

1. 页面标题改为 `任务流水`。
2. 在任务流水区域增加二级页签。
3. 默认选中 `账单生成任务`。
4. 切换页签时透传 `taskCategory` 并刷新列表。

### 5.2 请求参数

`queryTasks()` 增加：

```js
taskCategory: this.activeTaskCategory
```

`openDetail(row)` 增加：

```js
taskCategory: this.activeTaskCategory
```

### 5.3 列表字段

两类任务共用一套列表字段。没有业务意义的字段展示 `-` 或 `0`。

保留字段包括：

1. 任务编号。
2. 任务状态。
3. 开始时间。
4. 耗时。
5. 触发方式。
6. 数据拉取类型。
7. 配置编号。
8. 配置类型。
9. 客户名称。
10. 客户编码。
11. 会员编码。
12. 店铺。
13. 账期。
14. 拉取订单数。
15. 错误摘要。
16. 操作。

本期不展示生成金额字段。

### 5.4 详情弹窗

弹窗标题根据页签动态展示：

1. `账单生成任务详情`
2. `源数据同步任务详情`

内容仍复用现有结构。本期不新增源数据同步专属 SQL 或快照区域。

## 6. 权限

本期不新增权限：

1. 源数据同步任务沿用 `bill_generate_task` 权限。
2. 快照和 SQL 查看权限不新增细粒度控制。
3. 源数据同步任务不新增重试 / 补偿入口。

后续若要拆分权限，需要同步后端菜单权限和前端 `meta.code`。

## 7. 实施计划

### P0：后端判断口径

1. 确认 `bill_generate_task` 与账单的现有关联字段。
2. 明确“已产出账单”和“未产出账单”的 SQL 判断方式。

### P1：后端接口

1. 增加 `BmsTaskCategoryEnum`。
2. 分页请求支持 `taskCategory`。
3. 详情请求透传 `taskCategory`。
4. 分页和统计按 `taskCategory` 过滤。
5. 保持现有表结构和任务写入链路不变。

### P2：前端页面

1. 页面标题改为 `任务流水`。
2. 增加 `账单生成任务` / `源数据同步任务` 二级页签。
3. 查询列表和详情时透传 `taskCategory`。
4. 任务状态共用枚举。
5. 触发方式保持现有展示。
6. 隐藏生成金额统计和列表字段。

### P3：联调验收

1. 验证两个页签都查询 `bill_generate_task`。
2. 验证产出账单的任务只出现在 `账单生成任务` 页签。
3. 验证未产出账单的任务只出现在 `源数据同步任务` 页签。
4. 验证筛选条件在切换页签后保留。
5. 验证统计区按当前页签重新计算。
6. 验证详情弹窗仍可查看配置快照、规则快照和 SQL。

## 9. 已确认问题

1. 任务流水有两类：产生账单的是 `账单生成任务`，没有产生账单的是 `源数据同步任务`。
2. 当前任务表是 `bill_generate_task`。
3. 两类任务都是基于账单配置执行。
4. `漏执行` 不作为任务流水真实状态，必要时用 `待执行` 取代。
5. `配置变更`、`财务调整` 先预留枚举，后续账单重跑机制完善时再定义完整语义。
6. 源数据同步任务本期不需要新增重试 / 补偿入口。
7. 本期不新增快照和 SQL 细粒度权限。
8. 本期不做表结构调整。
9. 两类任务共用一套枚举。
10. 本期不需要生成金额字段。
11. 现有 `MANUAL_TEST`、`AUTO` 先保持现有展示，暂不映射。
12. 页面名称更正为 `任务流水`。

## 10. 风险点

1. “是否产出账单”的关联判断必须准确，否则两个页签会出现数据串栏。
2. 由于本期不改表结构，若历史任务缺少稳定的账单关联字段，可能需要用现有关联关系兜底判断。
3. 触发方式本期保持现有映射，和 PRD 新文案可能短期不完全一致。
4. 后续账单重跑机制完善后，预留枚举和任务流水口径可能还需要再补充。
