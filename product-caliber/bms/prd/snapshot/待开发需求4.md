# 待开发需求：按代收货款金额生成固定手续费

## 1. 需求概要

- 目的：把尾程派送商按代收货款金额分档的手续费价目表配置为系统报价，并自动形成可追溯的客户费用。
- 适用范围：订单已确定尾程派送商，且单个尾程包裹存在正数代收货款。普通线路选择、运输费用、到付附加费、返款计算和 BMS 账单计算不在本需求中重新定义。
- 核心结果：新增`代收货款手续费报价`。OIS按包裹的派送商、币种和代收货款金额命中唯一报价及区间，直接取得固定手续费，并汇总形成业务订单级费用结果；BMS只读取该订单级结果。

## 2. 核心场景与业务规则

### 2.1 配置手续费报价

- 类型：新增。
- 业务落点：供应链系统`线路报价管理`列表和详情页；联动原型为[`/business/route-quotes`](http://localhost:4173/#/business/route-quotes)。
- 配置规则：
  1. 报价沿用店铺、报价名称、报价分组、业务类型、目的地、货物类型、运输方式、适用仓库、启用时间和状态等公共字段。
  2. 至少选择一家尾程派送商。一份报价可关联多家独立派送商，共用报价币种、金额区间和手续费；费率不同时必须拆分报价。
  3. 报价币种同时作为代收货款金额和固定手续费的币种。订单原始币种不一致时不得换算或命中。
  4. 计费模式固定为`按代收货款金额分档`，计算方式固定为`多包裹单独算费`。
  5. 复用原有`默认价格区间`区域：规则类型固定为`代收货款金额`，价格类型固定为`一口价`，区间价格即固定手续费；沿用原有新增、编辑和删除交互，不新增独立区间表。
  6. 最低价格、渠道线路分配策略、费用取整、舍入、进位和抛重配置显示`不适用`并禁用；地区报价、箱型材积和超材配置不显示。

### 2.2 保存和启用校验

1. 区间边界固定为`下限 < 代收货款金额 <= 上限`，按金额升序连续排列，不得重叠或留空档。
2. 第一条从`0`以上开始；最后一条覆盖允许的最大金额，上限为`0`时表示无上限。
3. 固定手续费不得小于`0`；`0`表示免收手续费，不表示缺少规则。
4. 报价必须具备报价币种、至少一家尾程派送商和至少一条完整区间。
5. 同一适用范围、报价币种和尾程派送商的有效报价不得在有效时间上重叠。两份报价的派送商集合存在交集时，也按交集派送商校验冲突。

### 2.3 按包裹计算手续费

1. 代收货款为空或等于`0`时，不产生手续费。
2. 系统按订单店铺、客户报价分组、业务类型、目的地、货物类型、运输方式、实际发货仓、尾程派送商、原始币种和有效期筛选唯一报价。
3. 使用单个尾程包裹的代收货款金额命中唯一价格区间，直接取得该区间的一口价；代收货款金额不参与乘法计算。
4. 每个包裹分别匹配和计费，再汇总为业务订单手续费，不得先合并多个包裹的代收货款金额。
5. 费用明细保留尾程运单号、派送商、代收货款金额、命中区间、手续费、币种和报价版本。
6. 未找到报价、币种不匹配或金额未命中区间时，返回`未配置可用的代收货款手续费报价`及未命中的派送商、币种和金额；不得静默跳过、改用其他派送商报价或生成零金额费用。

| 尾程派送商 | 包裹代收货款 | 命中区间 | 手续费 |
| --- | ---: | --- | ---: |
| 大荣或东网 | `8,200 TWD` | `5,000 < 金额 <= 10,000` | `35 TWD` |
| 新竹 | `8,200 TWD` | `0 < 金额 <= 10,000` | `30 TWD` |

大荣和东网是两家独立派送商，但因费率相同可共用一份报价；新竹费率不同，需单独建立报价。

### 2.4 查询和追溯

1. 列表在公共报价字段外展示尾程派送商、报价币种、金额范围、区间数量和手续费范围；普通报价不显示空的专属字段。
2. 新增、编辑、复制新增、启用、禁用、删除、筛选、排序、分页和横向滚动沿用现有线路报价交互。
3. 报价保存后形成版本；历史版本只读展示派送商集合、报价币种和价格区间变化。
4. 后续修改报价不得改写既有订单费用。只有订单明确触发费用重算时，才按重算时适用的报价版本重新计算，并保留新旧结果的追溯关系。
