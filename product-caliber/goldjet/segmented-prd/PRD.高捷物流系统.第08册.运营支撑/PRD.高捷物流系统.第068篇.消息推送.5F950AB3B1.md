## 1. 消息推送

**业务触发：** 由订单操作、状态变化、外部处理结果或定时检查触发；具体入口和接收对象见各通知规则。

### 1.1 消息推送业务范围

<a id="doc-5F950AB3B1-section-64f8c72867c1"></a>
#### 1.1.1 消息渠道与适用范围

消息推送按业务触发条件，通过短信、企业微信、首页工作台站内消息或邮件向指定对象发送通知。

通知接收对象按本篇各事件规则确定；接收通知后访问业务记录，仍须满足[关联对象与跨入口访问](PRD.高捷物流系统.第066篇.角色与访问权限.5E31456F30.md#doc-5E31456F30-related-object-access)的授权边界。

### 1.2 航晟物流消息推送规则

<a id="doc-5F950AB3B1-section-11ddcb71608e"></a>
#### 1.2.1 调度邮件通知规则

- 系统根据用车调度结果，自动发送邮件到预留的客户邮箱地址。

**业务范围**：对于调度和修改调度的信息，系统提供发送邮件通知给客户

**参与角色**：系统自动触发

**前置条件**：录入调度信息（单笔调度和批量调度）与修改调度，才会自动触发邮件通知。

**业务结果**：符合自动发送邮件条件时，系统将邮件发送至指定邮箱地址。

**处理规则**

- 邮件按订单发送；批量调度多笔订单时，每笔订单分别发送一封邮件。

- 单笔调度提交、批量调度提交或单笔调度修改保存后触发邮件。

- 收件人为订单中选定的委托方联系人邮箱；抄送人为主数据中配置的航晟物流客服部邮箱。

- 调度邮件标题为“《单号：`<单号>`》的调度安排”；修改调度邮件标题为“《单号：`<单号>`》的调度调整”。

- 正文字段无值时不显示对应行。调度邮件正文包含车辆数，以及每辆车的车牌号、司机姓名、联系电话、司机身份证、车型、公司地址、海关编号、车自重、柜号、架重、柜重和客户密码；多辆车之间空一行。正文附用车申请的件数、重量、体积、尺寸、提货点和卸货点。

- 修改调度邮件先展示原车牌号与变更后车牌号，再按调度邮件格式展示各车辆和原用车申请信息；未变更车辆仍按相同格式展示。

- 调度及修改调度邮件均提示：“关于此调度若需后续交流，请回复全部，以便及时处理。”

**后续处理与分支**：取消调度的场景，则不用发送系统邮件。

#### 1.2.2 订单企业微信通知规则

**业务范围**：系统自动触发发送微信消息内容到指定的企业微信账号

**参与角色**：航晟物流

**处理规则**

| 通知场景 | 触发条件、接收对象与通知内容 |
| --- | --- |
| 未调度订单提醒 | 每天18:00检查状态为“未调度”且提货日期不晚于次日的运输订单。存在符合条件的订单时，向配置的航晟卡车部主管和客服人员发送“今天还有`<未调度订单数量>`个订单未处理，请尽快处理！” |
| 司机异常提醒 | 司机通过小程序上报运单异常后，立即向航晟卡车部客服人员发送“运单号`<运单号>`：司机（联系方式：`<司机联系方式>`）上报了异常（`<异常类型>`），请关注处理！” |
| 调度取消提醒 | 已调度订单被取消后，向航晟卡车部客服人员发送“委托方：`<委托方>`，订单号：`<订单号>`，已取消订单，请关注处理！”订单号为空时依次改用子单号、批次号。 |

#### 1.2.3 车辆到期通知规则

**业务范围**：系统自动触发发送微信消息内容到指定的企业微信账号

**参与角色**：航晟物流

**处理规则**

#### 1.2.4 登录验证码规则

用户点击“获取验证码”并通过图形校验后，系统向登录手机号发送短信：“【高捷物流】您本次的验证码为`<验证码>`，请不要告诉其他人。”

手机号校验、重发间隔、验证码验证、保持登录和微信授权登录统一遵循[小程序登录规则](../PRD.高捷物流系统.第05册.运输管理/PRD.高捷物流系统.第041篇.陆运-司机端小程序.92E2D8A803.md#doc-92E2D8A803-section-6eb9a0fd9fc4)。

**参与角色**：地面服务人员

**前置条件**：基于空运的主单/分单进行预警时间段的提醒。

**处理规则**

| 通知场景 | 触发条件、接收对象与通知内容 |
| --- | --- |

| 中转派车预警 | 航班起飞时间距当前时间10小时30分钟且对应中转订单的仓库订单状态为“打包中”时，向航晟物流卡车客服人员发送“入仓号：`<入仓号>`的航班起飞时间为`<航班起飞时间>`，剩余时间已接近10小时，请跟进货物中转派车情况。” |

#### 1.2.6 货站打板企业微信通知规则

**业务范围**：系统在板纸修改和货站赶单预警场景触发企业微信通知。

**参与角色**：货站打板人员、货站打板主管、空运客服、航线部

**前置条件**：板纸修改提交成功，或当前时间距离航班起飞时间8小时30分钟。

**业务结果**：系统向对应业务角色发送通知。

**处理规则**

| 通知场景 | 触发条件、接收对象与通知内容 |
| --- | --- |
| 板纸修改通知 | 货站打板人员通过“板纸上传”功能修改已上传板纸并提交后，系统向货站打板主管、空运客服和航线部人员发送企业微信通知。消息内容为“航班号：`<航班号>`，板纸已修改，请留意变更！” |
| 货站赶单预警 | 当前时间距离航班起飞时间8小时30分钟时，系统向货站打板人员和货站打板主管发送企业微信通知。消息内容为“提单号：`<提单号>`，距离航班起飞已不足8.5小时，请及时跟进货物进站！” |

### 1.3 空运业务消息推送规则

<a id="doc-5F950AB3B1-section-89184bd561de"></a>
#### 1.3.1 入仓图邮件规则

- 系统根据客服手动操作结果，发送入仓图到预留的客户邮箱地址。

**业务范围**：对于入仓图，客服手动点击发送后，发送邮件给客户

**参与角色**：空运客服

**前置条件**：当空运客服手动点击发送时

**业务结果**：客户有指定的邮箱地址。

**处理规则**

- 订单状态为“待订舱”“待补录”或“待出提单”时显示“发送”按钮；同一订单仅可发送一次，发送后按钮不再显示。

- 客服点击“发送”后触发邮件。收件人为客服在订单委托方联系人邮箱中勾选的联系人，抄送人为订单创建客服及空运客服主管。

- 邮件标题为“入仓图通知：《订单号：`<订单号>`（毛件体：`<毛件体>`；中文品名：`<中文品名>`；出港日期：`<出港日期>`）》的入仓地图”。

- 正文字段无值时不显示对应行；正文说明订单货物的入仓图已下发，并提示附件SO可供查收，客服联系方式取配置的`<客服联系方式>`。

- 附件中的订单号、目的港、件数、商品名、体积、重量和操作人取订单数据，操作人为当前客服姓名。

<a id="doc-5F950AB3B1-section-e48548e84cac"></a>
#### 1.3.2 空运服务节点邮件规则

出口订单只对已选择的服务及已开启邮件通知的订单发送节点邮件。创建/编辑订单选择客户后，“发送邮件”默认否；选择是并提交后，后续匹配的节点使用对应模板；选择否不发送邮件，但订单按原业务流程继续。

收件人为出口订单中录入的委托方联系人邮箱；抄送至少包含订单创建人邮箱，是否还包括空运客服主管见 OPS-45。邮件标题包含订单号、总运单号、毛件体、中文品名和出港日期：

`《订单号：<订单号>（总运单号：<总运单号>；毛件体：<毛件体>；中文品名：<中文品名>；出港日期：<出港日期>）》的状态轨迹`。

正文只显示有值的内容行；字段说明、示例人名、示例手机号和截图批注不进入实际邮件。通用结束语提供订单创建人账号姓名和手机号，并在相应模板提示客户尽快提供补料信息；固定模板联系方式与原配置来源的差异见 OPS-45。

| 通知场景 | 触发与汇总边界 | 正文内容及字段来源 |
| --- | --- | --- |
| 已订舱 | 选择订舱服务，空运订舱提交且服务节点为已订舱；与原“订单待补录”触发差异见 OPS-46 | “已为您预订好航班”；总运单号、头程航班/日期、该航班对应货站、头程截单时刻、打板公司 |
| 修改航班 | 终止原订舱后重新订舱，头程航班/日期、截单时刻、打板公司任一变化；是否覆盖直接编辑见 OPS-46 | “航班信息已修改”；新总运单号，并只显示实际变化项的原值与新值 |
| 修改运费卖价 | 出口订单编辑后运费卖价（不含 TC）变化；原有后段卡车/分泡修改的独立触发边界见 OPS-46 | “价格已修改”；毛件体、总运单号、头程航班/日期、货站，运费卖价、后段卡车卖价、分泡比例的原值与新值；毛件体按提单、入仓、预计顺序取值 |
| 已派车 | 订单关联全部运输服务单均完成调度 | “高捷已为您派车”；提货地点，逐次调度的司机姓名、身份证、车牌、车型，多次调度逐项展示 |
| 已提货 | 订单关联全部运输运单状态均已提货，来自后台或小程序状态更新 | “货物已提走，即将送达”；送达地点与来源写作提货地点的差异见 OPS-47 |
| 已入仓库 | 订单关联全部集货入库服务单均完成入库；原服务单已完成状态与实际入库时点的对应见 OPS-47 | “货物已入仓库”；仓库地点、实际入库总重量/总件数/总体积 |
| 已出仓库 | 订单关联全部集货出库服务单均已完成 | “货物已出仓库”；目的地取所订航班对应货站 |
| 到货站 | 运输运单中转服务到货站并更新已卸货；单次卸货与全部服务完成的差异见 OPS-47 | “货物已到货站”；货站取所订航班对应货站 |
| 已过安检 | 选择安检服务，后台更新已安检或小程序上传托书；两入口是否等价见 OPS-47 | “货物已过安检” |
| 报关放行 | 关联全部普货出口关务服务报关状态放行；主单下全部分单放行后发送 | “货物已放行，请查收报关单”；一次附全部报关单 PDF，截图附件格式差异见 OPS-48 |
| 已出运 | 全部分单节点轨迹均含航班起飞信息 | “货物已出运”；头程航班号及日期 |
| 已中转 | 按既有航班中转事件发送，具体全单汇总边界未补定 | “航班已中转” |
| 已到达 | 全部分单节点轨迹均含航班落地信息 | “货物已到达目的港” |
| 目的地提货 | 清关派送状态管理选择目的地提货，填写必填项后更新成功 | “货物已在目的地提货” |
| 已清关送达 | 清关派送状态管理选择已清关送达，填写必填项后更新成功 | “货物已清关送达” |

上表是独立事件规则，不表示这些事件全部必经或按表顺序执行。订单增加/取消服务后“全部”的取数范围、空收件人、发送失败、重复回执、重试及首次开启通知的历史节点补发未定义，见 OPS-49，不据此生成额外发送动作。

#### 1.3.3 空运订单企业微信通知规则

**业务范围**：系统自动触发发送微信消息内容到指定的企业微信账号

**参与角色**：空运客服、客服主管、空运航线运营、空运航线操作

**处理规则**

- 客服提交订单且订单状态变为“待订舱”后，系统按舱位产品管理中的航司关联关系，向对应航线运营人员发送“订单号：`<订单号>`待订舱，请尽快处理！”

- 航线运营人员填写航程信息并确认航班后，系统向对应航线操作人员发送“订单号：`<订单号>`航线信息待补充，请尽快处理！”

- 航线操作人员完成航程补充并点击“订舱完成”、订单状态变为“待补录”后，系统向订单客服发送“订单号：`<订单号>`待补录，请尽快处理！”订单已派给跟单客服时发送给跟单客服。

- 客服修改预计毛件体或入仓毛件体的通知对象为对应航司的航线运营和航线操作人员，通知携带订单号及修改前后的毛件体，供航线运营判断是否调整预计盈利规则区间。每次修改均通知，还是仅超出区间时通知，触发范围待确认，见问题清单 GJ-WORD-P1-02；“修改后的毛件体不符合航线预计盈利规则区间，请及时处理”仅用于超出区间的情形。

- 入仓实际毛件体不在预计盈利规则区间时，系统向订单客服发送“订单号：`<订单号>`的毛件体与预期不符，请尽快联系客户处理。”订单已派给跟单客服时发送给跟单客服。

- 客服修改卖价后，系统向对应航司的航线运营和航线操作人员发送订单号，以及运费卖价、后端卡车卖价和分泡比例的变更前后值。

- 航线运营人员修改航程信息后，系统向订单客服发送订单号、提单号，以及航班号、货站、截单时间和装板公司的变更前后值；订单已派给跟单客服时发送给跟单客服。

- 建单客服派单后，系统向所选接单客服发送“客服`<建单客服姓名>`给您派单，订单号：`<订单号>`，备注：`<备注>`。”

- 接单客服拒绝接单后，系统向建单客服发送“客服`<接单客服姓名>`拒绝您的接单，订单号：`<订单号>`，备注：`<备注>`。请查收。”

- 报关行客服要求补齐材料时，系统向建单客服发送“分单号：`<分单号>`的`<材料名称>`有误，请补齐材料。”直单使用“订单号”。

- 客服申请作废主订单、分单或服务单后，系统向客服主管发送“订单号：`<订单号>`申请作废，理由：`<作废理由>`。请及时审核。”

- 客服主管同意作废后，系统向对应客服发送“订单号：`<订单号>`的作废申请已通过。请查收。”

- 客服主管拒绝作废后，系统向对应客服发送“订单号：`<订单号>`的作废申请已拒绝，理由：`<拒绝理由>`。请查收。”

## 2. 消息中心与接收对象

消息中心列表默认每页 50 条。新增使用提交、取消入口，修改使用保存、取消入口；提交成功显示成功提示。输入不符合规范或缺少必填值时标识对应字段，并禁用提交、保存入口。

消息中心按业务节点维护消息类型、内容和对象，由各业务模块（含风控中心）在正式业务事件发生时调用。支持站内信、短信、邮件和企业微信。通知内容的业务依据仍为本篇对应事件，不以通用模板配置反向改变业务触发条件。

| 业务事件传入对象 | 模板配置对象 | 最终接收对象 |
| --- | --- | --- |
| 有 | 有 | 两个对象集合的交集 |
| 有 | 无 | 业务事件传入的对象 |
| 无 | 有 | 模板配置的对象 |
| 无 | 无 | 空集，不产生接收对象 |

内部对象可按固定账号或角色配置；角色展开到相应员工后取得通知身份信息。外部对象按客户选择，再取得客户联系人。无客户联系人类型时，默认首位联系人还是全部联系人的口径冲突见 OPS-36，不擅自扩大发送范围。

| 删除、标记已读 | 未选择记录时禁用，选中后可操作，通过确认弹窗承载 |
| 全部已读、全部删除 | 确认后按本章规则作用于当前用户全部消息 |
| 创建时间 | 显示至秒 |

**界面原型概述 · 消息详情**

- **区域字段或业务元素**：标题内容、消息时间、消息详情、返回。
- **区域级通用规则**：展示所选消息的只读内容，返回恢复消息列表。

| 字段或控件特例 | 界面特例或可见反馈 |
| --- | --- |
| 标题内容 | 固定显示“消息通知” |
| 消息时间 | 显示至秒 |
| 消息详情 | 展示事件触发的文案；1000 字符详情与2000 字符模板的范围冲突见 OPS-38 |

## 5. 消息配置

消息配置按用户所属部门隔离，创建时间倒序。保存新模板时校验必填信息和至少一种消息渠道，校验通过后生成 `XXPZ+YYMMDD+5位流水` 的模板编号，并进入待审核状态；未提交返回不保存输入。内部允许四种渠道，外部允许站内信、短信、邮件，不提供企业微信渠道。

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 待审核 | 审核通过 | 已启用 |
| 待审核 | 拒绝 | 结果状态已拒绝/已禁用存在冲突，见 OPS-37 |
| 已启用 | 禁用 | 已禁用 |
| 已禁用 | 启用 | 已启用 |
| 允许编辑的模板 | 编辑并提交 | 保存可修改字段；编辑后的重新审核边界未明确 |
| 任意可见模板 | 查看 | 只读展示，不改变模板 |

**界面原型概述 · 消息配置查询栏**

| 字段或控件 | 个别界面约束或可见反馈 |
| --- | --- |
| 模板名称 | 最多 20 字符，模糊查询 |
| 消息节点 | 来自已定义的消息节点，多选、精确查询 |
| 状态 | 单选待审核、已启用、已禁用、已拒绝 |
| 查询、重置 | 无条件查询范围内全部配置；重置清空条件 |

**界面原型概述 · 配置列表**

- **区域字段或业务元素**：模板编号、模板名称、消息节点、消息通道、状态、创建人、创建时间、新建、审核、拒绝、编辑、查看、启用、禁用。
- **区域级通用规则**：只读展示已保存配置，按当前业务资格开放操作；新建、编辑和查看进入相应页面。

| 字段或控件特例 | 界面特例或可见反馈 |
| --- | --- |
| 消息通道 | 多种渠道用分号分隔，无渠道显示“无” |
| 查看 | 全部表单字段只读 |
| 审核、拒绝、启用、禁用 | 按本章状态操作表显示可执行入口 |

**界面原型概述 · 配置表单**

| 字段或控件 | 个别界面约束或可见反馈 |
| --- | --- |
| 模板编号 | 提交成功后生成，只读 |
| 模板名称 | 录入名称，最多 20 字符 |
| 是否用于风控中心 | 单选，默认否 |
| 内部/外部、消息节点 | 默认内部；切换对象类型后切换节点选项和表单内容，节点来自消息节点清单 |
| 消息通道及正文 | 至少选一种，可多选；各渠道正文默认禁用，选中渠道后可编辑，正文最多 2000 字符 |
| 动态参数 | 随节点显示可用参数，点击后追加到消息正文末尾 |
| 固定对象、内部角色 | 可配置固定对象；内部角色从启用角色中多选 |
| 指定客户、客户名称 | 勾选指定客户后可新增客户，从有效客户档案模糊查询后选择 |
| 客户联系人类型、联系人 | 可选负责人、业务联系人、财务联系人；客户行按表头类型带入并可改选，同类型多人可选择单个；未选择时默认范围见 OPS-36 |
| 客户删除、批量删除 | 选择客户行后移除该行；仅改变本模板接收范围 |
| 提交、返回列表 | 校验通过后保存并回到列表；返回不保存本次输入 |

## 6. 消息记录查询

查询实际调用各消息渠道的记录，不把业务触发视为渠道发送成功。页面初始为空，执行查询后显示匹配记录；无查询条件时查询授权范围内全部调用记录。查看内容以当次调用的实际文案为准，不重新套用后来修改的模板。

**界面原型概述 · 调用记录查询栏**

| 字段或控件 | 个别界面约束或可见反馈 |
| --- | --- |
| ID、模板名称、对象名称 | 手工输入、模糊查询 |
| 是否用于风控中心 | 是/否选择 |
| 对象类型 | 内部/外部选择 |
| 状态 | 成功/失败选择 |
| 查询、重置 | 执行检索或清空条件 |

**界面原型概述 · 调用记录结果区**

- **区域字段或业务元素**：ID、模板名称、消息节点、消息通道、是否用于风控中心、对象类型、对象名称、状态、发送时间、查看。
- **区域级通用规则**：只读展示当次调用记录，发送时间精确到秒。

| 字段或控件特例 | 界面特例或可见反馈 |
| --- | --- |
| 查看 | 弹窗展示实际发送内容；短信、企业微信标题为空，站内信、邮件标题为“高捷平台系统提示” |

## 7. 待确认边界

OPS-36 至 OPS-38、OPS-45 至 OPS-49 的完整证据与待确认问题记录在 PRD 自洽性问题清单。未确定的默认接收人、审核结果、邮件触发边界、附件和异常处理不作为已确认规则。
