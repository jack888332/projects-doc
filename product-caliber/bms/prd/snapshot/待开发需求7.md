# 待开发需求：修正附加费落入账单的门禁

## 1. 需求概要

| 项目 | 内容 |
| :--- | :--- |
| 需求目的 | 当前附加费挂靠真实业务订单后，系统按订单履约时间确定归属账期；订单履约时间早于本账期开始日，而附加费创建时间落入本账期时，附加费仍被排除在本期应收账单之外，造成本期应收金额遗漏。本次修改为：附加费一律按来源记录创建时间确定归属账期，订单履约时间只作归集资格校验，不再决定账期。 |
| 本次范围 | 应收账单归集中，`附加费用报表导入`和`记账单导入`形成的附加费进入费项池及账单时的账期归属口径和履约门槛。 |
| 需求来源 | `PRD.账单系统.md` @ Commit `e053043b5159c58dbe73373340955f5ebcee3d3f`（修正附加费落入账单的门禁），主要章节 9.4、9.5.4。 |

## 2. 本次变更

### 2.1 附加费按创建时间归属账期，订单履约节点只作归集资格（修改）

#### 2.1.1 变更定位

| 业务落点 | 参与方与对象 | 触发或操作 | 本项结果 |
| :--- | :--- | :--- | :--- |
| 应收账单生成中的来源数据筛选与费项入池（[9.4 第三步：哪些来源数据可以由本次任务处理？](../PRD.账单系统.md#section-9-4)、[9.5.4 费用达到什么条件才能入池？](../PRD.账单系统.md#section-9-5-4)） | 系统任务、附加费来源记录、真实业务订单及尾程包裹 | 费项入池任务或账单生成任务处理附加费来源 | 附加费按创建时间落入对应账期；订单履约时间早于本账期的附加费也纳入本期应收账单。 |

#### 2.1.2 变更明细

| 变更动作 | 变更对象或位置 | 目标规则 | 业务影响 |
| :--- | :--- | :--- | :--- |
| 修改 | 附加费的账期归属口径 | `附加费用报表导入`和`记账单导入`形成的附加费均以来源记录创建时间（`sale_order_additional_matter.create_time`）作为费用发生时间并确定归属账期，不得改用订单履约时间。 | 创建时间在本账期、订单履约时间早于本账期的附加费纳入本期账单，消除应收金额遗漏。 |
| 修改 | 附加费的履约门槛 | 挂靠真实尾程包裹的附加费，其所属真实业务订单必须在本次任务的数据截止点前达到配置要求的`出库`或`订单完结`履约节点；履约节点只决定该附加费是否具备归集资格，不决定归属账期。 | 订单未达履约节点时附加费暂不入池；达到后仍按原创建时间确定归属账期。 |
| 修改 | 附加费的来源数据筛选 | 附加费按创建时间筛选归属账期；履约时间可以早于本账期开始日，不要求与附加费创建时间落在同一账期。 | 附加费不再因订单履约时间不在本账期而被排除。 |

#### 2.1.3 详细规则

| 场景 | 处理结果 |
| :--- | :--- |
| 附加费创建时间在本账期内，订单在本次任务数据截止点前已出库或订单完结 | 附加费纳入本期账单；订单履约时间早于本账期开始日也纳入本期。 |
| 附加费创建时间在本账期内，订单在本次任务数据截止点前尚未出库或订单完结 | 附加费暂不入池；订单达到履约节点后，仍按原创建时间确定归属账期，对应账单已经生成或发出时按[9.8 第七步：账单生成后又有变化，应该走哪条路？](../PRD.账单系统.md#section-9-8)承接。 |

#### 2.1.4 本项边界与例外

1. 新规则生效时，来源行仍为`未处理（null）`且尚未进入费项池的存量附加费按新规则处理，并按原创建时间确定归属账期。
2. 已经处于`已入池（synced）`或已经归入有效账单的附加费，保持原费项、原账单和原快照，不回写、不迁移，也不得重复归集。
