# 账单系统验收计划

## 1. 验收目的与需求基线

本计划用于组织财务代表、产品经理和测试人员对账单系统本期交付进行业务验收，确认客户配置、费项归集、账单生成、账单审核、导出及报表比对能够按同一套业务口径闭环运行。

- 需求基线：[`PRD.账单系统.md`](../PRD.账单系统.md) 当前工作区版本。
- 基线冻结要求：正式验收开始前，必须记录本次发布对应的 PRD Commit、应用版本和验收环境版本；验收期间不得静默切换版本。
- 验收环境：BMS 测试环境。
- 验收对象：财务日常操作和财务可观察的系统结果，不验收内部数据库、接口实现或技术重试状态。

## 3. 验收组织与通过规则

### 3.1 参与角色

| 角色 | 职责 |
| :--- | :--- |
| 财务验收人 | 按真实财务操作完成配置、账单核对、审核、导出和报表比对，确认结果可用于对账。 |
| 产品经理 | 解释 PRD 口径，确认边界和争议，不在验收现场临时引入未写入 PRD 的规则。 |
| 测试人员 | 准备数据、执行场景、记录证据、复测缺陷并汇总验收结果。 |
| 研发支持 | 处理环境和程序故障，说明技术异常，但不得替代财务确认业务结果。 |

### 3.2 准入条件

1. 本计划第 4 章客户样本已建立，来源订单、费项、汇率、配置版本和预期金额已经由产品与财务共同核对。
2. 财务管理员、普通财务和无权限账号均已准备，客户邮箱统一使用测试邮箱，不得向真实客户发送邮件。
3. 费项入池任务、账单生成任务、导出任务和邮件任务能够在测试环境执行；系统时间或任务触发时间可控。
4. 用于报表比对的财务侧文件和系统侧新版应收账单对账报表已经准备。
5. 每个样本订单均保留可追溯的来源单号、费项原始金额、结算币种、履约时间和预期归属方案。
6. 第 8 章中的阻断问题已经关闭；未关闭时，只能执行不受影响的场景，不得签署整体验收通过。

### 3.3 通过规则

1. `P0`和`P1`场景必须全部通过；任何金额错误、重复归集、漏归集、错误客户通知、已发账单被替换或越权下载均视为阻断缺陷。
2. `P2`场景允许存在不影响账单金额、状态、客户信息边界和后续操作的展示类缺陷，但必须有责任人和修复时间。
3. 场景通过必须同时具备操作证据和结果证据；仅页面提示成功但账单、任务或文件结果不正确，不视为通过。
4. 缺陷修复后必须使用原样本数据复测受影响场景，并回归其上游配置和下游导出/比对链路。
5. 所有场景执行完成后，由财务验收人、产品经理和测试负责人共同确认最终结论。

### 4.2 公共订单与费项样本

每个客户至少准备下列订单结构，金额统一保留内部计算精度，导出时按 3 位小数展示：

| 样本 | 数据要求 | 预期用途与结果 |
| :--- | :--- | :--- |
| 单包裹订单 | 1 个业务订单、1 个子运单号，包含`运费`和`派送费` | 对账明细只输出业务订单行，不额外生成尾程包裹行。 |
| 多包裹订单 | 1 个业务订单、2 个不同子运单号，订单级费用与包裹级费用并存 | 导出时输出 1 条业务订单行和 2 条尾程包裹行；包裹行不复制订单专有金额，两层金额不得重复求和。 |
| 多币种订单 | 同一订单至少包含 GBP、USD、CNY 中两种原始币种，并命中不同费项结算币种 | 页面和导出按结算币种分桶；金额可计算，币种不写入 Excel 单元格真实值。 |
| 迟到费项订单 | 订单已进入待审核账单后，新增一笔仍属于同账期、同配置的有效费项 | 补充生成把新费项加入既有待审核账单并形成新结果版本，不新建重复账单。 |
| 配置切换订单 | 旧配置和新配置的数据范围存在重叠，切换时点前后均有费项 | 费项按配置切换规则唯一归属；旧待审核账单仅在替换成功后失效。 |
| 异常导出订单 | 缺失`核重时间` | 对该账单的客户对账文件生成失败，任务详情明确定位数据异常；不得输出看似成功但字段为空的文件。 |

| 汇率样本 | 配置 | 预期结果 |

### 4.4 报表比对专用样本

使用`UAT-TK9012`的客户版应收账单 Excel 作为系统侧文件，另准备一份财务侧文件，至少包含：

1. 一个两侧订单号完全一致且金额一致的订单。
2. 一个财务侧`订单号 = /`、可用`承运单号`关联的订单。
3. 一个仅系统侧存在的订单和一个仅财务侧存在的订单。
4. 一个同名费项金额不同的订单。
5. 一个仅财务侧存在的费项和一个仅系统侧存在的费项。
6. 一个金额为`0`的费项和一个空金额费项。
7. 一个重复订单号和一个缺少必要字段的错误文件副本。

预期：系统侧独有订单保留，财务侧独有订单不单独形成结果行；同名费项并排展示，异名或单侧费项分别形成成对列；`0`显示为`0`，无金额保持空白；系统只展示两侧金额，不自动判定一致或不一致。

## 5. 验收执行顺序

1. 先验收`账单配置`和`汇率配置`，固定四个客户的生效版本。
2. 再验收`生成任务`，确认费项入池、账单生成和账单重算结果可追溯。
3. 在`应收账单`完成金额核对、提前收口、审核、通知和状态流转。
4. 在`导出管理`验证客户版、内部拆分式和内部合并式文件。
5. 使用已通过验收的客户版文件进入`报表比对`，验证导入、比对和结果导出。

前一步出现账单范围、金额、币种或状态阻断缺陷时，后续依赖场景暂停，避免用错误账单继续验收导出和报表比对。
