### 0.1 2026-08-20 口径修订

按源库实测数据，实收回款可能落在 `sale_order_package_fee.type = 2` 成本行，不再用 `type = 1` 限定有效回款。有效回款统一为 `tail_way_bill_no` 非空且 `COALESCE(recovery_money, 0) > 0`；包级手续费仍按 `receivable_collection_amount` 采集，当前源数据中该字段仅出现在应收行。回款管理列表仍按包裹粒度展示，为避免同一尾程号出现应收/成本两行，本轮未直接去掉其 `type` 过滤，如需按新口径显示实收回款，需单独按尾程号合并取数。

## 1. 需求概要

### 1.1 目的

在回款返款模式下，一张业务订单包含多个尾程包裹时，不再等待全部包裹录入实收回款。任一包裹已有非空且非零的有效实收回款，即可按业务订单归集返款。

### 1.2 适用范围

- COD 业务订单。
- 返款模式为 `RECEIVED` 回款返款。
- 一票多件场景。

### 1.3 核心结果

1. 首个符合条件的包裹只负责触发整单归集，不承担订单级金额分摊。
2. 订单级应付返款（即代收货款）和订单级机算代收货款手续费按业务订单挂靠并各归集一次。
3. 包裹级导入手续费按尾程包裹挂靠并按导入值单独归集。
4. 其他包裹后续录入或更新实收回款时，只更新对应包裹回款事实，不重复归集订单级金额。

## 2. 修改前后口径

| 业务位置 | 修改前 | 修改后 |
| --- | --- | --- |

2. `isRefundCandidateOrder`（`BillGenerateServiceImpl.java:2441`）只按订单头金额判断：
   - `resolveRefundDeclaredAmount`（`2446`）：优先 `h_cod_price`，回退 `h_collection_price`。
   - `resolveRefundCollectedAmount`（`2454`）：取 `h_collection_price`。
3. 生成主订单快照、调用 `persistOrderWaybillSnapshots`（`3628`）写 `bill_order_waybill_snapshot`。
4. `buildRefundPrincipalFee`（`2595`）：回款模式 `principalSourceAmount = collectedAmount`，即当前用订单头 `collection_price` 作为已回款返款本金。
5. `buildRefundUncollectedFee`（`2624`）：`gap = declared - collected`，即当前实际是 `cod_price - collection_price`。
6. `buildRefundDeductions`（`2643`）：
   - 只有 `resolveRefundCollectedAmount(orderRow) > 0` 时才继续扣减。
   - 订单级代收货款手续费读取 `h_collection_premium_amount`，按业务订单计一次。
   - 超材/重出费按本期回款订单读取关联 `sale_order_additional_matter` 或订单头扩展字段，不再按上一账期或附加费 `create_time` 开窗。

## 5. 目标落地方案

### 5.1 总体思路

```text
OFP 主订单查询（保留现有订单级金额/币种/状态）
  -> 按订单批量查询 sale_order_package_fee（不限定 type）
  -> Java 内按 sale_order_id 归并包裹回款事实和包裹导入手续费
  -> 回款返款：任一包裹满足有效实收回款 => 订单进入候选
  -> 订单级应付返款 / 订单级机算手续费按订单归集一次
  -> 包裹级导入手续费按包裹归集
  -> 写入 fee_detail 时用 sourceTable + sourceId + dedupeKey 防重
```

不改动应收账单生成；不改动签收返款的触发事实；不改动回款管理的包裹级独立判定。

### 5.2 有效包裹回款事实的统一判定

建议在生成层新增一个“包裹回款事实查询 + 有效性判定”能力。Q-02 已确认：生成层只判别回款，不叠加签收/异常状态条件；理论上异常签收包裹不会产生回款，但源数据上没有必然关系。

```text
有效包裹回款事实 =
  p.tail_way_bill_no 非空
  AND COALESCE(p.recovery_money, 0) > 0
  （不限定 p.type，应收行或成本行均可）
```

推荐查询骨架（仅作方案示意，实施时按项目 SQL 规范和 PreparedStatement 分页/批查落地）：

```sql
SELECT p.id,
       p.sale_order_id,
       p.tail_way_bill_no,
       h.warehouse_code AS warehouse_code,
       p.recovery_money,
       p.receivable_collection_amount,
       p.create_time,
       p.modify_time,
       h.delivery_order_code,
       h.order_status,
       h.cancel_reason,
       h.signed_time,
       h.cod,
       h.collection_price,
       h.cod_price,
       e.recovery_time
FROM sale_order_package_fee p
LEFT JOIN sale_order_header h ON h.id = p.sale_order_id
LEFT JOIN sale_order_header_extend e ON e.sale_order_id = h.id
WHERE p.tail_way_bill_no IS NOT NULL AND p.tail_way_bill_no <> ''
  AND COALESCE(p.recovery_money, 0) > 0
  AND h.member_code = ?
  AND h.shop_id = ?
  AND (h.sc_id = ? OR h.sc_id IS NULL)
  AND (LOWER(COALESCE(h.cod, '')) = 'y'
       OR COALESCE(h.collection_price, 0) > 0
       OR COALESCE(h.cod_price, 0) > 0)
  AND COALESCE(h.order_type, '') <> 'BILL'
```

> 实施说明：代码为一次拉取包级费用行，不在 SQL 层限定 `type`，也不在 SQL 层过滤 `recovery_money`；有效回款统一在 Java 内按“尾程单号非空 + `recovery_money > 0`”判定，包级手续费按 `receivable_collection_amount > 0` 采集。

约束：

1. 有效回款只按 `recovery_money` 非空非零判断，不限定 `type`（应收行/成本行均可）；不做订单状态、签收状态、轨迹关键字过滤。
2. 同一尾程运单号可能跨仓库/跨订单出现，包级事实必须携带 `warehouse_code`，按 `sale_order_id + warehouse_code + tail_way_bill_no` 或 `business_order_no + warehouse_code + tail_way_bill_no` 定位，避免数据重复。
3. 数据隔离三字段 `sc_id / shop_id / user_id` 在 BMS 侧落库时仍必须完整；OFP 源查询使用 `member_code + shop_id + sc_id`。

### 5.3 回款返款候选订单判定

`executeRefundTaskInternal` 中建议改为：

```text
RECEIVED（回款返款）：
  hasEffectivePackageReceipt = 该业务订单任一包裹满足 5.2 有效回款事实
  candidate = resolveRefundPayableAmount(orderRow) > 0
              AND hasEffectivePackageReceipt

SIGNED（签收返款）：
  继续沿用现有正常签收/金额归集条件，不套用“任一包裹回款”规则
```

说明：

1. “应付返款 > 0”即 `collection_price > 0`，仍是进入返款账单的必要前提；没有应付返款的订单不进入，包裹级手续费也不能进入（Q-06）。
2. Q-10 已确认：按新规以包裹回款事实为准，不保留旧订单头 `collection_price > 0` 兜底。
3. `validateUniqueBusinessOrderNos` 已保证同任务内业务订单号唯一，继续保留。

### 5.4 金额挂靠层级

| 数据 | 来源 | 挂靠对象 | 本次用途 |
| --- | --- | --- | --- |
| 应付返款 | `sale_order_header.collection_price`（OIS 机算） | 业务订单 | 触发后按订单计入返款账单一次 |
| 订单级代收货款手续费 | `sale_order_header.collection_premium_amount`（OIS 机算） | 业务订单 | 命中直接扣减配置后按订单计入一次 |
| 实收回款 | `sale_order_package_fee.recovery_money`（不限定 type，导入） | 尾程包裹 | 判断订单是否具备回款返款归集条件，保留包裹事实 |
| 包裹级导入手续费 | `sale_order_package_fee.receivable_collection_amount`（导入；当前源数据仅应收行存在该字段） | 尾程包裹 | 按包裹导入值单独归集 |
| 到付总额 | `sale_order_header.cod_price` | 业务订单 | 仅用于核对，不作为应付返款 |

具体生成建议：

1. 订单级应付返款：
   - Q-01 已确认：新建/调整金额解析为 `resolveRefundPayableAmount`，直接取 `h_collection_price`，不再优先 `cod_price`。
   - `buildRefundPrincipalFee` 在两种模式下都使用应付返款作为本金来源；回款返款不再用“订单头 collection_price 当已回款金额”的隐含双关。
   - `cod_price` 只进入主订单/导出/回款管理的到付核对字段，不参与返款本金。
2. 订单级机算代收货款手续费：
   - 命中客户级返款配置 `COD_SERVICE_FEE`、`collection_price > 0` 且 `collection_premium_amount > 0` 时，按业务订单生成一条 `REFUND_DEDUCTION`。
   - `attachedObject = ORDER`，`sourceTable = sale_order_header`，`sourceId = h_id`，`sourceFeeField = collection_premium_amount`。
   - 去掉当前 `resolveRefundCollectedAmount <= 0` 的前置门，改为“订单已进入归集范围”后再判断。
3. 包裹级导入手续费：
   - 仅当订单 `collection_price > 0` 且命中直接扣减配置时（Q-06），对已进入归集范围订单下所有 `sale_order_package_fee.receivable_collection_amount > 0` 的包裹行逐包裹生成一条 `REFUND_DEDUCTION`（不限定 `type`；当前源数据中该字段只出现在应收行，成本行为空）。
   - `attachedObject = LAST_PACKAGE`，`sourceTable = sale_order_package_fee`，`sourceId = p.id`，`sourceOrderId = p.sale_order_id`，`sourceFeeField = receivable_collection_amount`。
   - `lastMileWaybillNo` 取该包裹 `tail_way_bill_no`，不拼接其他包裹；`businessOrderNo` 取 `delivery_order_code`。
   - 包级手续费不要求该包裹自身已录入回款（Q-05）；两者没有必然先后关系，订单触发后随订单一起归集。
   - 包级手续费跟随所属订单账期归集，不按 `p.create_time` 单独开窗（Q-09）。
   - 原始币种默认沿用订单目的国币种（`dest_country_currency_code` 优先，回退 `currency_code/currency`），与现有 `resolveRefundSourceCurrency` 一致；若包级字段提供明确币种则按字段确认。
4. 订单级与包裹级手续费并存（Q-04）：
   - 不去重，以本次需求口径（前者）为准，订单级机算手续费与包裹级导入手续费按各自挂靠层级同时归集。
   - 不因两者金额相同或同一业务费用而互相覆盖、互相核销或只保留一笔。
5. 未回款费项（Q-07）：
   - 以 PRD 为准：`cod_price` 是到付总额，`collection_price` 是应付返款；不再用 `cod_price - collection_price` 充当“未回款金额”费项。
   - 待回款/未回款口径按 PRD 回款管理和“到付与回款汇总”单独展示，不进入返款费项计算。
6. 禁止行为：
   - 不把包裹级实收回款复制到同一订单的其他包裹。
   - 不把订单级金额拆分为各包裹金额。
   - 不把包裹级实收回款作为应付返款计算输入。
   - 不因包裹级回款事实更新而自动追加已生成订单级金额。

### 5.5 去重与幂等

1. 订单级去重：
   - `validateUniqueBusinessOrderNos` 保证同任务内一个业务订单只处理一次。
   - 回款返款模式下，首个有效包裹只负责把订单加入候选集合；订单级金额在 `matchedRows` 循环中只生成一次。
2. 费项级去重：
   - 现有 `dedupeKey` 规则为 `COD_REFUND:{billNo}:{feeCode}:{sourceId}:{settlementRole}`。
   - 订单级手续费 `sourceId = 订单 id`，一单一条。
   - 包裹级手续费 `sourceId = 包裹费行 id`，一包裹一条。
   - 同尾程运单号跨仓库时，以 `business_order_no + warehouse_code + tail_way_bill_no` 定位包级事实，避免同单号不同仓库被合并。
3. 重跑：
   - `prepareRefundRetryBill` 已清理同账期失败残留的 `fee_detail`、汇总、汇率和包裹快照，再重建。
   - 新规则继续沿用：同账期重跑先清理再重建，不会在旧明细上追加订单级金额。
4. 后续包裹回款：
   - 订单已生成返款账单后，来源订单被 `e.bms_bill_no` 等标记占用，后续任务不会再次拉取同一订单。
   - 后续包裹的 `recovery_money` 更新只影响回款管理展示和包裹事实，不影响已生成账单。
5. 建议把触发包裹信息写入追溯快照：
   - 可在订单级主订单或应付返款 `fee_detail.source_extra_json` 中保存 `refundTriggerPackageId`、`refundTriggerWaybillNo`、`refundTriggerRecoveryMoney`、`refundTriggerTime`，用于审计“首个包裹触发”事实，不新增物理表。

### 5.6 账期与时间口径

已确认（Q-03、Q-09）：

1. 回款返款只认 `sale_order_header_extend.recovery_time`；`recovery_time` 为空则不进入本期归集，不回退签收时间、出库时间或包裹 `modify_time/create_time`。
2. 当前 `resolveRefundOrderTimeField` 在 RECEIVED 模式下应固定返回 `recovery_time`；若 `fee_source_dataset.received_time_column` 未配置或配置了其他字段，需按此确认口径处理，不能静默回退到 `signed_time`。
3. 包裹级导入手续费跟随所属订单进入本期返款账单，不按 `p.create_time` 单独开窗。
4. 返款直接扣减费用按本期回款订单关联采集；订单级/包级手续费跟随订单进入本期，附加费不按 `create_time` 开窗。

### 5.7 存量与生效边界

1. 新规则只用于上线后新发起的返款账单生成，以及按既有机制允许重新生成的未发出待审核账单。
2. `REFUND_RERUN_ALLOWED_STATUSES = {DRAFT, UNDER_REVIEW}`：只有起草中/待审核账单可重跑，已发出、待结清、已结清账单不自动作废、替换或回写。
3. 已生成账单不得因后续包裹回款或本规则上线而静默增加订单金额；差异通过重算、调账、冲正或后续账单承接。
4. Q-10 已确认：按新规以包裹回款事实为准，不保留旧订单头 `collection_price > 0` 兜底；历史数据如需重跑，也按新规判定。
5. 若最终需要新增 DDL（例如触发包裹快照列），必须同步完整 `CREATE TABLE` 到 `aidocs/technical-caliber/sql/ar_bill.sql`，禁止只写 `ALTER` 片段；本文默认不新增物理表。

## 8. 风险与验收

### 8.1 风险

1. 金额口径风险：`cod_price` 与 `collection_price` 当前混用，若未确认就改，可能影响签收返款历史结果。
2. 重复归集风险：包级手续费按包生成后，若同一包数据在重跑中未被清理，可能出现重复明细；必须依赖 `dedupeKey` 和重跑清理链路。
3. 漏单风险：订单头回款时间缺失时，包裹已回款但订单不进入账期。
4. 口径不一致风险：回款管理、生成层、导出层对“有效回款”和“包级手续费”语义不一致。
5. 配置冲突风险：`queryRefundFeeDefinitionByName` 按名称取费项，FEE0023 与 FEE0060 同名“代收货款手续费”，按名称解析可能歧义，实施时应用显式费项编码或挂靠对象过滤。

### 8.2 验收清单

1. 同一订单多个包裹，仅一个包裹有非空非零 `recovery_money`，回款返款生成时该订单进入账单，订单级应付返款计一次。
2. 同一订单其他包裹后续录入/更新实收回款，不新增订单级金额，包裹回款管理事实正常更新。
3. 生成层只判别包裹回款事实，不叠加签收/异常状态条件；异常签收理论上不会产生回款，但源数据无必然关系。
4. 订单级机算代收货款手续费命中直接扣减配置后按订单计一次。
5. 包裹级导入手续费按包裹 `receivable_collection_amount` 逐条归集；同一订单多个包裹产生多条包级明细。
6. 订单级与包级手续费并存时不去重，按各自挂靠层级同时归集。
7. 签收返款仍按既有正常签收条件触发，不要求先录入实收回款。
8. 只影响新生成和 `DRAFT / UNDER_REVIEW` 重跑；已发出、待结清、已结清账单不自动变化。
9. 生成 SQL、费项来源、币种、汇率、汇总、导出和回款管理口径保持一致。
10. 同尾程单号跨仓库/跨订单时，按 `business_order_no + warehouse_code + tail_way_bill_no` 定位，不产生重复归集。
