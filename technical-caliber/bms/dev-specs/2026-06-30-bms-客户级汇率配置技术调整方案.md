# 2026-06-30 BMS 客户级汇率配置技术调整方案

## 1. 文档目的

本文基于 `aidocs` 提交 `96d69ff35229e13720033ef8f1205ba55ec1cf7c`（“增加【客户级汇率配置】章节，账单生成之前的预置汇率”）和补充提交 `d2589ff7c49a3307f6b955f4638a75da88c21abb`（“补全【客户级汇率配置】章节原型概述和逻辑漏洞”），结合当前 `bms` 后端与 `admin_shell/src/views/billing/` 前端代码现状，整理客户级汇率配置的技术调整方案、实施计划和已确认口径。

本方案只讨论“账单生成前的默认汇率维护、命中、固化与展示”，不直接改造既有账单详情页的账单级汇率编辑流程，也不扩展到跨币种核销规则重写。

## 2. PRD 变更整理

### 2.1 提交涉及文档

本次提交修改了两个 PRD 文档：

1. `aidocs/product-caliber/bms/prd/财务系统.PRD.md`
2. `aidocs/product-caliber/bms/prd/derivant/财务系统验收标准.md`

核心变化是将原第 11 章“金额汇兑”后移为第 12 章，并新增第 11 章“客户级汇率配置”。补充提交将“银行汇率表”统一调整为更抽象的“基准汇率表”，补充了页面原型、汇率来源优先级、通用/专属客户规则优先级等内容；其中“账单汇率日期”已按最新确认从本方案实现范围移除。验收标准同步新增 AC-11-01 至 AC-11-06。

### 2.2 新增业务要求

1. 客户级汇率配置用于在账单生成前确定默认汇率，是账单汇率快照的前置配置。
2. 汇率来源分两层：
   - 基准汇率表：由财务手动导入，或由系统按指定来源自动抓取。
   - 客户特调汇率规则：按客户、账单类型、货币对、生效周期和可选基准汇率来源维护调整规则。
3. 客户特调汇率规则支持三种调整方式：
   - 百分比缩放：`账单默认汇率 = 基准汇率 * (1 + 调整比例)`
   - 固定汇率差：`账单默认汇率 = 基准汇率 + 固定差值`
   - 固定汇率值：直接使用固定值，不依赖基准汇率。
4. 账单生成命中顺序：
   - 指定账单类型的客户特调规则
   - 不区分账单类型的通用客户特调规则
   - 已确认生效的基准汇率
   - 缺失则阻断生成；同币种固定为 `1`
5. 生成成功后必须把命中的客户特调规则、基准汇率、汇率来源、调整方式、调整参数和默认汇率固化到账单汇率快照。
6. 已审核、待结清、已结清账单不随后续基准汇率表或客户特调汇率规则变化自动回写。
7. 页面需要支持基准汇率导入/抓取、客户特调汇率添加/编辑、规则变更历史；基准汇率无需支持货币对预览。

### 2.3 补充提交新增约束

1. 页面原型入口为 `客户账单 > 汇率配置`，原型链接：`http://localhost:10000/#id=u23631&p=客户级汇率配置&g=1`。
2. 页面原型分为顶部操作区、基准汇率表区、客户特调汇率区；顶部操作包含 `导入` 和 `抓取`。
3. 基准汇率表区展示 `货币对`、`汇率`，基准汇率中的货币对决定客户特调汇率区可维护的货币对列。
4. 客户特调汇率区展示 `客户编号`、`客户名称`、`所属店铺`、各货币对特调汇率列和 `操作`；`所属店铺`只辅助识别客户，不改变规则归属。
5. 系统必须配置默认汇率来源，默认汇率来源由财务维护，维护方式包括手动导入或系统抓取；客户特调规则可指定汇率来源，指定来源优先，未指定时使用默认来源。
6. 同一货币对存在多个基准汇率来源时，系统不得随机选择，也不得在指定/默认来源缺失时自动切换到其它来源。
7. 固定汇率值规则不要求存在对应基准汇率；百分比缩放和固定汇率差必须存在对应基准汇率。
8. 同一客户、同一货币对、同一生效周期内，指定账单类型的专属规则优先于不区分账单类型的通用规则。
9. 除固定汇率值外，客户特调规则与基准汇率表的货币对方向必须一致；允许系统按倒数反向推导，并在快照中记录推导来源。
10. 账单生成失败时，错误信息必须指出缺失的客户、货币对、账单类型和汇率来源。
11. 基准汇率货币对必须是“外币 -> 财务本位币”。
12. 店铺汇率不再作为账单生成实时兜底来源；当前系统抓取只抓取店铺汇率并沉淀为基准汇率，以后再扩展外部数据源抓取。

## 3. 现有代码盘点

### 3.1 已有能力

当前代码已经具备“账单生成后锁定汇率并重算”的基础能力：

1. `bill_exchange_rate` 表已经用于保存账单级汇率快照，包含 `bill_type`、`rate_date`、`rate_source`、`source_type`、`edit_reason` 等字段。
2. 应收账单和返款账单详情页已有汇率编辑入口：
   - `admin_shell/src/views/billing/receivableBill/index.vue`
   - `admin_shell/src/views/billing/refundBill/index.vue`
3. 前端已有保存汇率 API：
   - `/portal/bms/arBill/exchangeRate/save`
   - `/portal/bms/refundBill/exchangeRate/save`
4. 后端已有账单汇率保存、重算、快照查询链路：
   - `ArBillServiceImpl.saveExchangeRates(...)`
   - `RefundBillServiceImpl.saveExchangeRates(...)`
   - `ArBillMapper.upsertBillExchangeRate(...)`
   - `RefundBillMapper.upsertBillExchangeRate(...)`
5. 账单详情展示已经能区分汇率命中级别和来源，现有来源包括 `FEE_DETAIL`、`MANUAL`、`SHOP`、`DIRECT`。
6. 币种模板已独立存在，前端入口为 `客户账单 > BMS币种模板`，代码集中在 `admin_shell/src/views/billing/feeItem/index.vue`。

### 3.2 关键差距

当前实现与新增 PRD 仍有明显差距：

1. 当前默认汇率主要来自店铺汇率接口，代码命名为 `loadShopRateMap(...)`，命中级别为 `SHOP`，不符合“基准汇率表 + 客户特调规则”的新来源模型。
2. `BmsConstants` 没有 `BASE_RATE`、`CUSTOMER_FIXED`、`CUSTOMER_ADJUST` 等汇率来源或命中级别常量。
3. `bill_exchange_rate` 只能保存账单侧最终快照，缺少“命中的基准汇率记录 ID、客户特调规则 ID、汇率来源、调整方式、调整值、基础基准汇率、反向推导来源”等可追溯字段。
4. 当前没有基准汇率表、客户特调汇率规则表、导入批次表、规则操作日志表和默认汇率来源配置。
5. `BillExchangeRateController` 为空，尚未形成“账单生成前汇率配置中心”的 API。
6. `ArBillServiceImpl.resolveRateDecision(...)` 和 `RefundBillServiceImpl.resolveRateDecision(...)` 中的命中顺序是：费项级、账单级、店铺汇率、同币种；缺少客户特调规则和基准汇率。
7. 前端 `admin_shell/src/router/billing.js` 目前没有 `客户账单 > 汇率配置` 路由。
8. `admin_shell/src/api/billing.js` 目前只有账单详情汇率保存 API，没有基准汇率导入/抓取、客户特调规则分页、预览和操作日志 API。
9. PRD 要求“批量导入逐行反馈失败原因”，当前 billing 目录下没有可复用的基准汇率导入页面。
10. 基准汇率“系统抓取”涉及外部汇率来源，目前没有配置来源、调度任务或凭据管理实现。

## 4. 技术调整方案

### 4.1 总体边界

本次建议拆成两个阶段：

1. P0 实现手动维护闭环：基准汇率表导入/确认、客户特调规则维护、默认汇率预览、账单生成命中并固化。
2. P1 再实现系统自动抓取基准汇率表：汇率来源配置、定时抓取、异常告警和人工确认。

原因是 PRD 同时提到“导入”和“抓取”，但当前代码没有外部汇率来源基础设施。先做手动导入可以满足财务在账单生成前预置默认汇率的主目标，并降低外部依赖风险。

### 4.2 数据库设计

新增四类业务表和一类默认来源配置，后续需要同步到 `aidocs/technical-caliber/sql/ar_bill.sql` 的完整结构归档。

#### 4.2.1 基准汇率表 `base_exchange_rate`

建议字段：

| 字段 | 说明 |
| :--- | :--- |
| `id` | 主键 |
| `sc_id` / `shop_id` / `user_id` | 数据隔离字段 |
| `rate_source_code` / `rate_source_name` | 汇率来源 |
| `rate_date` | 汇率日期 |
| `source_currency` | 基准币种 |
| `target_currency` | 目标币种，必须为财务本位币 |
| `conversion_direction` | 换算方向：`MUL` / `DIV` |
| `exchange_rate` | 基准汇率，`DECIMAL(18,8)` |
| `fetch_type` | 获取方式：`MANUAL_IMPORT` / `SYSTEM_FETCH` |
| `status` | `PENDING` / `EFFECTIVE` / `INVALID` |
| `import_batch_no` | 导入批次号 |
| `confirmed_by` / `confirmed_at` | 确认人和确认时间 |
| `created_by` / `created_at` / `updated_by` / `updated_at` | 审计字段 |
| `is_deleted` | 逻辑删除 |

索引建议：

1. `uk_base_rate_effective`：`sc_id, rate_source_code, rate_date, source_currency, target_currency, conversion_direction, is_deleted`
2. `idx_base_rate_lookup`：`sc_id, status, rate_source_code, rate_date, source_currency, target_currency`
3. `idx_base_rate_batch`：`import_batch_no`

基准汇率约束：

1. 货币对必须是“外币 -> 财务本位币”，不维护任意两外币之间的基准汇率。
2. 基准汇率允许财务编辑；编辑后重算所有客户特调汇率的展示结果和预计算结果，但不触发任何账单重跑。
3. 当前系统抓取只抓取店铺汇率，并将抓取结果沉淀为基准汇率；外部数据源抓取后续再扩展。

#### 4.2.2 基准汇率导入批次表 `base_exchange_rate_import_batch`

用于承接批量导入和逐行反馈。

建议字段包括批次号、文件名、总行数、成功行数、失败行数、导入状态、导入人、导入时间和失败摘要。

#### 4.2.3 客户特调汇率规则表 `customer_exchange_rate_rule`

建议字段：

| 字段 | 说明 |
| :--- | :--- |
| `id` | 主键 |
| `sc_id` / `shop_id` / `user_id` | 数据隔离字段 |
| `member_code` / `member_name` | 客户 |
| `bill_type` | `MEMBER_AR` / `COD_REFUND` / `ALL` |
| `source_currency` / `target_currency` | 货币对 |
| `conversion_direction` | 换算方向 |
| `effective_start_date` / `effective_end_date` | 生效周期 |
| `rate_source_code` | 指定基准汇率来源，为空时使用系统默认来源 |
| `adjust_type` | `PERCENT` / `DELTA` / `FIXED` |
| `adjust_value` | 调整值 |
| `fixed_exchange_rate` | 固定汇率值 |
| `status` | 启用/停用 |
| `change_reason` | 最近一次变更原因 |
| `created_by` / `created_at` / `updated_by` / `updated_at` | 审计字段 |
| `is_deleted` | 逻辑删除 |

约束建议：

1. 服务层校验同一客户、账单类型、货币对、生效周期内不能存在互相重叠的启用规则。
2. 指定账单类型规则优先于 `ALL` 通用规则；保存时允许二者共存，但命中时必须稳定按专属优先。
3. `PERCENT` 和 `DELTA` 必须能按规则指定来源或默认来源命中已确认生效的基准汇率。
4. `FIXED` 必须填写大于 0 的固定汇率，且不强制要求存在对应基准汇率。
5. 百分比缩放输入值按百分数理解，录入 `2` 表示 `2%`。
6. 固定汇率差不允许为负数。
7. 客户特调规则允许停用或修改，不做版本控制。
8. 同币种不允许维护客户特调规则，统一由系统固定为 `1`。

#### 4.2.4 客户特调汇率规则日志表 `customer_exchange_rate_rule_log`

记录新增、修改、启用、停用、确认等操作，保存前值、后值、操作原因、操作人、操作时间。

#### 4.2.5 默认汇率来源配置

建议优先以配置表或现有系统参数承接默认汇率来源：

1. 配置项至少包含 `sc_id`、`rate_source_code`、`rate_source_name`、`enabled`、`updated_by`、`updated_at`。
2. 同一供应链范围只允许一个启用的默认汇率来源。
3. 默认汇率来源由财务维护，设置默认来源必须记录操作日志，避免账单生成时命中来源不可追溯。

### 4.3 账单汇率快照扩展

为满足“生成后固化命中的客户特调规则、基准汇率、汇率来源、调整方式、调整参数和默认汇率”，建议扩展 `bill_exchange_rate`：

| 字段 | 说明 |
| :--- | :--- |
| `base_rate_id` | 命中的基准汇率记录 ID，固定汇率值时可为空 |
| `customer_rate_rule_id` | 命中的客户特调规则 ID |
| `base_rate_source_code` | 命中的基准汇率来源 |
| `base_exchange_rate` | 基准汇率，固定汇率值时可为空 |
| `adjust_type` | 命中规则的调整方式 |
| `adjust_value` | 命中规则的调整值 |
| `default_exchange_rate` | 账单生成前计算出的默认汇率，可与最终锁定汇率区分 |
| `reverse_derived` | 是否按反向货币对推导 |
| `derived_rate_pair` | 反向推导时记录原始命中货币对 |

现有字段继续使用：

1. `exchange_rate`：最终锁定汇率。
2. `rate_date`：汇率日期。
3. `rate_source`：建议新增 `CUSTOMER_FIXED`、`CUSTOMER_ADJUST`、`BASE_RATE`、`MANUAL`、`FEE_DETAIL`、`DIRECT`。
4. `source_type`：系统命中为 `SYSTEM`，账单详情页人工修改为 `MANUAL`。

### 4.4 后端模块设计

#### 4.4.1 Model

新增实体和 DTO：

1. `BaseExchangeRate`
2. `BaseExchangeRateImportBatch`
3. `CustomerExchangeRateRule`
4. `CustomerExchangeRateRuleLog`
5. `BaseExchangeRateQueryReqDTO`
6. `BaseExchangeRateImportPreviewRespDTO`
7. `BaseExchangeRateConfirmReqDTO`
8. `CustomerExchangeRateRuleQueryReqDTO`
9. `CustomerExchangeRateRuleSaveReqDTO`
10. `CustomerExchangeRatePreviewReqDTO`
11. `CustomerExchangeRatePreviewRespDTO`

所有实体和 DTO 字段按项目规范补齐 JavaDoc，不使用 `Map` 作为 Controller 或 Service 入参/返回值。

#### 4.4.2 DAO

新增 Mapper 与 XML：

1. `BaseExchangeRateMapper`
2. `BaseExchangeRateImportBatchMapper`
3. `CustomerExchangeRateRuleMapper`
4. `CustomerExchangeRateRuleLogMapper`

SQL 规则：

1. 动态条件写在 XML 中。
2. WHERE 条件不对列套日期函数，生效周期使用 `effective_start_date <= #{billingDate}` 和 `effective_end_date >= #{billingDate}`。
3. 重叠周期校验使用范围交叉条件。
4. 金额和汇率用 `BigDecimal` / `DECIMAL(18,8)`，账单金额仍保持既有 `DECIMAL(18,4)` 口径。

#### 4.4.3 Service

新增 `CustomerExchangeRateService`，负责：

1. 基准汇率导入预览与确认。
2. 基准汇率分页查询和状态变更。
3. 客户特调规则保存、启用、停用和分页查询。
4. 默认汇率预览。
5. 账单生成时批量解析货币对默认汇率。
6. 基准汇率编辑后，重算所有客户特调汇率展示结果和预计算结果，但不触发账单重跑。

建议提供内部方法：

```java
CustomerExchangeRateDecision resolveDefaultRate(CustomerExchangeRateResolveReqDTO reqDTO);
```

命中顺序：

1. 同币种：返回 `DIRECT`，汇率 `1`。
2. 费项级已有汇率：仍优先保留 `FEE_DETAIL`。
3. 已存在账单级快照：优先用于重算当前账单。
4. 指定账单类型客户特调固定汇率值：`CUSTOMER_FIXED`。
5. 通用客户特调固定汇率值：`CUSTOMER_FIXED`。
6. 指定账单类型客户特调百分比缩放/固定汇率差：`CUSTOMER_ADJUST`，基于指定来源或默认来源的基准汇率计算。
7. 通用客户特调百分比缩放/固定汇率差：`CUSTOMER_ADJUST`，基于指定来源或默认来源的基准汇率计算。
8. 基准汇率：`BASE_RATE`。
9. 缺失异币种汇率：抛出业务异常，阻断账单生成，并返回客户、货币对、账单类型和汇率来源。

#### 4.4.4 账单生成接入

调整位置：

1. `ArBillServiceImpl.resolveRateDecision(...)`
2. `RefundBillServiceImpl.resolveRateDecision(...)`
3. `persistShopRateSnapshotIfNeeded(...)` 需要泛化为 `persistDefaultRateSnapshotIfNeeded(...)`

调整策略：

1. 保留费项级和账单级优先级，避免破坏账单详情页人工调整后的重算口径。
2. 移除现有 `loadShopRateMap(...)` 在账单生成时的兜底职责；店铺汇率只通过抓取流程进入基准汇率表，不再运行时直接兜底。
3. 账单生成前根据客户、账单类型和货币对批量命中默认汇率，避免每条费项重复查库。
4. 命中结果写入 `bill_exchange_rate`，并将 `rate_source`、`source_type`、规则 ID、基准汇率 ID、基准汇率来源一并保存。
5. 继续在 `fee_detail` 写入 `exchange_rate_to_bill`、`exchange_rate_level_to_bill`、`exchange_rate_to_fin`、`exchange_rate_level_to_fin`，并新增来源字段时同步回写来源。
6. 异币种缺汇率时，账单生成任务失败，任务详情展示缺失客户、货币对、账单类型和汇率来源，不允许按 `1` 强制生成。
7. 允许按倒数反向推导汇率，但必须在账单汇率快照中记录原始货币对、推导方向和推导后汇率。

#### 4.6.3 页面

新增目录：

```text
admin_shell/src/views/billing/exchangeRateConfig/index.vue
```

页面建议按原型收敛为三个主区，并可用抽屉/弹窗承接导入预览、编辑和历史：

1. 顶部操作区：`导入` 基准汇率表、`抓取` 基准汇率表，显示当前默认汇率来源。
2. 基准汇率表区：展示 `货币对`、`汇率`、`汇率来源`、`汇率日期`、状态，可查看导入/抓取结果和失败原因。
3. 客户特调汇率区：展示 `客户编号`、`客户名称`、`所属店铺`、各货币对特调汇率列、`操作`；支持 `添加` 和 `编辑`。
4. 客户特调汇率明细建议使用抽屉展示，承接多货币对明细、调整方式、调整参数、规则状态和操作历史。
5. 变更历史可作为页面内弹窗或抽屉，不必强制做独立页签。

交互要求：

1. 导入基准汇率表必须逐行展示成功/失败原因。
2. 修改、启用、停用客户特调规则必须二次确认并填写操作原因。
3. 固定汇率值、百分比、固定差值要按调整方式动态校验。
4. 货币对方向必须清晰展示为 `sourceCurrency -> targetCurrency`，避免无方向汇率。
5. 客户特调汇率区的货币对列来自已维护的基准汇率货币对。
6. `所属店铺`仅用于辅助识别，不作为规则唯一归属维度。
7. 基准汇率货币对固定为“外币 -> 财务本位币”，页面不提供任意货币对预览。
8. 规则冲突和命中优先级由服务端最终校验，前端只做友好提示。

### 4.7 与现有账单详情页的关系

1. 客户级汇率配置只影响新生成账单和仍允许重算的当前账单。
2. `receivableBill/index.vue` 与 `refundBill/index.vue` 的“编辑汇率”继续作为账单级覆盖入口。
3. 账单详情页展示需要新增来源文案：
   - `CUSTOMER_FIXED`：客户固定汇率
   - `CUSTOMER_ADJUST`：客户调整汇率
   - `BASE_RATE`：基准汇率
4. 当财务在账单详情页手工修改汇率后，`source_type` 应变为 `MANUAL`，不得回写客户特调规则。

## 7. 已确认口径与遗留说明

### 7.1 已确认口径

1. 默认汇率来源由财务维护，支持手动导入或通过系统抓取。
2. 本方案不设计“账单汇率日期”字段，也不围绕该字段做命中规则。
3. 允许系统按倒数进行反向汇率推导，并在快照中记录推导来源。
4. 百分比缩放录入 `2` 表示 `2%`。
5. 固定汇率差不允许出现负数。
6. 基准汇率允许编辑；编辑后重算所有客户特调汇率的展示结果和预计算结果，但不会导致账单重跑。
7. 客户特调规则允许停用或修改，客户特调汇率不做版本控制。
8. 基准汇率无需支持货币对预览，且基准汇率货币对必须是“外币 -> 财务本位币”。
9. 店铺汇率不再兜底，由客户级汇率兜底。
10. 目前系统抓取只抓取店铺汇率，以后再抓取外部数据源。
11. 客户特调汇率区货币对较多时，使用明细抽屉承接。

### 7.2 遗留说明

后端没有权限码概念。本方案不要求后端新增权限码或按权限码鉴权；页面可见性、菜单标识、按钮控制若仍需要 `meta.code`，仅在 `admin_shell` 前端路由或菜单配置侧处理。当前方案中的 `bms_customer_exchange_rate` 只是前端建议值，落地时可按既有前端菜单配置调整。

## 8. 推荐验收用例

1. 导入一批基准汇率，其中包含币种缺失、汇率为 0、重复货币对，页面逐行显示失败原因。
2. 确认一条基准汇率生效后，未配置客户特调规则时，账单生成使用默认来源下的基准汇率并固化为 `BASE_RATE` 来源。
3. 配置客户固定汇率值后，账单生成优先命中固定值并固化为 `CUSTOMER_FIXED` 来源，且不要求存在对应基准汇率。
4. 配置客户百分比缩放后，账单生成按规则指定来源或默认来源下的基准汇率计算默认汇率，并固化基础汇率、调整方式和调整值。
5. 同一客户同账单类型同货币对生效周期重叠时，保存规则失败。
6. 同一客户同时存在 `MEMBER_AR` 专属规则和 `ALL` 通用规则时，应收账单优先命中 `MEMBER_AR` 专属规则。
7. 指定汇率来源缺少对应货币对时，账单生成失败，不自动切换到其它来源。
8. 缺少异币种汇率时，账单生成任务失败并展示客户、货币对、账单类型和汇率来源。
9. 修改客户特调规则后，历史已审核账单详情仍展示原快照汇率。
10. 在账单详情页人工编辑汇率后，只影响当前账单，不回写客户特调规则。
11. 基准汇率编辑后，客户特调汇率展示结果刷新，但不创建账单生成任务，也不重跑历史账单。
12. 固定汇率差录入负数时，保存失败并提示固定汇率差不能为负数。
13. 基准汇率只允许维护“外币 -> 财务本位币”货币对。
14. 系统抓取店铺汇率后，结果进入基准汇率确认流程；账单生成不再直接读取店铺汇率兜底。
