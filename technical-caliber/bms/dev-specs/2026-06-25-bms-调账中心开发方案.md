## 1. 文档目的

本文基于 `aidocs/product-caliber/bms/prd/财务系统.PRD.md` 第 14 章【调账中心】制定技术开发方案，并结合当前仓库中的已有实现，明确：

### 2.2 PRD 核心要求摘要

调账中心的产品目标不是“账单详情里的一个 Tab”，而是财务处理冲正差异的统一入口。按新版 PRD，必须满足以下要求：

1. 【本次更新】统一承接账单录入和批量导入的冲正记录，覆盖应收账单调账和返款账单调账两类场景。
2. 【本次更新】调账记录自身有独立审核流，且审核状态不同于账单状态。
3. 【本次更新】原型字段以“费项挂靠对象、冲正前后币种、归属账单、登记人”为主，不再以旧版“调账对象 / 调账类型”作为主展示口径。
4. 【本次更新】`待审核` 支持修改、移除、审核；`审核驳回` 支持修改并重新提交；`审核通过` 只读。
5. 调账记录审核前必须确认归属账单，支持系统默认归属和财务人工改派。
6. 调账审核通过后才允许影响账单金额。
7. 调账不能回写源数据、不能触发源数据重采、不能改变 `BMS检阅标记`。
8. 批量移除、批量审核只能作用于待审核记录。
9. 【本次更新】账单中只要存在未移除调账记录，必须在调账中心全部审核通过后，整份账单才允许复核通过。

## 3. 现有实现盘点

### 3.1 已有数据库表

当前 `aidocs/technical-caliber/sql/ar_bill.sql` 中与调账中心相关的表主要有：

1. `fee_adjustment_order`
   - 承载调账单头。
   - 已包含 `adjustment_type`、`adjustment_period_type`、`source_bill_no`、`target_bill_no`、`adjustment_status`、`rebuild_flag` 等字段。
   - 更适合账单级、本期/往期账单冲正记录。

2. `fee_adjustment_record`
   - 承载费用级冲正记录。
   - 已包含 `fee_id`、`trigger_bill_id`、两级汇率、三套金额、凭证、`approval_status`。
   - 更贴近 PRD 第 14 章“调账中心”的最小业务实体。

3. `fee_detail`
   - 作为原始费用快照来源。
   - 已包含 `fee_status`、`manual_flag`、`original_fee_id`、`voucher_url`、`remark`。

4. `ar_bill`
   - 当前账单主表，承接调账结果的落账对象。

### 3.2 已有后端能力

当前仓库中的调账实现已经分成两条线：

1. 账单侧调账能力
   - BMS：`bms/biz/.../ArBillServiceImpl.adjustment()`
   - BMS：`bms/biz/.../ArBillServiceImpl.rebuildAdjustment()`
   - 主要面向账单详情内的“红冲调账 / 选中重整”
   - 审核口径仍偏“直接生效”

2. 调账中心能力雏形
   - BMS：`bms/biz/.../FeeAdjustmentRecordServiceImpl`
   - BMS：`bms/web/.../FeeAdjustmentRecordController`
   - Client：`bms/client/.../FeeAdjustmentRecordRemoteService`
   - Platform：admin：`platform-admin/.../BmsFeeAdjustmentRecordController`
   - Admin Shell：`admin_shell/src/views/billing/feeAdjustmentCenter/index.vue`
   - 已支持：
     - 分页查询
     - 修改
     - 删除
     - 审核通过 / 审核驳回
     - 审核通过后将结果落入 `fee_adjustment_order`
     - 审核通过后回写 `ar_bill` 与 `fee_detail`

### 3.3 已有前端能力

## 4. 当前实现与 PRD 的差距分析

### 4.1 已满足项

以下能力当前已经具备基础版本：

1. 有独立调账中心页面，而不是完全附属于账单详情。
2. 调账记录有独立审核状态：`PENDING / APPROVED / REJECTED`。
3. 待审核记录支持修改、删除、审核。
4. 审核通过后记录进入只读态。
5. 审核通过后才影响账单金额。
6. 审核通过后不回写源数据，只回写账单侧结果。

### 4.2 未满足项

按 PRD 第 14 章核对，当前仍有以下缺口：

1. 【本次更新】返款账单链路已完成基础落账分流，但仍未形成完整闭环。
   - 当前 `FeeAdjustmentRecordServiceImpl` 已支持返款账单调账在审核通过后回写返款账单的应返 / 未返金额口径。
   - 返款账单详情回显、导入链路、自动归属、账单侧统一发起等外围流程仍未补齐。

2. 自动归属能力尚未实现。
   - 还未按“同客户、同账期、优先待审核、再起草、再按财务本位币汇总金额最高、相同则账单号升序”的规则生成默认归属。

3. 缺少批量导入链路。
   - 当前仅有页面内维护能力，没有导入模板、预校验、确认导入，也没有导入后自动归属任务。

4. 【本次更新】账单复核前拦截已完成基础后端落地，详情页也已补充基础前端提示，但仍未达到最终闭环。
   - 当前应收账单、返款账单的复核入口已阻断“存在未移除调账记录但未全部审核通过”的场景。
   - 本次已在账单详情页补充阻断提示与复核按钮禁用态。
   - 本次已补充“从账单详情快捷跳转到调账中心筛选结果”和“返款账单关联调账记录列表”。
   - 后续仍建议补充分页能力、快捷审批入口和更完整的双向回跳。

5. 缺少“账单侧发起统一进入调账中心”的收口改造。
   - 当前账单侧 `ArBillServiceImpl.adjustment()` 仍然保留直接生效路径，不符合“账单侧发起、调账中心审核”的最终口径。

6. 【本次更新】页面字段虽然已开始向新版原型对齐，但导入域、返款场景字段和账单侧结果回显仍未完整打通。

7. 【本次更新】自动归属悬空记录的运营闭环仍缺失。
   - 目前只有“审核前必须确认归属账单”的基础校验，没有“悬空原因识别、候选账单推荐、批量改派”的完整操作面。

## 5. 技术方案总原则

### 5.1 核心判断

建议将 `fee_adjustment_record` 作为调账中心主实体，将 `fee_adjustment_order` 作为账单侧落账单头留痕表。

### 5.2 原因

1. `fee_adjustment_record` 已经具备费用级冲正所需的三套金额与两级汇率。
2. 原型图和 PRD 第 14 章更接近“记录中心 + 审核流”，而不是单纯账单单头。
3. `fee_adjustment_order` 更适合表达“审核通过后最终记入哪张账单”的承接结果。

### 5.3 最终分层定位

1. `fee_adjustment_record`
   - 调账中心主记录
   - 负责录入、编辑、审核、驳回、归属、导入留痕

2. `fee_adjustment_order`
   - 审核通过后的账单承接结果
   - 负责账单侧展示本期/往期调账

3. `ar_bill`
   - 最终金额承接主体

## 6. 推荐分阶段开发方案

## 6.1 阶段一：调账中心基础可用版

### 目标

在当前已实现雏形基础上，补齐最关键的 PRD 基础口径，使调账中心可以真正作为独立审核入口使用。

### 范围

1. 新增调账单号字段，替代页面直接展示 UUID。
2. 【本次更新】列表 / 筛选 / 编辑弹窗口径切到新版原型字段，重点围绕费项挂靠对象、冲正前后币种、归属账单、登记人展开。
3. 新增驳回原因字段。
4. 新增归属账单字段：
   - `assigned_bill_no`
   - `assigned_bill_id`
   - `assigned_bill_type`
   - `assignment_mode`
5. 审核前必须确认归属账单。
6. 页面增加：
   - 指定归属账单
   - 查看驳回原因
   - 审核弹窗
7. 【本次更新】提交人仅可修改 / 移除本人待审核记录，驳回记录支持修改并重新提交。

### 建议库表变更

建议对 `fee_adjustment_record` 补充以下字段：

| 字段 | 说明 |
| --- | --- |
| `adjustment_no` | 调账单号 |
| `adjustment_object` | 调账对象：BILL / ORDER / FEE |
| `object_no` | 对象编号 |
| `adjustment_type` | 调账类型：ADJUST / REVERSAL |
| `assigned_bill_id` | 归属账单ID |
| `assigned_bill_no` | 归属账单编号 |
| `assigned_bill_type` | 归属账单类型 |
| `assignment_mode` | 归属方式：AUTO / MANUAL |
| `rejected_reason` | 驳回原因 |
| `approved_by` | 审核人 |
| `approved_at` | 审核时间 |
| `updated_at` | 更新时间 |
| `updated_by` | 更新人 |

### 后端改造点

1. `FeeAdjustmentRecordMapper.xml`
   - 扩展分页查询字段
   - 【本次更新】支持按调账单号、费项挂靠对象、冲正前币种、归属账单、冲正后币种、登记人、审核人筛选

2. `FeeAdjustmentRecordServiceImpl`
   - 保存时生成 `adjustment_no`
   - 审核时校验归属账单
   - 驳回时记录原因
   - 【本次更新】编辑时校验提交人本人权限，驳回后重新提交时回到 `PENDING`

3. `platform-admin`
   - 增加“指定归属账单”透传接口

### 前端改造点

1. `admin_shell/src/views/billing/feeAdjustmentCenter/index.vue`
   - 【本次更新】筛选区补齐新版 PRD 字段
   - 【本次更新】列表列切换到新版 PRD 原型口径
   - 审核弹窗支持：
     - 归属账单确认
     - 驳回原因

## 6.2 阶段二：自动归属与批量导入版

### 目标

补齐 PRD 第 14.5 自动归属规则和“批量导入”能力。

### 范围

1. 调账记录导入模板。
2. 导入预校验。
3. 导入确认入库。
4. 默认归属计算。
5. 悬空记录管理。

### 自动归属规则实现建议

对“未指定归属账单”的记录，导入完成后执行候选账单选择：

1. 同客户。
2. 同账期。
3. 【本次更新】按账单类型分流：应收调账只匹配应收账单，返款调账只匹配返款账单。
4. 优先 `PENDING`。
5. 再选 `DRAFT`。
6. 在候选账单中按财务本位币汇总金额最大优先。
7. 若金额相同，按 `bill_no` 升序。
8. 若无候选账单，则记录保持悬空。

### 建议新增接口

1. `/portal/bms/feeAdjustmentRecord/importPreview`
2. `/portal/bms/feeAdjustmentRecord/importConfirm`
3. `/portal/bms/feeAdjustmentRecord/assignBill`
4. `/portal/bms/feeAdjustmentRecord/candidateBills`

### 导入数据校验规则

1. 必填：来源、去向、金额、币种、原因、凭证。
2. 费项必须存在。
3. 触发账单必须存在且属于当前 `scId`。
4. 金额不能为 0。
5. 已归档或已通过记录不允许重复导入覆盖，只能新增反向调账。

## 6.3 阶段三：账单侧发起统一接入版

### 目标

让账单详情页内的调账入口不再“直接生效”，而是统一改为向调账中心发起待审核记录。

### 范围

1. `ArBillServiceImpl.adjustment()`
   - 从“直接插 `fee_adjustment_order` + 直接改账单金额”
   - 改成“先生成待审核 `fee_adjustment_record`”

2. `ArBillServiceImpl.rebuildAdjustment()`
   - 重整结果不直接生效
   - 改成生成待审核调账记录或待审核调账单头

3. 账单详情页
   - 展示调账中心审核状态
   - 未审核通过前只展示“待处理差异”

### 收益

1. 符合 PRD“账单侧发起、调账中心审核”的职责边界。
2. 避免账单侧与调账中心出现两套冲正口径。

## 6.4 阶段四：返款账单联动版

### 目标

补齐 PRD 第 14.6 中“调账中心可作用于返款账单”的要求。

### 范围

1. 归属账单支持 `COD_REFUND`。
2. 审核通过后按账单类型分流：
   - `MEMBER_AR` 写应收账单口径
   - `COD_REFUND` 写返款账单口径
3. 返款账单详情页引用调账中心结果。

### 风险

返款账单虽然已补入基础调账回写链路，但返款账单详情展示、自动归属、导入任务和账单侧统一发起仍未打通，后续开发需要继续保持和返款账单状态机、金额口径、本位币快照一致。

7. 【本次更新】调账中心批量导入、导入预校验、确认导入链路已落地，支持导入批次号留痕。
8. 【本次更新】自动归属候选账单计算已落地，导入与账单侧新建调账都会走同一套默认归属规则。
9. 【本次更新】应收账单详情与返款账单详情已统一改为从费用明细发起调账中心待审核记录。
10. 【本次更新】返款账单详情“关联调账”分页化、更多筛选维度和快捷审批入口已落地。

### 本轮暂未完成

## 8. 状态机与权限建议

### 8.1 调账记录状态机

沿用 PRD：

- `PENDING`
- `APPROVED`
- `REJECTED`

补充实现规则：

1. `PENDING` 可编辑、可删除、可审核。
2. `APPROVED` 只读。
3. `REJECTED` 可编辑后重新提交为 `PENDING`。

### 8.2 权限建议

建议增加以下最小权限点：

1. `fee_adjustment_center_view`
2. `fee_adjustment_center_edit_self`
3. `fee_adjustment_center_delete_self`
4. `fee_adjustment_center_audit`
5. `fee_adjustment_center_assign_bill`
6. `fee_adjustment_center_import`

## 9. 关键技术风险

1. 当前 `fee_adjustment_record` 还没有完整“调账单号 + 归属账单 + 驳回原因”结构，继续在现状上堆页面会导致后续返工。
2. 当前账单侧 `ArBillServiceImpl.adjustment()` 仍是直接生效，如果不改，最终会长期存在“两套调账入口、两套审核口径”。
3. 自动归属依赖账期、客户、账单状态和本位币金额筛选，必须先统一账单查询口径。
4. 返款账单联动若提前硬接，会把应收与返款金额语义混在一起。

## 10. 推荐实施顺序

建议按以下顺序推进：

1. 阶段一：补齐主记录字段、归属确认、驳回原因。
2. 阶段二：补齐导入与自动归属。
3. 阶段三：把账单侧直接调账改造成“发起待审核记录”。
4. 阶段四：接入返款账单。

## 11. 验收标准

完成本方案后，调账中心至少应满足：

1. 【本次更新】可独立按调账单号、审核状态、客户名称、应收账单号、冲正费项、费项挂靠对象、业务订单号、尾程运单号、首程运单号、冲正前币种、归属账单、冲正后币种、登记人、审核人筛选。
2. 待审核记录支持修改、移除、审核。
3. 【本次更新】驳回记录保留驳回原因，并支持“修改并重新提交”后回到 `待审核`。
4. 审核通过前必须确认归属账单。
5. 审核通过后才影响账单金额。
6. 已通过记录不可直接修改，只能新增反向调账。
7. 批量审核、批量删除只能作用于待审核记录。
8. 【本次更新】若账单存在未移除调账记录，则这些记录必须先在调账中心全部审核通过，账单才允许复核通过；当前后端复核入口已执行该拦截。
9. 【本次更新】返款账单调账已支持基础落账分流与账单金额回写；但详情展示、导入归属、账单侧统一发起等外围链路仍属于后续阶段。

## 12. 结论

结论上，当前仓库已经完成了“调账中心基础雏形”，但距离 PRD 第 14 章的完整要求仍有明显差距。下一轮开发不建议继续堆前端展示，而应先把调账主记录模型补齐，再推进自动归属、导入链路和账单侧统一发起改造。这样才能让调账中心真正成为财务统一审核入口，而不是“费用级冲正列表 + 审核按钮”的半成品。
