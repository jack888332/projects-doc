#### 1.3.2 业务规则说明

| 场景名称 | 发送运单 |
| --- | --- |
| 范围/概述 | 发送运单。 |
| 主要参与者 | 客服、打单员 |
| 前置条件 | 客服、打单员在提单管理列表操作后触发 |
| 业务结果 | 正确的场景触发正确的处理。 |
| 主业务流程 | - 批量发送运单按钮：<br>当且仅当已有提单号的订单数据才可使用该功能，勾选对应数据，发送相应提单或者分单的数据到翌飞系统。<br>发送规则：<br>1）必须先发送主单（提单）的运单信息给翌飞（航班信息，起飞港，降落港，件数，重量等，相关文档要求详见：云盘-数字化项目-现状资料-数据项说明）。发送主单成功后，发送分单运单信息给翌飞。如果先发送分单没发主单，则返回翌飞报错信息。<br>2)一个主单（提单）/分单发送成功后2分钟内不可以重复提交,否则返回翌飞报错信息<br>场景：一个主单有两个分单，其中一个分单1已发送成功，则2分钟内勾选全选后批量发送返回翌飞报错信息，大于2分钟勾选全选后则再次发送所有主单和分单的数据给翌飞（含分单1）<br>1. 关于每票发送的DescriptionCode字段说明<br>在选择的批量数据中如果提单号有784（CZ）、043（KA）、131(JL)、235(TK)、999(CA)航司，则需要弹窗显示，其余航司DescriptionCode赋值为空<br>1.784、043、131、235<br>必填： 有DescriptionCode选项两种：EAP（默认选项）、EAW。<br>2.999航司<br>有DescriptionCode选项两种：EAP（默认选项）、EAW<br>中性提单（自填）选项：支持手工录入<br>3.其它航司<br>默认DescriptionCode选择为空。不需要显示在弹窗<br>1. 主单“发送状态”含义：<br>说明：异常中将有标识<br>1. 分单“发送总状态”含义：<br>说明：异常中将有标识<br>1. 提单号和分单号交互逻辑：<br>点击序号前的多选框，默认选中该提单号下的所有分单，单独勾选下拉框的某选项（提单号/分单号），则选中某单项 |
