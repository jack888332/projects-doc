# PRD｜BMS 集运计费与账单管理

## 文档信息

1. 产品线：BMS
2. 模块：集运计费 / 账单管理
3. 版本：V1.0
4. 文档类型：PRD（产品需求文档）
5. 关联设计：[bms-consolidation-billing-design.md](./bms-consolidation-billing-design.md)

## 1. 产品背景

当前集运业务在账单配置、费项归集、调账留痕、收款分摊、通知客户等环节存在分散处理问题。需要建设统一的 BMS 账单域能力，形成可配置、可审核、可追溯、可运营的结算闭环。

## 2. 目标与成功指标

### 2.1 业务目标

1. 支持按周期与结算节点自动出账。
2. 支持费项自动拉取（含 DB 源配置化读表）与人工录入并存。
3. 支持调账、红冲、导入调整且全链路留痕。
4. 支持单账单部分收款与多账单合并收款。
5. 支持账单邮件通知客户（客户来自 `platform_crm.customer`）。
6. 支持同一账单内多费项按不同币种结算。

### 2.2 指标（建议）

1. 自动出账成功率 >= 99.5%。
2. 自动费项拉取成功率 >= 99.0%。
3. 收款分摊正确率 100%（账单未收金额不出现负值）。
4. 账单通知送达成功率 >= 98.0%（失败可重试）。
5. 调账/红冲/导入操作审计覆盖率 100%。

## 3. 用户与角色

1. 财务专员：账单审核、出账、收款分摊、通知重发。
2. 结算运营：费项配置、数据源配置、调账导入处理。
3. 财务主管：调账/红冲审核、账单关闭审批。
4. 管理员：菜单权限、参数配置、异常排查。

## 4. 范围与边界

### 4.1 本期范围

1. 账单配置、账单生成、审核、生效、收款、调账、红冲。
2. 费项采集：API/DB/文件适配器 + 手工录入。
3. 客户通知：账单邮件发送、重试、日志查询。
4. 操作日志、导入日志、通知日志、任务日志。
5. 多币种账单汇总与同币种收款分摊。

### 4.2 非本期范围

1. 第三方支付自动对账与自动核销。
2. 财务总账凭证自动生成。
3. 多币种自动换汇与跨币种抵扣（可后续扩展）。

1. 账单配置（周期、结算节点、生效范围）。

3. 账单主单/明细。

### 6.1 对象模型（客户可配置默认/非默认账单）

目标：同一客户可配置一个默认账单配置，以及多个非默认账单配置。例如某些目的国或仓库需要单独出账，就建立非默认配置。

默认配置与非默认配置的关系不是包含关系，而是互斥分桶关系：

1. 命中非默认配置的订单，只进入该非默认配置生成的账单。
2. 默认配置只接收没有命中任何非默认配置的剩余订单。
3. 同一订单在同一账期内只能被一个账单配置命中，不能同时进入默认账单和分支账单。
4. 非默认配置优先级高于默认配置。

对象关系简图：

`Customer(客户)` `1` -> `N` `CustomerBillProfile(客户账单配置)`  
`CustomerBillProfile` `1` -> `N` `Bill(账单)`  
`Bill` `1` -> `N` `BillCurrencySummary(结算币种汇总)`
`Bill` `1` -> `N` `BillItem(账单明细)`  
`Bill` `1` -> `N` `Adjustment/Writeoff(调账/红冲)`  
`Bill` `N` <-> `N` `Receipt(收款)`（通过 `ReceiptAllocation` 关联）

建议对象定义：

1. `Customer`：来源 `platform_crm.customer`，主键 `customer_id`。
2. `CustomerBillProfile`：客户账单配置对象，建议唯一键：`customer_id + destination_country + cycle_type + settlement_node + enabled`。
3. `Bill`：由某个 `CustomerBillProfile` 在某账期生成，持有 `profile_id`。
4. `BillItem`：明细包含 `destination_country`、`fee_item_code`、`settle_currency`、`settle_amount`。
5. `BillCurrencySummary`：按 `bill_id + currency` 汇总应收/已收/未收。

按目的国分账示例：

1. 客户 `C10001` 配置了 3 个 `CustomerBillProfile`：
`P-DEFAULT`（默认配置，半月结，签收结算）  
`P-US`（目的国=US，半月结，签收结算）  
`P-DE`（目的国=DE，半月结，签收结算）
2. 在 `2026-05-01 ~ 2026-05-15` 账期内，系统会生成三张互斥账单：
`B-C10001-US-20260515`（只包含 US 目的国订单费项）  
`B-C10001-DE-20260515`（只包含 DE 目的国订单费项）  
`B-C10001-DEFAULT-20260515`（只包含未命中 US/DE 的剩余订单费项）
3. 三张账单独立审核、独立调账/红冲、独立收款分摊。
4. 默认账单不会重复包含 US/DE 订单。

### 6.2 费项来源数据源对象

BMS 需要管理供 `fee_index` 使用的数据源连接信息，用于自动拉取订单和费用数据。

建议对象：

1. `FeeSourceDatasource`：数据源配置，保存数据源编码、URL、账号、加密密码、默认库名、连接池和超时参数。
2. `FeeSourceRule`：费项来源规则，保存来源表、字段映射、过滤条件，并通过 `datasource_code` 引用 `FeeSourceDatasource`。
3. `FeeIndex`：费项索引，只定义费项身份和业务含义，不直接保存数据库 URL/账号/密码。

`FeeSourceDatasource` 字段要求：

1. `datasource_code`：数据源编码，例如 `OFP_DB`，全局唯一。
2. `datasource_name`：数据源名称。
3. `source_system`：来源系统，例如 `OFP`。
4. `env_code`：环境编码，例如 `DEV/TEST/UAT/PROD`。
5. `db_type`：数据库类型，V1 支持 `MYSQL`。
6. `jdbc_url`：连接 URL。
7. `username`：连接账号。
8. `password_cipher`：加密后的密码。
9. `password_mask`：脱敏展示密码。
10. `default_database/default_schema`：默认库或 schema。
11. `connect_timeout_seconds/query_timeout_seconds/max_rows_per_query`：连接、查询和单次拉取限制。
12. `last_test_status/last_test_at/last_test_message`：最近一次连接测试结果。
13. `enabled/is_deleted`：启用和逻辑删除标记。

对象关系：

```text
FeeSourceDatasource.datasource_code
  -> FeeSourceRule.datasource_code
  -> BusinessTypeFeeIndex.fee_source_rule_id
  -> FeeIndex
```

安全要求：

1. 数据源密码必须加密存储。
2. 页面和日志只能展示脱敏信息。
3. 运行时只能执行白名单内的 `SELECT` 查询。
4. 拉取任务必须记录数据源、表名、行数、耗时和失败原因。
5. `fee_index` 不保存 URL、账号、密码；敏感连接信息只能存在于 `FeeSourceDatasource`。

## 7. 状态机设计

### 7.1 账单状态机

状态集合：

1. `DRAFT`
2. `PENDING_REVIEW`
3. `ISSUED`
4. `PARTIALLY_PAID`
5. `PAID`
6. `CLOSED`

状态机图：

`[开始]`
-> `DRAFT`（生成草稿）
-> `PENDING_REVIEW`（提交审核）
-> `ISSUED`（审核通过/直接出账）
-> `PARTIALLY_PAID`（部分收款）
-> `PAID`（所有币种未收=0）

回退路径：

1. `ISSUED/PARTIALLY_PAID/PAID -> PENDING_REVIEW`（调账或红冲影响金额）。
2. `DRAFT/PENDING_REVIEW/ISSUED -> CLOSED`（人工关闭）。

### 7.2 通知任务状态机

`PENDING`（待发送）
-> `SENDING`（发送中）
-> `SUCCESS`（发送成功）

失败路径：

1. `SENDING -> FAILED`（发送失败）。
2. `FAILED -> PENDING`（系统重试/手工重发）。
3. `PENDING -> CANCELLED`（人工取消）。

## 8. 主流程图（端到端）

主流程简图：

1. 配置账单规则 -> 配置费项规则（API/DB/文件/手工）。
2. 费项采集入池 -> 按币种汇总 -> 生成账单草稿 `DRAFT`。
3. 提交审核 -> 审核通过 -> 账单生效 `ISSUED` -> 邮件通知。
4. 收款登记（同币种分摊）-> 状态更新为 `PARTIALLY_PAID/PAID`。
5. 调账/红冲/导入调整 -> 回退 `PENDING_REVIEW` -> 复核通过后重新 `ISSUED`。

## 9. 功能需求（FR）

### 9.1 账单配置

1. 支持周、半月、月、自定义天数。
2. 支持结算节点：出库核重、广义签收。
3. 支持配置生效时间段与自动出账开关。

### 9.2 费项配置与采集

1. 费项支持 `AUTO_PULL` 与 `MANUAL_INPUT`。
2. 自动拉取支持 API/DB/文件适配器。
3. DB 适配器支持“数据源配置 + 读表规则配置”。
4. 读表必须参数化、只读、表白名单、行数上限控制。

### 9.3 账单生成与审核

1. 定时生成账单草稿。
2. 审核通过后生效为 `ISSUED`。
3. 已生效账单若发生金额调整，自动回到 `PENDING_REVIEW`。

### 9.4 调账/红冲

1. 支持调增、调减。
2. 支持红冲原记录，禁止物理删除。
3. 支持导入订单调整并记录批次与行级结果。

### 9.5 收款与分摊

1. 支持单账单多次部分收款。
2. 支持一次收款分摊多个账单。
3. 自动分摊默认 FIFO，可手工覆盖。
4. 默认仅支持同币种分摊，不支持跨币种自动抵扣。

### 9.6 多币种结算

1. 同一账单允许存在多个费项币种（例如 USD、EUR）。
2. 账单明细按 `费项+币种` 记录结算金额。
3. 账单头按币种展示 `应收/已收/未收` 三类金额。
4. 账单结清条件：所有币种未收均为 0。
5. 调账、红冲必须带币种并影响对应币种余额桶。
6. 可选展示“本位币折算总览”，仅展示不参与结算。

### 9.7 账单通知

1. 账单生效自动发邮件。
2. 调账复核后再次生效触发变更通知。
3. 支持失败重试与手工重发。
4. 收件人优先级：指定收件人 > `customer.enterprise_mailbox` > `customer_contact_info.email`。

### 9.8 审计与日志

1. 金额变更操作全量审计。
2. 导入、拉取、通知任务均有执行日志。
3. 关键动作记录操作者、时间、前后值、原因。

## 10. 用例场景（含验收要点）

### UC-00 全流程数据样例（账单生成->调账->红冲->收款）

场景：客户 `C10001`，账期 `2026-05-01 ~ 2026-05-15`，账单号 `B20260515-0001`。

步骤 1：账单生成（草稿）

1. 费项明细：
`国际运费` USD 100.00  
`操作费` EUR 40.00  
`偏远附加费` USD 20.00
2. 币种汇总：
USD 应收 120.00，EUR 应收 40.00
3. 状态：`DRAFT -> PENDING_REVIEW -> ISSUED`

步骤 2：调账（调减）

1. 发现操作费应减免 EUR 5.00，创建调账单 `DECREASE EUR 5.00`。
2. 账单回退：`ISSUED -> PENDING_REVIEW`。
3. 审核后生效：EUR 应收由 40.00 变为 35.00，状态回到 `ISSUED`。

步骤 3：红冲

1. 发现偏远附加费多收，红冲 USD 10.00（关联原费项记录）。
2. 账单回退：`ISSUED -> PENDING_REVIEW`。
3. 审核后生效：USD 应收由 120.00 变为 110.00，状态回到 `ISSUED`。

步骤 4：收款（同币种分摊）

1. 收到 USD 80.00：USD 已收 80.00，USD 未收 30.00，状态 `PARTIALLY_PAID`。
2. 收到 EUR 35.00：EUR 已收 35.00，EUR 未收 0.00，状态仍 `PARTIALLY_PAID`（因 USD 未收>0）。
3. 收到 USD 30.00：USD 已收 110.00，USD 未收 0.00；全部币种未收为 0，状态 `PAID`。

关键校验：

1. 不允许用 USD 收款去抵 EUR 未收（V1 规则）。
2. 每次调账/红冲都必须触发回审。
3. `PAID` 判定以“所有币种未收=0”为准。

### UC-01 自动出账（标准）

1. 前置：客户已配置周期、结算节点、费项。
2. 操作：定时任务执行生成账单并提交审核。
3. 结果：审核通过后账单为 `ISSUED`，自动触发通知。

验收：

1. 账单金额 = 明细汇总金额。
2. 通知任务创建成功。

### UC-02 账单部分收款

1. 前置：账单状态 `ISSUED`。
2. 操作：登记 30% 收款并自动分摊。
3. 结果：账单状态变为 `PARTIALLY_PAID`。

验收：

1. `已收 + 未收 = 应收`。
2. 生成收款分摊记录。

### UC-03 多账单合并收款

1. 前置：同客户存在 3 张未结清账单。
2. 操作：登记一笔收款并手工分摊到 3 张账单。
3. 结果：各账单状态按分摊金额更新。

验收：

1. 分摊总额 = 收款金额。
2. 任一账单未收不得为负。

### UC-03A 单账单多币种结算

1. 前置：同一账单含 USD 运费、EUR 服务费。
2. 操作：查看账单详情与币种汇总，登记 USD 收款并分摊。
3. 结果：仅 USD 桶余额变化，EUR 桶不变，账单仍可能为 `PARTIALLY_PAID`。

验收：

1. 结算币种汇总与明细汇总一致。
2. 不允许使用 USD 收款直接抵扣 EUR 未收（V1 规则）。

### UC-04 调账导致回审

1. 前置：账单为 `ISSUED` 或 `PAID`。
2. 操作：新增调减或红冲并审批通过。
3. 结果：账单状态回退 `PENDING_REVIEW`，复核后重新 `ISSUED`。

验收：

1. 回退逻辑自动触发。
2. 复核通过前禁止自动新增分摊。

### UC-05 DB 源适配器读表

1. 前置：配置数据源与读表规则。
2. 操作：触发 `adapter-db/test` 与正式拉取任务。
3. 结果：BMS 成功读表并生成标准费项记录。

验收：

1. 仅执行 `SELECT`。
2. SQL 命中白名单表。
3. 拉取结果与源表样本一致。

### UC-06 邮件通知失败重试

1. 前置：客户有邮箱，邮件通道短暂失败。
2. 操作：系统自动重试 3 次，仍失败则人工重发。
3. 结果：通知状态最终 `SUCCESS` 或保留 `FAILED` 待处理。

验收：

1. 每次重试均有日志。
2. 可查询失败原因与回执码。

## 11. 异常场景

1. 无收件人邮箱：账单不阻断生效，通知任务置 `FAILED` 并告警。
2. 导入数据脏值：行级失败，不影响批次内其他合法行。
3. DB 源超时：任务可重试，超过阈值转人工。
4. 收款超分摊：禁止提交，返回校验错误。
5. 跨币种分摊：禁止提交，返回“币种不一致”校验错误。
6. 账单关闭后操作：禁止再调账、收款、重发通知。

## 12. 非功能要求（NFR）

1. 并发：支持 10w+ 账单明细批量处理。
2. 性能：单次账单查询 P95 < 1s（管理端分页查询场景）。
3. 安全：数据源密码加密存储，日志脱敏展示。
4. 可观测：任务、通知、导入链路可追踪。
5. 稳定性：核心定时任务可重入且幂等。
6. 准确性：多币种汇总与明细逐币种一致性 100%。

## 13. 验收标准（UAT）

1. 关键用例 UC-01 ~ UC-06 全通过。
2. 多币种用例 UC-03A 通过。
3. 状态机流转与规则一致，无非法跳转。
4. 菜单与权限点完整可控。
5. 关键日志与审计可回放。
6. 上线灰度期间无 P1/P2 故障。

## 14. 里程碑建议

1. M1：配置中心 + 账单生成审核 + 收款分摊。
2. M2：调账红冲 + 导入 + 状态回审闭环。
3. M3：DB 读表适配器 + 邮件通知 + 运维看板。
4. M4：稳定性优化与全量切换。
