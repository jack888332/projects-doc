# 2026-07-24 BMS 供应商管理功能需求落地方案及调整计划

## 1. 文档目的

本文针对成本中心中的“供应商管理”功能，结合产品原型、PRD、概念实体关系图、现有代码和开发库实际结构，给出可执行的需求落地方案、代码调整计划、数据库设计、验收标准及已确认业务口径。

设计依据：

1. 成本中心原型：`http://192.168.2.2:10100/`。
2. PRD：`aidocs/product-caliber/bms/prd/财务系统.PRD.md` 的 `13.4 供应商管理`，并参考 `13.1`、`13.3`、`13.5`。
3. 实体关系图：`aidocs/product-caliber/bms/prd/derivant/概念实体关系图.md`。
4. 当前 `bms`、`platform-admin`、`admin_shell`、`admin` 代码。
5. 开发库 `tmall_bms` 的实际表结构。

本文是实施方案，不直接修改业务代码或执行数据库变更。

## 2. 调研结论

### 2.1 业务定位

供应商管理是由 BMS 独立建设和维护的成本中心“供应商财务档案”。本方案忽略现有 SRM 代码，并按当前不存在 SRM 系统设计：

1. 为供应商账单导入提供供应商身份。
2. 限定供应商可使用的成本板块。
3. 提供账单缺少币种时的默认币种。
4. 维护供应商常规成本账期，用于导入时推导、预填和校验实际成本账期。
5. 按供应商、成本账期和币种汇总成本账单及结清金额。
6. 停用只阻止后续新建导入任务和成本账单，不影响历史账单继续归集、分摊和结清。

供应商管理不承接供应商付款申请、审批、实际付款、供应商价卡、计价复算、信用账期和付款排程。

原型中的供应商管理页面包含：

   - 查看详情。

4. 新增/编辑表单：

### 2.3 PRD 与原型差异

| 编号 | PRD 要求 | 原型现状 | 落地建议 |
| --- | --- | --- | --- |
| D-01 | 成本账期配置必须有生效开始日和生效结束日 | 新增/编辑表单未展示生效起止日 | 表单补充“生效期间”开始、结束日期；后端必须保存并校验 |
| D-02 | 同一供应商、同一成本板块任一日期只能有一套生效账期配置，期间不得重叠 | 原型只保存一个账期文本 | 账期配置独立建表，每条配置绑定唯一成本板块，按生效期间追加保存 |
| D-03 | 列表至少展示成本账单数、待结清数、已结清数、待结清金额、已结清金额、累计成本金额 | 原型只展示成本账单数、待结清金额、已结清金额 | 正式页面补齐三类账单数量和累计成本金额 |
| D-04 | 所有金额按币种分别统计，不同币种不得相加 | 原型样本每个供应商只展示单一币种文本 | 响应使用币种统计列表，列表直接展开全部币种分桶 |
| D-05 | 最近动态包含最近账期、最近账单编号、最近账单状态、最近更新时间 | 原型列表未完整展示 | 列表可保留最近账单编号/状态，完整最近动态放详情 |
| D-06 | 可启用、停用；未被引用时允许删除 | 原型只有新增、编辑、详情，未提供删除入口 | 初版增加删除入口，后端执行引用检查和逻辑删除 |
| D-07 | 档案变更只影响后续账单，不回写历史 | 原型使用浏览器本地对象直接修改 | 后续成本账单必须保存供应商业务快照 |
| D-08 | 详情可查看各币种统计、最近成本账单并跳转筛选后的账单列表 | 原型只有汇总卡片和普通跳转 | 详情增加币种统计表和最近账单列表；跳转携带 supplierId |

### 2.4 现有代码和数据库基线

#### 2.4.1 Admin Shell

当前已有：

1. 路由：`admin_shell/src/router/billing.js` 中的 `costSupplier`。
2. 页面：`admin_shell/src/views/billing/costSupplier/index.vue`。
3. 公共静态脚手架：`admin_shell/src/views/billing/costCenter/components/CostListScaffold.vue`。
4. 路由权限占位值：`meta.code = "CostSupplier"`。

当前页面只是静态配置：

1. `loadList()` 固定清空列表。
2. 新增、详情和其它操作只提示“待后端接口确认后接入”。
3. 没有供应商管理 API 定义。
4. 公共脚手架不支持多币种统计、账期配置编辑、详情抽屉和真实启停。

因此正式落地时，供应商页面应改为独立业务页面，不继续把复杂逻辑堆入 `CostListScaffold.vue`，避免影响其它仍为占位状态的成本中心页面。

#### 2.4.2 BMS、Platform Admin

当前没有供应商财务档案对应的 Model、Mapper、Service、Feign、Controller 和 Platform Admin 门户代理接口。

现有成本费项索引链路已经形成可复用的实现模式：

```text
admin_shell
  → /platform/portal/bms/...
platform-admin Controller
  → BMS Feign Client
bms web Controller
  → Service
  → Mapper + XML
  → tmall_bms
```

供应商管理应沿用该链路，但供应链维度数据隔离、账期配置、分币种统计和状态控制必须按本方案单独实现。

#### 2.4.3 外部供应商系统边界

本方案明确不读取、不复用、不依赖现有 SRM 代码或接口，按 BMS 当前没有外部供应商主数据系统落地。供应商由 BMS 自主创建，供应商编码由 BMS 后端生成；将来如接入外部主数据系统，应另立迁移和绑定方案，不在本期表中预留 SRM 专用字段。

#### 2.4.4 开发库

开发库 `tmall_bms` 当前与本功能相关的结论：

1. 没有名称包含 `supplier` 的表。
2. 没有成本账单、成本账单结清记录表。
3. 已有 `ar_bill`、`fee_detail` 等客户侧账单表，不能直接承载供应商成本账单。
4. 已有 `cost_fee_index`，可作为后续供应商账单导入的标准成本费项基础，但不保存供应商档案。

供应商列表中的账单数量和金额统计目前没有真实数据源，必须依赖后续成本账单模块。

## 3. 本期范围建议

### 3.1 本期必须实现

1. 供应商财务档案分页查询。
2. 按编码/名称、状态、成本板块、账期类型、账期范围组合筛选。
3. 新增供应商财务档案。
4. 编辑供应商名称、默认币种、成本板块、备注和后续生效的账期配置。
5. 启用、停用供应商。
6. 查询供应商详情。
7. 根据当前日期计算并展示当前成本账期。
8. 为成本账单导入提供“启用供应商下拉”接口。
9. 记录操作人、创建时间、更新时间和版本号。
10. 为未来成本账单保存稳定的 `supplierId`，并要求账单同时保存供应商编码、名称快照。
11. 删除未被业务引用的供应商，采用数据库逻辑删除。

### 3.2 依赖成本账单模块实现

以下展示字段由供应商管理页面承载，但真实数据依赖成本账单和结清记录：

1. 成本账单数。
2. 待结清账单数。
3. 已结清账单数。
4. 待结清金额。
5. 已结清金额。
6. 累计成本金额。
7. 最近账期、最近账单编号和最近账单状态。
8. 跳转到筛选后的成本账单列表。

在成本账单表落地前，接口不得伪造 `0` 代表真实统计。建议响应增加 `statisticsAvailable`：

- `false`：页面展示“成本账单模块未接入”，金额显示 `--`。
- `true`：列表直接展开全部币种分桶并展示真实统计。

2. 供应商付款审批、付款排程和实际付款。
3. 供应商价卡及成本自动复算。
4. 供应商原始费项别名维护。
5. 成本账单导入、成本明细、成本池和成本分摊。
6. 供应商财务档案批量导入和导出。
7. 档案变更独立审批流。

## 4. 总体技术方案

### 4.1 聚合设计

将“供应商财务档案”作为 BMS 聚合根，拆为三张表：

```text
cost_supplier_profile
  └── 1:N cost_supplier_period_config
            └── 1:1 cost_supplier_board

未来：
cost_supplier_profile
  ├── 1:N cost_bill
  ├── 1:N cost_bill_import_task
  └── 1:N cost_detail
```

设计原因：

1. 一个供应商可有多条成本账期配置，每条账期配置必须且只能绑定一个适用成本板块。
2. 账期配置有生效期间、按板块不可重叠和历史追溯要求，不能只保存在主表当前值。
3. 供应商基本信息与账期版本的生命周期不同。
4. 概念实体关系图允许物理落库时合并或拆分实体；本方案把“供应商主体”和“财务档案”合并为 BMS 聚合根，避免当前阶段额外建立无业务字段的主体表。

### 4.2 BMS 自主管理策略

1. BMS 以 `cost_supplier_profile.id` 作为成本域内部稳定主键。
2. `supplier_code` 由 BMS 后端生成并永久只读，格式为 `CSP_{yyyyMMddHHmmss}_{6位随机串}`。
3. `supplier_name`、默认币种、状态和备注均在 BMS 中持久化。
4. 后续成本账单和成本明细必须同时保存 `supplier_id` 及编码、名称快照。
5. 不增加 SRM 来源字段，不建立外部系统在线依赖。

### 4.3 数据隔离

供应商财务档案按供应链维度隔离，三张表统一包含 `sc_id`，不包含 `shop_id`、`user_id`：

1. 同一供应链下的不同店铺和用户共享该供应链的供应商档案。
2. 不同供应链之间数据不可见，供应商编码在同一 `sc_id` 的有效数据中唯一。
3. Platform Admin 从登录上下文取得 `scId` 和 `operatorId`，覆盖前端传值。
4. BMS 查询、详情、保存、启停、删除和下拉选项接口都必须强制携带 `scId`。
5. 主表与子表写入相同 `sc_id`，关联查询同时校验主子表 `sc_id` 一致。
6. 这是对 BMS 通常 `sc_id + shop_id + user_id` 三维隔离规范的业务特例：本模块只按 `sc_id` 隔离。

### 4.4 历史不回写

供应商档案编辑只影响未来业务：

1. 历史成本账单保留创建时的供应商编码、名称、默认币种、成本板块和实际账期。
2. 历史成本明细保留供应商 ID、编码和名称。
3. 当前档案停用或改名，不修改历史成本账单数据。

## 5. 页面落地方案

### 5.1 页面结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 供应商管理                                  [新增供应商财务档案]     │
│ 维护成本账期、适用成本板块及按币种分桶的账单金额                    │
├──────────────────────────────────────────────────────────────────────┤
│ 供应商 [编码或名称____] 成本板块 [全部▼] 账期类型 [全部▼]           │
│ 状态 [全部▼] 成本账期范围 [开始日期 至 结束日期] [查询] [重置]       │
├──────────────────────────────────────────────────────────────────────┤
│ 编码 │ 名称 │ 板块 │ 账期 │ 当前账期 │ 默认币种 │ 账单统计 │ 状态 │
│ ...  │ ...  │ ...  │ ...  │ ...      │ ...      │ 分币种   │ ...  │
├──────────────────────────────────────────────────────────────────────┤
│                                                       分页           │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 查询规则

1. 首次进入按更新时间倒序、ID 倒序查询。
2. 供应商关键词去除首尾空格后，模糊匹配编码或名称。
3. 成本板块筛选通过“账期配置 → 适用成本板块”关联表 `EXISTS` 查询，不使用逗号字符串。
4. 账期类型按当前或筛选期间内有效的账期配置查询。
5. 成本账期范围使用日期范围控件：
   - 查询与选择范围有交集的有效账期配置。
   - SQL 使用 `effective_start_date <= endDate` 和 `effective_end_date >= startDate`。
   - 不在 WHERE 列上使用 `DATE_FORMAT` 等函数。
6. 查询、重置和筛选变化均把页码重置为 1。
7. 页面大小默认 20，最大 200。

| 字段 | 展示规则 |

| 供应商编码 | 可点击进入详情 |

| 最近动态 | 最近账单编号、状态、账期和更新时间 |

### 5.4 新增/编辑表单

| 字段 | 新增 | 编辑 | 校验 |
| --- | --- | --- | --- |
| 供应商编码 | 后端生成、页面只读 | 只读 | 同一供应链内唯一；格式 `CSP_{yyyyMMddHHmmss}_{6位随机串}` |
| 供应商名称 | 必填 | 可编辑 | 最长 128 |
| 状态 | 默认启用 | 可编辑 | `ENABLED`/`DISABLED` |
| 默认币种 | 必填 | 可编辑 | 选项来自系统现有币种接口，不在页面硬编码；后端校验有效币种 |
| 板块账期配置 | 至少一组 | 只允许新增板块或变更已有板块账期 | 每组由一个成本板块和一套账期配置组成；同一时段板块不可重复 |
| 适用成本板块 | 每组必填、单选 | 已有配置只读 | 五大板块之一；已建立的板块不可移除 |
| 成本账期类型 | 每组必填 | 以新版本生效 | 周/半月/月/自然天 |
| 周期天数 | 对应组为自然天时必填 | 对应组为自然天时必填 | 大于等于 1，默认 7 |
| 首个账期开始日 | 对应组为自然天时必填 | 对应组为自然天时必填 | 单日控件，锚点日期不得晚于当前日期 |
| 生效期间 | 每组必填开始日 | 新配置必填开始日 | 日期范围；结束日可空 |
| 备注 | 选填 | 可编辑 | 最长 500 |

保存时：

1. 新增档案、各板块账期配置及其一对一成本板块记录在同一事务提交。
2. 编辑基本信息时使用行锁或版本号防止覆盖更新。
3. 已被导入任务引用的配置不可修改；未被引用的未来配置可编辑；其它变更采用“结束旧配置 + 新增新配置”。
4. 同一供应商、同一成本板块的新账期生效期间与已有配置重叠时拒绝保存；不同板块允许同期生效。
5. 每条账期配置必须恰好包含一个板块；已保存的板块只能保留或新增，提交缺少已有板块时拒绝保存。
6. 停用和删除必须二次确认。
7. 保存期间按钮进入 loading，禁止重复提交。

### 5.5 当前成本账期计算

先按成本板块获取当前日期唯一生效的账期配置，再分别按类型计算：

1. 周：
   - 周一为开始日。
   - 周日为结束日。
2. 半月：
   - 1 日至 15 日。
   - 16 日至月末。
3. 月：
   - 当月 1 日至月末。
4. 自然天：
   - 以首个账期开始日为锚点。
   - 锚点日期不得晚于服务端 Asia/Shanghai 时区的当前日期。
   - `offset = floor(锚点日至当前日的天数 / 周期天数)`。
   - 开始日为 `anchor + offset * cycleDays`。
   - 结束日为 `开始日 + cycleDays - 1`。

计算结果还应与配置生效期间取交集。某成本板块在当前日期不存在生效配置时，该板块展示“当前无生效账期”，不能使用最近一张成本账单的实际账期代替。

### 5.6 详情抽屉

详情至少包含：

1. 档案基本信息。
2. 各成本板块的当前账期配置和当前成本账期。
3. 按成本板块分组的历史/未来账期配置列表。
4. 每条账期配置一对一关联的适用成本板块。
5. 按币种的账单数量和金额统计。
6. 最近成本账单列表。
7. 跳转成本账单按钮，携带 `supplierId`、可选账期范围。

## 6. 数据库设计

### 6.1 供应商财务档案

```sql
CREATE TABLE `cost_supplier_profile` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `sc_id` bigint(20) NOT NULL COMMENT '供应链ID，数据隔离字段',
  `supplier_code` varchar(64) NOT NULL COMMENT 'BMS后端生成的供应商编码',
  `supplier_name` varchar(128) NOT NULL COMMENT '供应商名称',
  `supplier_status` varchar(16) NOT NULL DEFAULT 'ENABLED' COMMENT '供应商状态：ENABLED/DISABLED',
  `default_currency` varchar(16) NOT NULL COMMENT '默认币种，ISO 4217三位大写代码',
  `remark` varchar(500) DEFAULT NULL COMMENT '财务对账口径、账期例外及其它备注',
  `version` int(11) NOT NULL DEFAULT '0' COMMENT '乐观锁版本号',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除：0正常，1删除',
  `active_supplier_code` varchar(64)
    GENERATED ALWAYS AS (CASE WHEN `is_deleted` = 0 THEN `supplier_code` ELSE NULL END) STORED
    COMMENT '有效供应商编码唯一键辅助列',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_supplier_sc_code` (`sc_id`, `active_supplier_code`),
  KEY `idx_cost_supplier_status`
    (`sc_id`, `supplier_status`, `is_deleted`, `updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='BMS成本供应商财务档案';
```

设计说明：

1. `id` 是成本域内部关联主键。
2. `supplier_code` 同时作为对外业务编号，由后端生成，创建后不可修改。
3. `sc_id + active_supplier_code` 保证供应商编码在同一供应链有效数据中唯一。
4. `version` 用于基本信息并发更新。
5. 金额统计不反写主表，避免账单变更后主表统计失真。
6. 本表按 `sc_id` 隔离，不按店铺或用户隔离。

### 6.2 供应商成本账期配置

```sql
CREATE TABLE `cost_supplier_period_config` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `sc_id` bigint(20) NOT NULL COMMENT '供应链ID，数据隔离字段',
  `config_no` varchar(64) NOT NULL COMMENT '账期配置编号，全局唯一',
  `supplier_id` bigint(20) unsigned NOT NULL COMMENT '供应商财务档案ID',
  `period_type` varchar(16) NOT NULL COMMENT '账期类型：WEEK/HALF_MONTH/MONTH/NATURAL_DAY',
  `natural_days` int(11) DEFAULT NULL COMMENT '自然天周期天数，仅NATURAL_DAY使用',
  `anchor_date` date DEFAULT NULL COMMENT '首个账期开始日，仅NATURAL_DAY使用',
  `effective_start_date` date NOT NULL COMMENT '生效开始日',
  `effective_end_date` date NOT NULL COMMENT '生效结束日',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除：0正常，1删除',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_supplier_period_config_no` (`config_no`),
  KEY `idx_cost_supplier_period_effective`
    (`sc_id`, `supplier_id`, `is_deleted`, `effective_start_date`, `effective_end_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='供应商成本账期配置';
```

约束规则：

1. `period_type` 为 `NATURAL_DAY` 时：
   - `natural_days >= 1`。
   - `anchor_date` 不为空。
   - `anchor_date` 不得晚于当前日期。
2. 其它类型：
   - `natural_days` 为空。
   - `anchor_date` 为空。
3. `effective_end_date` 必填且不得早于 `effective_start_date`。
4. 同一供应商、同一成本板块有效配置的生效期间不得重叠；不同成本板块允许生效期间重叠。
5. MySQL 无法用普通唯一索引表达日期区间不重叠，Service 写入时必须：
   - 对供应商档案 `SELECT ... FOR UPDATE`。
   - 关联 `cost_supplier_board`，按供应商和目标成本板块查询重叠配置。
   - 无重叠后插入。
6. 已被导入任务引用的配置不可修改；未被引用的未来配置可编辑；其它修改关闭旧配置并新增配置。
7. 重叠查询使用：

```sql
SELECT COUNT(1)
FROM cost_supplier_period_config pc
INNER JOIN cost_supplier_board b
  ON b.period_config_id = pc.id
 AND b.sc_id = pc.sc_id
 AND b.is_deleted = 0
WHERE pc.sc_id = #{scId}
  AND pc.supplier_id = #{supplierId}
  AND b.cost_board = #{costBoard}
  AND pc.is_deleted = 0
  AND pc.effective_start_date <= #{effectiveEndOrMax}
  AND pc.effective_end_date >= #{effectiveStart};
```

### 6.3 供应商适用成本板块

```sql
CREATE TABLE `cost_supplier_board` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `sc_id` bigint(20) NOT NULL COMMENT '供应链ID，数据隔离字段',
  `period_config_id` bigint(20) unsigned NOT NULL COMMENT '供应商成本账期配置ID',
  `cost_board` varchar(32) NOT NULL COMMENT '成本板块：DELIVERY/CUSTOMS/SEA_FREIGHT/AIR_FREIGHT/TRUCKING',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除：0正常，1删除',
  `active_period_config_id` bigint(20) unsigned
    GENERATED ALWAYS AS (CASE WHEN `is_deleted` = 0 THEN `period_config_id` ELSE NULL END) STORED
    COMMENT '有效账期配置唯一键辅助列',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_supplier_board_period` (`sc_id`, `active_period_config_id`),
  KEY `idx_cost_supplier_board`
    (`sc_id`, `cost_board`, `is_deleted`, `period_config_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='供应商成本账期配置适用板块';
```

成本板块使用已存在的统一编码：

| 编码 | 名称 |
| --- | --- |
| `DELIVERY` | 派送成本 |
| `CUSTOMS` | 清关成本 |
| `SEA_FREIGHT` | 海运成本 |
| `AIR_FREIGHT` | 空运成本 |
| `TRUCKING` | 租车成本 |

一对一约束规则：

1. `cost_supplier_board.period_config_id` 指向同一 `sc_id` 下的 `cost_supplier_period_config.id`。
2. `uk_cost_supplier_board_period` 保证一条有效账期配置最多关联一条有效成本板块记录。
3. Service 新增账期配置后必须在同一事务插入一条板块记录，保证一条账期配置至少关联一个板块。
4. 日常编辑不允许单独删除或更换已有板块；变更账期时新增账期配置及其对应板块记录。
5. 删除供应商时，账期配置及其一对一板块记录在同一事务逻辑删除。
6. 延续现有 BMS 库不使用物理外键的惯例，不增加 `FOREIGN KEY`；引用完整性由 `period_config_id` 索引、唯一键和 Service 事务共同保证。

### 7.5 Service 关键规则

#### 新增

1. 校验 `scId`、名称、默认币种和板块账期配置；每条账期配置必须且只能包含一个成本板块。
2. 后端生成 `CSP_{yyyyMMddHHmmss}_{6位随机串}` 供应商编码。
3. 校验供应商编码在当前 `scId` 内唯一；碰撞时重新生成并在有限次数后失败告警。
4. 主表、账期配置和板块记录均写入相同 `sc_id`。
5. 逐项校验账期参数，先新增账期配置并取得主键。
6. 使用账期配置主键插入唯一的成本板块记录。
7. 主表、全部账期配置和一对一板块记录在同一事务完成。

#### 编辑

1. `SELECT ... FOR UPDATE` 查询档案。
2. 按 `scId + id` 校验记录存在且未被逻辑删除。
3. 使用版本号防止旧页面覆盖新修改。
4. 供应商编码默认不可修改。
5. 通过账期配置关联板块比较已有板块集合：允许新增，若提交集合缺少已有板块则拒绝保存。
6. 基本信息变化更新主表。
7. 某板块账期变化时，新增该板块的账期配置及一对一板块记录，不覆盖历史记录。
8. 档案名称、币种、板块和账期变化不回写历史账单。

#### 启停

1. 启用和停用均加事务。
2. 停用前加行锁。
3. 停用后：
   - 不出现在导入供应商选项中。
   - 禁止新建导入任务和成本账单。
   - 历史账单仍允许归集、分摊、调账和结清。
4. 重复提交相同状态按幂等成功处理。

#### 删除

1. 仅逻辑删除。
2. 必须先检查导入任务、成本明细、成本账单和分摊规则等业务引用；操作日志不作为阻塞引用。
3. 有任何业务引用时拒绝删除，只允许停用。
4. 无业务引用时，主表、板块和账期配置在同一事务逻辑删除。
5. 删除前锁定供应商主表并二次检查引用，避免并发新建导入任务。

### 7.6 Mapper 和 SQL 规范

1. Mapper 接口只声明方法。
2. 动态 SQL 全部写入 `CostSupplier-mapper.xml`。
3. 使用 `<resultMap>` 显式映射。
4. 列片段和查询条件使用 `<sql>` + `<include>` 复用。
5. 分页先 `COUNT`，再查询列表。
6. 本模块按供应链隔离，所有查询必须先包含 `sc_id = #{scId}` 和 `is_deleted = 0`，不拼接 `shop_id`、`user_id`。
7. 账期范围使用原始日期范围比较，不对列使用 SQL 函数。
8. 成本板块筛选使用“账期配置 → 成本板块”的两级 `EXISTS`，每层同时校验 `sc_id`，避免跨供应链关联以及 JOIN 导致供应商重复和统计放大。
9. 新增使用 `useGeneratedKeys` 回写主键。
10. 所有写 Service 方法使用 `@Transactional(rollbackFor = Exception.class)`。

1. 验证新增、编辑、启停和逻辑删除。
2. 验证同一供应链内共享、不同供应链之间数据隔离。
3. 验证同一供应商同一板块账期不重叠、不同板块允许同期配置，以及四类账期边界。
4. 验证每条账期配置恰好关联一个成本板块，且已有成本板块不能移除。
5. 验证多板块筛选及全部币种分桶展开。
6. 验证多币种不合计。
7. 验证历史供应商快照不回写。
8. 回归成本费项索引及现有应收、返款账单链路。

## 10. 验收标准

### 10.1 列表与查询

- [ ] 支持按编码/名称、板块、账期类型、状态、账期范围组合查询。
- [ ] 同一供应链内不同店铺和用户查询到同一套供应商档案。
- [ ] 不同供应链之间不能查询、查看或操作对方供应商档案。
- [ ] 多板块供应商只返回一行。
- [ ] 当前成本账期按成本板块分别由当前配置实时计算。
- [ ] 某板块无生效配置时不使用最近账单账期替代。
- [ ] 分页总数、页码和每页数量正确。
- [ ] 默认按更新时间、ID 倒序。

### 10.2 新增与编辑

- [ ] 供应商编码由后端生成、页面不可编辑，且同一供应链内唯一。
- [ ] 供应商名称、状态、默认币种、板块、账期类型和生效开始日必填。
- [ ] 默认币种来自系统现有币种接口。
- [ ] 至少维护一组“成本板块 + 账期配置”。
- [ ] 每条账期配置恰好关联一个适用成本板块。
- [ ] 已保存的成本板块不可移除，只能新增。
- [ ] 自然天周期默认 7，且只允许大于等于 1 的整数。
- [ ] 自然天锚点日期不得晚于当前日期。
- [ ] 非自然天类型不保存周期天数和锚点。
- [ ] 生效结束日不得早于开始日。
- [ ] 同一供应商、同一成本板块的账期生效期间不得重叠。
- [ ] 同一供应商的不同成本板块允许账期生效期间重叠。
- [ ] 编辑账期形成新配置，不覆盖历史。
- [ ] 并发编辑不会静默覆盖他人修改。

### 10.3 启停与历史

- [ ] 停用前出现二次确认。
- [ ] 停用供应商不出现在新建导入任务选项中。
- [ ] 停用不影响历史成本账单归集和结清。
- [ ] 档案改名、改币种或改板块不回写历史账单。
- [ ] 重复启停按幂等成功处理。
- [ ] 无业务引用的供应商可以逻辑删除。
- [ ] 有导入任务、成本明细、成本账单或分摊规则等业务引用时拒绝删除。

### 10.4 金额统计

- [ ] 相同币种分别统计待结清、已结清、累计成本。
- [ ] 不同币种不得直接相加。
- [ ] 部分结清金额计入已结清金额，剩余计入待结清金额。
- [ ] 同一金额不会同时重复计入待结清和已结清。
- [ ] 尚未形成成本账单的成本池明细不进入供应商账单金额统计。
- [ ] 成本账单模块未接入时明确展示统计不可用，不伪造真实统计。
- [ ] 列表直接展开全部币种分桶，不折叠成单一金额摘要。

### 10.5 工程规范

- [ ] 三张供应商表均包含非空 `sc_id`，主子表关联时 `sc_id` 一致。
- [ ] Platform Admin 使用登录上下文覆盖请求中的 `scId`，前端不能指定数据归属。
- [ ] 分页、详情、写操作和选项查询 SQL 均强制包含 `sc_id` 条件。
- [ ] Controller 实现 Feign 契约。
- [ ] DTO、实体字段和 API 方法有完整 JavaDoc。
- [ ] 不使用 `Map` 作为 Controller/Service 参数或返回值。
- [ ] 写操作使用 `@Transactional(rollbackFor = Exception.class)`。
- [ ] Mapper 使用接口 + XML，不新增 SqlProvider。
- [ ] 动态查询使用 `<if>`、`<sql>` 和 `<include>`。
- [ ] WHERE 列不使用 SQL 函数。
- [ ] 数据库、实体、resultMap 和归档 SQL 一致。
- [ ] 前端 API 全部通过 `src/api/billing.js` 和 `@/utils/request`。
- [ ] 本期未新增菜单、按钮或后端操作权限控制，现有路由元数据保持不变。

## 11. 已确认口径

| 编号 | 已确认决策 | 方案落点 |
| --- | --- | --- |
| C-01 | 忽略当前 SRM 代码，视为没有 SRM 系统 | BMS 自主管理供应商，不增加 SRM 来源字段和依赖 |
| C-02 | 供应商档案按供应链维度隔离 | 三张表包含 `sc_id`，不包含 `shop_id`、`user_id`；编码在供应链内唯一 |
| C-03 | 供应商编码由系统生成 | 后端生成 `CSP_{yyyyMMddHHmmss}_{6位随机串}`，前端只读 |
| C-04 | 账期配置修改采用建议方案 | 已引用配置不可改；未引用未来配置可改；其它变更结束旧配置并新增 |
| C-05 | 自然天锚点不得晚于当前日期 | 前后端双重校验，日期控件禁选未来日期 |
| C-06 | 允许删除，数据库状态删除 | 无业务引用时逻辑删除主表和子表，有引用时拒绝 |
| C-07 | 账单模块未落地时统计不可用 | 返回 `statisticsAvailable=false`，页面展示 `--` |
| C-08 | 默认币种来自系统现有币种接口 | 复用现有币种服务，前端不硬编码币种 |
| C-09 | 成本板块不可移除 | 每条账期配置一对一绑定板块；编辑仅允许新增板块或新增已有板块的账期版本 |
| C-10 | 列表展示全部币种分桶 | 全部展开，不跨币种求和、不折叠为单一摘要 |
| C-11 | 菜单权限暂不实施 | 本期不新增菜单、按钮和后端操作权限配置 |
| C-12 | 优化表关联关系 | 供应商财务档案 1:N 账期配置；账期配置 1:1 适用成本板块 |

上述口径已形成可直接实施的方案，不再作为开发阻塞问题。后续若变更任一口径，必须同步调整数据库、DTO、接口、页面和验收用例，不能只修改单层实现。

## 12. 最终落地结论

本期供应商管理应建设为 BMS 自有、按供应链维度隔离并在供应链内共享的供应商财务档案能力，且不能只保留原型静态页面。

推荐落地结果：

1. 新增 `cost_supplier_profile`、`cost_supplier_period_config`、`cost_supplier_board` 三张表。
2. 建立完整的 BMS Model、Mapper XML、Service、Feign、Controller 链路。
3. 三张表均通过 `sc_id` 进行供应链隔离，Platform Admin 注入当前 `scId` 和操作人。
4. 将 `admin_shell` 供应商页面改为真实列表、表单、详情、启停和删除页面。
5. 供应商与账期配置为 1:N，账期配置与成本板块为 1:1；账期按板块独立版本化并校验生效期间不重叠。
6. 金额统计按币种建模并在列表全部展开，不跨币种相加。
7. 成本账单未落地前明确展示统计不可用，不制作假数据。
8. 供应商档案变更只影响未来业务，历史成本账单数据不回写。
9. 无业务引用时允许逻辑删除，有引用时拒绝删除并引导停用。
10. 已有成本板块不可移除，默认币种复用系统现有币种接口。
11. 本期不实施菜单和按钮权限控制。

十二项关键口径均已确认，本方案可直接进入数据库迁移和编码实施。
