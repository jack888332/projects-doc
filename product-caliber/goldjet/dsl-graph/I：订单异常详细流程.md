# I：订单异常详细流程（订单异常子流程）

> 来源：`temp/流程图SVG/I：订单异常详细流程.svg`（Visio 流程图），转换为 PlantUML 活动图（新语法）。

```plantuml
@startuml
title 订单异常子流程
start
switch (订单申报，海关回执异常)
case (退单)
  :通知客户，让客户修改订单、\n重新申报；或者取消订单;
case (退运)
  :通知客户，和客户沟通达成一致意见，\n可以让客户退单，也可以做退运出区申报退运。;
  if (需要退运？) then (是)
    :退运子流程;
  endif
case (订单信息不存在)
  :重新推送清单（报机场跨境清单）;
case (运单信息不存在)
  :重新推送运单;
case (支付信息不存在)
  :重新推送支付单;
case (撤单)
  if (是否已出库) then (是)
    :申报撤销单;
    if (海关审核通过？) then (是)
      :撤单成功;
    endif
  else (否)
    :库内拦截并把订单取消;
  endif
case (查验)
  :订单下发给仓库;
  :仓库把需要查验的订单单独打包;
  if (海关查验通过？) then (是)
    :放行;
  else (否)
    :发送消息通知，联系客户解决;
  endif
case (挂起)
  :发送消息通知，联系客户解决;
case (人工审核)
  :等待回执状态更新;
case (担保金不足)
  :提醒客服;
case (其他异常)
  :提醒客服;
endswitch
stop
@enduml
```

## 转换说明

- 原图中“撤单/查验/挂起/人工审核/担保金不足/其他异常”为连接线上的分支标注（Visio 动态连接线文字），此处作为 switch 分支条件保留；“退单/退运/订单信息不存在/运单信息不存在/支付信息不存在”同为原图分支标注。
- “挂起”分支按位置就近归入“发送消息通知，联系客户解决”（与查验不通过分支共用该节点）。
- 原图“需要退运？”仅有“是”分支连线、“海关审核通过？”仅有“是”分支连线，未标注的分支未纳入。
- “海关查验通过？→否→发送消息通知，联系客户解决”及两个“提醒客服”节点在原图中无后续连线，按流向汇入结束。
