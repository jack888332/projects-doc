# 2026-07-23 BMS 供应商管理功能需求落地方案及调整计划

## 1. 文档目的

本文针对成本中心中的“供应商管理”功能，结合产品原型、PRD、概念实体关系图、现有代码和开发库实际结构，给出可执行的需求落地方案、代码调整计划、数据库设计、验收标准及待确认问题。

设计依据：

1. 成本中心原型：`http://192.168.2.2:10100/`。
2. PRD：`aidocs/product-caliber/bms/prd/财务系统.PRD.md` 的 `13.4 供应商管理`，并参考 `13.1`、`13.3`、`13.5`。
3. 实体关系图：`aidocs/product-caliber/bms/prd/derivant/概念实体关系图.md`。
4. 当前 `bms`、`platform-admin`、`admin_shell`、`admin` 代码。
5. 开发库 `tmall_bms` 的实际表结构。

本文是实施方案，不直接修改业务代码或执行数据库变更。

## 2. 调研结论

### 2.1 业务定位

供应商管理不是通用 SRM 供应商管理的替代品，而是 BMS 成本中心内的“供应商财务档案”：

1. 为供应商账单导入提供供应商身份。
2. 限定供应商可使用的成本板块。
3. 提供账单缺少币种时的默认币种。
4. 维护供应商常规成本账期，用于导入时推导、预填和校验实际成本账期。
5. 按供应商、成本账期和币种汇总成本账单及结清金额。
6. 停用只阻止后续新建导入任务和成本账单，不影响历史账单继续归集、分摊和结清。

供应商管理不承接供应商付款申请、审批、实际付款、供应商价卡、计价复算、信用账期和付款排程。

### 2.2 原型页面已体现的内容

原型中的供应商管理页面包含：

1. 查询条件：
   - 供应商编码或名称。
   - 成本板块。
   - 成本账期类型。

   - 成本账期范围。
2. 列表字段：

   - 成本账单数。
   - 待结清金额。
   - 已结清金额。
   - 状态。
3. 操作：
   - 新增供应商财务档案。
   - 查看详情。
   - 编辑档案。
   - 从详情跳转成本账单。
4. 新增/编辑表单：
   - 供应商编码。
   - 供应商名称。
   - 状态。
   - 默认币种。

   - 当前导入设置快照摘要。

### 2.3 PRD 与原型差异

| 编号 | PRD 要求 | 原型现状 | 落地建议 |
| --- | --- | --- | --- |
| D-01 | 成本账期配置必须有生效开始日和可选生效结束日 | 新增/编辑表单未展示生效起止日 | 表单补充“生效期间”日期范围；后端必须保存并校验 |
| D-02 | 同一供应商任一日期只能有一套生效账期配置，期间不得重叠 | 原型只保存一个账期文本 | 账期配置独立建表，按生效期间追加保存，不覆盖历史 |
| D-03 | 列表至少展示成本账单数、待结清数、已结清数、待结清金额、已结清金额、累计成本金额 | 原型只展示成本账单数、待结清金额、已结清金额 | 正式页面补齐三类账单数量和累计成本金额 |
| D-04 | 所有金额按币种分别统计，不同币种不得相加 | 原型样本每个供应商只展示单一币种文本 | 响应使用币种统计列表，页面按币种分行或弹层展示 |
| D-05 | 最近动态包含最近账期、最近账单编号、最近账单状态、最近更新时间 | 原型列表未完整展示 | 列表可保留最近账单编号/状态，完整最近动态放详情 |
| D-06 | 可启用、停用；未被引用时允许删除 | 原型只有新增、编辑、详情，未提供删除入口 | 初版实现启停；删除是否开放见疑问 Q-06 |
| D-07 | 档案变更只影响后续任务和账单，不回写历史 | 原型使用浏览器本地对象直接修改 | 成本账单和导入任务后续必须保存供应商快照 |
| D-08 | 详情可查看各币种统计、最近成本账单并跳转筛选后的账单列表 | 原型只有汇总卡片和普通跳转 | 详情增加币种统计表和最近账单列表；跳转携带 supplierId |

### 2.4 现有代码和数据库基线

#### 2.4.1 Admin Shell

当前已有：

1. 路由：`admin_shell/src/router/billing.js` 中的 `costSupplier`。
2. 页面：`admin_shell/src/views/billing/costSupplier/index.vue`。
3. 公共静态脚手架：`admin_shell/src/views/billing/costCenter/components/CostListScaffold.vue`。
4. 路由权限占位值：`meta.code = "CostSupplier"`。

当前页面只是静态配置：

1. `loadList()` 固定清空列表。
2. 新增、详情和其它操作只提示“待后端接口确认后接入”。
3. 没有供应商管理 API 定义。
4. 公共脚手架不支持多币种统计、账期配置编辑、详情抽屉和真实启停。

因此正式落地时，供应商页面应改为独立业务页面，不继续把复杂逻辑堆入 `CostListScaffold.vue`，避免影响其它仍为占位状态的成本中心页面。

#### 2.4.2 BMS、Platform Admin

当前没有供应商财务档案对应的 Model、Mapper、Service、Feign、Controller 和 Platform Admin 门户代理接口。

现有成本费项索引链路已经形成可复用的实现模式：

```text
admin_shell
  → /platform/portal/bms/...
platform-admin Controller
  → BMS Feign Client
bms web Controller
  → Service
  → Mapper + XML
  → tmall_bms
```

供应商管理应沿用该链路，但数据隔离、账期配置、分币种统计和状态控制必须按本方案单独实现。

#### 2.4.3 现有 SRM 供应商能力

`admin` 服务已通过 `supplychain-srm-client` 使用 SRM 供应商服务，现有接口主要面向仓储供应商、运输供应商、易速供应商、合同、价格和认证流程。

当前无法从本工作区确认以下口径：

1. SRM 中是否包含成本中心所需的全部供应商类型。
2. SRM 供应商编码是否能作为 BMS 成本供应商的稳定业务主键。
3. SRM 状态与 BMS “启用/停用”的含义是否一致。
4. BMS 是否允许新增一个 SRM 中不存在的临时成本供应商。
5. SRM 服务的数据隔离范围和 BMS 成本中心是否一致。

因此不能直接把 `SupplierDTO` 当作 BMS 供应商财务档案，也不能在未确认前让 BMS 强依赖 SRM 在线可用性。

#### 2.4.4 开发库

开发库 `tmall_bms` 当前与本功能相关的结论：

1. 没有名称包含 `supplier` 的表。
2. 没有成本账单、成本账单结清记录表。
3. 已有 `ar_bill`、`fee_detail` 等客户侧账单表，不能直接承载供应商成本账单。
4. 已有 `cost_fee_index`，可作为后续供应商账单导入的标准成本费项基础，但不保存供应商档案。

供应商列表中的账单数量和金额统计目前没有真实数据源，必须依赖后续成本账单模块。

2. 待结清账单数。
3. 已结清账单数。
4. 待结清金额。
5. 已结清金额。

## 4. 总体技术方案

### 4.1 聚合设计

将“供应商财务档案”作为 BMS 聚合根，拆为三张表：

```text
cost_supplier_profile
  ├── 1:N cost_supplier_board
  └── 1:N cost_supplier_period_config

未来：
cost_supplier_profile
  ├── 1:N cost_bill
  ├── 1:N cost_bill_import_task
  └── 1:N cost_detail
```

设计原因：

1. 供应商可适用多个成本板块，不能用逗号字符串保存。
2. 账期配置有生效期间、不可重叠和历史追溯要求，不能只保存在主表当前值。
3. 供应商基本信息与账期版本的生命周期不同。
4. 概念实体关系图允许物理落库时合并或拆分实体；本方案把“供应商主体”和“财务档案”合并为 BMS 聚合根，避免当前阶段额外建立无业务字段的主体表。

### 4.2 SRM 对接策略

推荐采用“BMS 自有财务档案 + 可选 SRM 来源引用”：

1. BMS 以 `cost_supplier_profile.id` 作为成本域内部稳定主键。
2. 预留 `source_system`、`source_supplier_id`，用于以后绑定 SRM。
3. `supplier_code`、`supplier_name` 在 BMS 中持久化，不能在查询时实时反查 SRM。
4. SRM 绑定后是否允许修改编码由最终主数据口径决定。
5. 成本账单、导入任务和成本明细必须同时保存 `supplier_id` 及编码、名称快照。
6. SRM 不可用时，不应影响历史成本账单查询和结清。

若产品最终确认“只能从 SRM 选择供应商”，前端新增表单改为供应商选择器，但本方案的财务档案、账期配置、板块关联和历史快照结构仍可保留。

### 4.3 数据隔离

按当前 BMS 项目规范，三张业务表均包含：

- `sc_id`
- `shop_id`
- `user_id`

Platform Admin 从登录上下文填充隔离字段，Admin Shell 不得传入或覆盖。

默认唯一性按 `sc_id + shop_id + user_id + supplier_code` 处理。该口径是否应上收为供应链级共享，属于疑问 Q-02；未确认前不得省略隔离字段。

### 4.4 历史不回写

供应商档案编辑只影响未来业务：

1. 历史成本账单保留创建时的供应商编码、名称、默认币种、成本板块和实际账期。
2. 历史导入任务保留供应商档案快照或对应字段快照。
3. 历史成本明细保留供应商 ID、编码和名称。
4. 当前档案停用或改名，不修改历史快照。

## 5. 页面落地方案

### 5.1 页面结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 供应商管理                                  [新增供应商财务档案]     │
│ 维护成本账期、适用成本板块及按币种分桶的账单金额                    │
├──────────────────────────────────────────────────────────────────────┤
│ 供应商 [编码或名称____] 成本板块 [全部▼] 账期类型 [全部▼]           │
│ 状态 [全部▼] 成本账期范围 [开始日期 至 结束日期] [查询] [重置]       │
├──────────────────────────────────────────────────────────────────────┤
│ 编码 │ 名称 │ 板块 │ 账期 │ 当前账期 │ 默认币种 │ 账单统计 │ 状态 │
│ ...  │ ...  │ ...  │ ...  │ ...      │ ...      │ 分币种   │ ...  │
├──────────────────────────────────────────────────────────────────────┤
│                                                       分页           │
└──────────────────────────────────────────────────────────────────────┘
```

### 5.2 查询规则

1. 首次进入按更新时间倒序、ID 倒序查询。
2. 供应商关键词去除首尾空格后，模糊匹配编码或名称。
3. 成本板块筛选通过关联表 `EXISTS` 查询，不使用逗号字符串。
4. 账期类型按当前或筛选期间内有效的账期配置查询。
5. 成本账期范围使用日期范围控件：
   - 查询与选择范围有交集的有效账期配置。
   - SQL 使用 `effective_start_date <= endDate` 和 `effective_end_date >= startDate`。
   - 不在 WHERE 列上使用 `DATE_FORMAT` 等函数。
6. 查询、重置和筛选变化均把页码重置为 1。
7. 页面大小默认 20，最大 200。

### 5.3 列表字段

| 字段 | 展示规则 |
| --- | --- |
| 供应商编码 | 可点击进入详情 |

### 5.4 新增/编辑表单

| 字段 | 新增 | 编辑 | 校验 |
| --- | --- | --- | --- |
| 供应商编码 | 必填 | 只读 | 当前隔离范围内唯一；最长 64 |
| 供应商名称 | 必填 | 可编辑 | 最长 128 |
| 状态 | 默认启用 | 可编辑 | `ENABLED`/`DISABLED` |
| 默认币种 | 必填 | 可编辑 | 三位大写币种代码 |
| 适用成本板块 | 必填、多选 | 可编辑 | 至少一项，最多五项 |
| 成本账期类型 | 必填 | 以新版本生效 | 周/半月/月/自然天 |
| 周期天数 | 自然天必填 | 自然天必填 | 大于等于 1，默认 7 |
| 首个账期开始日 | 自然天必填 | 自然天必填 | 单日控件 |
| 生效期间 | 必填开始日 | 新配置必填开始日 | 日期范围；结束日可空 |
| 备注 | 选填 | 可编辑 | 最长 500 |

保存时：

1. 新增档案、板块和首个账期配置在同一事务提交。
2. 编辑基本信息时使用行锁或版本号防止覆盖更新。
3. 修改账期不能覆盖原记录，必须新增配置版本。
4. 新账期生效期间与已有配置重叠时拒绝保存。
5. 停用必须二次确认。
6. 保存期间按钮进入 loading，禁止重复提交。

### 5.5 当前成本账期计算

先根据当前日期获取唯一生效的账期配置，再按类型计算：

1. 周：
   - 周一为开始日。
   - 周日为结束日。
2. 半月：
   - 1 日至 15 日。
   - 16 日至月末。
3. 月：
   - 当月 1 日至月末。
4. 自然天：
   - 以首个账期开始日为锚点。
   - `offset = floor(锚点日至当前日的天数 / 周期天数)`。
   - 开始日为 `anchor + offset * cycleDays`。
   - 结束日为 `开始日 + cycleDays - 1`。

计算结果还应与配置生效期间取交集。当前日期不存在生效配置时，展示“当前无生效账期”，不能使用最近一张成本账单的实际账期代替。

### 5.6 详情抽屉

详情至少包含：

1. 档案基本信息。
2. 当前账期配置和当前成本账期。
3. 历史/未来账期配置列表。
4. 适用成本板块。
5. 按币种的账单数量和金额统计。
6. 最近成本账单列表。
7. 跳转成本账单按钮，携带 `supplierId`、可选账期范围。
8. 导入设置快照摘要只在导入模块落地后展示，本期不制作模拟数据。

## 6. 数据库设计

### 6.1 供应商财务档案

```sql

  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `profile_no` varchar(64) NOT NULL COMMENT '供应商财务档案编号，全局唯一',
  `sc_id` bigint(20) NOT NULL COMMENT '供应链ID',
  `shop_id` bigint(20) NOT NULL COMMENT '店铺ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `source_system` varchar(32) NOT NULL DEFAULT 'BMS' COMMENT '供应商来源系统：BMS/SRM',
  `source_supplier_id` bigint(20) unsigned DEFAULT NULL COMMENT '来源系统供应商ID',
  `supplier_code` varchar(64) NOT NULL COMMENT '供应商编码',
  `supplier_name` varchar(128) NOT NULL COMMENT '供应商名称',
  `supplier_status` varchar(16) NOT NULL DEFAULT 'ENABLED' COMMENT '供应商状态：ENABLED/DISABLED',
  `default_currency` varchar(16) NOT NULL COMMENT '默认币种，ISO 4217三位大写代码',
  `remark` varchar(500) DEFAULT NULL COMMENT '财务对账口径、账期例外及其它备注',
  `version` int(11) NOT NULL DEFAULT '0' COMMENT '乐观锁版本号',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除：0正常，1删除',
  `active_supplier_code` varchar(64)
    GENERATED ALWAYS AS (CASE WHEN `is_deleted` = 0 THEN `supplier_code` ELSE NULL END) STORED
    COMMENT '有效供应商编码唯一键辅助列',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_supplier_profile_no` (`profile_no`),
  UNIQUE KEY `uk_cost_supplier_scope_code`
    (`sc_id`, `shop_id`, `user_id`, `active_supplier_code`),
  KEY `idx_cost_supplier_scope_status`
    (`sc_id`, `shop_id`, `user_id`, `supplier_status`, `is_deleted`, `updated_at`),
  KEY `idx_cost_supplier_source` (`source_system`, `source_supplier_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='BMS成本供应商财务档案';
```

设计说明：

1. `id` 是成本域内部关联主键。
2. `profile_no` 用于审计和外部展示，不使用数据库自增 ID 作为业务编号。
3. `supplier_code` 创建后默认不可修改。
4. `source_supplier_id` 仅用于可选绑定，不作为历史查询唯一依据。
5. `version` 用于基本信息并发更新。
6. 金额统计不反写主表，避免账单变更后主表统计失真。

### 6.3 供应商成本账期配置

```sql
CREATE TABLE `cost_supplier_period_config` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `config_no` varchar(64) NOT NULL COMMENT '账期配置编号，全局唯一',
  `supplier_id` bigint(20) unsigned NOT NULL COMMENT '供应商财务档案ID',
  `sc_id` bigint(20) NOT NULL COMMENT '供应链ID',
  `shop_id` bigint(20) NOT NULL COMMENT '店铺ID',
  `user_id` bigint(20) NOT NULL COMMENT '用户ID',
  `period_type` varchar(16) NOT NULL COMMENT '账期类型：WEEK/HALF_MONTH/MONTH/NATURAL_DAY',
  `natural_days` int(11) DEFAULT NULL COMMENT '自然天周期天数，仅NATURAL_DAY使用',
  `anchor_date` date DEFAULT NULL COMMENT '首个账期开始日，仅NATURAL_DAY使用',
  `effective_start_date` date NOT NULL COMMENT '生效开始日',
  `effective_end_date` date DEFAULT NULL COMMENT '生效结束日，为空表示长期有效',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除：0正常，1删除',
  `created_by` bigint(20) unsigned NOT NULL COMMENT '创建人用户ID',
  `updated_by` bigint(20) unsigned NOT NULL COMMENT '最后更新人用户ID',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_cost_supplier_period_config_no` (`config_no`),
  KEY `idx_cost_supplier_period_effective`
    (`supplier_id`, `is_deleted`, `effective_start_date`, `effective_end_date`),
  KEY `idx_cost_supplier_period_scope`
    (`sc_id`, `shop_id`, `user_id`, `supplier_id`, `is_deleted`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci
  ROW_FORMAT=DYNAMIC COMMENT='供应商成本账期配置';
```

约束规则：

1. `period_type` 为 `NATURAL_DAY` 时：
   - `natural_days >= 1`。
   - `anchor_date` 不为空。
2. 其它类型：
   - `natural_days` 为空。
   - `anchor_date` 为空。
3. `effective_end_date` 不为空时不得早于 `effective_start_date`。
4. 同一供应商有效配置的生效期间不得重叠。
5. MySQL 无法用普通唯一索引表达日期区间不重叠，Service 写入时必须：
   - 对供应商档案 `SELECT ... FOR UPDATE`。
   - 查询重叠配置。
   - 无重叠后插入。
6. 重叠查询使用：

```sql
SELECT COUNT(1)
FROM cost_supplier_period_config
WHERE supplier_id = #{supplierId}
  AND is_deleted = 0
  AND effective_start_date <= #{effectiveEndOrMax}
  AND (effective_end_date IS NULL OR effective_end_date >= #{effectiveStart});
```

### 7.5 Service 关键规则

#### 新增

1. 校验隔离字段、编码、名称、默认币种、板块和账期配置。
2. 对供应商编码去除首尾空格并统一保存口径。
3. 校验当前范围内编码唯一。
4. 新增主表。
5. 批量新增成本板块。
6. 校验账期参数并新增首个配置。
7. 三步在同一事务完成。

#### 编辑

1. `SELECT ... FOR UPDATE` 查询档案。
2. 校验数据隔离字段匹配。
3. 使用版本号防止旧页面覆盖新修改。
4. 供应商编码默认不可修改。
5. 比较板块集合并新增/逻辑删除差异项。
6. 基本信息变化更新主表。
7. 账期变化时新增配置，不覆盖历史记录。
8. 档案名称、币种、板块和账期变化不回写历史账单。

#### 启停

1. 启用和停用均加事务。
2. 停用前加行锁。
3. 停用后：
   - 不出现在导入供应商选项中。
   - 禁止新建导入任务和成本账单。
   - 历史账单仍允许归集、分摊、调账和结清。
4. 重复提交相同状态按幂等成功处理。

#### 删除

若最终开放删除：

1. 仅逻辑删除。
2. 必须先检查导入任务、成本明细、成本账单、分摊规则和审计记录引用。
3. 有任何业务引用时拒绝删除，只允许停用。
4. 主表、板块关联和未生效账期配置在同一事务逻辑删除。

### 7.6 Mapper 和 SQL 规范

1. Mapper 接口只声明方法。
2. 动态 SQL 全部写入 `CostSupplier-mapper.xml`。
3. 使用 `<resultMap>` 显式映射。
4. 列片段和查询条件使用 `<sql>` + `<include>` 复用。
5. 分页先 `COUNT`，再查询列表。
6. 隔离条件放在 WHERE 最前面。
7. 账期范围使用原始日期范围比较，不对列使用 SQL 函数。
8. 成本板块使用 `EXISTS`，避免 JOIN 导致供应商重复和统计放大。
9. 新增使用 `useGeneratedKeys` 回写主键。
10. 所有写 Service 方法使用 `@Transactional(rollbackFor = Exception.class)`。

2. BMS 可以独立新增成本供应商。
3. BMS 可选择 SRM 供应商，也允许新增临时成本供应商。

建议：采用第 3 种。BMS 保存自有财务档案，SRM 引用可选；绑定 SRM 时保存来源 ID 和编码、名称快照。

### Q-02：供应商档案按什么范围共享？【阻塞唯一键与查询条件】

可选口径：

1. 全平台全局共享。
2. 供应链级共享。
3. 店铺级共享。
4. 供应链 + 店铺 + 用户三维隔离。

建议：未确认前遵循 BMS 当前开发规范，使用三维隔离；如果业务确认财务档案应在供应链内共享，再统一调整查询范围和唯一键，不能只在页面放宽。

### Q-03：供应商编码由谁生成？【阻塞表单与编码规则】

原型允许财务输入，PRD只要求唯一，未定义生成规则。

建议：若绑定 SRM，沿用 SRM 编码；BMS 自建时由后端生成 `CSP_{yyyyMMddHHmmss}_{6位随机串}`，页面不允许自由输入，避免编码格式和重复问题。若业务必须录入外部供应商编码，应另设“外部供应商编码”，不要替代系统主键。

### Q-04：账期配置修改如何生效？【阻塞编辑事务】

需确认：

1. 是否允许回溯修改已生效但尚未用于导入的配置。
2. 新配置是否只能从未来日期生效。
3. 是否允许提前结束当前配置并立即启用新配置。

建议：已被导入任务引用的配置不可修改；未被引用的未来配置可编辑；其它变更采用“结束旧配置 + 新增新配置”，并保留历史。

### Q-05：自然天锚点晚于生效开始日时如何处理？【影响当前账期计算】

建议：要求锚点日期不晚于生效开始日；否则在锚点前不存在可推导账期，容易产生导入空档。

### Q-06：初版是否开放删除？【影响 API、按钮和引用检查】

PRD允许删除未被引用的供应商，原型未提供删除入口。

建议：初版先不开放删除，只提供停用。待导入任务、成本明细、成本账单和审计表全部落地后，再实现完整引用检查和逻辑删除。

### Q-07：成本账单模块尚未落地时，列表统计如何展示？【影响一期验收】

建议：接口返回 `statisticsAvailable=false`，页面展示 `--` 和说明，不返回伪造的 0；成本账单模块上线后切换为真实统计。

### Q-08：默认币种可选范围来自哪里？【影响表单选项】

原型硬编码 `CNY/TWD/USD/HKD/JPY/EUR`，PRD只要求默认币种。

建议：复用系统统一币种字典或 ISO 4217 启用币种；前端不得长期硬编码六种币种。后端至少校验三位大写代码。

### Q-09：适用成本板块移除时是否检查历史或进行中任务？【影响编辑校验】

建议：历史账单保留快照，不阻止移除；存在待执行/导入中的任务时禁止移除对应板块；移除只影响后续新建任务。

### Q-10：列表是否必须一次展开全部币种统计？【影响页面宽度和响应体】

建议：列表展示币种摘要，点击展开各币种明细；详情展示完整币种统计表。不得为了压缩列宽把不同币种折算后合并成单一金额。

### Q-11：正式权限码是什么？【阻塞路由和按钮权限】

当前路由使用占位值 `CostSupplier`。

建议至少拆分：

- `bms:costSupplier:view`
- `bms:costSupplier:create`
- `bms:costSupplier:edit`
- `bms:costSupplier:status`
- `bms:costSupplier:delete`（若后续开放）

最终值必须与后端菜单权限配置一致。

### Q-12：详情中的“导入设置快照 8 项”是否属于本期？【影响详情范围】

建议：不属于本期。只有供应商账单导入模块形成真实快照后才展示，当前正式页面不保留原型模拟数量。

## 12. 最终落地结论

本期供应商管理应建设为 BMS 自有的供应商财务档案能力，而不是复制 SRM 全套供应商管理，也不能只保留原型静态页面。

推荐落地结果：

1. 新增 `cost_supplier_profile`、`cost_supplier_board`、`cost_supplier_period_config` 三张表。
2. 建立完整的 BMS Model、Mapper XML、Service、Feign、Controller 链路。
3. 通过 Platform Admin 注入登录隔离信息和操作人。
4. 将 `admin_shell` 供应商页面改为真实列表、表单、详情和启停页面。
5. 账期配置独立版本化，补齐原型遗漏的生效期间和重叠校验。
6. 金额统计按币种建模，不跨币种相加。
7. 成本账单未落地前明确展示统计不可用，不制作假数据。
8. 供应商档案变更只影响未来业务，历史成本账单和导入任务保存快照。
9. 初版建议不开放删除，先用停用保证历史引用安全。
10. SRM 对接保留可选来源引用，最终新增交互在 Q-01 确认后实施。

完成 Q-01、Q-02、Q-03、Q-04、Q-07 和 Q-11 的口径确认后，本方案即可进入编码实施。
