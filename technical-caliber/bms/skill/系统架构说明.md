# 系统架构说明

## 项目职责

当前系统由两个前端项目和两个后端项目组成，整体按“前端页面 -> 平台 API -> BMS 内部服务”的方式分层。

### super_admin_front

`super_admin_front` 是超级管理端前端项目，主要负责：

- 前端登录入口。
- 菜单管理、权限相关管理。
- 部分非集运业务相关页面。

本项目更偏平台管理能力，不作为集运业务和 BMS 计费页面的主要承载入口。

### admin_front

`admin_front` 是集运业务前端项目，主要负责：

- 集运订单相关页面。
- 集运客户相关页面。
- 计费 BMS 相关页面。
- 账单配置、账单查看、账单生成结果等业务页面。

涉及集运业务操作、BMS 计费配置和账单处理时，页面优先放在 `admin_front`。

### platform-admin

`platform-admin` 是提供给 `admin_front` 调用的后端 API 项目，主要负责：

- 接收 `admin_front` 的页面请求。
- 做登录态、权限、参数校验、业务编排。
- 对外暴露平台管理和集运业务 API。
- 调用内部微服务完成具体业务能力。

对于 BMS 相关页面，`admin_front` 不直接调用 `bms` 服务，而是通过 `platform-admin` 提供的 API 间接访问。

### bms

`bms` 是 BMS 计费内部微服务，主要负责：

- 账单配置的保存、查询和编辑。
- 费项、费用明细、账单生成等计费核心逻辑。
- 为 `platform-admin` 提供内部服务接口。

`bms` 不直接面向前端页面，主要作为 `platform-admin` 的内部依赖服务。

## 调用链路

集运和 BMS 相关页面的标准调用链路如下：

```text
admin_front
    -> platform-admin
        -> bms
            -> tmall_bms / 其他业务数据库
```

超级管理端相关页面的调用链路如下：

```text
super_admin_front
    -> platform-admin
        -> 相关平台管理服务或数据库
```

## BMS 页面接口原则

BMS 页面接口对接时，建议遵循以下原则：

- 页面入口、路由和展示逻辑放在 `admin_front`。
- 页面请求统一调用 `platform-admin` 暴露的 API。
- `platform-admin` 负责把前端请求转换成内部服务调用。
- BMS 核心数据读写、账单配置、账单生成逻辑放在 `bms`。
- 不建议让前端直接访问 `bms`，避免绕过平台权限、登录态和统一网关逻辑。

## 本地启动端口

本地开发环境常用端口如下：

| 项目 | 端口 | 说明 |
| --- | --- | --- |
| `super_admin_front` | `9529` | 超级管理端前端 |
| `admin_front` | `9528` | 集运业务前端 |
| `platform-admin` | `8896` | 前端调用的 API 服务 |
| `bms` | `8908` | BMS 内部微服务 |
