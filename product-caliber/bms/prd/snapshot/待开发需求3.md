# 待开发需求：适配新版系统侧报表并完成两侧报表比对

## 1. 需求概要

- 目的：财务试运营期间，继续使用现有财务侧报表，并适配 BMS 新版应收账单对账报表，使财务能够按业务订单和费项并排核对两侧原始金额，定位缺单、重复数据、文件结构异常和费用取数差异。
- 影响范围：辅助测试菜单的`报表比对`页面；财务侧报表导入、系统侧报表导入、订单关联、动态费项列生成、履约时间选择、结果展示和结果导出。
- 不包含：返款账单比对、客户对账、正式账单核销或审批、币种换算、来源报表或 BMS 费项池反写，以及结果跨登录或跨天保存。
- 生效边界：仅在财务试运营 BMS 阶段使用；试运营结束后关闭入口，不再创建新的比对任务。

## 2. 核心场景与业务规则

### 2.1 两侧报表怎样上传并开始比对？

- 类型：修改。
- 修改前表现及依据：两侧文件导入后即可点击比对，页面没有明确要求两侧均成功上传；两侧均按指定模板导入。依据为目标提交的父提交 PRD `19.4.2.1` 原规则。
- 参与方、触发和对象：财务在 BMS 辅助测试菜单的`报表比对`页面，分别处理一份财务侧`.xlsx`报表和一份系统侧`.xlsx`报表。
- 业务落点：`报表比对`页面；原型路径为`/billing/report-compare`。
- 目标系统处理：页面同一行显示`财务侧报表`卡片、`系统侧报表`卡片和`履约时间`控件；两侧各显示一个`上传`按钮和已上传文件名。只有两侧均上传成功后，结果区工具栏中的`开始比对`才可用；点击后系统才生成并展示结果。
- 完整业务结果：比对只使用本次成功上传的两份文件；任一侧重新上传后，既有结果立即失效，但保留当前`履约时间`选择。
- 局部边界：比对入口不依赖账单是否已生成、待结算或已结清；尚未生成结果时`导出`不可用。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-1">19.4.2.1 使用入口与前提</a>。

### 2.2 系统侧报表怎样识别？

- 类型：修改并删除旧格式支持。
- 修改前表现及依据：财务侧报表和系统侧报表均按指定模板识别；旧版系统侧单 Sheet 报表可以进入比对。依据为父提交 PRD `19.4.2.1` 原规则。
- 参与方、触发和对象：财务上传系统侧报表并点击`开始比对`后，系统识别文件结构和账单明细。
- 目标系统处理：
  1. 财务侧格式保持不变，继续识别现有模板中的 Sheet、表头、数据起始行、`订单号`、`承运单号`、`出库时间`、`结单时间`和费用字段。
  2. 系统侧必须符合<a href="../PRD.账单系统.md#section-19-6-1">19.6.1 面向客户的对账报表导出</a>中的新版应收账单对账报表格式。
  3. 系统只读取`费项明细` Sheet；`账单汇总`和`往期账单冲正信息`不参与比对；返款账单文件不得作为系统侧输入。
  4. 文件缺少`费项明细`、只有`返款明细`或缺少新版必需字段时，不得开始比对，并一次性提示缺少的 Sheet 或字段。
  5. 识别到旧版字段`内部订单号`且不存在`费项明细`时，提示财务从 BMS 重新导出新版应收账单对账报表，不混合猜测新旧格式。
- 完整业务结果：符合新版格式的`费项明细`才能进入订单级比对；旧版系统侧单 Sheet 报表不能形成结果。
- 局部边界：两侧费项结算币种必须一致；系统不在比对过程中换算币种，系统侧金额单元格中的币种只属于 Excel 显示格式，读取时只保留金额数值。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-1">19.4.2.1 使用入口与前提</a>。

### 2.3 新版系统侧明细怎样转为订单级数据？

- 类型：新增处理规则。
- 参与方、触发和对象：系统在成功上传新版系统侧报表并开始比对后，整理`费项明细`中的业务订单父行和尾程包裹子行。
- 目标系统处理：
  1. `业务订单号`不以`>`结尾的记录认定为业务订单父行。
  2. 以`>`结尾的记录认定为尾程包裹子行；`>`只是导出文件中的层级展示符号，不属于真实业务订单号，整理时移除。
  3. 订单级比对只保留业务订单父行；系统侧金额直接读取父行，不累计尾程包裹子行金额。
  4. 整理后的系统侧数据至少保留业务订单号、财务选择的履约时间字段和全部动态费项金额字段，并保留原费项字段名。
- 完整业务结果：新版系统侧报表被转换为一条业务订单对应一条可比数据，供订单关联和动态费项比对使用。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-2">19.4.2.2 新版系统侧报表怎样进入 SQL 比对？</a>。

### 2.4 两侧订单怎样关联？

- 类型：修改。
- 修改前表现及依据：以财务侧订单号和系统侧旧版订单字段构造订单并集；存在性标记按订单并集生成。依据为父提交 PRD `19.4.2.2` 原规则。
- 参与方、触发和对象：系统整理两侧报表后，对财务侧`订单号`和系统侧`业务订单号`进行订单级关联。
- 目标系统处理：
  1. 以系统侧业务订单父行为结果主集合。
  2. 财务侧`订单号`与系统侧`业务订单号`相等时，认定为同一业务订单。
  3. 财务侧`订单号`为`/`时，附加费用和代收返款使用`承运单号`作为关联值；财务侧订单号为空时，不自动改用承运单号。
  4. 系统侧业务订单号为`/`的记录排除；空值、重复值和未关联记录不自动修正。
  5. 对应侧存在订单时，`财务侧报表`或`系统侧报表`标记为`✅`，否则留空。
- 完整业务结果：系统侧独有订单保留在结果中；财务侧独有订单不单独形成结果行。订单存在性与费项金额可以并排查看。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-3">19.4.2.3 两侧订单怎样关联？</a>；SQL 业务口径见<a href="../analysis/对账报表比对分析.md#财务侧报表与系统侧报表比对-sql">财务侧报表与系统侧报表比对 SQL</a>。

### 2.5 两侧费项怎样对齐和动态输出？

- 类型：修改。
- 修改前表现及依据：费项可以使用配置映射、名称相似度或人工确认进行归一。依据为父提交 PRD `19.4.2.4` 原规则。
- 参与方、触发和对象：系统在订单关联后，识别两侧报表的费用字段并生成比对列；财务负责保证同一费项在两侧使用相同字段名。
- 目标系统处理：
  1. 分别识别两侧全部费用字段，不设置固定费项清单。
  2. 只有字段名完全相等才认定为同一费项；文字、字符或空格任一处不同，都视为两个不同费项。
  3. 不提供费项映射区域、别名、名称相似度、匹配建议或人工改名入口。
  4. 按两侧费项字段的并集生成动态列；任一侧存在的费项，都输出一组相邻的`<费项名称><财务侧>`和`<费项名称><系统侧>`列，另一侧没有金额时留空。
  5. `运费`和`派送费`分别排在第一组和第二组；其它费项按原字段名排序；页面和导出保持相同顺序。
  6. 财务侧`运费`、`派送费`按订单号汇总；`超材费`、`转板费`、`税金`按收件人地址识别并汇总`其它费用`；收件人地址为`代收返款`时，分别汇总`应收货款`和`手续费`。
  7. 财务侧金额按业务订单和费项汇总后按三位小数四舍五入；系统侧直接读取业务订单父行金额，不累计子行。
- 完整业务结果：不论费项出现在两侧还是仅出现在一侧，结果都能输出完整的成对比对列；同名费项可直接并排人工核对，异名费项分别保留。
- 局部边界：异名费项不是导入异常，不触发人工映射流程。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-4">19.4.2.4 两侧费项怎样按字段名对齐和汇总？</a>。

### 2.6 财务怎样选择履约时间并查看结果？

- 类型：修改。
- 修改前表现及依据：结果固定使用`核重时间`，只用于排序和人工核对。依据为父提交 PRD `19.4.2.5` 原规则。
- 参与方、触发和对象：财务在报表比对页面选择履约时间并查看订单级结果。
- 目标系统处理：
  1. 页面固定提供`履约时间`，可选`出库时间`或`结单时间`，默认`出库时间`。
  2. 系统分别从两侧报表读取所选字段；同一订单优先取财务侧值，财务侧为空时取系统侧值，两侧均为空时留空。
  3. 结果固定列依次为`业务订单号`、所选履约时间、`财务侧报表`、`系统侧报表`；动态费项列位于固定列之后。
  4. 结果默认按所选履约时间倒序；时间相同时按业务订单号倒序。
  5. 生成结果后切换履约时间，只更新结果第二列的列名、取值和排序，不重新执行金额比对。
- 完整业务结果：财务可以在开始比对前或生成结果后，用更符合当前核对场景的履约时间查看和排序结果。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-1">19.4.2.1 使用入口与前提</a>、<a href="../PRD.账单系统.md#section-19-4-2-5">19.4.2.5 结果怎样展示和导出？</a>。

### 2.7 财务怎样导出比对结果？

- 类型：修改。
- 修改前表现及依据：导出结果保持页面列结构和金额原值；此前没有新版费项明细、导入反馈 Sheet 和结果时间切换要求。依据为父提交 PRD `19.4.2.5` 原规则。
- 参与方、触发和对象：财务在结果表工具栏点击`导出`。
- 目标系统处理：结果生成后，系统按当前履约时间字段和当前页面列结构导出一个明细 Sheet，并将文件结构异常、缺少字段、重复订单、重复承运单号和补充匹配未命中等导入反馈写入独立的`比对说明` Sheet；没有反馈时仍保留说明 Sheet 表头，不写空白说明行。
- 完整业务结果：财务获得一份与页面当前结果一致、可线下留存和人工核对的比对文件；导出不自动判定两侧金额一致或差异。
- 来源位置：<a href="../PRD.账单系统.md#section-19-4-2-5">19.4.2.5 结果怎样展示和导出？</a>。

## 3. 生效、存量与上下游

- 生效范围和时点：目标规则适用于提交 `aa49c2249319f5c4c41a1b473cf0398a2a96faa5` 对应的新版报表比对能力；仅在财务试运营 BMS 阶段开放。
- 存量数据与已生效结果：旧版系统侧单 Sheet 报表不再作为正式输入；既有比对结果不要求跨登录或跨天保存，重新上传任一侧文件后当前结果失效。需要留存时，财务通过导出功能保存当前结果。
- 上游输入：现有财务侧报表；BMS 新版应收账单对账报表的`费项明细` Sheet及其业务订单父行、履约时间字段和动态费项金额字段。
- 下游结果：页面展示订单级、费项级两侧金额；导出文件供财务内部人工核对，不进入客户对账、账单核销或财务审批流程。
- 不反写：比对过程不得覆盖、修正或反写来源报表，不改变正式账单、BMS 费项池或费项配置。
