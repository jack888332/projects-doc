# 供应商侧账单样本分析

## 1. 文档目的

本文分析 `aidocs/product-caliber/bms/prototype/财务侧成本账单` 下现有的 10 份供应商侧账单样本，用于说明原始账单在文件结构、关键单号、成本金额、成本粒度和辅助字段上的实际差异，并为《财务系统 PRD》`13.5 供应商侧账单导入`提供样本依据。

本文不是供应商导入模板，也不要求财务按本文重新整理原始文件。正式产品规则以《财务系统 PRD》为准；本文只记录样本事实、分析判断和导入建议。

## 3. 总体结论

### 3.1 不宜采用固定导入模板

10 份样本不存在可由财务低成本维护的统一表格结构，主要差异如下：

1. 同一业务板块的关键单号不同。派送账单可能使用宅配单号、追踪号、明细表号或出货单号；清关账单可能使用清关条码、主提单号、分提单号、报单号、税单号或柜号。
2. 同一文件内可能同时出现逐票明细、账期汇总、付款跟踪、报价参考、内部核对和异常说明，不能把所有工作表都当作成本明细导入。
3. 同一原始行可能同时包含多项金额，例如运费、超大费、偏远费、报关费、税金、仓租、罚款或操作费；若要求财务预先拆行，容易重复计算或遗漏金额。
4. 部分费用只有月份、车种、提单、柜号或事件范围，无法直接定位到单个包裹或订单，不能为了满足模板而虚构业务单号。
5. 文件中存在大量用于业务识别但定义不稳定的字段，例如目的港、柜型、司机、行家、收件信息、货况和备注；将其全部固化为财务标准字段会增加维护成本。

因此，适合本批样本的方案是：财务直接上传供应商原始文件，系统按成本板块和历史配对记录推荐数据范围、关键单号和成本金额，财务确认后再由系统生成统一的 `BMS费项池` 成本明细。

### 3.2 五大板块都包含间接成本

成本板块不能直接等同于成本类别。同一份派送或清关账单中既可能有能落到单票的直接成本，也可能有按车趟、柜号、提单、批次或账期发生的间接成本。

| 成本板块 | 直接成本特征 | 间接成本特征 |
| :--- | :--- | :--- |
| 派送成本 | 具有宅配单号、追踪号、转单号或明确包裹范围。 | 车趟、续仓、批量贴单、货故赔款和账务调整只覆盖某个批次或事件。 |
| 清关成本 | 具有分提单号、报单号、税单号或明确票件范围。 | 仓租、罚款、规费、拆装柜、移仓、退运及主提单或柜号级费用覆盖多票货物。 |
| 海运成本 | 少数费用能够通过提单、柜号和业务关系直接定位。 | 海运费、拖柜费、操作费等通常按整票或整柜发生。 |
| 空运成本 | 少数费用能够通过提单、磅单和业务关系直接定位。 | 提单费、中港段费、打包费、压夜或查验费通常覆盖一批货物。 |
| 租车成本 | 具有车次和明确承载范围时可以直接归集到该范围。 | 样本以月份、地区和车种汇总为主，通常无法直接定位包裹。 |

### 3.3 工作表必须先区分业务角色

导入前应先判断工作表角色，再推荐数据范围：

| 工作表角色 | 样本特征 | 默认处理 |
| :--- | :--- | :--- |
| 成本明细 | 同时具有关键单号或明确费用范围，以及一个或多个成本金额列。 | 优先作为导入来源。 |
| 请款或账期汇总 | 按月份、账期、供应商或费用大类合计。 | 默认用于核对；不存在更细明细时，才可作为间接成本来源。 |
| 付款跟踪 | 记录账单金额、付款日期、付款金额和欠款。 | 用于结清核对，不作为成本费项主来源。 |
| 报价或计算参考 | 记录单价、价格表或核销价格。 | 不作为实际成本主来源。 |
| 内部核对 | 包含我方订单、重算金额、差额或核对结果。 | 用于辅助核对，不能与供应商原始收费明细重复导入。 |
| 异常或凭证 | 记录问题件、罚单、图片或异常原因。 | 有明确费用和范围时单独导入；否则只作为追溯材料。 |

## 4. 各文件分析

### 4.1 派送成本

#### 4.1.1 `台湾端派送 （东风.xlsx`

该文件覆盖范围最广，24 个工作表同时承载派送收费、税金、批量服务费、异常费用、账务调整和内部核对。它说明同一供应商也不能只保存一套固定字段配对，至少需要按工作表结构和费用口径区分配对结果。

| 工作表分组 | 工作表 | 主要字段或费用 | 分析判断 |
| :--- | :--- | :--- | :--- |
| 汇总与付款 | `2026`、`帳單總表` | 日期、各派送商费用、车趟费、货故赔款、税金、付款金额、累计应付、付款编号、汇率。 | 主要用于账期合计和付款核对，不应与明细工作表重复导入。 |
| 派送明细 | `黑貓`、`新竹`、`大榮`、`東風`、`未列帳派件`、`帳列`、`應收` | 袋号、提单号、追踪号、转单号、收件信息、重量、运费、转发费、超才费、手续费、税金、报单费。 | 可按追踪号、转单号或袋号识别直接成本；同一行多个金额列应分别展开。 |
| 贴单与批量作业 | `貼單`、`貼單拖袋費`、`貼單超才`、`貼單貨故賠款` | 订单编号、物流号码、袋号、提单号、件数、贴单费、拖车及叠货费、超才费、货故赔款。 | 有稳定单号时可直接归属；只有行家、批次、件数或金额时作为间接成本或待人工确认。 |
| 其他费用 | `續倉費用`、`車趟費`、`帳務調整` | 单号、日期、货柜号、车趟、件数、续仓费、车辆费用、超时费、调整金额和原因。 | 单号明确的可直接归属；车趟、货柜或批量调整通常进入成本池。 |
| 内部核对 | `新竹核对`、`大荣核对`、`东风核对`、`拖车核对` | 我方订单、客户、店铺、计费时间、供应商金额、重算金额和差额。 | 属于派生核对结果，不与供应商原始明细同时入池。 |
| 异常与辅助 | `问题件`、`代退貨款`、`平均` | 问题原因、索赔范围、退款资料、统计均值。 | `问题件`有明确赔款时可作为异常费用来源；退款资料含敏感信息，只保留成本所需手续费或赔款口径；统计表不入池。 |

建议优先识别的关键单号包括`追踪号`、`转单号`、`袋号`、`提单号`、`订单编号`、`物流号码`、`货柜号`和`税单号`。典型金额字段包括派送费、转发费、手续费、超才费、拖车及叠货费、运费合计、税金、报单费、车趟费、货故赔款和续仓费。

#### 4.1.2 `台湾端派送 （宅配通.xlsx`

文件只有`5月明細`一个工作表，核心字段包括`宅配單號`、`出貨單號`、`客戶別`、`取件日`、`規格`、`運費`、`超大`、`偏遠`和`跨區`。

1. `宅配單號`应作为首选关键单号，`出貨單號`可作为辅助关键单号。
2. `運費`、`超大`、`偏遠`和`跨區`代表不同费项，应分别展开为成本明细。
3. `出貨單號`为空时不得丢弃该行，仍可使用宅配单号追溯供应商收费并等待业务匹配。
4. 普通派送费通常具备直接归属条件；无法匹配包裹的附加费进入待人工确认或成本池。

#### 4.1.3 `台湾端派送 （顺盛.xlsx`

文件只有`Sheet1`一个工作表，核心字段包括`明細表號`、`請款書號碼`、`客戶用傳票_管理號碼`、发到站、件数、重量、`本款`、`聯運費`、`附加費用`、`請款金額`和代收手续费。

1. `明細表號`和`客戶用傳票_管理號碼`应优先作为关键单号，`請款書號碼`用于账单来源追溯。
2. `本款`、`聯運費`、`附加費用`和代收手续费应分别映射；`請款金額`若为这些字段的合计，不得再次导入。
3. 收件人、电话和地址只作为原始行辅助信息保留，不要求财务映射为成本标准字段。

### 4.2 清关成本

#### 4.2.1 `海快清关（东风.xls`与`空运清关（东风.xls`

两个文件具有相同的 12 个工作表名称和相近结构，但文件内容不同，且分别属于海快清关和空运清关。系统可以复用字段配对方式，但导入批次、成本场景和成本池范围必须分开，不得因结构相同而合并账单数据。

| 工作表 | 主要关键单号 | 主要费用或用途 | 分析判断 |
| :--- | :--- | :--- | :--- |
| `罰款總表` | 处罚或预收编号、袋号、分提单号 | 罚款、预收罚款、原因。 | 事件或批次级成本；无法定位单票时进入成本池。 |
| `２０２６ (無罰款)`、`帳單總表` | 月份、付款编号 | 清关费、税金、报关费、移仓、退运、罚款、赔款、派送和账期合计。 | 汇总核对和付款用途，不与明细工作表重复入池。 |
| `清關費` | 清关条码、主提单号、分提单号 | 一般清关费、包税清关费、处理费、传输报关费、赔款。 | 逐票明细优先作为导入来源；一行多金额列分别展开。 |
| `稅金` | 主提单号、报单号、袋号、分提单号、税单号 | 税金、报关费、运费、派送费。 | 可按税单、报单或分提单形成直接成本；覆盖多包裹时再分摊。 |
| `實名認證` | 报单号、主提单号、分提单号 | 实名认证费。 | 能定位分提单时直接归属，否则按报单范围分摊。 |
| `遠雄進倉重` | 主提单号、并袋号、分提单号、报单号 | 进仓重量、仓租和作业信息。 | 主提单、袋号或报单级间接成本居多。 |
| `罰款` | 公文号、袋号、分提单号 | 罚款金额和说明。 | 先保留处罚依据；按受影响范围归属或待人工确认。 |
| `移倉費` | 航班主号、分提单号 | 税金、仓租、查验、报关、移仓、规费、叉车等。 | 多金额列应分别展开；覆盖多包裹时进入成本池。 |
| `退運費用` | 提单号 | 出口或进口运费、报单费、规费、仓储手续费、改名、销毁、包装。 | 事件级费用，按受影响提单或包裹范围归集。 |
| `帳列下期` | 与清关明细相近 | 跨账期后移费用。 | 必须按实际归属账期处理，不能同时计入当前账期。 |
| `清关重量 核对` | 清关条码 | 计费重量、进仓重量、配送重量和差额。 | 内部核对资料，不作为独立成本金额来源。 |

#### 4.2.2 `海快清关（福广.xlsx`

该文件包含 9 个工作表，清关费按主号和柜号汇总，税金与规费则下钻到分提单、报单或税单粒度，体现了同一供应商账单内多种归集粒度并存。

| 工作表 | 核心字段 | 主要用途 | 导入判断 |
| :--- | :--- | :--- | :--- |
| `請款單(總) `、`請款單(清關費)` | 日期、主号或分号、柜号、件数、实际重量、请款重量 | 仓租、拆装柜、EZ Way、正报单费和合计。 | 请款汇总；有更细明细时用于核对，只有该层数据时按主号或柜号级间接成本导入。 |
| `請款單  (稅金)` | 日期、主号、柜号 | 税金合计。 | 与逐票税金明细核对，不与`稅金明細`重复导入。 |
| `稅金明細` | 主号、分号、报单号、税单号 | 税单金额、报关费。 | 逐票税费主来源，可按分号、报单号或税单号直接归属。 |
| `規費請款單` | 分号或主提单号 | 监视或分项规费、报单修改规费、短溢卸规费。 | 各规费列分别展开；不能定位单票时按报单或提单范围分摊。 |
| `請款明細表` | 主号、柜号、挂号 | 申报件数、各口径重量、重量差。 | 主要用于重量核对和支持柜号级费用分摊。 |
| `EZ Way 明細` | 主提单号、分提单号 | 认证日期和时间。 | 用于计算或核对 EZ Way 范围；无独立金额时不单独入池。 |
| `頻繁稅` | 主提单号、分提单号、报单号、税单号 | 扣缴金额。 | 有金额时作为税费明细导入。 |
| `罰單` | 报单号、主提单号、分提单号、案件号 | 罚款金额和原因。 | 事件级成本，按受影响范围归属或待人工确认。 |

### 4.3 海运成本

#### 4.3.1 `海快船公司（联多.xlsx`

文件包含`sheet1`和`sheet1 (2)`两个结构相近的工作表。核心字段包括推单日期、集运线路、目的港、提单号、柜数、柜型、柜号、报关单号、项数、总毛重，以及报关费、续单费、操作费、海运费、普货海运费、拖柜费和目的港拖车费。

1. 推荐以`提单号 + 柜号`作为主匹配组合，报关单号作为辅助关键单号。
2. 多个费用列必须分别展开，金额合计列只用于预览核对。
3. 海运费、拖柜费、操作费等通常覆盖整票或整柜，应先进入对应提单或柜号成本池，再分摊到包裹和订单。
4. 两个工作表结构接近时可以复用配对模板，但仍须检查是否属于不同账期、不同数据范围或重复清单。

### 4.4 空运成本

#### 4.4.1 `空运头程（力宝.xls`

| 工作表 | 核心字段 | 角色判断 |
| :--- | :--- | :--- |
| `对帐单` | 日期、提单号、磅单号、件数、重量、单价、提单费、收送或打包费、中港段费、报关费、压夜或查验费、金额、账单号。 | 实际成本主来源；多个费用字段分别展开。 |
| `核销报关货价格` | 货物价格或核销参考。 | 报价或计算参考，不作为实际成本主来源。 |
| `付款进度表` | 账单日期、账单金额、付款日期、付款金额、欠款。 | 用于供应商账单结清登记和付款核对，不作为成本明细主来源。 |

提单号和磅单号用于确定空运批次范围。空运费、提单费、中港段费和打包费通常覆盖多件货物，应按提单、磅单、重量或明确包裹范围分摊。

### 4.5 租车成本

#### 4.5.1 `海快租车（仓库送船公司.xlsx`

文件只有`租车`工作表，按月份、地区、发车地、车种和集运线路列示车辆费用及应付金额。典型字段包括不同地区、`9.6米车`、`75方`、小车、挂车、海运、各发车地合计和应付金额。

该样本缺少包裹或订单级关键单号，原则上按月份、集运线路、发车地和车种进入成本池。若后续能够补充车次及其承载范围，可将该范围作为分摊依据；不得仅为通过导入而填入虚构单号。

#### 4.5.2 `海快（深圳搬运工.xlsx`

文件只有`Sheet1`工作表，按月份或汇总口径列示`17.5米车`、`70方车`、海运、其他、金额、已付、差额、图片和备注。

1. 车辆费用、海运相关费用和其他费用应按不同金额含义分别形成成本明细。
2. `已付`和`差`属于付款或核对字段，不应与应付成本金额重复导入。
3. 样本没有稳定包裹或订单单号，整体应作为间接成本进入成本池，并按月份、线路、作业量或财务确认的范围分摊。

## 6. 对导入向导的样本要求

根据上述文件结构，导入向导至少应支持以下能力：

1. 识别一个文件内的多个工作表，并由财务选择实际参与导入的数据范围。
2. 根据工作表角色，优先推荐成本明细，避免把汇总、付款跟踪、报价参考和内部核对重复当作成本金额。
3. 允许同一文件、同一供应商按不同工作表结构保存多套核心财务字段配对模板。
4. 允许指定一个主关键单号和多个辅助关键单号，并明确每个单号的类型。
5. 允许一次选择多个成本金额列，分别映射常规成本费项，再自动展开为一行一项成本明细。
6. 能识别合计列与明细列的包含关系，并在两者同时被选择时阻断重复金额。
7. 原文件没有关键单号时，允许财务显式确认`无关键单号`，将费用作为间接成本或待人工确认成本导入。
8. 完整保留未映射的原始列、原始文件和字段配对版本，但不要求财务填写来源文件名、工作表名或原始行号等追溯字段。
9. 导入前展示原始金额、拟入池金额、展开后明细数、无法匹配数、疑似重复数和阻断异常。
10. 供应商文件结构改变时，应提示差异并要求重新确认受影响字段，不得直接沿用旧配对结果入池。

## 7. 分析边界

1. 本次分析只覆盖现有 10 份样本，不能据此认定其他供应商必然使用相同字段或工作表结构。
2. 本文对直接成本和间接成本的判断基于样本可见单号和费用覆盖范围；最终归属仍取决于 BMS 能否匹配业务对象及财务审核结果。
3. 本文不判断供应商收费金额是否正确，也不替代供应商合同、报价表、付款凭证和财务审核。
4. 工作表名称、繁简体字段和供应商原始用词按样本保留；产品标准字段及枚举以《财务系统 PRD》为准。
