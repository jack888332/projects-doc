## 1. 背景与目标

财务试运营期间需要把现有财务侧报表与 BMS 新版应收账单对账报表按订单、费项并排核对，定位缺单、重复数据、结构异常和费用差异。本轮 PRD 明确收窄了系统侧输入格式、订单主集合、费项对齐方式和结果列结构，同时新增履约时间切换和结构化导入反馈。

本次目标是让“报表比对”变成以系统侧新版`费项明细`父行为主集合、按业务订单号精确关联、按费项字段名完全相等动态对齐的内部测试工具：

1. 只接受新版应收账单对账报表的`费项明细` Sheet，旧版单 Sheet 报表不得再进入比对。
2. 履约时间支持`出库时间`和`结单时间`，默认`出库时间`；生成结果后切换时间只更新第二列、取值和排序，不重新比对。
3. 结果以系统侧业务订单父行为基础，财务侧独有订单不单独成行。
4. 费项不再做映射、别名、相似度或人工确认，只按字段名完全相等对齐，并按两侧并集输出成对列。
5. 固定列收敛为`业务订单号`、所选履约时间、`财务侧报表`、`系统侧报表`；动态费项列与导出保持一致。
6. 导入反馈结构化到来源文件、Sheet 和行号；导出包含`比对明细`和`比对说明`两个 Sheet。

本轮不覆盖返款账单比对、客户对账、账单核销/审批、币种换算、BMS 费项池反写，以及结果跨登录或跨天保存。

新版系统侧文件已经具备 PRD 需要的父行/子行结构和时间字段：

5. `ArBillServiceImpl.exportData`（`bms/biz/.../ArBillServiceImpl.java:438-457`）先生成业务订单父行，再对多于一个子运单号的订单生成尾程包裹子行。

## 5. 落地方案

### 5.1 总体架构

```mermaid
flowchart LR
  U[admin_front 报表比对页] -->|上传两侧 xlsx + 开始比对| C[BmsReportComparisonController]
  C --> S[BmsReportComparisonService]
  S --> FP[财务侧解析：订单号/承运单号/出库/结单/费用字段]
  S --> SP[系统侧解析：仅费项明细/父行/子行/动态费项]
  FP --> M[订单关联 + 财务侧既有汇总]
  SP --> M
  M --> R[系统侧父行主集合 + 费项精确并集 + 结构化反馈]
  R --> E[页面展示/时间切换/导出]
  R --> D[短时会话缓存]
```

继续采用“一次上传、一次计算、短时内存会话、默认不落库”的实现方式，不新增数据库表。

### 5.2 文件解析规则

#### 财务侧

1. 保持现有财务侧格式识别：继续识别`订单号`、`承运单号`、`出库时间`、`结单时间`、`收件人地址`和各费用字段。
2. 兼容财务旧模板多明细 Sheet（如 `6.22`、`6.30`），`核重时间`可识别为出库时间、`末条时间`可识别为结单时间；底部无订单号/承运单号的汇总行直接跳过，不参与金额解析。
3. `核重时间`不再作为比对必需列，也不再进入结果固定列；文件里有该列时保留原始值但不参与比对。
4. 财务侧仍需要至少一个订单关联键；订单号为空且承运单号存在时，该行不自动作为普通订单匹配，只能作为“未关联”反馈保留。
5. 财务侧费用字段继续按现有取数口径汇总，见 5.4。

#### 系统侧

1. 只读取名称完全等于`费项明细`的 Sheet；`账单汇总`、`往期账单冲正信息`、`返款明细`等一律不参与比对。
2. 系统侧必需字段建议至少包括：`业务订单号`、`出库时间`、`结单时间`，且必须存在至少一个费项金额字段。
3. `业务订单号`以`费项明细`首列单元格文本为准；尾程包裹行当前由导出端写成`<订单号> >`，解析时把尾部空格与`>`剔除，不把它计入真实订单号。
4. 以 `BillExportRowTypeEnum.ORDER_LINE` 语义识别父行，即`业务订单号`不以`>`结尾的行；`PACKAGE_LINE` 语义的`以>结尾`子行不进入订单主集合，金额不累计到父行。
5. 系统侧金额直接读取父行单元格数值，不做跨行求和；单元格为数值时优先按数值读取，为文本时才去除显示币种符号后解析，避免把 Excel 显示币种拼入金额。
6. 旧版识别：文件中不存在`费项明细`但表头含`内部订单号`时，一次性提示“请从 BMS 重新导出新版应收账单对账报表”；只存在`返款明细`或缺少必需 Sheet/字段时，按缺失项逐条提示，不开始比对。

#### 币种与文件门禁

1. 两侧文件都必须为 `.xlsx`，文件大小和数据行数沿用当前限制（10MB、5000 行）。
2. 分别按费项收集两侧结算币种。新版系统侧报表通过 Excel 数字格式展示币种；财务旧模板按金额文本或收件人场景识别人民币、新台币。任一侧完全无法识别币种时一次性提示；两侧存在多币种时按各自原币并排输出，不做整体单一币种阻断。
3. 系统不换算币种，也不把 Excel 显示币种拼入金额；金额文本中的“人民币/台币/RMB/NTD”仅用于币种识别和金额清洗。

### 5.3 订单整理与关联

#### 系统侧主集合

1. 结果行只来自系统侧业务订单父行：`业务订单号`非空、不等于`/`、不以`>`结尾。
2. 产品确认正常导出不存在同一业务订单号多条父行；解析仍保留重复校验与反馈作为文件异常兜底，不按多行结果设计。
3. 系统侧业务订单号为空或`/`的记录排除，并作为结构反馈记录到`比对说明`。

#### 财务侧关联

| 财务侧订单号 | 财务侧承运单号 | 关联行为 |
| --- | --- | --- |
| 非空且不等于 `/` | 任意 | 与系统侧`业务订单号`完全相等时认定同一订单；运费、附加费、其他费项都按该订单号关联 |
| `/` | 有值 | 运费和附加费不回连；其他费项（含代收返款相关费项）可按承运单号关联系统侧业务订单号 |
| `/` | 无值 | 不匹配，记入补充匹配未命中反馈 |
| 空 | 有值 | 运费和附加费不成行；其他费项可按承运单号命中系统侧业务订单后成行；未命中时记入补充匹配未命中反馈 |
| 空 | 无值 | 不自动改用承运单号，记入未关联/未命中反馈 |

财务侧同一订单多行时，允许在财务侧汇总阶段按业务订单号和费项字段名求和，但必须在`比对说明`中记录重复订单及原始行号，不静默掩盖重复事实。

### 5.4 费项对齐与汇总

1. 分别识别两侧全部费用字段，形成费项并集；字段名文字、字符或空格不同都视为两个不同费项。
2. 只有字段名完全相等时才认为同一费项；不提供映射区域、别名表、相似度、编辑距离或人工改名入口。
3. 单侧费项也必须输出成对列：仅一侧有值时，另一侧列留空。
4. 动态费项排序：`运费`第一组、`派送费`第二组，其它费项按字段名字符串升序；页面与导出使用同一排序。
5. 财务侧既有汇总口径保持不变：
   - `运费`、`派送费`按订单号汇总。
   - `超材费`、`转板费`、`税金`（含实际报表中的`税金一进一退`）按`收件人地址`筛选同名记录并汇总`其它费用`。
   - `收件人地址 = 代收返款`时，分别把`应收货款`汇总为`代收货款`、把`手续费`汇总为`货到付款手续费`。
6. 财务侧金额按订单和费项汇总后 `setScale(3, HALF_UP)`；系统侧直接读取父行金额原值，不累计子行，也不重新做小数进位。
7. 零值显示`0`；该订单不存在、或该费项无值时对应单元格留空。
8. 校验辅助：比对服务输出以`[报表比对]`为前缀的日志，包含两侧固定字段映射、费项字段并集映射（结果费项 = 财务侧列 / 系统侧列）、解析行数、结算币种和比对结果统计，便于验收时直接核对字段映射关系。

### 5.5 履约时间切换

1. 页面顶部固定展示`履约时间`，默认`出库时间`，可选`出库时间`、`结单时间`。
2. `preview` 只执行一次；响应中每个结果行同时返回两侧的`出库时间`、`结单时间`，页面生成结果后切换时间只做前端列名、取值和排序切换，不重新调用 `preview`。
3. 时间取值：同一订单优先取财务侧值，财务侧为空时取系统侧值，两侧都为空时留空。
4. 排序：按当前履约时间字段倒序；时间相同不作为业务规则要求，实现可保留`业务订单号`倒序作为稳定次排序。
5. 任一侧重新上传后，前端清空比对结果但保留当前履约时间选择；`开始比对`在两侧文件均成功后可用。
6. 导出时把当前时间字段传给后端，导出列名、取值和排序与页面一致。

### 5.6 结果展示

固定列依次为：

| 列 | 说明 |
| --- | --- |
| `业务订单号` | 系统侧父行业务订单号 |
| `出库时间` 或 `结单时间` | 当前履约时间，列名随选择变化 |
| `财务侧报表` | 财务侧存在性打钩，不存在留空 |
| `系统侧报表` | 系统侧存在性打钩，不存在留空 |

其后为动态费项成对列：`<费项名称><财务侧>`、`<费项名称><系统侧>`。

页面不再展示`订单号/匹配键`、`主运单号`、`核重时间`、`财务侧行号`、`系统侧行号`、`差异类型`；这些定位信息只进入导入反馈或`比对说明`。

结果上方展示结构化导入反馈摘要：

| 反馈类型 | 建议文案 | 定位信息 |
| --- | --- | --- |
| 文件结构异常 | 缺少 Sheet、缺少必需字段、文件损坏等 | 来源文件、Sheet、表头或数据行号 |
| 重复订单 | 财务侧或系统侧同业务订单号出现多行 | 来源文件、Sheet、各原始行号 |
| 重复承运单号 | 财务侧或系统侧承运单号重复 | 来源文件、Sheet、各原始行号 |
| 补充匹配未命中 | `/`订单号的附加/代收行、空订单号行未命中系统侧订单 | 来源文件、Sheet、行号 |

异名费项不作为导入异常，按两个单侧费项正常输出。

### 5.7 导出

导出文件固定为两个 Sheet：

1. `比对明细`：列结构与页面一致，固定列在前，动态费项成对列在后，按当前履约时间字段导出并排序。
2. `比对说明`：保留表头，写入本次结构化导入反馈；没有反馈时不写空白说明行，只保留表头。

`比对说明`表头建议为：`反馈类型`、`来源文件`、`Sheet`、`行号`、`说明`。

导出只输出当前用户短时会话内的结果；结果未生成时前端禁用导出按钮。

### 5.8 接口与 DTO 调整

建议保留现有两个接口路径，内部语义调整：

| 接口 | 调整 |
| --- | --- |
| `POST /reconciliation/preview` | 删除 `confirmedMappings` 参数；响应增加结构化反馈、两侧出库/结单时间，移除 mappings/差异类型等旧字段 |
| `GET /reconciliation/export` | 增加 `timeField`（`DELIVERY_TIME` 或 `SETTLEMENT_TIME`），默认 `DELIVERY_TIME`；按该时间字段和页面列结构导出 |

DTO 调整：

1. `BmsReportComparisonPreviewRespDTO`：保留 `sessionId`、`feeColumns`、`rows`、`summary`；新增 `feedbacks`，删除 `mappings`。
2. `BmsReportComparisonRowDTO`：增加 `financeDeliveryTime`、`financeSignedTime`、`systemDeliveryTime`、`systemSignedTime`；移除 `orderKey/mainWaybillNo/measureTime/financeMeasureTime/systemMeasureTime/differenceTypes/financeRowNo/systemRowNo/feeDifferences`，或仅保留内部用于反馈的原始行号但不出现在页面固定列。
3. `BmsReportComparisonFeeColumnDTO`：可简化为 `feeName` 加两侧原始列名，页面和导出都按同一集合渲染。
4. `BmsReportComparisonSummaryDTO`：移除 `financeOnlyCount/measureTimeMismatchCount/unconfirmedMappingCount`；建议改为 `systemOrderCount`、`financeMatchedCount`、`systemOnlyCount`、`duplicateOrderCount`、`duplicateWaybillCount`、`unmatchedCount`、`settlementCurrency`。
5. 新增 `BmsReportComparisonFeedbackDTO`：`type`、`source`（FINANCE/SYSTEM）、`sheetName`、`rowNo`、`message`。
6. 删除 `BmsReportComparisonMappingDTO` 或停止使用。

### 5.9 试运营关闭入口

1. 路由 `meta.code` 或菜单 `permissionButtonCode` 增加固定权限码，已按权限系统实际配置使用 `reportComparison`。
2. 试运营结束时通过权限码关闭入口：菜单不可见、路由不可访问、不再创建新的比对任务；已生成的短时会话到期后自然失效。
3. 不在本次新增后端独立开关；后端接口按平台现有权限体系校验权限码。

## 7. 疑问点与确认结果

Q1. `结单时间`字段是否就是当前新版导出中的 `signedTime`，还是需要换用订单完结时间？

已确认：`结单时间`就是订单完结时间，方案沿用当前新版导出中的 `signedTime` 列。

Q2. 系统侧同一业务订单号出现多条父行时，结果页如何展示？

已确认：正常导出不存在这种情况；实现仍保留重复校验和反馈作为文件异常兜底，不设计多行结果展示。

Q3. 财务侧订单号为空但承运单号能命中系统侧订单时，是否完全不成行？

已确认：运费和附加费不成行；其他费项可以按承运单号命中系统侧业务订单后成行。未命中时在`比对说明`保留可定位信息。

Q4. `/`订单号行的直接费用如何呈现？

已确认：运费和附加费不回连；其他费项（含代收返款相关费项）可以按承运单号回连。

说明：该口径与 PRD 19.4.2.3 原文“附加费用和代收返款使用承运单号”不完全一致，本文档按产品本次答复执行，建议同步修订 PRD。

Q5. 缺少必需字段时“一次性提示缺失项”的最小集合是什么？

已确认：按方案默认执行，系统侧至少要求`业务订单号`、`出库时间`、`结单时间`和至少一个费项字段；`核重时间`不作为必需列。

Q6. 生成结果后切换履约时间，排序规则如何？

已确认：按当前履约时间倒序即可；时间相同不再要求按业务订单号倒序，实现可保留该次排序作为稳定排序。

Q7. 页面费项列标签使用哪种括号？

已确认：使用尖括号，即`<财务侧>`和`<系统侧>`。

Q8. 是否完全删除“差异类型”概念？

已确认：是。页面和导出都不再输出差异类型，只保留存在性和金额并排。

Q9. 试运营结束关闭入口使用权限码还是配置开关？

已确认：使用权限码即可，不在本次新增后端独立开关。

Q10. 财务侧汇总后的 3 位小数和系统侧父行金额如何处理？

已确认：系统侧读取父行金额原值，不需要考虑小数进位；财务侧汇总口径继续按 PRD 使用三位小数四舍五入。

## 8. 验收与回归建议

| 场景 | 预期结果 |
| --- | --- |
| 上传旧版单 Sheet 系统侧报表 | 提示重新导出新版应收账单对账报表，不开始比对 |
| 上传只有`返款明细`或缺少必需字段的文件 | 一次性列出缺失项，不开始比对 |
| 上传新版`费项明细`文件 | 只取父行，尾程包裹子行不进入结果、金额不累计 |
| 两侧订单号一致 | 同一订单一行，两侧存在性都打钩 |
| 财务侧独有订单 | 不单独成行，但可在反馈中看到未关联信息 |
| 财务侧`/`订单号的运费和附加费 | 不回连，不输出对应金额 |
| 财务侧`/`订单号的其他费项 | 按承运单号命中系统侧订单并输出对应财务侧金额 |
| 财务侧空订单号的运费和附加费 | 不成行；其他费项可按承运单号成行；均保留未命中反馈 |
| 两侧同名字段但字符/空格不同 | 视为两个费项，分别输出单侧空白列 |
| `运费`、`派送费`动态列 | 分别第一、第二组，其它费项按字段名排序 |
| 金额为 0 与无金额 | 0 显示为 `0`，无金额留空 |
| 生成结果后切换履约时间 | 第二列列名/取值/排序变化，不重新调用 `preview` |
| 任一侧重新上传 | 结果立即失效，履约时间选择保留 |
| 导出 | 一个`比对明细` Sheet + 一个`比对说明` Sheet；无反馈时说明 Sheet 只有表头 |
| 试运营关闭 | 通过权限码关闭后菜单隐藏、路由不可访问、不再创建新的比对任务 |

回归建议：

1. `mvn -f platform-admin/pom.xml -pl web -am test-compile -DskipTests` 验证 Java 编译。
2. `admin_front` 使用项目固定 Node 14 执行构建，确认 Vue 2.6 页面可编译。
3. 手工准备一份财务侧样本、一份新版系统侧导出，覆盖 Q1-Q10 的主要边界后记录验收结果。
