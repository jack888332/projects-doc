# BMS 应收账单履约节点由“核重”调整为“出库”技术方案（2026-06-26）

## 1. 文档目的

本文基于 `aidocs/product-caliber/bms/prd/财务系统.PRD.md` 在提交 `8272e1ab6890d8c25fe76e02120a135450afc9f6` 中的变更，结合当前仓库实现，制定“应收账单配置中的履约节点由【核重】调整为【出库】”的完整技术调整方案。

本次文档已经结合产品确认结论收口，不再是待确认方案：

1. 真实出库时间字段已确认使用 `sale_order_header.delivery_time`。
2. 本轮按“一次改全量”执行，不拆成“先改展示、后改逻辑”两期。
3. 历史编码 `WEIGHT_OUTBOUND` 保留。
4. 数据库字段名、接口字段名不改。
5. 不做历史数据清洗。
6. `admin-front` 和 `admin_shell` 两个前端都需要同步调整。

## 2. 需求结论

根据新版 PRD，本次变更的最终业务口径如下：

1. 应收账单配置中的履约节点只允许选择【出库】和【签收】。
2. 原“核重出库”口径在产品和页面层面全部收敛为“出库”。
3. `WEIGHT_OUTBOUND` 仅作为历史编码沿用，其业务含义从“核重出库”改为“出库”。
4. 出库节点的归集时间口径不再使用 `measure_time`，统一改为 `sale_order_header.delivery_time`。
5. 与出库节点关联的账单生成、费项数据集配置、源数据迁移、页面展示、初始化 SQL、技术文档都要同步切换。

## 3. 现状盘点

## 3.1 后端现状

当前 BMS 后端仍把“普通履约节点”绑定为 `measure_time`：

1. `bms/model/src/main/java/com/szt/supplychain/bms/model/enums/ContractNodeEnum.java`
   - `WEIGHT_OUTBOUND("WEIGHT_OUTBOUND", "核重出库")`

2. `bms/client/src/main/java/com/szt/supplychain/bms/client/api/enums/ContractNodeEnum.java`
   - 同样返回“核重出库”

3. `bms/biz/src/main/java/com/szt/supplychain/bms/biz/service/impl/BillConfigServiceImpl.java`
   - 新建账单配置默认 `contractNode = WEIGHT_OUTBOUND`
   - `options()` 中的履约节点选项描述来自枚举

4. `bms/biz/src/main/java/com/szt/supplychain/bms/biz/service/impl/BillGenerateServiceImpl.java`
   - `defaultOrderTimeFieldByContractNode()` 非签收节点默认走 `measure_time`
   - `normalizeOrderTimeField()` 不支持 `delivery_time`
   - `orderTimeExpr()` 不支持 `delivery_time`

5. `bms/dao/src/main/java/com/szt/supplychain/bms/dao/mapper/BillGenerateMapper.java`
   - `billingTimeExpr()` 非签收节点默认拼接 `measure_time`

6. `bms/disconf/download/bill_generate_conf.properties`
   - `order.time.field.default=measure_time`

7. `bms/biz/src/main/java/com/szt/supplychain/bms/biz/service/impl/SourceDataMigrationServiceImpl.java`
   - 时间字段白名单不含 `delivery_time`

8. `bms/model/src/main/java/com/szt/supplychain/bms/model/dto/SourceDataMigrationReqDTO.java`
   - 默认时间字段仍为 `measure_time`

结论：当前系统不是只有文案旧，而是“默认履约节点 = measure_time”已经进入了真实归集逻辑。

## 4. 核心设计决策

## 4.1 保留历史编码，不改物理字段

本次明确不改以下编码和字段名：

1. `WEIGHT_OUTBOUND`
2. `contract_node`
3. `weight_outbound_time_column`
4. `supported_contract_nodes`

原因：

1. PRD 已允许 `WEIGHT_OUTBOUND` 作为历史编码沿用。
2. 当前后端、前端、SQL 初始化脚本、已有配置结构均依赖这些名称。
3. 本次目标是“业务语义切换 + 真实时间口径切换”，不是“全链路字段重命名”。

最终策略：

1. 编码不变。
2. 展示文案全部改为“出库”。
3. `WEIGHT_OUTBOUND` 在逻辑上统一解释为“出库节点”。

## 4.2 本轮直接完成逻辑切换

本轮不拆期，直接完成以下两类改动：

1. 展示和命名切换
2. 真实归集时间由 `measure_time` 切到 `delivery_time`

因此本次文档不是“阶段性过渡方案”，而是本轮交付口径。

## 4.3 不处理历史数据

本轮明确不处理以下历史数据：

1. 已落库的 `bill_config.contract_node`
2. 已落库的 `fee_source_dataset.supported_contract_nodes`
3. 已落库的 `settlement_terms_profile` 中历史中文值
4. 已存在的数据集时间字段配置

本轮只保证：

1. 新代码兼容读取历史 `WEIGHT_OUTBOUND`
2. 新页面统一展示为“出库”
3. 新逻辑统一按 `delivery_time` 执行

## 5. 目标方案

## 5.1 业务语义目标

改造完成后，系统内关于出库节点的统一语义如下：

1. 页面展示：`WEIGHT_OUTBOUND -> 出库`
2. 配置语义：应收账单履约节点只允许“出库 / 签收”
3. 数据集语义：`weight_outbound_time_column` 表示“出库时间表达式”
4. 账单生成语义：出库节点统一使用 `h.delivery_time`
5. 源数据迁移语义：出库时间筛选统一使用 `delivery_time`

### 5.2.5 返款账单影响说明

虽然本次 PRD 直接修改的是“应收账单履约节点”，但当前系统中的订单类主数据集是共享的，因此会带来以下联动：

1. `BillGenerateServiceImpl.resolveRefundOrderTimeField()`
   - 当返款模式不是回款模式，且数据集使用 `WEIGHT_OUTBOUND` 时，回退路径也会随 `weightOutboundTimeColumn` 改到 `delivery_time`

本次建议：

1. 不单独新增返款专属口径分叉
2. 保持共享数据集的一致性
3. 在文档中显式说明这是“共享数据集联动结果”，不是额外需求扩张

## 8. 风险与注意事项

1. 本轮虽然不处理历史数据，但新逻辑切到 `delivery_time` 后，同一账期下的命中订单范围可能与旧口径不同，这是预期变化，不是回归缺陷。
2. 当前系统里仍有一些“核重”字样用于仓储业务字段，如“核重重量”，这些不属于本次账单履约节点改造范围，不能误改。
3. `weight_outbound_time_column` 字段名虽然保留，但其业务含义已变为“出库时间表达式”，后续开发必须按新语义使用。
4. 如果某些测试环境里的数据集配置仍停留在 `h.measure_time`，即使代码改完，生成结果也可能仍像旧逻辑，因此必须补数据修正。

## 9. 结论

本次调整不是简单的文案替换，而是一次真实业务口径切换：

1. 编码层仍保留 `WEIGHT_OUTBOUND`
2. 展示层统一改为“出库”
3. 逻辑层统一把出库时间从 `measure_time` 切到 `sale_order_header.delivery_time`

改造完成后，BMS 中“应收账单履约节点 = 出库”的含义才能与新版 PRD 完全一致，且两个前端、后端生成逻辑、源数据迁移工具、初始化 SQL 和技术文档都将保持同一口径。
