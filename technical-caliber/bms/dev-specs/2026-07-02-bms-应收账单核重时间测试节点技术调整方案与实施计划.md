### 2.2 核心业务变化

1. 生产环境的应收账单履约节点仍只允许“出库时间”和“订单完结”。
2. 测试环境额外开放“核重时间”，用于验证账单生成、费项归集和重跑链路。
3. “核重时间”使用独立编码 `WEIGHT_MEASURED`，时间口径可取 `sale_order_header.measure_time`。
4. “出库时间”继续使用历史编码 `WEIGHT_OUTBOUND`，但业务含义必须是出库完成时间，不能再把该编码解释为核重。
5. 生产环境不仅要隐藏“核重时间”，还必须阻止保存、启用和生成任务按 `WEIGHT_MEASURED` 生效。
6. “签收”仍不是应收账单履约节点；订单广义签收由“订单完结”承接。
7. 验收标准新增环境差异：测试环境可见、可选、可生成；生产环境不可见、不可选、不可通过接口绕过。

## 3. 当前代码核对结果

### 3.1 后端现状

1. `bms/model/.../ContractNodeEnum.java` 和 `bms/client/.../ContractNodeEnum.java` 目前只有：
   - `WEIGHT_OUTBOUND("WEIGHT_OUTBOUND", "出库")`
   - `ORDER_COMPLETED("ORDER_COMPLETED", "订单完结")`
2. `BillConfigServiceImpl.options()` 无环境过滤，直接遍历枚举并返回全部履约节点。
3. `BillConfigServiceImpl.buildBillConfig()` 只允许 `WEIGHT_OUTBOUND` 和 `ORDER_COMPLETED`，其它值统一抛出“履约节点仅支持出库或订单完结”。因此当前即使前端提交 `WEIGHT_MEASURED` 也无法保存。
4. 新建配置未传履约节点时默认使用 `WEIGHT_OUTBOUND`，该默认值应继续保留，不能因测试节点加入而改变。
5. `BillGenerateServiceImpl` 当前只针对 `ORDER_COMPLETED` 和历史签收编码分流，其余节点走默认出库时间口径；若只新增枚举而不新增显式分支，`WEIGHT_MEASURED` 会错误地走出库时间。
6. 当前工程可以通过 Spring Profile 区分 `dev/local` 等运行环境，但业务层尚未形成“测试环境能力开关”的统一判定方式。

### 3.2 Admin Shell 现状

1. 指定目录内的主要入口是 `admin_shell/src/views/billing/billConfig/index.vue`。
2. 该页面的分支方案列表通过 `formatContractNode()` 本地映射履约节点，目前仅包含：
   - `WEIGHT_OUTBOUND -> 出库`
   - `ORDER_COMPLETED -> 订单完结`
   - 兼容历史 `SIGN/SIGNED -> 签收`
3. 选项接口已定义在 `admin_shell/src/api/billing.js`：`GET /portal/bms/billConfig/options`，符合 API 必须通过 `src/api/` 的项目规范。
4. `billConfig/index.vue` 自身没有应收配置表单，而是导入 `admin_shell/src/views/clientmgr/listofCustomers/SettlementSettingPanel.vue` 完成新建和编辑。也就是说，仅修改 `src/views/billing/` 无法完成测试节点的选择与保存。
5. 前端不应自行通过域名、端口或构建模式决定能否显示测试节点，应直接使用后端 `contractNodeOptions`，后端是环境权限的唯一可信来源。

## 4. 技术调整方案

### 4.1 总体原则

1. 新增独立编码 `WEIGHT_MEASURED`，不得复用或改写 `WEIGHT_OUTBOUND`。
2. 采用“服务端环境开关 + 服务端强校验 + 前端按接口展示”的三层控制。
3. 测试能力默认关闭；只有明确配置为开启的环境才允许核重节点，避免把未知环境误判为测试环境。
4. 生产禁用必须覆盖选项查询、配置保存/启用、手动生成、定时生成和重跑，不能只靠前端隐藏。
5. 历史生产配置如异常存在 `WEIGHT_MEASURED`，允许查询展示审计信息，但禁止启用和生成；不得静默改写成出库时间。

### 4.2 环境控制设计

在实际声明 Maven Profiles、并执行资源过滤的 `bms/web/pom.xml` 中显式增加业务属性，通过 `application.yml` 注入 Spring 配置。目标矩阵如下：

| Maven Profile | 开关值 |
| --- | --- |
| `dev` | `true` |
| `test` | `true` |
| `local` | `true` |
| `prod` | `false` |

建议 Maven 属性使用 `bms.bill-config.weight-measured-enabled` 或等价的点分属性，并在 `application.yml` 中通过资源过滤形成最终配置。`prod` 必须显式写为 `false`，同时代码读取时仍以 `false` 为缺省值，形成“双保险”。不得仅通过 `spring.profiles.active != prod` 推断。

当前 BMS 聚合根 `pom.xml` 没有声明 profiles；实际 profiles 位于 `bms/web/pom.xml`。实施时在该 POM 的现有 `dev/test/prod` 中增加属性，并新增 `local` Profile，保持 `dev` 默认激活和原有 `env` 资源过滤行为不变。

后端封装单一判断方法，例如 `isWeightMeasuredEnabled()`，供以下流程统一复用：

1. `BillConfigServiceImpl.options()`：仅开关开启时追加核重时间选项。
2. 配置保存与启用：`WEIGHT_MEASURED` 必须同时满足开关开启。
3. 手动生成、定时扫描、失败重试和账单重跑：执行前再次校验，防止历史数据或接口绕过。

开关常量和节点编码应放入 `common/model` 现有常量或枚举体系，不在 Service 中散落字符串。

### 4.3 后端枚举与接口调整

建议修改：

1. `bms/model/.../ContractNodeEnum.java`
2. `bms/client/.../ContractNodeEnum.java`
3. `bms/biz/.../BillConfigServiceImpl.java`

目标：

1. 两份契约枚举同步增加 `WEIGHT_MEASURED("WEIGHT_MEASURED", "核重时间")`。
2. `WEIGHT_OUTBOUND` 的显示名由当前“出库”统一为 PRD 的“出库时间”。
3. `options()` 按开关动态构造节点列表；生产只返回出库时间、订单完结，测试额外返回核重时间。
4. 抽取节点合法性校验，分别处理“未知节点”和“当前环境禁止节点”。
5. 保持未传值时默认 `WEIGHT_OUTBOUND`。

接口 DTO 无需新增字段，继续使用现有 `BillConfigOptionDTO` 和 `contractNodeOptions`，避免使用 `Map`。

### 4.4 配置保存、启用与历史数据保护

`BillConfigServiceImpl` 的创建、整份保存、状态启用流程均应调用同一环境化校验：

```text
节点不在枚举中 -> 拒绝
WEIGHT_MEASURED 且开关关闭 -> 拒绝
WEIGHT_MEASURED 且开关开启 -> 允许
WEIGHT_OUTBOUND / ORDER_COMPLETED -> 允许
```

错误信息应可直接用于联调，例如：“核重时间履约节点仅允许在测试环境使用”。

不建议执行数据库批量清洗。本需求新增的是测试能力，生产侧应通过扫描 SQL 或启动检查确认不存在启用中的 `WEIGHT_MEASURED` 配置；若存在，先停用并人工核对，不自动改成 `WEIGHT_OUTBOUND`。

### 4.5 账单生成与重跑调整

建议修改 `BillGenerateServiceImpl` 及实际生成 SQL 表达式选择位置：

1. `WEIGHT_MEASURED` 显式映射到 `measure_time` 或数据集定义的核重时间表达式。
2. `WEIGHT_OUTBOUND` 显式映射到真实出库时间表达式，不能再依赖“非订单完结就走默认字段”的兜底逻辑。
3. `ORDER_COMPLETED` 继续映射订单完结时间表达式。
4. 生成任务创建时将节点编码、实际时间字段/表达式、环境开关状态固化到任务快照或日志。
5. 执行任务和重跑任务时重新校验环境权限；生产环境遇到 `WEIGHT_MEASURED` 任务必须失败并记录明确原因。
6. 核重测试账单仍遵守来源行锁、幂等、账期范围和费项唯一归集规则，不能因“仅测试”绕过正常生成约束。

### 4.6 数据集设计

已确认不新增 `fee_source_dataset.weight_measured_time_column`，采用后端受控固定映射：

1. `WEIGHT_MEASURED` 固定映射为主订单 `sale_order_header.measure_time`，在现有查询别名下使用 `h.measure_time`。
2. `WEIGHT_OUTBOUND` 继续使用现有出库时间配置，不能复用 `weightOutboundTimeColumn` 表达核重时间。
3. 附加费和其它非主订单来源通过既有主订单关联取得 `h.measure_time`；没有合法主订单关联或主订单核重时间为空时，不得猜测其它时间字段，应按来源不满足归集条件处理并记录原因。
4. 固定表达式只由后端常量/分支产生，不接受前端、接口参数或数据库配置传入任意 SQL。
5. 任务快照必须记录最终使用的 `h.measure_time`，弥补数据库没有独立核重时间配置字段的可追溯性。

该方案不涉及数据库结构变更，也不需要修改 `fee_source_dataset` 实体、DTO、Mapper 和建表归档。

### 4.7 Admin Shell 调整

指定目录内建议调整：

1. `admin_shell/src/views/billing/billConfig/index.vue`
   - `formatContractNode()` 增加 `WEIGHT_MEASURED: "核重时间"`。
   - `WEIGHT_OUTBOUND` 展示统一为“出库时间”。
   - 不在本地维护“测试环境选项集合”，列表只负责兼容回显。
2. `admin_shell/src/api/billing.js`
   - 继续复用现有 `getBillConfigOptions`，无需新增接口或硬编码 URL。

已确认纳入的关联调整：

1. `admin_shell/src/views/clientmgr/listofCustomers/SettlementSettingPanel.vue`
   - 该组件才是 `billing/billConfig/index.vue` 实际使用的应收配置表单。
   - 下拉选项应完全使用后端 `contractNodeOptions`。
   - 测试环境后端返回核重时间时允许选择；生产未返回时不展示。
   - 编辑历史核重配置但当前环境禁用时，可只读回显并提示，不允许保存为启用状态。

该目录外组件已获准纳入后续实施范围，可以完成“新增/编辑配置选择核重时间”的产品闭环。

### 4.8 数据库与文档同步

1. 本方案不新增数据集字段，不涉及数据库结构变更，无需调整完整建表归档。
2. 不修改 `bill_config.contract_node` 字段结构，现有字符串字段直接承载 `WEIGHT_MEASURED`。
3. 测试环境可按需补充测试配置数据，但不得把测试数据 SQL 混入生产初始化脚本。
4. 实施完成后同步账单生成流程文档，明确三个节点的编码、时间字段和环境边界。

### 阶段三：生成时间口径（P0）

1. 为三个节点建立显式时间表达式映射。
2. 补齐核重字段的数据集配置或受控固定映射。
3. 在任务创建、执行、重跑入口加入生产禁用校验。
4. 固化任务快照和失败原因。

1. 修改 billing 目录内列表回显。
2. 经范围确认后修改实际表单组件，使下拉完全由后端选项驱动。

交付物：测试环境可选核重时间，生产不可见；列表名称一致。

### 阶段五：验证与发布（P0）

1. 测试环境分别用三个节点生成相同账期账单，核对来源 SQL、命中订单和任务快照。
2. 验证核重时间为空、账期边界、重复重跑、部分失败和来源行幂等。
3. 在生产配置下验证选项不返回核重、直接调用保存接口被拒绝、历史核重任务不能执行。
4. 发布顺序建议：后端防护与时间映射 -> 数据配置/DDL -> 前端。

## 7. 风险与注意事项

1. 最大风险是只改前端隐藏。接口、历史配置和任务重跑仍可能让生产按核重出账，必须服务端全链路防护。
2. `WEIGHT_OUTBOUND` 是历史编码，名称带 `WEIGHT` 但当前业务语义是出库；实现时不能根据字符串猜测时间字段。
3. 若出库节点当前仍实际使用 `measure_time`，本次核重节点加入会暴露两个编码命中同一字段的问题，联调前必须核对真实生成 SQL。
4. `measure_time` 早于出库完成，测试账单金额可能尚未稳定；该节点只能验证技术链路，不能把结果作为生产结算依据。
5. 前端实际编辑组件位于 billing 目录外，现已纳入实施范围；开发时需同时验证 billing 入口和复用表单，避免只改列表回显。
6. 本方案明确不新增数据集字段；后端固定映射必须保持受控，不能演变为可由请求参数拼接的动态 SQL。

## 8. 疑问点

### 8.1 已确认问题

1. 开放环境：`test`、`dev`、`local`；关闭环境：`prod`。
2. 开关位置：`bms/web/pom.xml` 的 Maven Profile 中显式配置，并过滤到 `application.yml`。
3. 正式编码：`WEIGHT_MEASURED`，无需兼容其它编码。
4. 时间字段：固定使用 `sale_order_header.measure_time`，其它来源跟随主订单关联取值。
5. 数据结构：不新增 `weight_measured_time_column`，采用后端受控固定映射。
6. 前端范围：允许修改 `SettlementSettingPanel.vue`。

### 8.2 发布前确认

1. 生产数据库是否可能已经存在手工写入的核重节点配置或未完成任务？发现后应停用、删除还是保留审计？
2. 测试核重账单是否需要明显的测试标识，防止导出、发送、核销或财务对账误用？
3. 核重节点生成的测试账单是否允许进入审核、发送和核销，还是只允许停留在起草/任务验证阶段？
4. 核重节点是否只开放给特定测试账号/权限码？仅按环境开放可能让测试环境所有财务用户都可见。
5. 前端历史 `SIGN/SIGNED` 回显是否继续保留，还是应按 PRD 彻底隐藏并只做后端审计展示？

## 9. 结论

该提交要求新增的是一个独立、仅非生产环境可用的“核重时间”节点，而不是把生产“出库时间”改回核重。最终方案已收口为：`WEIGHT_MEASURED` 编码，`dev/test/local` 在 POM 中显式开启、`prod` 显式关闭，服务端在选项、保存、启用、生成和重跑全链路校验，核重时间由后端受控固定映射到主订单 `sale_order_header.measure_time`，不新增数据库字段；前端同时调整 billing 页面和其实际复用的 `SettlementSettingPanel.vue`。
